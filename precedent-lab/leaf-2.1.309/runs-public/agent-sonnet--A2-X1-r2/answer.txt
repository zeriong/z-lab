**Risks**
- **Remounting:** the comment at the top of the module says the tab key is also the React key and the URL state. The record says §stable-tab-keys came from the 2026-08-29 incident. Now, closing a tab gives every tab to its right a new key, so React remounts them and they lose scroll position and unsaved input. That brings back the incident's behaviour. If you want contiguous keys without this, give each tab a separate stable id to use as its React key. That wasn't added.
- **Stale URLs:** `?tabs=` links or bookmarks saved before a close may now point to a different tab, or to none.
- **Held keys:** any code that holds a key across a close will be wrong, because `closeTab` doesn't return an old-to-new key mapping. Examples are async results, handler closures, caches and saved layouts. A late write could land on the wrong tab. Nothing in this repo does that, but code outside it might.

To double-check, run `git diff` and `npm test` yourself.
