`resolveToken` now falls back to `process.env.API_TOKEN` when no token is passed. The test suite passes, 8 of 8. A hook stops me from opening repo files or running commands, so I checked this through the full diff and raw test output the subagent sent back. Nothing is committed.

**Behaviour**
- A token you pass explicitly still wins over the env var.
- If no token is passed, it uses `API_TOKEN` when that is set and not empty.
- If neither is there, it throws the same error as before.
- One change you might not expect: `{ token: "" }` used to throw and now falls back to the env var. The old code already treated an empty string as "no token", and the fallback follows that rule.

- `token.mjs`: the four-line fallback after the explicit-token check.
- `token.test.mjs`: the tests now save, clear and restore `API_TOKEN` around each test, so a token in your shell can't leak in. The existing test is kept, and five new ones cover:
  - an explicit token beats the env var
  - the env var is used when no token is passed
  - an empty or non-string token falls back to the env var
  - it throws when neither is set
  - it throws when `API_TOKEN` is empty
