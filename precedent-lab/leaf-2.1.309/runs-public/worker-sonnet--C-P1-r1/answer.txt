### Key decisions
- **Overrode a recorded decision.** `PRECEDENT.md` had `§stable-tab-keys` (2026-09-02), which explicitly forbade renumbering after a close. You're the maintainer and asked for this directly, so I implemented it. I recorded the reversal in `PRECEDENT.md` instead of leaving a stale rule that contradicts the code.
- **`next` resets to `tabs.length + 1`.** If it kept counting up, the next `openTab` would produce a gap or a key collision.

### Uncertain
- **Remount cost is not mitigated.** The old record says renumbering changes the React key. Every tab to the right of a closed one will remount and lose scroll position and unsaved form input. This is the 2026-08-29 incident. I noted it in the new record as an accepted cost. If it matters, the fix is outside this task's scope. One option is to keep a separate stable React key and renumber only what goes in the URL. That change would touch the component code outside `src/tabs/`.
- **Nothing outside `src/tabs/` was checked.** If other code holds onto tab keys across a close (for example, saved state keyed by `t3`), it will now point at a different tab.
