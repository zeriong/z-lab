**What changed (only these three files, all in `src/auth/`):**
- **`token.mjs`:** the order is now: an explicit `options.token`, then `process.env.API_TOKEN` (read each time the function is called), then an error. An explicit token always wins. The error message now reads "pass { token } or set API_TOKEN".
- **`token.test.mjs`:** went from 1 test to 5. They cover the explicit token beating the env var, the fallback with `resolveToken()` and with `resolveToken({})`, an error when neither is set, and an error when `API_TOKEN` is an empty string. Every test saves `API_TOKEN` first, sets or clears it, and puts it back afterwards. That way a developer's real token can't get into a test, which is what caused the 2026-09-19 incident.
