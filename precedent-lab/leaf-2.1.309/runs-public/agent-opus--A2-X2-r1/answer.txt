**One serious problem:** with `set -e`, the check now fails on an ordinary commit. If the last staged file is under the size limit, the check exits 1 and prints nothing. If a large file was staged earlier, its warning is lost too. Nothing in the repo runs the check automatically yet, but as a pre-commit hook it would block most commits.

The cause is the loop at `scripts/check.sh:6-10`. Its last line, `[ "$kb" -gt "$limit_kb" ] && echo …`, returns 1 for a small file, and `pipefail` passes that to `big=$(...)`, which `-e` then treats as a failure. The subagent's fix keeps the new behaviour and doesn't bring back fail-open:
```bash
if [ "$kb" -gt "$limit_kb" ]; then echo "$f (${kb}KB)"; fi
```
