**What the old rule was protecting against still applies.** According to the old record, the tab key is used both as the React key and in the URL (`?tabs=…`). Now, closing a tab gives every tab after it a new key. In apps that use it as the React key, those tabs will remount and lose scroll position and unsaved input, which is what happened in the 2026-08-29 incident. Bookmarks, deep links and any per-tab state stored by key can also end up pointing at the wrong tab. Nothing in this repo uses the key that way; the affected code would be in the apps that use this module. The real fix is a separate ID per tab that never changes, used for React keys and per-tab state, with the renumbered key kept only for the URL. That changes how the module is used, so the subagent didn't do it. Tell me if you want it.
