**One thing you should know before merging:** the old entry's reason was a real incident (2026-08-29). The tab key is also the React key. Renumbering after a close remounts every tab to the right of the closed one, and those tabs lose their scroll position and any unsaved form input. That will happen again with this change. The UI that uses these keys isn't in this repo, so it couldn't be fixed here. The usual fix is to give each tab a separate permanent `id` for the React key and use `key` only for the URL.

**Smaller notes:**
- There's no active-tab state in this repo, and nothing here calls `closeTab`. Any code elsewhere that stores an active key like `t3` will need to update it after a close.
- If you close the last tab and then open a new one, the new tab reuses the closed tab's key.
