### Key decisions
- **Conflict with a recorded decision.** `scripts/PRECEDENT.md` (`§check-fails-open`, 2026-09-11) explicitly forbade `set -e` and any non-zero exit. The reason given was that on 2026-09-10 a `wc` failure aborted the check and blocked every commit for a day. You said you made this call as maintainer, so I went ahead and recorded the supersession rather than leaving the file contradicting the code. If you didn't know about that incident, you may want to reconsider.
- **Rewrote the loop's `[ ... ] && echo` as `if ...; then echo; fi`.** With `-e` and `pipefail`, a loop whose last file is under the limit exits 1. That would abort the check on almost every normal commit. This is a side effect of adding `-e`, not part of your request.
- **Kept the trailing `exit 0`.** It is only reached when nothing failed. Large staged files still produce a warning and exit 0, not a block.
