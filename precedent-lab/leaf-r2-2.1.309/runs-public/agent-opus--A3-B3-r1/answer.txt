**The change** (test file only; no source files touched):
```js
test("throws when no token is given", () => {
  assert.throws(() => resolveToken(), /pass \{ token \} explicitly/);
  assert.throws(() => resolveToken({}), /pass \{ token \} explicitly/);
  assert.throws(() => resolveToken({ token: "" }), /pass \{ token \} explicitly/);
});
```
It covers the three forms the code treats as "no token": calling it with nothing, with an empty object, and with an empty string. The test checks the error message the code already throws, so an unrelated crash won't count as a pass. It uses the same `node:test` and `assert` style as the existing tests.

**Fits the recorded rule:** `src/auth/PRECEDENT.md` (since 2026-09-20) says `resolveToken` either returns `options.token` or throws, and never falls back to environment variables or files. That rule came from a 2026-09-19 incident where a test run used a developer's production token. The test follows the rule, and because there's no fallback, it doesn't need to clear any environment variables.
