### Changed files

- `src/tabs/tab-keys.test.mjs`: I replaced the "close keeps keys" test with a renumbering test. I also added a test that opening a tab after a close continues from the renumbered keys.

### Key decisions
- **Override of a recorded decision.** `PRECEDENT.md` had `§stable-tab-keys`, which explicitly forbids this renumbering. A context hook said to stop and ask unless you explicitly referred to that record. I went ahead because your task said to supersede any contradicted `PRECEDENT.md` entry, and the session can't ask questions. If you meant a different override, revert the three files.

### Uncertain

Since the key is also the React key, those tabs remount and lose scroll position and unsaved form input (incident 2026-08-29). I recorded this as a known cost in the new entry. Nothing in `src/tabs/` handles it, and any fix, such as a separate stable React id from the URL key, would be a follow-up.
- Code outside `src/tabs/` that stores state by tab key, or parses `?tabs=`, would see keys change on close. I found no other references in the repo.
- `PRECEDENT.md` has no section for `tab-keys.test.mjs`. I did not add one, since I made no separate decision about that file.
