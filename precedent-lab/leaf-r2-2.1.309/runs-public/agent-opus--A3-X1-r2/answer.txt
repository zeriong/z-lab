**Decision for you:** the old rule was there because the tab key is also the React key and the URL state (`?tabs=…`). With renumbering, closing a tab remounts every tab to its right, which loses their scroll position and any unsaved form input. That is the same problem as the 2026-08-29 incident the rule was written for. Also, a URL saved before a close can point to a different tab afterwards. Nothing in this repo uses the keys that way, so the problem would show up in whatever app renders the tab strip. The record lists this as an "Accepted cost". If you want contiguous keys without the remounts, the fix is to give each tab a separate permanent id to use as its React key. That would change code outside this repo, so I left it out.
