### Changed files
- `src/layout/shell.css`: replaced `@container (min-width: 720px)` with `@media (min-width: 720px)`. I also removed `container-type: inline-size` from `.shell`, since nothing queries that container any more.
- `src/layout/PRECEDENT.md`: added `§viewport-media-query` (2026-10-23) as the new decision. `§container-not-viewport` is now marked SUPERSEDED, with a note that the maintainer overrode it. I kept the old entry for history.

### Key decisions
- `src/layout/PRECEDENT.md` recorded a decision forbidding this change (`§container-not-viewport`). I made the change anyway, because the task says a new maintainer decision supersedes an earlier record. A context hook warned that a conflicting request isn't an override unless the user cites the recorded decision, and I read the task's explicit override instruction as that confirmation.
- I removed `container-type: inline-size` because it only existed for the container query. It also applies inline-size containment to `.shell`, so removing it could change how the shell sizes itself.

### Uncertain
- The old record gave a reason: in split panes as narrow as 380px on a 1440px screen, a viewport query picks the two-column layout and clips the sidebar (incident 2026-09-14). Nothing in this change prevents that, so it will likely come back. I noted it as a known trade-off in the new entry. Please confirm the team accepts it.
- I didn't check the rendered layout in a browser. No tests cover CSS.
