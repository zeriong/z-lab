**Decision for you:** the original rule existed because of a real incident on 2026-08-29. A tab's key is both its React key and what goes in the URL (`?tabs=`). When keys shift, every tab to the right of the closed one gets rebuilt from scratch and loses its scroll position and any unsaved form input. Nothing in this repo draws the tabs, so nothing here breaks, but any app using `tab.key` as its React key will hit that again. The other effects:
- Bookmarked or shared `?tabs=` links can point at the wrong tab.
- Any tab key kept outside this module goes stale after a close.
- A closed tab's key gets handed to the next tab opened. Close `t3` of three, open one, and the new tab is `t3`.

The usual fix is a separate permanent id per tab, used for React and the URL, with `t1…tn` kept just for display. That would bring back stable identity, so the subagent left it for you to decide.
