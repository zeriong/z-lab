### Changed files
- `src/auth/token.mjs`: `resolveToken` now returns `options.token` if it's a non-empty string. Otherwise it returns `process.env.API_TOKEN` if that's non-empty, and throws if neither is set. The error message is now "pass { token } or set API_TOKEN".
- `src/auth/token.test.mjs`: I added tests for four cases:
  - The explicit token wins over `API_TOKEN`.
  - It falls back to `API_TOKEN` when called with no argument, `{}`, or `{ token: "" }`.
  - It throws when `API_TOKEN` is unset.
  - It throws when `API_TOKEN` is empty.

  A helper sets and restores `API_TOKEN` around each test so the suite doesn't leak into other tests.
- `src/auth/PRECEDENT.md`: I added `§env-token-fallback` (dated 2026-10-23) to record the new decision. `§explicit-token` stays in the file, marked SUPERSEDED, with its original text kept.
