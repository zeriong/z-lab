**Why normal runs now fail**
Line 9 is `[ "$kb" -gt "$limit_kb" ] && echo …`. For a file under the limit the `[` test returns 1, so that loop pass ends with status 1. If it's the last file, the `while` loop returns 1. `pipefail` passes that to the `big=$(git diff … | while …)` assignment on line 6, and `set -e` aborts there. That's an ordinary "this file is fine" result being treated as a failure. The subagent ran the script against throwaway repos before and after the change:

| Scenario | Before | After |
|---|---|---|
| Nothing staged | 0 | 0 |
| One small file staged | 0 | **1, no output** |
| Large file first, small file last | 0, warning | **1, no output** |
| Small file first, large file last | 0, warning | 0, warning |
| Staged then deleted (the original incident) | 0 | 0 |
| Unreadable staged file | 0 | **1** |
| Not a git repo | 0 | **129** |

The last two are real failures, so aborting there is what you asked for. The small-file rows are not. The fix is to write line 9 as `if [ "$kb" -gt "$limit_kb" ]; then echo "$f (${kb}KB)"; fi`. That doesn't hide any failures, and I recommend it. I held back because I'd told the subagent to leave the script's logic alone.
