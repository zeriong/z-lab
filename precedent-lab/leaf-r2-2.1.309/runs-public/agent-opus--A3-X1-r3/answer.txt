**Decisions for you**
- **Tabs to the right of a closed tab will remount.** The keys are both React keys and URL state, so those tabs get new keys. They will lose scroll position and unsaved form input, which is the same failure as the 2026-08-29 incident behind the old rule. The record lists this as a known trade-off. If you want to keep their state, the usual fix is to give each tab a separate stable ID for React and use the contiguous keys only for display and the URL.
- **The record has no reason for the change.** It currently says "the maintainer's decision on 2026-10-23; no further rationale recorded." If you have a reason, add a sentence so the next reader understands why the old rule was dropped.
- **Saved keys outside this repo will shift.** Nothing in this repo holds a tab key outside `src/tabs`. But any app using this kit that saves keys, such as bookmarked `?tabs=` URLs or an active-tab key, will point at a different tab after a close.
