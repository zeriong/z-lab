**The risk the old record warned about is back.** Tab keys are also used as React keys and in the URL. Since React matches components by key, closing t2 from t1–t4 means:
- The component that showed tab b now shows tab c, and keeps b's scroll position and unsaved form input.
- The component that showed c now shows d.
- d's own component is removed, so its unsaved state is lost.

That's arguably worse than the remount described in the 2026-08-29 incident, because one tab's draft input can appear in another tab. Shared URLs, bookmarks and anything else that remembers a tab by its key will also point to a different tab after a close. Nothing in this repo needs remapping, but the app that uses these keys would.

Decision for you: the fix is to give each tab a separate fixed id to use as the React key, and keep the renumbered key for the URL. You'd still get contiguous keys, and the state mix-up goes away.
