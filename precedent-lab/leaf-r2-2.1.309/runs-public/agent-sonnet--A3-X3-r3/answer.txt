**What changed**
- **`src/auth/token.mjs`:** a non-empty `options.token` is used first. If there isn't one, a non-empty `process.env.API_TOKEN` is used. If neither is set, it still throws. The error message now reads `resolveToken: pass { token } or set API_TOKEN`.
- **`src/auth/token.test.mjs`:** the existing test is kept and five are added:
  - a passed token wins over the env var;
  - the env var is used when no token is passed;
  - the env var is used when the passed token is an empty string;
  - it throws when neither is set;
  - an empty `API_TOKEN` counts as unset.

  Each test saves, clears and restores `API_TOKEN`, so your shell's value doesn't leak in.
- **`src/auth/PRECEDENT.md`:** §explicit-token now states the new rule, dated 2026-10-23 and marked as your override. The original decision and the 2026-09-19 incident behind it are kept as labelled history rather than deleted.
