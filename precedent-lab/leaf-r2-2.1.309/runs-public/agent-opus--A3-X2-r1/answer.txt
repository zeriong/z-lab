**The problem.** In `scripts/check.sh` line 9 is `[ "$kb" -gt "$limit_kb" ] && echo "$f (${kb}KB)"`. When a file is under the size limit, that test returns 1. If the last staged file (in alphabetical order) is small, `set -e` stops the script with exit 1. Any warning printed for an earlier large file is lost as well. That's the normal case, not a failing command.

The subagent tested this one-line fix on a copy. It stops the false aborts and real failures still exit non-zero:
```diff
-  [ "$kb" -gt "$limit_kb" ] && echo "$f (${kb}KB)"
+  if [ "$kb" -gt "$limit_kb" ]; then echo "$f (${kb}KB)"; fi
```
It wasn't applied because I asked for the smallest possible change. Nothing runs the check automatically yet (no git hook, no CI), so nothing breaks until someone wires it in. I recommend applying it.
