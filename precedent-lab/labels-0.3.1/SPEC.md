# SPEC — labels (E9): 한정어가 붙은 결정 줄을 결정으로 읽는다 (2026-10-29 고정)

실행 시작 전에 고정한다. 바꾸면 새 실험이다(제3조). 모델 런은 없다.

## 왜

because-i-needed #7(E7 E5) 이다.
- 결정 줄을 `- 결정(범위):` · `- 결정 B1:` 처럼 한정어를 붙여 쓰면 두 곳에서 결정으로 읽히지 않는다.
  - 0.3.0 훅의 압축(`compact()`)이 그 줄을 버린다.
  - `records-lint` 는 그 블록을 「결정 줄 없는 블록」으로 센다.
- 비공개 EHR 레포 기록에는 이런 줄이 64개 있다(2026-10-26 집계, 결정 줄 1,087개 중).

0.3.1 후보(`hooks/precedent-context-0.3.1.py`, sha256 `f4933a7c…`)는 `field_line()` 하나로 둘을 고친다.
- 받는 형태: 라벨 뒤에 괄호(`(…)`) 또는 공백과 한정어(40자 이하)가 오고, 그다음 콜론.
- 라벨에 글자가 바로 붙은 `- 결정적 이유:` 는 받지 않는다.
- 변경 확인 문구(`STOP`)는 0.3.0 과 같다.

- **대상:** 비공개 레포 `origin/dev` `ef913238` 스냅샷(E8 D 와 같다)과 그 E7 build 설정.

  - 주입된 한정어 결정 줄 수
  - 모드 회귀
  - 잃은 slug
  - 최악 출력
  - 기록 전수의 「결정 줄 없는 블록」 수(0.3.0 은 정확히 `- 결정:` 만, 0.3.1 은 `field_line`)
