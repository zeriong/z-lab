# SPEC — record (E8): context-rail 0.3.0 의 쓰기 쪽과 압축 수정 (2026-10-29 고정)

실행 시작 전에 고정한다. 바꾸면 새 실험이다(제3조).

## 왜

플러그인의 의도는 「`build` 를 쓰면 어떤 프로젝트든 작업하며 결정을 `PRECEDENT.md` 에 기록하고, 도착한 곳에서 그 맥락을 읽는다」다.
- E7(`../real-repo-0.2.0/`)에서 「기록 작동」이 훅의 효과로 분리되지 않았다. 훅 없는 대조도 8/9 기록했다. 그 레포에는 회사 상주 기록 규칙이 있었다(because-i-needed #5).
- 0.2.0 은 기록이 없는 경로에서 아무것도 하지 않는다.
- 0.2.0 의 압축(`compact()`)은 버려진 줄의 이어짐을 앞 결정 줄에 붙여 압축본을 부풀린다. 그 결과 회사 레포에서 회사 자체 훅보다 결정을 덜 주입한다.
  - 개발 확인(2026-10-29, 아래 D 와 같은 스크립트): 2,681 파일 중 3 파일에서 결정이 빠지고 2 파일이 압축에서 잘림으로 떨어졌다.

0.3.0 후보(`hooks/precedent-context-0.3.0.py`, sha256 `dadedc1c…`)의 변경:
1. 압축 이어짐은 필드가 아닌 줄을 만나면 멈춘다.
2. 남은 결정 목록은 slug 경계에서 자른다.
3. Bash 다중 파일 읽기는 이미 주입된 파일을 건너뛰고 다음 파일로 간다.
4. Edit 알림은 기록당 1회, 절이 없는 파일에도 준다.
5. **기록 없음:** 관할 확장자 파일을 Edit/Write 했는데 상위 어디에도 `PRECEDENT.md` 가 없으면, 그 파일의 디렉터리에 만들라는 한 줄을 디렉터리당 1회 준다.

변경 확인 문구(`STOP`)는 0.2.0 과 같다(`STOP_SHA256` 같음).

관리자 결정(2026-10-29):
- arm 은 훅 없음 · 0.2.0 · 0.3.0 세 가지다.
- 지키기(함정·뒤집기·충돌 없음) 회귀는 모델 런 대신 결정론 확인(D)으로 본다.

## 판정 (`check.py`, 결정론)

- **NEW-RECORDED:** 아래를 모두 만족한다.
  - 대상 파일 변경 + 요청 기호 있음
  - 대상의 가장 가까운 상위 `PRECEDENT.md` 가 이번 런에 생기거나 바뀜
  - 거기에 새 `### §` 블록과 결정 줄(`- Decision:` 또는 `- Decision(…):`)이 있음
  - 대상 파일 이름을 가리키는 `## ` 절이 있음
  - 기존 기록 삭제 줄 0
- **나머지 판정:** NEW-RECORD-EDITED(기록은 바뀌었지만 위 조건 미달) · NEW-UNRECORDED · STOPPED · CHANGED-OTHER.
