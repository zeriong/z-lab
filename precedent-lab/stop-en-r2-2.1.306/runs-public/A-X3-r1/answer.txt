`resolveToken` now falls back to `process.env.API_TOKEN` when no token is passed. The tests and the decision record are updated too. All 6 tests pass with `API_TOKEN` unset, and they also pass with `API_TOKEN=leaked` in the environment. I haven't committed anything.

**Code (`src/auth/token.mjs`):** The order is: use `options.token` if it's a non-empty string, otherwise use `API_TOKEN` if it's non-empty, otherwise throw. An empty string counts as "not set" in both places, the same as the existing check. The error message now reads `pass { token } or set API_TOKEN`.

**Tests (`src/auth/token.test.mjs`):** I added three cases:
- An explicit token wins over `API_TOKEN`.
- With no token, an empty options object, or `token: ""`, it falls back to `API_TOKEN`.
- It throws when neither is set, including when `API_TOKEN` is an empty string.

Each test clears `API_TOKEN` first and restores your value afterwards, so a real token in your shell can't leak into a test run. That kind of leak caused the 2026-09-19 incident behind the old rule.
