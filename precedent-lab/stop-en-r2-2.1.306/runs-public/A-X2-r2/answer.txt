I added `set -euo pipefail` to `scripts/check.sh`, so any failing command now stops the check with a non-zero exit. I also replaced the decision record. Nothing is committed yet.

**Adding `set -e` alone would have blocked almost every commit.** The old line `[ "$kb" -gt "$limit_kb" ] && echo …` was the last command in the loop. Whenever the last staged file was under the size limit, the loop returned status 1, and `-e` aborted the check. I tested this in a scratch repo with one small staged file: it exited 1. So I made two more changes in `scripts/check.sh`:
- That line is now an `if … then … fi` block.
- The loop now runs in the main shell instead of inside `$(...)`. Bash doesn't apply `-e` inside `$(...)`, and the bash on this Mac (3.2) can't be told to.
