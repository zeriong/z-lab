## Background (why now)
- 이 작업은 비교 실험의 공통 입력(`game-prompt.md`)이다. `{fable, opus, sonnet} × {/plan, /plan-smith}` 6개 셀이 같은 요구사항으로 각자 계획서 1개를 만든다. 이 셀은 opus × plan-smith.
- 이 단계에서는 게임을 구현하지 않는다. 산출물은 계획서뿐이다.
- 계획서는 나중에 **claude-opus-5-5 구현자**에게 넘어간다. 구현자는 **이 계획서만** 읽는다 — 이 패킷도, 대화도, 계획 작성자도 보지 못한다.
- frames.md의 Provenance에 따르면, 이 작업과 사실상 같은 과제(브라우저 게임: 10 스테이지, 물리 루프, 이름 붙은 UI 요구사항)에서 좁히는 프레임(`backward`)을 쓴 계획은 프레임 없는 계획보다 나빴다. 사운드·이펙트·저장·점수·별·배경·스택이 빠졌고, 사용자 요구사항 하나를 "cosmetic"으로 재분류했다. 이 계획은 그 실패를 반복하면 안 된다.

## Goal — definition of success
- 구현자(claude-opus-5-5)가 **이 계획서만** 읽고 **파일 읽기/쓰기만으로** 게임 파일을 작성한다. 결과물은 나중에 사람이 브라우저로 열었을 때 **한 번에** 다음이 되어야 한다:
  1. 메인 화면 → "게임 시작" → 스테이지 플레이 진입
  2. 새총에서 새를 드래그해 당기고 놓으면 포물선으로 날아간다. 중력·충돌·구조물 파괴가 일어나고, 돼지가 모두 제거되면 클리어, 새를 다 쓰고도 돼지가 남으면 실패
  3. 서로 다른 내용과 난이도 곡선을 가진 스테이지 10개
  4. 인게임 화면 우측의 일시정지 버튼 → 오버레이에 "다시하기" / "메인으로" 버튼, 두 버튼 모두 실제로 동작
- 구현자는 실행·테스트로 오류를 발견할 수 없다. 따라서 계획서의 성공 기준은 "기능 목록이 있다"가 아니다. **"실행해 보지 않고 쓴 코드가 첫 로드에 동작할 확률을 최대화하도록, 배선(wiring)과 접합부(glue)가 결정되어 있다"**이다.

- **Machinery budget 적용 판단**: 이름만 보면 "strong implementer" 줄에 해당한다. 하지만 피드백 루프가 0회이므로, weak/unknown 줄의 조항 중 **실행과 관련된 것은 전부 적용**한다:
  - 빌드 체인 없음. 브라우저가 직접 로드하는 평문 파일, 적은 파일 수. config가 다른 config를 참조하지 않음.
  - 모든 외부 의존은 **정확한 버전이 박힌 완전한 복사 가능 문자열**로 쓴다.
  - **접합부를 그대로 복사할 수 있는 블록**으로 준다: 의존성 별칭 줄, 파일별 공개 함수의 정확한 시그니처 표, 초기 상태 선언.
  - 구현자가 실행할 수 없는 명령형 완료 기준은 쓰지 않는다. 대신 **자기 산출물을 읽어서 확인할 수 있는 점검**을 준다.
  - 근거: frames.md에 관측된 실패(환각된 버전, 별칭 없는 `Composite`, 정의되지 않은 `setState`)는 강한 모델도 저지르는 **기억 회상 오류**다. 그리고 실행만이 그것을 잡는다.
  - frames.md "Implementer contract"는 "스택이 사 오는 보장마다 done에 명령과 exit status"를 요구한다. 이 조항과 실행 불가 구현자 사이의 충돌은 이렇게 해소한다: 명령으로만 증명되는 보장을 사지 않는다(예: TypeScript 불채택). done의 실행형 검증은 (B) 사후 사람 수용 시나리오로 분리하고, 구현자에게 할당하지 않는다. 이 해소 방식은 작성자가 더 나은 안으로 바꿀 수 있지만, 바꾼다면 이유를 밝힐 것.

## Load-bearing path candidate (build-out only)
- Path: 메인 화면 "게임 시작" 클릭 → 스테이지 1 로드(새총 위 새·구조물·돼지가 물리 월드에 생성, 상태 PLAYING) → 새를 포인터로 잡아 당김(조준) → 놓음 = 당긴 거리와 방향에 비례한 속도로 발사 → 물리 스텝에서 포물선 비행·충돌 → 충돌 충격이 돼지 내구도를 넘으면 돼지 제거·점수 가산 → 돼지 0마리 → 클리어 결과 표시
- Why this one: 이 경로가 닫히지 않으면 10개 스테이지, 점수, 일시정지 모두 무의미하다. 과거 관측 실패 "커버리지 만점, 주 상호작용 먹통"이 정확히 이 경로가 끊긴 경우다. (5홉 이내로 압축하는 방식은 작성자 재량이다.)
- 참고: 일시정지 경로(우측 버튼 → 오버레이 → 다시하기/메인으로)는 load-bearing path가 아니지만 **명시 요구사항**이다. 전형적 결함 두 가지를 피하도록 결정이 필요하다: (1) 오버레이만 뜨고 물리/루프가 계속 도는 것, (2) 다시하기 후 이전 월드의 바디·이벤트 리스너·타이머가 남아 중복 실행되는 것.

## Frame selection
- Frame: `spec-coverage`
- Rationale: Gate 0 = build-out. 명세가 완결되어 있고 위험은 누락이므로 spec-coverage로 보낸다. 도메인 힌트("Games → emotion-curve / failure-first")는 권고일 뿐이며, 예측변수 ①(불확실성: 실행만 남음)에서 Gate 0이 결정한다. 차순위 `failure-first`는 좁히는 성격이 약하지만, 문서 중심이 실패 목록이 되어 콘텐츠 축(10 스테이지 저작)이 약해질 위험이 있어 기각했다.

## Style selection
- Style: `opus` (coverage-first disciplined draft)
- Execution mode: **standalone** — 다음 패스는 없다. 고백(confession)에서 "다음 패스"로 작업을 미룰 수 없다.
