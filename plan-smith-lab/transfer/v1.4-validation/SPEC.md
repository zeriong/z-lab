# v1.4-validation — 릴리스 선행 검증 (실행 전 고정)

## 무엇을 검증하는가 — v1.4.0 후보 (아직 미릴리스, 소스 초안 상태)

1. **복사 가능한 접착부(copyable glue)** — 기계장치 예산 확장: 약한 구현자용 플랜은 최고 위험
   접착부(의존성 별칭 줄·파일별 공개 함수 심볼표와 시그니처·초기 상태 선언)를 **문자 그대로 복사
   가능한 블록**으로 담는다. 근거: 복사 가능하게 만든 URL은 유령 버전을 5건→0건으로 없앴고,
   잔여 실패 2건은 둘 다 회상된 접착부였다(`setState` 미정의, `Composite` 별칭 누락).
2. (동반 수정, 검증 대상 아님) v1.2/1.3 규칙 절이 프로덕션 집필자 전달 목록에 없던 결함 수정,
   런 스탬프의 plugin.json 위치 힌트.

**이번엔 순서가 다르다: 릴리스 전에 검증한다.** 통과해야만 v1.4.0을 출하한다.

## 설계

| arm | 플랜 | 구현 |
|---|---|---|
| A `informed-baseline` | opus, 방법론 없음 + "구현자는 haiku" 고지 (v1.3-validation과 동일 문안) | haiku × 4 |
| B `copyable-glue` | opus + v1.4 초안 스킬 문서 4종 + 같은 고지 | haiku × 4 |

n을 3→4로 올린 이유: 1차 지표가 실패 건수 비교라서 표본이 하나라도 더 필요하다. 여전히 방향 신호.

## 판정 (실행 전 고정)

**1차 — 접착부 사망 수**: 미정의 심볼/별칭/메서드로 인한 uncaught ReferenceError/TypeError로
부팅 또는 스테이지 진입이 죽는 셀 수 (콘솔 에러 원문으로 분류, 셀별 기록).
**2차 — 사다리 중앙값** (transfer와 동일한 L0~L6).

**릴리스 조건**:
- (B 접착부사망 < A) **그리고** (B 중앙값 ≥ A) → **v1.4.0 출하**
- (B 접착부사망 = A) 그리고 (B 중앙값 > A) → 출하
- 그 외(동률 포함) → **출하 안 함**, 소스 초안 되돌림, 판정을 백로그에 기록

역사적 기저율: 같은 조건에서 haiku의 접착부 사망은 6셀 중 2건(1/3). A가 4셀에서 0건이면
1차 지표는 판정력이 없고, 그 경우 2차 단독으로는 출하하지 않는다(우연 동률 방지).

## 순수성 (이전과 동일)

bare-model(Read/Write) · advisor 세션 비활성(사후 0회 검증) · arm 간 열람 금지 · baseline의
스킬 문서 접근 0 검증 · resolved id 확정. 측정 규율: 리스너·좌표는 소스에서, 0이 나오면 계측 먼저 의심.

## 측정하지 않는 것

n=4/플랜 n=1 · 과제 1종 · 약한 모델 1종 — 방향 신호. 강한 구현자에서의 부작용(불필요한 접착부
블록이 강한 구현자를 제약하는지) 미측정. 게임 밸런스 미측정.
