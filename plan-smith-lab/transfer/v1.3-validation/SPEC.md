# v1.3-validation — 사전 등록 검증 (실행 전 고정)

## 무엇을 검증하는가

v1.3.0의 **기계장치 예산** 조항. CHANGELOG가 릴리스 시점에 등록한 채택 조건 그대로:

> 이 조항의 가장 값싼 라이벌은 패킷에 구현자를 적는 한 줄이다. 따라서 대조군은 무지한
> 베이스라인이 아니라 **정보를 받은 베이스라인**이다. B가 사다리에서 A를 이겨야 조항이 값을 한다.

| arm | 계획자 | 플랜 조건 | 구현 |
|---|---|---|---|
| **A `informed-baseline`** | opus (bare-model) | 방법론 없음 + **"이 플랜의 구현자는 claude-haiku-4-5다"** 한 줄 | haiku × 3 |
| **B `plan-smith-1.3`** | opus (bare-model) | plan-smith v1.3.0 스킬 문서 4종 + **같은 한 줄** | haiku × 3 |

두 arm의 프롬프트 차이는 **스킬 문서 열람 여부 하나**다(transfer·pure-model과 동일 설계).
구현 프롬프트는 transfer와 문안 동일, 입력은 plan.md 단독.

## 판정 (transfer와 동일한 사다리, 오케스트레이터 사후 측정)

L0 빌드 → L1 부팅 → L2 월드 렌더 → L3 발사 → L4 턴 진행 → L5 종결 도달 · L6 콘텐츠(소스).
계측 규율 동일: 리스너·좌표는 소스/스크린샷에서 읽고, 0이 나오면 계측 먼저 의심.

**결정 규칙 (지금 고정):**
- **B > A (중앙값)** → 조항 채택 확정. CHANGELOG에 판정 기입.
- **B ≈ A** → 조항이 아니라 패킷 필드 하나로 충분했다는 뜻. CHANGELOG에 그 판정을 기입하고
  릴리스는 유지(이력 불변). 백로그 B12를 그 결과로 갱신.
- **B < A** → 조항이 해롭다는 뜻. CHANGELOG 기입 + v1.4에서 조항 철회 검토.

참조 기준(같은 사다리, transfer 실측): haiku 자기 플랜 중앙값 L0, 무정보 opus 플랜들 중앙값 L0 미달.
**A와 B 둘 다 이 참조선을 넘는지**도 함께 본다 — "정보를 준 것" 자체의 효과 크기.

## 순수성 조건 (transfer와 동일)

bare-model(Read/Write만) · advisor 세션 비활성(실행 후 트랜스크립트 0회 검증) · arm 간 열람 금지
· 지침 유입 grep · resolved model id 확정. 플랜 계획자는 opus, 구현자는 haiku — 사후 검증.

## 측정하지 않는 것

- n=3(구현) / n=1(플랜) — 플랜 생성 변동은 이번에도 미측정. 방향 신호이지 유의성 아님.
- 과제 1종(앵그리버드), 약한 모델 1종(haiku). 일반화 미보장.
- Stage 1 의도 교정 게이트(배치라 제거됨), 게임 품질.
