# 웹 앵그리버드 구현 플랜 — 10스테이지 · 물리 슬링샷 · 우측 일시정지

- 추론 프레임: spec-coverage / 스타일: opus
- 한 줄 요약: 빌드 도구 없이 브라우저가 직접 여는 파일 6개(HTML/CSS/JS 4)로, Matter.js 물리 위에 10개 스테이지의 슬링샷 게임을 만든다. 상태 전이·오버레이·점수·저장까지 포함한 표면 전체를 커버리지 원장으로 고정하고, 실행·검증이 불가능한 구현자를 전제로 모든 완료 기준을 "읽어서 셀 수 있는 것"으로 쓴다.

> 이 문서를 읽는 구현자에게: 당신은 명령을 실행할 수 없다. 따라서 이 플랜은 당신이 **파일을 쓰고 다시 읽어서** 확인할 수 있는 것만 완료 기준으로 요구한다. §11의 기준을 만족시키는 것이 당신의 일이고, "실제로 재미있는가"는 사람이 나중에 판정한다.

## 1. 요구사항 × 표면 커버리지 매트릭스

### 1.1 표면 목록과 품질 바닥선

표면(surface)은 사용자가 실제로 마주치는 화면·상태·입출력 단위다. 각 표면에 대해 "여기서 완성이란 무엇인가"를 한 문장으로 고정한다. 이 문장이 없으면 커버리지는 스텁 목록으로 퇴화한다.

| 표면 | 식별자 | 품질 바닥선 (여기서 "완성"이란) |
|---|---|---|
| 메인 메뉴 | S-MENU | 처음 연 사람이 아무 설명 없이 30초 안에 1스테이지 발사까지 도달할 수 있다 — 시작 버튼과 조작 안내가 한 화면에 있다. |
| 스테이지 선택 | S-SELECT | 10개 슬롯이 한 화면에 모두 보이고, 각 슬롯이 잠김/해금/획득 별을 눈으로 구분시킨다. |
| 인게임 캔버스 | S-CANVAS | 발사한 새가 포물선을 그리고, 맞은 구조물이 **눈에 보이게 무너지며**, 돼지가 사라지는 순간이 프레임 단위로 분간된다. |
| 인게임 HUD | S-HUD | 남은 새·현재 점수·일시정지가 게임 중 언제나 보이고, 캔버스 위 요소와 겹쳐 읽기 어려운 지점이 없다. |
| 일시정지 오버레이 | S-PAUSE | 열려 있는 동안 물리 시뮬레이션이 완전히 멈추고, 닫으면 멈춘 지점에서 튀지 않고 이어진다. |
| 클리어 오버레이 | S-CLEAR | 획득 점수와 별이 즉시 읽히고, 다음 행동(다음 스테이지 / 다시하기 / 메인)이 한 번의 클릭이다. |
| 실패 오버레이 | S-FAIL | 왜 실패했는지(새 소진)가 문장으로 보이고, 재시도가 한 번의 클릭이다. |
| 저장소 | S-STORE | 브라우저를 껐다 켜도 해금 단계와 스테이지별 최고 별이 그대로 남는다. |
| 오디오 | S-AUDIO | 발사·충돌·돼지 제거가 서로 구분되는 소리를 갖고, 음소거하면 완전히 조용해진다. |
| 부트/파일 로딩 | S-BOOT | `index.html`을 더블클릭해 여는 것만으로 게임이 뜬다. 설치·빌드·서버가 필요 없다. |

### 1.3 build 항목의 동사 문장 (표 밖)

원장의 행은 장부이고, 아래 문장이 지시다. 형식은 **⟨행위자⟩가 ⟨행동⟩하면 ⟨관찰 가능한 결과⟩가 일어난다; 없으면 ⟨증상⟩으로 드러난다.**

**메인 메뉴**

- **V1** 사용자가 `게임시작`을 클릭하면 메뉴 오버레이가 사라지고 캔버스에 1스테이지의 지형·구조물·돼지가 그려진다; 없으면 클릭 후에도 타이틀 화면이 그대로 남는 증상으로 드러난다.
- **V2** 사용자가 메인 화면을 보면 `게임시작`·`스테이지 선택` 두 버튼과 "새를 당겼다 놓아 발사" 한 줄 안내가 같은 화면에 보인다; 없으면 처음 연 사람이 캔버스를 클릭만 하다 아무 일도 못 하는 증상으로 드러난다.

**스테이지 선택**

- **V3** 사용자가 `스테이지 선택`을 열면 1부터 10까지 번호가 붙은 슬롯 10개가 한 화면에 격자로 보인다; 없으면 슬롯 수가 10개가 아니거나 스크롤해야 보이는 증상으로 드러난다.
- **V4** 사용자가 아직 해금되지 않은 슬롯을 클릭하면 아무 화면 전환도 일어나지 않고 슬롯에 자물쇠 표시가 계속 보인다; 없으면 10번 슬롯을 눌러 곧장 마지막 스테이지가 시작되는 증상으로 드러난다.
- **V5** 사용자가 한 번이라도 클리어한 슬롯을 보면 그 슬롯 안에 획득 별(★ 개수)이 표시된다; 없으면 클리어 이력이 있는 스테이지와 없는 스테이지가 똑같이 보이는 증상으로 드러난다.
- **V6** 사용자가 스테이지 선택 화면의 `메인으로`를 클릭하면 메인 메뉴가 다시 보인다; 없으면 선택 화면에서 브라우저 새로고침 말고는 빠져나갈 방법이 없는 증상으로 드러난다.

**인게임 캔버스**

- **V7** 게임이 스테이지 n을 로드하면 `STAGES[n-1]`의 블록·돼지 좌표대로 물리 바디가 생성되어 첫 프레임에 정지 상태로 그려진다; 없으면 시작하자마자 구조물이 스스로 튀어 오르거나 바닥으로 가라앉는 증상으로 드러난다(좌표 겹침의 신호).
- **V8** 사용자가 새총 위의 새를 누른 채 끌면 새가 커서를 따라오되 앵커에서 최대 120px까지만 멀어지고, 앵커와 새를 잇는 고무줄 선이 그려진다; 없으면 커서를 멀리 끌었을 때 새가 화면 밖까지 따라가는 증상으로 드러난다.
- **V9** 사용자가 새를 끌고 있는 동안 발사 예상 궤적이 점 18개로 캔버스에 그려지고, 당김이 깊을수록 점들이 더 멀리 뻗는다; 없으면 어디로 날아갈지 모른 채 감으로 쏘게 되는 증상으로 드러난다.
- **V10** 사용자가 드래그 중 마우스를 놓으면(또는 손가락을 떼면) 그 자리에서 새 바디가 물리 월드에 추가되고 당김 반대 방향으로 날아간다; 없으면 놓았는데 새가 새총에 붙어 있는 증상으로 드러난다.
- **V11** 발사된 새가 비행하면 매 프레임 아래로 가속되어 포물선을 그리고, 화면 밖(x < -200, x > 1480, y > 920)으로 나가면 월드에서 제거된다; 없으면 직선으로 날아가거나, 화면 밖 바디가 계속 쌓여 정지 판정이 영원히 안 나는 증상으로 드러난다.
- **V12** 새나 블록이 충분한 상대속도로 다른 블록에 부딪히면 그 블록의 체력이 깎이고, 0 이하가 된 블록은 그 프레임 끝에 사라지면서 파편이 튄다; 없으면 아무리 세게 때려도 구조물이 통째로 밀리기만 하는 증상으로 드러난다.
- **V13** 돼지가 체력을 모두 잃으면 월드에서 제거되고 점수가 5000 오르며 남은 돼지 수가 1 줄어든다; 없으면 돼지가 새에 맞아 굴러만 다니고 스테이지가 끝나지 않는 증상으로 드러난다.
- **V14** 발사 후 모든 동적 바디의 속도가 임계값 아래로 45프레임 연속 유지되거나 6초가 지나면 턴이 종료되어, 남은 새가 있으면 새총에 다음 새가 놓이고 없으면 결과 판정이 실행된다; 없으면 첫 발 이후 두 번째 새가 영원히 오지 않는 증상으로 드러난다.
- **V15** 사용자가 일시정지를 누르면 그 프레임 이후 물리 스텝이 호출되지 않아 공중의 새와 무너지던 블록이 그 자리에 멈추고, 계속하기를 누르면 멈춘 자세 그대로 이어진다; 없으면 오버레이 뒤에서 새가 계속 날아 돌아왔을 때 이미 상황이 끝나 있는 증상으로 드러난다.
- **V16** 블록이 파괴되면 그 자리에서 같은 색 사각 파편 8개가 튀어 0.6초에 걸쳐 사라지고, 비행 중인 새는 지나온 자리에 옅은 원 잔상을 남긴다; 없으면 블록이 소리 없이 증발해 무엇이 부서졌는지 못 보는 증상으로 드러난다.
- **V17** 게임 화면이 그려지면 하늘 그라디언트·먼 언덕·초록 지면·새총 기둥이 매 프레임 캔버스에 그려진다; 없으면 검은 배경 위에 도형만 떠 있어 지면 위치를 눈으로 못 찾는 증상으로 드러난다.

**인게임 HUD**

- **V18** 스테이지가 로드되면 화면 좌하단에 남은 새 개수만큼 새 아이콘이 표시되고 발사할 때마다 하나씩 줄어든다; 없으면 몇 발 남았는지 모른 채 갑자기 실패 화면을 보는 증상으로 드러난다.
- **V19** 점수가 오르면 좌상단 점수 숫자가 같은 프레임에 갱신된다; 없으면 클리어 화면에서 처음으로 점수를 보게 되는 증상으로 드러난다.
- **V20** 게임 중 사용자가 화면 **우측 상단**의 일시정지 버튼(⏸)을 클릭하면 일시정지 오버레이가 즉시 나타난다; 없으면 게임 중 화면 오른쪽에 아무 버튼도 보이지 않는 증상으로 드러난다.
- **V21** 사용자가 우측 상단 음소거 버튼을 클릭하면 이후 모든 효과음이 나지 않고 버튼 아이콘이 🔇로 바뀐다; 없으면 소리를 끌 방법이 없어 탭을 닫게 되는 증상으로 드러난다.

**일시정지 오버레이**

- **V22** 사용자가 일시정지 오버레이의 `다시하기`를 클릭하면 현재 스테이지가 처음 상태로 재구성되고 점수·남은 새가 초기값으로 돌아간 뒤 오버레이가 닫힌다; 없으면 다시하기를 눌러도 부서진 구조물이 그대로 남는 증상으로 드러난다.
- **V23** 사용자가 일시정지 오버레이의 `메인으로`를 클릭하면 물리 월드가 비워지고 메인 메뉴가 보인다; 없으면 메인으로 돌아간 뒤 다시 시작했을 때 이전 스테이지의 블록이 섞여 나오는 증상으로 드러난다.
- **V24** 사용자가 일시정지 오버레이의 `계속하기`를 클릭하면 오버레이가 닫히고 물리 스텝이 재개된다; 없으면 일시정지가 게임을 되돌릴 수 없게 만드는 증상으로 드러난다.

**클리어 / 실패 오버레이**

- **V25** 마지막 돼지가 제거되어 결과 판정이 클리어로 나면 클리어 오버레이가 뜨고 최종 점수와 별 1~3개가 표시된다; 없으면 돼지가 다 사라진 빈 화면에서 아무 일도 일어나지 않는 증상으로 드러난다.
- **V26** 클리어 오버레이에서 사용자가 `다음 스테이지`를 클릭하면 n+1 스테이지가 로드되고, n이 10이면 그 버튼 대신 `메인으로`만 보인다; 없으면 11번 스테이지를 로드하려다 화면이 멈추는 증상으로 드러난다.
- **V27** 남은 새가 0이고 정지 판정이 났는데 돼지가 남아 있으면 실패 오버레이가 뜨고 "새를 모두 사용했습니다" 문장과 `다시하기`·`메인으로` 버튼이 보인다; 없으면 새가 다 떨어진 채 아무것도 못 하는 화면에 갇히는 증상으로 드러난다.

**저장소 / 오디오 / 부트**

- **V28** 스테이지를 클리어하면 해금 단계와 그 스테이지의 최고 별·최고 점수가 브라우저 저장소에 기록되어, 탭을 닫았다 다시 열어도 스테이지 선택 화면에 그대로 보인다; 없으면 새로고침마다 1스테이지만 열려 있는 증상으로 드러난다.
- **V29** 발사·충돌·돼지 제거가 일어나면 각각 다른 높이의 짧은 합성음이 난다; 없으면 파괴가 일어나도 화면만 움직이고 완전히 무음인 증상으로 드러난다.
- **V30** 사람이 `index.html`을 브라우저로 열면 설치나 서버 없이 메인 메뉴가 보이고, 창 폭을 줄여도 캔버스가 비율을 유지한 채 축소되며 클릭 좌표가 그림과 어긋나지 않는다; 없으면 창을 줄였을 때 새총을 눌러도 엉뚱한 곳에서 드래그가 시작되는 증상으로 드러난다.
- **V31** 물리 라이브러리가 로드되지 않은 채 페이지가 뜨면 캔버스 자리에 빨간 배경의 "물리 엔진 로드 실패 — 인터넷 연결을 확인하세요" 배너가 표시되고 게임 루프가 시작되지 않는다; 없으면 아무 설명 없는 흰 화면과 콘솔 오류만 남는 증상으로 드러난다.

## 2. 문제 정의와 목표

브라우저에서 바로 실행되는 앵그리버드형 물리 슬링샷 게임을 만든다. 사용자는 새총으로 새를 당겨 쏘고, 포물선을 그리며 날아간 새가 구조물을 무너뜨려 돼지를 제거한다. 스테이지는 10개이고, 인게임 우측의 일시정지 버튼은 `다시하기`/`메인으로`를 담은 오버레이를 연다.

성공 판정: §11의 완료 기준을 모두 만족하는 파일 세트가 존재하는 것.

## 3. 전제와 틀린 경우의 영향

- **전제 1 (가장 중요) — `https://cdn.jsdelivr.net/npm/matter-js@0.19.0/build/matter.min.js` 가 실제로 응답한다.** 이 플랜의 유일한 외부 의존이다.
  - 틀리면: 게임이 아예 뜨지 않는다.
  - 가장 싼 조기 확인: 사람이 브라우저 주소창에 그 URL을 그대로 붙여 넣어 자바스크립트 텍스트가 보이는지 본다(구현자는 할 수 없다).
  - 폴백 경로: V31의 배너가 흰 화면 대신 원인을 화면에 띄운다. 그 배너를 본 사람은 §9의 기각안 1(물리 직접 구현)을 부활시킨다.
- **전제 2 — 사람이 `file://`로 파일을 직접 연다(로컬 서버 없음).** 이 전제가 `fetch`·ES 모듈·JSON 로딩을 전부 금지시킨다.
  - 틀리면(정적 서버로 서빙한다면): 아무것도 깨지지 않는다. 이 전제는 더 좁은 쪽으로만 틀릴 수 있다.
- **전제 3 — `localStorage`가 사용 가능하다.** 일부 브라우저는 `file://`에서 막는다.
  - 틀리면: 진행이 저장되지 않는다.
  - 폴백 경로: V28의 저장 함수는 `try/catch`로 감싸고 실패 시 모듈 내 메모리 객체에 저장한다 — 세션 안에서는 해금이 동작하고, 탭을 닫으면 사라진다.
- **전제 4 — 대상 브라우저는 Canvas 2D·Pointer Events·WebAudio를 지원하는 최신 Chromium/Firefox다.**
  - 틀리면: 입력이나 소리가 죽는다. 오디오는 `try/catch`로 감싸 실패해도 게임 진행에는 영향이 없게 한다.
- **전제 5 — 이미지·음원 파일은 존재하지 않는다.** 구현자는 텍스트 파일만 만들 수 있다.
  - 틀리면(에셋이 생기면): 도형 렌더를 스프라이트로 교체하는 별도 작업. 이 플랜의 구조는 바뀌지 않는다.

## 4. 딜리버리 스택 — 무엇을 사기 위해 골랐나

| 선택 | 무엇을 사는가 |
|---|---|
| **빌드 도구 없음** (번들러·트랜스파일러·패키지 매니저 전부 없음) | 구현자가 실행할 수 없는 단계를 0개로 만든다. 실패할 수 있는 표면은 "파일을 정확히 썼는가" 하나만 남는다. |
| **클래식 `<script>` 태그** (`type="module"` 아님) | `file://`에서 동작한다. 모듈은 `file://`에서 CORS로 거부된다. 파일 간 심볼은 스크립트 전역으로 공유하고, 로드 순서를 §5.1에 고정한다. |
| **Matter.js 0.19.0 (CDN, 클래식 스크립트)** | 강체 충돌 해석·마찰·수면(sleeping)·안정적인 적층. 실행해 튜닝할 수 없는 구현자에게 이걸 직접 만들게 하는 것이 이 플랜의 가장 큰 위험이었다. |
| **Canvas 2D 직접 렌더** (Matter.Render 사용 안 함) | 배경·HUD·궤적 점·파티클을 한 파이프라인에서 그린다. Matter.Render는 디버그용 와이어프레임이라 게임 화면이 되지 못한다. |
| **오버레이는 DOM, 게임은 캔버스** | 버튼 히트테스트·포커스·텍스트 레이아웃을 브라우저가 처리한다. 캔버스 안에 버튼을 그리면 좌표 변환 버그가 UI 전체로 번진다. |
| **스테이지 데이터는 `.js` 파일의 배열** (`.json` + `fetch` 아님) | `file://`에서 `fetch`는 실패한다. 데이터를 스크립트로 두면 로드 문제가 사라진다. |

**정확히 이 한 줄을 `index.html`에 넣는다** (기억으로 재구성하지 말고 그대로 복사할 것):

```
<script src="https://cdn.jsdelivr.net/npm/matter-js@0.19.0/build/matter.min.js"></script>
```

## 5. 데이터 · 좌표 · 상수 규격

### 5.1 파일과 로드 순서, 그리고 공개 심볼

파일은 6개다. 폴더 구조는 평평하다(하위 디렉토리 없음).

```
index.html
style.css
stages.js
physics.js
ui.js
game.js
```

`index.html` 의 `</body>` 직전에 **정확히 이 순서로** 스크립트를 넣는다. 순서가 곧 의존 방향이다.

1. `matter.min.js` (위 CDN 한 줄)
2. `stages.js`
3. `physics.js`
4. `ui.js`
5. `game.js`  ← 마지막 줄에서 `Game.boot()` 를 호출한다

각 JS 파일은 전역에 **하나의 객체만** 노출한다. 이렇게 하면 이름 충돌이 사라지고, §8의 홉이 가리키는 심볼이 어디 있는지 한눈에 확인된다. 아래 표는 21행이며, 각 행의 심볼(슬래시로 둘이 적힌 행은 둘 다)은 소스 전체에서 정확히 한 번 정의되어야 한다.

| 심볼 | 파일 | 책임 (한 줄) |
|---|---|---|
| `STAGES` | stages.js | 10개 스테이지 정의 배열. 길이는 정확히 10 |
| `BLOCK_TYPES` | stages.js | 블록 종류별 크기·재질 표 |
| `Physics.createWorld()` | physics.js | 엔진 생성, 지면·벽 추가, `collisionStart` 핸들러 등록. 부팅 시 1회 |
| `Physics.loadStage(stage)` | physics.js | 이전 바디 제거 후 블록·돼지 바디 생성. `{blocks, pigs}` 반환 |
| `Physics.spawnBirdBody(x, y, vx, vy)` | physics.js | 새 바디를 만들어 월드에 넣고 속도를 준다. 바디 반환 |
| `Physics.step()` | physics.js | 고정 스텝 1회 진행 + 사망 표시된 바디 일괄 제거 |
| `Physics.isSettled()` | physics.js | 모든 동적 바디가 정지 임계 아래인지 boolean |
| `Physics.clear()` | physics.js | 지면·벽을 제외한 모든 바디 제거 |
| `Physics.engine` | physics.js | Matter 엔진 인스턴스 |
| `UI.init()` | ui.js | 모든 DOM 버튼에 클릭 리스너 바인딩. 부팅 시 1회 |
| `UI.show(id)` / `UI.hide(id)` | ui.js | 오버레이 표시/숨김 (`'menu'`,`'select'`,`'pause'`,`'clear'`,`'fail'`) |
| `UI.renderSelect()` | ui.js | 10개 슬롯을 잠금/별 상태로 다시 그린다 |
| `UI.setHud(score, birdsLeft)` | ui.js | HUD 숫자·새 아이콘 갱신 |
| `Store.load()` / `Store.save()` | ui.js | 해금 단계·최고 별 읽기/쓰기 (실패 시 메모리 폴백) |
| `Sound.play(name)` / `Sound.toggle()` | ui.js | `'launch'`,`'hit'`,`'pop'` 합성음 재생 / 음소거 전환 |
| `Game.boot()` | game.js | 월드 생성 → UI 초기화 → 메뉴 표시 → `requestAnimationFrame` 시작 |
| `Game.start(n)` | game.js | 스테이지 n 로드, 상태를 `'PLAYING'` 으로 |
| `Game.tick()` | game.js | 매 프레임: 상태 분기 → 물리 스텝 → 판정 → 렌더 |
| `Game.launchBird()` | game.js | 드래그 릴리스 시 새 발사 |
| `Game.checkResult()` | game.js | 클리어/실패 판정 및 오버레이 전환 |
| `Game.state` | game.js | `'MENU'|'SELECT'|'PLAYING'|'PAUSED'|'CLEAR'|'FAIL'` |

### 5.2 스테이지 데이터 스키마

`stages.js` 는 `STAGES` 라는 배열 하나를 정의한다. 각 원소의 모양:

| 필드 | 타입 | 의미 |
|---|---|---|
| `id` | number | 1~10, 배열 순서와 일치 |
| `name` | string | 스테이지 이름(한국어) |
| `birds` | number | 지급되는 새 개수 |
| `blocks` | array | `{ type, x, y }` — `type`은 `BLOCK_TYPES`의 키, `x`/`y`는 **중심 좌표** |
| `pigs` | array | `{ x, y }` — **중심 좌표**, 반지름은 고정 20 |

`blocks`/`pigs`의 좌표는 모두 **중심**이다(Matter의 `Bodies.rectangle`/`Bodies.circle`이 중심을 받기 때문). 좌상단이 아니다 — 이 하나를 헷갈리면 전 스테이지가 지면에 반쯤 박힌 채 시작한다.

### 5.3 좌표계 · 블록 팔레트 · 배치 규칙

**좌표계**: 월드는 1280 × 720. 원점은 좌상단, y는 아래로 증가. 지면 상단은 **y = 640**. 새총 앵커는 **(200, 540)**. 구조물은 x = 760 ~ 1220 사이에 놓는다(그 왼쪽은 비행 공간).

**블록 팔레트** (`BLOCK_TYPES`):

| 키 | 크기(w×h) | 재질 | 밀도 | 체력 | 색 |
|---|---|---|---|---|---|
| `wood_pillar` | 20 × 120 | wood | 0.0015 | 120 | `#b9813f` |
| `wood_beam` | 120 × 20 | wood | 0.0015 | 120 | `#c8964f` |
| `wood_long_beam` | 200 × 20 | wood | 0.0015 | 140 | `#c8964f` |
| `ice_pillar` | 20 × 120 | ice | 0.0008 | 60 | `#a9dcf0` |
| `ice_beam` | 120 × 20 | ice | 0.0008 | 60 | `#a9dcf0` |
| `stone_block` | 60 × 60 | stone | 0.0040 | 260 | `#8d8d92` |
| `stone_beam` | 120 × 20 | stone | 0.0040 | 260 | `#8d8d92` |

**탑 레시피 (모든 스테이지가 이것을 조립해서 만들어진다).** 중심 x = `cx`, 바닥 높이 = `base`(첫 층은 640)일 때 한 층은 블록 3개다:

- `wood_pillar` 중심 `(cx - 50, base - 60)`
- `wood_pillar` 중심 `(cx + 50, base - 60)`
- `wood_beam` 중심 `(cx, base - 130)`

다음 층의 `base` 는 `base - 140`. 이 산수는 맞닿음을 보장한다: 기둥 상단 = `base - 120`, 판 하단 = `base - 130 + 10 = base - 120`. 판 상단 = `base - 140`.

**돼지 배치 규칙**: 돼지 반지름은 20. 층 안에 두려면 중심 `(cx, base - 20)` (하단이 정확히 `base`에 닿는다). 기둥의 x 범위는 `cx±50` 기준 `±10`이므로 돼지(`cx±20`)와 겹치지 않는다.

**배치 3원칙** — 어기면 첫 프레임에 구조물이 폭발한다:

1. **어떤 두 바디도 겹치지 않는다.** 접촉은 허용, 침투는 금지.
2. **공중에 뜬 바디를 두지 않는다.** 모든 블록·돼지는 지면 또는 아래 블록에 닿아 있어야 한다.
3. **얼음/돌 기둥은 `wood_pillar` 자리에 그대로 치환한다.** 크기가 같으므로 좌표 산수는 바뀌지 않는다.

**스테이지 1 완성 예시** (이 숫자를 그대로 쓰고, 나머지 스테이지는 위 레시피로 만든다):

```
blocks: wood_pillar (900, 580), wood_pillar (1000, 580), wood_beam (950, 510)
pigs:   (950, 620)
birds:  3
```

검산: `cx=950`, `base=640` → 기둥 `(900,580)`,`(1000,580)`, 판 `(950,510)`. 돼지 `(950, 640-20=620)`. 겹침 없음. ✔

**충돌 처리 규칙** (여기서 버그가 가장 잘 난다):

- `collisionStart` 콜백은 `event.pairs` 배열을 받는다. 한 프레임에 여러 쌍이 들어온다 — 반드시 전체를 순회한다.
- 각 쌍에서 `bodyA`, `bodyB` 둘 다에 대해 피해를 계산한다. 상대속도는 `Math.hypot(bodyA.velocity.x - bodyB.velocity.x, bodyA.velocity.y - bodyB.velocity.y)`.
- `isStatic`인 바디(지면·벽)에는 피해를 주지 않고, 정적 바디에 **속도·힘을 주지 않는다**(무한 질량과 만나 NaN이 퍼진다).
- 체력이 0 이하가 되면 그 자리에서 `Composite.remove` 하지 **않는다**. `body.plugin.dead = true` 만 세우고, 파괴 목록에 밀어 넣은 뒤, **프레임 끝(`Physics.step()`의 마지막)** 에 한꺼번에 제거한다. 순회 중 제거하면 같은 프레임의 뒤쪽 쌍이 이미 사라진 바디를 참조한다.
- 피해 계산 시작에서 `if (body.plugin.dead) continue;` 로 이미 죽은 바디를 건너뛴다.

### 5.5 Matter.js 0.19.0 호출 크립 — 이 이름들만 쓴다

기억으로 API를 재구성하지 말 것. 이 목록 밖의 Matter 함수는 쓰지 않는다.

**쓰는 것**

- `const { Engine, Composite, Bodies, Body, Events } = Matter;`
- `Engine.create({ enableSleeping: true })` → 엔진 생성. 정지한 바디가 잠들어 정지 판정이 안정된다.
- `engine.gravity` → 중력 객체(`.x`, `.y`, `.scale`). 기본값을 그대로 둔다.
- `Bodies.rectangle(centerX, centerY, w, h, options)`
- `Bodies.circle(centerX, centerY, radius, options)`
- options 로 쓰는 키: `{ isStatic, density, restitution, friction, frictionAir, label, plugin }`
- `Composite.add(engine.world, bodyOrArray)`
- `Composite.remove(engine.world, body)`
- `Composite.allBodies(engine.world)` → 배열
- `Body.setVelocity(body, { x, y })`
- `Events.on(engine, 'collisionStart', function (event) { /* event.pairs */ })`
- `Engine.update(engine, 1000 / 60)` → 고정 스텝 1회
- 바디에서 읽는 속성: `body.position.x/.y`, `body.angle`, `body.velocity.x/.y`, `body.speed`, `body.mass`, `body.isStatic`, `body.label`, `body.plugin`, `body.bounds`, `body.circleRadius`

**쓰지 않는 것 (0.19.0에서 없거나, 이 플랜의 구조와 충돌)**

- `Matter.World.*` — 0.19에서 deprecated. `Composite` 를 쓴다.
- `Matter.Runner`, `Engine.run` — 자체 `requestAnimationFrame` 루프를 쓰므로 필요 없고, `Engine.run`은 존재하지 않는다.
- `Matter.Render` — 렌더는 직접 그린다.
- `Matter.Constraint` — 새총을 실제 스프링으로 만들지 않는다(§9 기각안 4).
- `Body.setStatic` — 정적/동적은 생성 시 `isStatic` 으로만 결정한다.

**커스텀 데이터는 `body.plugin` 에만 붙인다**: `body.plugin = { kind: 'block'|'pig'|'bird', mat: 'wood', hp: 120, maxHp: 120, color: '#c8964f', w: 120, h: 20, dead: false }`. 사각형은 `plugin.w/h` 로 그리고, 원은 `body.circleRadius` 로 그린다.

## 8. 로드베어링 경로

이 게임에서 실패하면 나머지 전부가 장식이 되는 경로는 하나다: **메인에서 시작 → 1스테이지 구성 → 당겨서 발사 → 충돌로 돼지 제거 → 클리어 표시**. 아래 표의 빈 칸은 없다.

## 9. 대안과 기각 사유 (부활 트리거 포함)

1. **물리 엔진 직접 구현** — 기각: 구현자가 실행·튜닝할 수 없어 강체 충돌 해석·적층 안정성을 맞출 수 없다. **부활 트리거: `#load-banner` 가 실제로 뜨는 것이 확인되면(= CDN 접근 불가), 또는 오프라인 배포가 요구되면.** 그 경우 범위를 원-대-AABB 충돌로 축소하고 스테이지를 축 정렬 블록으로 제한한다.
2. **npm + Vite + TypeScript** — 기각: 구현자가 설치·빌드할 수 없다. **부활 트리거: 셸을 쓸 수 있는 구현자로 교체되면.**
3. **ES modules / JSON + `fetch`** — 기각: `file://` 에서 CORS로 실패한다. **부활 트리거: 로컬 정적 서버로만 서빙한다고 확정되면.**
4. **Matter `Constraint` 로 실제 고무줄 물리 구현** — 기각: 스프링 강성·감쇠를 플레이 없이 맞출 수 없고, 앵커 이탈 시 새가 진동한다. 대신 릴리스 시점에 `Body.setVelocity` 로 속도를 직접 준다(§5.4). **부활 트리거: 플레이테스트에서 "발사감이 부자연스럽다"가 나오면.**
5. **`Matter.Render` 사용** — 기각: 와이어프레임 디버그 렌더러라 배경·HUD·궤적·파티클을 합칠 수 없다. **부활 트리거: 커스텀 렌더가 좌표계 문제로 화면을 못 그리면, 임시로 `Render` 를 붙여 물리만 먼저 확인한다.**
6. **이미지 스프라이트 / 음원 파일** — 기각: 구현자가 바이너리를 만들 수 없다. **부활 트리거: 에셋 파일이 별도로 제공되면.**
7. **발사 전 새를 정적 바디로 월드에 넣어두기** — 기각: 정적 바디는 무한 질량으로 취급되어 힘·속도를 주면 NaN이 퍼진다. 발사 전 새는 **물리 바디가 아니라 좌표만 가진 객체**이고, 릴리스 순간에 처음 바디가 생성된다. **부활 트리거: 새가 새총에 얹힌 채 물리적으로 흔들려야 한다는 요구가 생기면.**

## 11. 완료의 정의

**구현자가 자기 출력물을 읽어서 셀 수 있는 기준** — 이것이 구현자의 완료 조건이다. 전부 세어서 확인한다.

1. 파일이 정확히 6개 존재한다: `index.html`, `style.css`, `stages.js`, `physics.js`, `ui.js`, `game.js`. 하위 폴더는 없다.
2. `index.html` 의 `<script>` 태그가 정확히 5개이고, 첫 번째가 `https://cdn.jsdelivr.net/npm/matter-js@0.19.0/build/matter.min.js`, 나머지가 `stages.js` → `physics.js` → `ui.js` → `game.js` 순서다.
3. `STAGES` 배열의 길이가 10이고, `id` 1~10이 각각 정확히 한 번 나타난다.
4. 10개 스테이지 각각에서 `pigs.length >= 1`, `blocks.length >= 3`, `birds >= 3` 이다.
5. 모든 `blocks[i].type` 문자열이 `BLOCK_TYPES` 의 키 7개 중 하나다(오타 0건).
6. **§5.1 심볼 표의 21개 행 각각에 대해, 그 행이 지목하는 심볼(슬래시로 둘이 적힌 행은 둘 다)이 소스 전체에서 정확히 한 번 정의된다.** 정의 0개(유령 호출)나 2개(중복 정의)는 실패다.
7. **§5.1 DOM id 규약 표의 모든 id가 `index.html` 에 존재하고, `btn-` 으로 시작하는 id 각각에 대해 `ui.js` 에 `addEventListener('click', …)` 가 하나씩 있다.** (`btn-start` 는 그중 하나이며, 이것이 없으면 §8.1 홉 1이 끊긴다.)
8. §8.2 콜드스타트 표에 등장하는 모든 상태 변수(`Game.state`, `Game.stageNo`, `Game.pigs`, `Game.blocks`, `Game.birdsLeft`, `Game.currentBird`, `Game.dragging`, `Game.score`, `Game.settleFrames`, `Sound.ctx`, `Sound.muted`)가 표에 적힌 초기값으로 선언되어 있다.
9. `Physics.step()` 호출 지점이 소스 전체에서 정확히 1개이고, `Game.state === 'PLAYING'` 조건 안에 있으며, 바로 다음 줄에 `Game.checkResult()` 호출이 있다.
10. `ov-pause` 오버레이 DOM 안에 `다시하기`·`메인으로` 텍스트가 있고, 일시정지 버튼의 스타일에 `right:` 가 있고 `left:` 는 없다(우측 배치 요구).
11. `Sound.play(` 호출이 발사·충돌·돼지 제거 세 지점에 존재한다.
12. `localStorage` 를 읽거나 쓰는 모든 줄이 `try` 블록 안에 있다.
13. §1.3의 동사 문장 31개 각각에 대해, 그 결과를 만드는 코드가 어느 파일 어느 함수에 있는지 지목할 수 있다. 지목하지 못하는 문장이 있으면 미완이다.
14. `Matter.` 로 시작하는 모든 참조가 §5.5의 "쓰는 것" 목록에 있다. "쓰지 않는 것" 목록의 이름은 소스에 0회 등장한다.

**사람이 실행해서 확인하는 기준 (구현자의 범위 밖 — 구현자는 이것을 했다고 쓰면 안 된다)**

- `index.html` 을 브라우저로 열어 메인 메뉴가 보인다.
- `게임시작` → 새를 당겨 발사 → 돼지를 제거 → 클리어 오버레이 도달.
- 게임 중 우측 일시정지 버튼 → `다시하기`/`메인으로` 동작.
- 클리어 후 탭을 닫았다 다시 열면 2스테이지가 해금된 채로 있다.

이 문서는 실행 결과를 측정하지 않았다. 위 네 줄은 예측이 아니라 **사람이 수행할 검사 항목**이다.

## 12. 구현자 계약

- **스택 (핀 고정, 이 문자열 그대로)**: `https://cdn.jsdelivr.net/npm/matter-js@0.19.0/build/matter.min.js`. 이것 외의 외부 의존은 0개. 빌드 없음, 패키지 매니저 없음, 설정 파일 없음.
- **API는 §5.5의 목록만.** 목록 밖의 Matter 함수를 쓰고 싶으면 그것은 이 플랜을 벗어난 것이다.
- **기각안은 전부 부활 트리거를 갖는다(§9).** 금지처럼 보이는 항목을 만나면 트리거를 먼저 확인하라 — 특히 기각안 1(물리 직접 구현)은 CDN이 죽었을 때 되살아난다.
- **완료 증명은 명령이 아니라 세기다(§11).** 구현자에게 셸이 없으므로 이 플랜은 어떤 명령형 완료 기준도 주지 않는다. 대신 §11의 1~14를 세어 확인하고, 세지 않은 것을 "확인했다"고 쓰지 않는다.
- **좌표는 중심, 지면은 y=640, 앵커는 (200,540).** 이 셋만 지켜도 스테이지 저작 버그의 대부분이 사라진다.

## 13. 프레임 이탈과 습관 회귀

- **§6의 스테이지 2~10에 실좌표가 없다.** 1번만 검산된 숫자를 갖고, 나머지는 §5.3의 탑 레시피와 §6의 `cx` 값으로 조립하게 했다. 레시피의 산수는 검산했고 각 스테이지의 `cx` 를 §6 표에 박아 위험을 줄였지만, 구현자가 층수를 잘못 세어 두 탑을 겹치게 놓을 여지는 남아 있다 — §5.3의 배치 3원칙이 유일한 방어이고 그것은 구조가 아니라 규칙이다. 이 플랜에서 가장 약한 지점이다.
- **§5.4의 `LAUNCH_K`·피해 공식·체력은 전부 초기값이다.** 실행 없이 "재미"를 결정할 방법이 없어서 D4로 넘겼다. 즉 이 플랜은 게임이 **동작하는** 형태는 규정하지만 **재미있는** 형태는 규정하지 못한다. 계수를 한곳에 모은 것이 내가 할 수 있었던 전부다.
- **§7의 단계 번호가 시간축처럼 읽힌다.** S1→S10 오름차순이라 사다리처럼 보이지만 실제로는 S1·S2가 병렬이고 S8이 S6/S7과 병렬이다. 각 단계에 선행조건을 적어 방어했으나, 번호 자체가 순서를 암시하는 습관 회귀는 남겨 뒀다 — 번호를 지우면 상호 참조가 불가능해지기 때문이다.
- **§8.1 홉 4가 내가 리뷰어라면 칠 지점이다.** 한 프레임에 여러 충돌 쌍이 들어올 때의 유령 참조를 `dead` 플래그 + 프레임 끝 일괄 제거로 막았지만(§5.4), 같은 프레임 안에서 한 블록이 서로 다른 두 쌍에서 각각 피해를 받는 것은 의도적으로 허용했다(현실적이고, 막으면 다중 충돌이 약해진다). 이 선택이 틀렸다면 증상은 "구조물이 예상보다 쉽게 무너진다"로 나타난다.
- **커버리지 우선 본능 때문에 난이도 튜닝 축을 표에서 밀어냈다.** §1.2의 D4가 그것이다. 표면은 전부 덮었지만 "10개 스테이지가 실제로 점점 어려워지는가"는 블록·돼지·새 개수의 단조 증가로만 근사했다 — 이것은 난이도의 대리 지표이지 난이도가 아니다.
