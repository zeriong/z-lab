# 라운드 2 판정 루브릭 — 실행 **전에** 고정

> lab 규칙 제5·제6조: 판정 기준은 데이터를 보기 전에 못 박는다. 데이터를 본 뒤 기준을 정하면
> 원하는 결론을 고르게 된다. 이 파일은 라운드2 플랜 생성 **전에** 커밋되며, 사후 수정 금지
> (수정이 필요하면 그것은 라운드3의 기준이 된다).

## 무엇을 검증하는가

plan-smith **v1.1.1+**의 세 처방이 실제로 발화하는지:
① off-anchor 조항이 더 이상 범위를 자르지 않는가 ② canon이 명세를 종결시키지 않는가
③ Gate 0가 build-out을 좁히는 프레임에서 격리하는가

**절대 평가다.** 라운드1과의 정량 대비는 하지 않는다 — opus 셀에서 모델 버전이 함께 바뀌었기 때문
(→ [r1 RUN-META](v1.0.0-round-1/RUN-META.md)). 라운드1은 정성적 참조로만 인용한다.

## 채점 항목 (7개)

| # | 항목 | 통과 기준 | 실패의 의미 |
|---|---|---|---|
| **1** | Gate 0 발화 | 패킷/플랜에 deliverable type = **build-out**으로 판정·근거 기록 | 라우팅 단계에서 미작동 → Gate 0 문구 자체가 안 읽힘 |
| **2** | 프레임 라우팅 | 프레임 = **`spec-coverage`** (backward 아님). 다른 프레임을 썼다면 "한 하위 결정에만 차용"으로 기록됐는가 | Gate 0는 읽혔으나 라우팅이 관성으로 backward 회귀 |
| **3** | 커버리지 회복 | 사운드 · 파티클/파괴 이펙트 · 점수 산식 · 별 등급 · 진행 저장 · 스테이지 선택 · 배경/시각 품질 — **7항목 전부 명시**(침묵·배제 0) | 프레임은 바뀌었으나 내용이 여전히 얇음 → `spec-coverage`의 필수 부품(품질 하한선·콘텐츠 축) 부족 |
| **4** | 요구 격하 없음 | 우측 일시정지를 "cosmetic/장식"으로 재분류하지 않음. 사용자 명시 3요구가 모두 build로 표시 | 조항 ①(범위 필터 금지)이 미작동 |
| **5** | 스택 명세 | 스택을 **명명** + **"무엇을 위해 샀는지"** 기재(예: "TS로 스테이지 스키마·FSM을 검사 가능하게") | canon watch-out 미작동 → 또 구현자 기본값에 위임됨 |
| **6** | 문서 예산 | 프레임/스타일 라우팅 논증이 플랜 본문에 없음(헤더 한 줄 + 패킷). 메타 서술 본문 비중 **≤15%** (R1: 37%) | 조항 ②(문서 예산) 미작동 |
| **7** | 구현 지시 절대량 | 즉시 구현 가능한 지시 **≥ 777단어** (R1 베이스라인의 값 — 절대 기준선으로만 사용) | 넓지만 얕음(스텁 인벤토리) |

## 판정 규칙

- **1·2 실패** → 패치가 **라우팅 층에서** 안 듣는다. 3~7은 채점 무의미. 즉시 중단하고 SKILL/frames의 Gate 0 표현을 고친다.
- **1·2 통과 + 3~7 중 실패** → 라우팅은 되고 **프레임 내용**이 부족하다. 실패 항목이 어느 필수 부품인지 지목한다.
- **7항목 전부 통과** → 구현 단계로 진행(순수 추론, 검증·QA 없음). 코드에 `audio`/`effects`/`storage` 상응물이 생기는지가 최종 확인.

## 채점 방법

- 채점자는 **플랜을 쓰지 않은 별도 에이전트**(자가 채점 금지 — 두 코퍼스 모두 자가 등급이 부풀었다).
- 항목 3·5·6은 grep 가능한 형태로 근거를 남긴다(어느 문장이 그 요구를 명시하는가).
- 6번의 15%는 **선언된 임의 기준**이다(R1의 37%와 A의 0% 사이). 라운드3에서 재조정 가능.
