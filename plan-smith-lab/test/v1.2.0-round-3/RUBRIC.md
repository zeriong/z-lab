# 라운드 3 판정 루브릭 — 실행 **전에** 고정

> lab 제5조: 기준은 데이터를 보기 전에 못 박는다. 이 파일은 라운드3 플랜 생성 전에 커밋되며 사후 수정 금지.
> 라운드2 루브릭이 "수정이 필요하면 그것은 라운드3의 기준이 된다"고 규정했으므로, 이 파일이 그 개정판이다.

## 라운드 3이 답해야 할 단 하나의 질문

**라운드 2는 루브릭 7/7을 받은 플랜이 주 상호작용이 죽은 산출물을 낳았다.**
그래서 이번 라운드의 1차 지표는 문서 점수가 아니라 **산출물의 하중 경로가 닫히는가**이다.
문서 점수는 그 결과를 설명하기 위한 2차 지표로만 쓴다.

## ⚠️ 라운드2에서 확인된 하니스 결함 2건 — 이번에 고침

| 결함 | 라운드2 상태 | 라운드3 조치 |
|---|---|---|
| 단어 상한 비대칭 | 베이스라인만 "800~1500단어", plan-smith는 무제한 | **양쪽 모두 상한 없음**(동일 문구). v1.2.0이 필수 절을 추가했으므로 상한을 걸면 신규 조항을 벌하게 된다 |
| 채점자의 선행 라운드 열람 | 베이스라인 채점자가 R1 플랜·RUN-META를 열람(루브릭이 "R1의 777단어"를 인용해서) | **채점자에게 `v1.0.0-round-1`·`v1.1.2-round-3` 경로 열람 금지**를 명시하고, 기준선은 이 파일에 **숫자만** 적는다 |

## 1차 지표 — 하중 경로가 닫히는가 (구현 후, 오케스트레이터가 측정)

각 셀의 구현물을 빌드해 브라우저에서 **주 상호작용 1개**(발사: 조준 → 놓기 → 발사체가 날아감)를
프로그램적으로 구동하고 결과를 기록한다.

| 판정 | 뜻 |
|---|---|
| **PASS** | 합성 입력으로 발사가 일어나고 상태가 변한다(새 소진 또는 발사체 이동) |
| **FAIL** | 입력이 아무 상태도 바꾸지 못한다 |
| **N/A** | 빌드·설치 실패로 구동 자체가 불가 |

- 측정은 **오케스트레이터가 사후에** 한다. 구현 에이전트는 도구 제한으로 빌드·실행·QA가 여전히 불가능하다.
- **소스는 수정하지 않는다**(제1조). 설치 불가로 구동이 안 되면 그것이 결과다.
- 라운드2 실측 기준선(같은 방식으로 측정): `opus-5/plan-smith` = **FAIL**(합성 드래그가 상태를 바꾸지 못함).

## 2차 지표 — 문서 채점 (8항목, 플랜을 쓰지 않은 별도 에이전트)

**신규 5개 — v1.2.0 조항이 발화하는가**

| # | 항목 | 통과 기준 |
|---|---|---|
| **1** | 하중 경로 사슬 | `## Load-bearing path`에 홉 **5개 이하** 사슬이 있고, **모든 홉**에 "통과 조건"과 "그 조건이 처음 참이 되는 지점"이 **둘 다** 채워짐 |
| **2** | 최초 진입 상태표 | 홉의 조건에 등장하는 **모든** 상태·플래그·전제가 표에 있고 **빈 칸 0** |
| **3** | 홉의 실재성 | 사슬이 가리키는 심볼·단계를 플랜이 **다른 곳에서 만들기로 약속**함. 고아 홉 0건 |
| **4** | 동사 문장 | `build` 요구마다 **표 밖 문장** 존재. 원장 행 수 대비 문장 수를 세어 보고(행 > 문장이면 실패) |
| **5** | 구현자 계약 | 기각에 부활 트리거 · 의존성 버전 고정 · **스택이 산 보증마다 "done"에 명령과 종료 코드** |

**유지 3개 — 라운드2에서 이미 통과한 것이 무너지지 않았는가(회귀 검사)**

| # | 항목 | 통과 기준 |
|---|---|---|
| **6** | Gate 0 + 라우팅 | deliverable type = build-out 기록 + 프레임 = `spec-coverage`(차용은 범위 한정 기록 시 허용) |
| **7** | 커버리지 7항목 | 사운드·파티클/파괴·점수 산식·별 등급·진행 저장·스테이지 선택·배경/시각 — 침묵 0 |
| **8** | 구현 지시 절대량 | 즉시 구현 가능한 지시 **≥ 777단어**. **표 행은 지시로 세지 않는다** |

- 베이스라인 셀(`opus-5/plan`)은 1~6을 `na`로 두고 **7·8만** 채점한다.
- 항목 8의 기준선 777은 **이 파일에 적힌 숫자**이며, 채점자는 그 출처 문서를 찾아보지 않는다.

## 판정 규칙

- **1차 지표가 결론이다.** 문서 8항목이 만점이어도 하중 경로가 FAIL이면 **v1.2.0은 이 문제를 못 고친 것**이다.
- 1차 PASS + 2차 실패 항목 존재 → 어느 조항이 불필요했는지의 근거가 된다.
- 1차 FAIL + 항목 1·2 통과 → **조항이 발화했는데도 실패**한 것이므로 처방 자체가 틀렸다. 이 경우 v1.3으로
  조항을 더 붙이지 말고 **접근을 재설계**한다.
