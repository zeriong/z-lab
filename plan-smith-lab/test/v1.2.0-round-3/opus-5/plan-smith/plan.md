## 3. 명시적 가정

- **A1 (이 플랜 전체가 걸린 가정) 고정 스텝 물리는 환경이 달라도 *불변식 수준*에서 재현된다.** 좌표 일치가 아니라 "클리어 여부 / 사용한 새 수 / 스텝 수"가 같다는 뜻이다.
  - 틀리면: 스테이지 클리어 가능성을 픽스처로 증명하는 §11 D2·D3이 무너지고, 완료 판정이 사람의 손 플레이로 되돌아간다.
  - 가장 싼 조기 검증(단계 S6, 얇은 종단 슬라이스 직후): 스테이지 1 픽스처를 서로 다른 두 실행 환경(구현자 장비 + 다른 Node 메이저 또는 컨테이너 이미지)에서 각 2회 실행해 (클리어 여부, 사용 새 수, 총 스텝 수) 세 값을 비교한다. 스텝 수 허용오차 ±5%[초기값→교체: 구현자가 S6 첫 실측 산포로 대체].
  - 폴백(깨졌을 때 1줄): 스텝 수 비교를 버리고 "N스텝 이내에 `pigsAlive === 0` 도달"이라는 불변식만 남기며, N은 스테이지별 상한(§5 표)으로 둔다. 좌표·스텝 수 기반 회귀 테스트는 도입하지 않는다.
- **A2 대상 브라우저는 포인터 이벤트를 지원하는 데스크톱 최신 크롬/사파리/파이어폭스다.** 틀리면: D2(모바일 레이아웃)를 defer에서 build로 승격하고 §7 S10 뒤에 단계를 하나 추가한다.
- **A3 백엔드가 없고 정적 배포만 가능하다.** 틀리면: N1 셀을 재개봉하고 저장 계층(B20)의 인터페이스만 교체한다(저장은 `SaveStore` 뒤에서만 호출).
- **A4 원작 에셋은 사용할 수 없어 자체 도형·단순 스프라이트로 그린다.** 틀리면: 렌더러의 스프라이트 슬롯만 교체하면 되도록, 렌더 코드는 바디 종류→그리기 함수 매핑 1곳에서 분기한다.
- **A5 구현자는 1인이며 빌드·테스트 실행 환경을 두 벌(자기 장비 + 컨테이너/다른 Node 메이저) 만들 수 있다.** 틀리면: D3(결정성 교차 검증)이 단일 환경 2회 실행으로 축소되고, A1은 검증되지 않은 채 남는다는 사실을 릴리즈 노트에 적는다.

### 4.1 물리엔진 판정 (dialectic 차용 — 이 셀에 한정)

- **사전 고정 판정 함수**(판정 전에 확정): 실패 비용 = 폭발 반경 × 회복 난이도.
  - 직접 구현 실패(수치 불안정·복합 충돌·수면 처리) → 폭발 반경 = 게임 전체, 회복 = 엔진 재작성.
  - matter-js 실패(스텝 제어권·성능) → 폭발 반경 = 어댑터 1개 파일, 회복 = 어댑터 뒤 교체.
- **판정**: matter-js.
- **패자 논거 승격(승자에 붙는 제약)**: 직접 구현의 진짜 강점은 *스텝 루프 완전 통제*였다. 그래서 승자는 그 강점을 뺏어서 채택한다 — `Matter.Runner` 사용 금지, 자체 accumulator로 1/120초 고정 스텝 호출(B25), matter 타입·API는 어댑터 밖으로 새지 않는다. 이 제약이 없었다면 `Matter.Runner`를 쓰는 기본 구성이 됐을 것이고, A1의 재현성 검증 자체가 불가능해진다. 제약의 준수는 §11 D8(d)가 단언한다.
- **재판정 트리거**: 스테이지 10 픽스처에서 §11 D7 기준(평균 4ms/프레임)을 2회 연속 미달하거나, S6에서 A1 불변식이 깨지면 어댑터 뒤 구현을 재검토한다.

- 돼지/새/블록 수: `[유도]` — 새 수는 "돼지 수 − 1 이상, 돼지 수 + 1 이하"를 지키게 배치했다(여유가 2 이상이면 조준 학습 압력이 사라지고, 0이면 무손실 클리어를 강요한다).
- 스텝 상한 N: `[유도]` — 1스테이지 기준 "새 3마리 × 한 턴 최대 6초 × 120스텝/초 = 2,160"에서 여유를 깎아 1,800으로 두고, 새 수와 턴 수에 비례해 증가시켰다. 픽스처가 상한에 걸리면 상한이 아니라 스테이지 배치를 의심한다.
- **별 점수 확정 규칙**: 스테이지 파일은 저작 시점에 `starScore = {two: 1, three: 2}`라는 자리표시자로 만든다(스키마 제약 `0 < two < three`를 만족하므로 `validateStage`가 처음부터 통과한다). S9에서 해당 스테이지 저작이 끝나는 즉시 구현자가 자기 플레이 3회의 점수 중앙값을 `two`로, 그 값의 ×1.25[임의]를 `three`로 덮어쓴다. `[초기값→교체: 구현자가 각 스테이지 저작 직후]` — 자리표시자가 남아 있는 스테이지가 하나라도 있으면 §11 D8 미통과.
- 재질 파라미터: 나무 hp 60 / 얼음 hp 30 / 돌 hp 120, 데미지 = max(0, 상대속도 − 6) × 질량계수. 전부 `[초기값→교체: 구현자가 S9에서 스테이지 3까지 저작한 시점에 실측 조정]`.
- 폭발 배럴: 파괴 시 반경 140px 내 바디에 거리 반비례 임펄스 `[초기값→교체: S9 스테이지 7 저작 시]`.

**스테이지 스키마**(B4, 코드가 아닌 필드 명세로 고정; `tsc --noEmit`이 이 명세의 집행자다)

| 필드 | 형 | 필수 | 제약 |
|---|---|---|---|
| `id` | 정수 | 필수 | 1–10, 파일명과 일치 |
| `name` | 문자열 | 필수 | 1–24자 |
| `gravity` | 실수 | 선택 | 기본 1.0, 0.5–1.5 |
| `ground` | 세그먼트 배열 | 필수 | 1개 이상, 월드 폭 전체를 덮어야 함 |
| `sling` | {x, y} | 필수 | 월드 좌하단 25% 영역 안 |
| `birds` | 정수 | 필수 | 1–6 |
| `pigs` | {x, y, size} 배열 | 필수 | 1개 이상 |
| `blocks` | {x, y, w, h, angle, material} 배열 | 필수 | material ∈ wood·ice·stone·barrel, 최소 두께 20px |
| `starScore` | {two, three} | 필수 | 0 < two < three (저작 중에는 자리표시자 {1, 2}) |
| `stepCap` | 정수 | 필수 | 픽스처 상한(위 표의 N) |

해금 여부는 스테이지 파일의 필드가 아니라 **파생 술어 `isUnlocked(def, save)`** 로 계산한다: `def.id === 1 || save.cleared.includes(def.id - 1)`. 이 술어는 S8에서 만들며, 홉 2·콜드 스타트 표·V3가 모두 같은 이름을 쓴다.

## 6. build 25건의 동사 문장 (표 바깥, 대장 행과 1:1)

## 7. 접근과 단계 (의존성 순서)

각 단계는 **선행(무엇의 출력을 먹는가) / 검증 / 서비스하는 요구**를 갖는다. 달력 표기는 쓰지 않는다 — 순서는 의존성이 정한다.

- **S1 프로젝트 골격·스택 고정** — 선행: 없음(독립). 산출: Vite+TS 프로젝트, §12의 버전 resolve 게이트 통과, `tsc --noEmit` 통과하는 빈 엔트리. 검증: `npm view` 게이트 4건 종료코드 0 + `npx tsc --noEmit` 0. 서비스: 전 요구.
- **S2 부트·에셋 파이프라인 + 상태 머신 뼈대** — 선행: S1. 산출: `gameState`(BOOT/MENU/STAGE_SELECT/PLAYING/PAUSED/CLEAR/FAIL) 전이 표, `inputEnabled` + PLAYING 진입/이탈 액션(진입 true, PAUSED·CLEAR·FAIL 진입 false), `assetsReady`, `SaveStore.load()`, 메인 메뉴(B2)와 로딩 화면(B1). 검증: 상태 전이 단위 테스트(허용되지 않은 전이는 예외). 서비스: B1·B2·B24.
- **S3 스테이지 스키마 + 검증기 + 1번 스테이지 데이터** — 선행: S1(S2와 병렬 가능). 산출: §5 필드 명세의 타입 + `validateStage`, 자리표시자 `starScore`를 가진 스테이지 1 파일, `stageDefs` 빌드타임 임포트 배열. 검증: 고의로 망가뜨린 픽스처 파일에 대해 검증기 종료코드 1, 정상 파일(자리표시자 포함)에 대해 0. 서비스: B4·B6.
- **S4 PhysicsAdapter + 로더/월드 빌더** — 선행: S3(정의 형식), S1. 산출: matter-js를 감싼 어댑터(`create/step/onCollision/destroy/bodyCount/stepCount`), `loadStage()`가 `engine`·`pigsAlive`·`birdsRemaining`·충돌 구독 등록까지 수행. 검증: 스테이지 1 로드 후 `bodyCount()`가 정의된 블록·돼지·지형 수와 일치, `stepCount()`가 `loadStage()` 직후 0. 서비스: B5·B11.
- **S5 얇은 종단 슬라이스 — 메뉴→스테이지1→발사→제거→클리어** — 선행: S2·S4. 산출: 고정 스텝 루프(B25), Canvas 2D 렌더, 슬링샷 드래그(B7)·궤적(B8)·발사(B9)·카메라(B10)·데미지(B11)·제거(B12)·정지 감지(B13)·장전(B14)·클리어/실패 오버레이(B16·B17)·리사이즈(B23). 이 단계에서는 스테이지 1만 직접 로드한다(선택 화면·해금은 S8). 검증: §8 홉 5개가 전부 닫히는 것을 픽스처 1개로 통과(수동 확인 아님). 서비스: R2 전부.
- **S6 결정성·불변식 하니스 (A1의 조기 검증)** — 선행: S5. 산출: 입력열(드래그 벡터 시퀀스)을 먹여 헤드리스로 돌리는 픽스처 러너 + 스테이지 1 픽스처. 검증: 서로 다른 두 실행 환경(구현자 장비 + 다른 Node 메이저/컨테이너) × 2회 실행에서 (클리어 여부, 사용 새 수) 완전 일치, 스텝 수 ±5% 이내. 불일치 시 §3 A1 폴백으로 전환하고 그 사실을 커밋 메시지에 남긴다. 서비스: B6·§11 D2·D3.
- **S7 일시정지 표면** — 선행: S5(상태 머신·루프가 있어야 멈출 대상이 생김). 산출: 우측 일시정지 버튼(B18), 오버레이의 다시하기·메인으로(B19), S2의 `inputEnabled` 위에 오버레이 입력 가드 확장(B24 — 오버레이가 떠 있는 동안 뒤쪽 캔버스 히트 테스트 차단). 검증: PAUSED 동안 `adapter.stepCount()`(= `physicsStepCount`) 증분 0, 버튼 히트 영역 중심 x > 캔버스 폭/2, '메인으로' 후 `adapter.bodyCount() === 0`. 서비스: **R3 전부**.
- **S8 점수·별·진행도·스테이지 선택** — 선행: S5(클리어 판정), S2(SaveStore). 산출: 점수 집계·별 판정(B15), 저장 라운드트립(B20), `isUnlocked(def, save)` 술어와 선택 화면의 잠금/해금/별 표시(B3). 검증: 클리어 후 저장→재로드 시 `isUnlocked(다음 스테이지, save) === true`. 서비스: R1·R4.
- **S9 스테이지 2–10 저작 + 스테이지별 픽스처 + 별 임계 확정** — 선행: S6(픽스처 러너), S8(별 판정 로직). 산출: §5 표 10행 전부, 스테이지별 `starScore` 자리표시자 교체, 재질 파라미터 실측 조정. 검증: 10개 픽스처 모두 `stepCap` 이내에 `pigsAlive === 0` && 자리표시자 `{1,2}`가 남은 스테이지 0건. 서비스: **R1**.
- **S10 폴리시·피드백 레이어(명명된 단계 — 생략 금지)** — 선행: S9(부술 콘텐츠가 있어야 피드백을 조율할 수 있다). 산출: 파편 파티클·화면 흔들림(B21), 사운드 5종 + 음소거(B22), 화면 전환 연출, 궤적 점 수·카메라 복귀 시간 등 §6에서 `[초기값]`으로 남긴 값들의 확정. 검증: 각 `[초기값]` 항목이 확정값과 근거 한 줄로 교체됐는지 목록 대조. 서비스: R4.
- **S11 릴리즈 게이트** — 선행: S1–S10 전부. 산출: §11 완료 커맨드 일괄 실행 결과. 검증: D1–D9 전부 통과. 서비스: 전 요구.

**순서 근거**: S2와 S3는 공유 의존이 없어 병렬 가능. S6를 S7·S8보다 앞에 둔 이유는 하나뿐이다 — A1이 깨지면 §11의 완료 정의를 갈아엎어야 하고, 그 발견은 콘텐츠 9종을 저작하기 전에 나와야 싸다. S10은 S9 뒤지만 *반드시 존재하는 단계*다: 여기가 없으면 사운드와 파괴 피드백은 대장에 build로 적힌 채 구현되지 않는다.

## 8. Load-bearing path — 메인 메뉴에서 첫 클리어까지

이 경로가 닫히지 않으면 나머지 24개 표면은 장식이다. (부품이 있는 것과 부품이 연결된 것은 다르다.)

| 홉 | 이름 | 통과 조건(passes only if) | 그 조건이 처음 참이 되는 지점 |
|---|---|---|---|
| 1 | 메인 메뉴 '게임 시작' 클릭 → `gameState = 'STAGE_SELECT'` | `assetsReady === true` && `stageDefs.length === 10` && `gameState === 'MENU'` | `assetsReady`: S2 프리로더 완료 콜백. `stageDefs`: S3의 빌드타임 임포트(검증기가 10개 강제). `gameState='MENU'`: S2 부트 완료 전이 |
| 2 | 스테이지 카드 클릭 → `loadStage(def)` → `gameState = 'PLAYING'` | `isUnlocked(def, save) === true` && `validateStage(def)` 통과 && 어댑터 생성 성공 | `isUnlocked`: S8에서 정의(스테이지 1은 `save`가 비어도 true). `save`: S2 `SaveStore.load()`. `validateStage`: S3 산출(스키마 타입 + 검증기), 빌드타임 임포트 시점에 10개 정의 전부 통과. `engine`·`pigsAlive`·`birdsRemaining`: S4 `loadStage()` 본문 |
| 3 | 포인터 다운→드래그→릴리즈 → `birdOnSling`이 동적 바디로 전환되고 임펄스 인가 | `gameState === 'PLAYING'` && `turnPhase === 'AIMING'` && `inputEnabled === true` && `birdOnSling !== null` && 드래그 길이 ≥ 8px[임의, 오클릭 방지] | `birdOnSling`·`turnPhase='AIMING'`: S5 `loadNextBird()`(스테이지 로드 직후 + 매 턴 종료 후). `inputEnabled=true`: S2 상태 머신의 PLAYING 진입 액션 |
| 4 | 비행체·구조물 충돌 → 데미지 적용 → 돼지 제거 → `pigsAlive` 감소 | `rafId !== null` && `gameState === 'PLAYING'`(루프가 매 프레임 `adapter.step()` 호출) && `collisionHandlerRegistered === true` | `rafId`: S5 `Loop.start()`(PLAYING 진입 시). `collisionHandlerRegistered`: S4 `loadStage()` 말미의 `adapter.onCollision(handler)` |
| 5 | 월드 정지 감지 → 클리어 판정 → 결과 오버레이 표시(관측 가능한 효과) | `turnPhase === 'SETTLING'` && (`settleFrames >= 30` 또는 턴 경과 6초) && 판정 결과 `pigsAlive === 0` | `turnPhase='FLYING'→'SETTLING'`: S5 스텝 루프의 속도 임계 체크. `settleFrames`: S5 루프가 SETTLING 동안 증가(FLYING 진입 시 0으로 리셋). `turnStartedAt`: S5 릴리즈 핸들러(FLYING 진입 시 기록) |

**콜드 스타트 표** — 위 통과 조건에 등장한 모든 상태의 최초 진입 값. 빈 칸은 결함이다.

| 상태/플래그 | 최초 진입 값 | 바꾸는 주체 | 언제 실행되는가 |
|---|---|---|---|
| `assetsReady` | false | 부트 프리로더 | S2, 에셋 디코드 완료 시 1회 |
| `stageDefs` | 빌드타임 임포트로 10개 고정 | 없음(불변) | 번들 시점, S3 검증기가 개수·스키마 강제 |
| `validateStage(def)` | 술어 자체는 불변 | 없음(S3에서 정의) | 빌드타임 임포트 시 전 정의에 1회 + D8(b)에서 재평가 |
| `save` | localStorage 미존재/파싱 실패 시 `{cleared:[], best:[], stars:[], muted:false}` | `SaveStore.load()` / `SaveStore.write()` | S2 부트 직후 로드, S8 클리어 시 기록 |
| `isUnlocked(def, save)` | 스테이지 1만 true(`save.cleared`가 빈 배열이므로) | 술어 자체는 불변, 입력 `save`가 바뀜 | S8에서 정의, 선택 화면 렌더와 홉 2에서 매번 평가 |
| `gameState` | 'BOOT' | `StateMachine.transition()` | S2 부트 완료 시 MENU, 이후 홉 1·2와 오버레이 버튼에서 |
| `engine` | null | `PhysicsAdapter.create()` / `.destroy()` | S4 `loadStage()` 진입 시 생성, '메인으로'·재시작 시 파기 |
| `collisionHandlerRegistered` | false | `adapter.onCollision()` | S4 `loadStage()` 말미(월드 빌드 직후) |
| `pigsAlive` | 0 | `loadStage()` 초기화 / 제거 핸들러 | S4 로드 시 `def.pigs.length`, 이후 제거마다 −1 |
| `birdsRemaining` | 0 | `loadStage()` / 발사 핸들러 | S4 로드 시 `def.birds`, 발사마다 −1 |
| `birdOnSling` | null | `loadNextBird()` | S5, 스테이지 로드 직후와 턴 종료(RESOLVING) 직후 |
| `turnPhase` | 'AIMING' | 입력 핸들러 / 스텝 루프 | 릴리즈 시 FLYING, 속도 임계 하회 시 SETTLING, 판정 시 RESOLVING |
| `turnStartedAt` | null | 릴리즈 핸들러 / 턴 종료 처리 | S5, FLYING 진입 시 기록·RESOLVING에서 null 복귀 |
| `inputEnabled` | false | `StateMachine` 진입/이탈 액션 | PLAYING 진입 시 true, PAUSED·CLEAR·FAIL 진입 시 false |
| `dragActive` | false | 포인터 핸들러 | pointerdown에서 true, pointerup/cancel에서 false |
| `settleFrames` | 0 | 스텝 루프 | FLYING 진입 시 0 리셋, SETTLING 매 스텝 +1 |
| `accumulator` | 0 | 스텝 루프 | 매 rAF 프레임(경과시간 가산, 스텝마다 1/120 차감) |
| `rafId` | null | `Loop.start()` / `Loop.stop()` | PLAYING 진입 시 start, MENU 복귀·언마운트 시 stop |
| `physicsStepCount` | 0 | `adapter.step()` | 스텝마다 +1, `loadStage()`에서 0으로 리셋 |

## 9. 대안과 기각 사유 (각 항목에 부활 트리거)

- **물리 직접 구현** — 기각: §4.1 판정 함수에서 실패 폭발 반경이 게임 전체·회복은 엔진 재작성. **부활**: 어댑터 뒤 matter-js가 §11 D7 성능 기준을 스테이지 10에서 2회 연속 미달하면, 또는 A1 불변식이 S6에서 깨지면 재개.
- **Phaser/Cocos 등 게임 프레임워크** — 기각: 필요한 표면이 캔버스 1개 + 오버레이 3종뿐이라 씬·플러그인 체계의 학습·번들 비용이 이득을 넘는다. **부활**: 씬이 6개를 넘거나 타일맵·아틀라스 파이프라인이 필요해지면.
- **WebGL(PixiJS 등) 렌더** — 기각: 동시 바디 ~120개 규모에서 Canvas 2D로 충분. **부활**: 스테이지 10에서 렌더가 프레임 예산(§11 D7)을 초과하는 것이 측정되면.
- **서버 저장·온라인 랭킹** — 기각: 백엔드 자산 없음(A3). **부활**: 계정/랭킹 요구가 실제로 들어오면 `SaveStore` 인터페이스 뒤 구현만 교체.
- **스테이지 정의 런타임 fetch(JSON)** — 기각: 빌드타임 임포트여야 스키마가 `tsc`의 검사 대상이 되고 `stageDefs.length === 10`이 정적으로 보장된다. **부활**: 재배포 없이 스테이지를 갱신해야 하는 요구가 생기면(그때 런타임 `validateStage`가 유일한 방어선이 된다는 점을 함께 받아들인다).
- **점수 임계 기반 클리어 판정** — 기각: 원작 규칙은 "돼지 전멸"이고, 점수 임계를 클리어 조건으로 쓰면 돼지가 남아도 클리어되는 상태가 생긴다. **부활 없음 — 대신 점수는 기능으로 살아 있다**: 점수·별은 B15로 build이며 §11 D8이 그 존재를 검사한다(기각된 것은 *판정 규칙*이지 *기능*이 아니다).
- **`Matter.Runner` 사용** — 기각: 스텝 통제권을 잃으면 A1 재현성 검증이 불가능. **부활**: 자체 accumulator가 D7을 못 맞추고, Runner가 맞춘다는 측정이 나오면(그때는 D2·D3의 결정성 조항과 D8(d)를 함께 완화해야 한다).

## 11. 완료의 정의

전부 커맨드로 판정한다("확인해 본다"는 완료 조건이 아니다). 측정자는 구현자, 측정 도구는 아래 커맨드 그 자체다.

- **D1** `npx tsc --noEmit` 종료코드 0. (TypeScript를 산 이유 = 스키마·상태 머신 검사. 이 커맨드가 그 주장의 증거다.)
- **D2** `npx vitest run` 종료코드 0. 그 안에 10개 스테이지 픽스처가 있고, 각 픽스처는 고정 입력열로 `def.stepCap` 이내에 `pigsAlive === 0`에 도달한다. (블로커가 자동 충족할 수 없다 — 실제로 클리어에 도달해야 통과한다.)
- **D3** 결정성: 스테이지 1·5·10 픽스처를 서로 다른 두 실행 환경(구현자 장비 + 다른 Node 메이저 또는 컨테이너)에서 각각 실행해 (클리어 여부, 사용한 새 수)가 완전 일치, 총 스텝 수 차이 ±5%[초기값→교체: S6 첫 실측 산포] 이내. 좌표는 비교하지 않는다.
- **D4** 일시정지: 같은 테스트 파일에서 두 가지를 단언한다 — (a) PAUSED 상태로 60프레임[임의] 진행시켜도 `adapter.stepCount()`(= `physicsStepCount`) 증분이 0, (b) 일시정지 버튼 히트 영역 중심 x > 캔버스 폭 ÷ 2. (스펙 요구 ③의 '우측'과 '멈춤'을 각각 하나씩 잡는다.)
- **D5** 오버레이 복귀: '다시하기' 후 `birdsRemaining === def.birds` && `pigsAlive === def.pigs.length`, '메인으로' 후 `gameState === 'MENU'` && `adapter.bodyCount() === 0`.
- **D6** 진행도: 스테이지 n 클리어 → `SaveStore.write()` → 새 인스턴스에서 `SaveStore.load()` → `isUnlocked(스테이지 n+1, save) === true`.
- **D7** 성능: 스테이지 10 픽스처의 평균 스텝 처리 시간 ≤ 4ms/프레임[초기값→교체: 구현자가 S9 스테이지 10 저작 직후 자기 장비 실측 중앙값의 1.5배로 재설정]. 측정: 픽스처 러너가 스텝 시간 합 ÷ 스텝 수를 출력.
- **D8** 커버리지 대장 대조 — 네 개의 검사가 전부 맞아야 한다:
  (a) `grep -rho 'B[0-9]\+' src/ | sort | uniq -c` 의 출력이 **정확히 25행**이고, **모든 행의 카운트가 1**이며, **ID 집합이 `B1`–`B25`와 일치**(각 build 행 ID가 그 표면을 구현한 파일 헤더 주석에 정확히 한 번씩 존재 — 중복·누락·오타 ID가 전부 걸린다),
  (b) `stageDefs.length === 10` && 10개 정의 전부 `validateStage` 통과,
  (c) `stageDefs.every(d => !(d.starScore.two === 1 && d.starScore.three === 2))` 가 true(별 임계 자리표시자 잔존 0건). 스테이지 파일이 TS 리터럴인지 JSON인지에 의존하는 텍스트 grep 대신 값 비교로 판정한다,
  (d) matter 격리(§12·§4.1 차용의 산출물): `grep -rl "matter-js" src/ | wc -l` 이 **1** && `grep -rn "Matter.Runner" src/ | wc -l` 이 **0**.
  네 검사는 vitest 케이스 또는 `npm run check:coverage` 스크립트에 넣고 종료코드로 판정한다.
- **D9** 정적 산출물: `npx vite build` 종료코드 0 && `grep -rl "Matter.Render" dist/ | wc -l` 이 **0**. (Vite를 산 이유 = 정적 산출물, §4 렌더 행의 "프로덕션 빌드에서 제외" 주장이 여기서 증명된다. 부재 검사가 의미를 갖는 전제 — `Matter.Render`의 dev 가드 임포트 — 는 §12 matter 격리 규약에 있다.)

## 12. Implementer contract

- **스택 핀**: `typescript@5.6.3`, `vite@5.4.10`, `matter-js@0.20.0`, `vitest@2.1.8`. **설치 게이트**: `npm view typescript@5.6.3 version && npm view vite@5.4.10 version && npm view matter-js@0.20.0 version && npm view vitest@2.1.8 version` 이 종료코드 0. 하나라도 실패하면 그 패키지만 동일 마이너의 최신 patch로 올리고, 올린 사실과 실제 버전을 커밋 메시지에 남긴다(메이저·마이너 변경은 금지).
- **타입 정의**: `@types/matter-js`는 버전을 못 박지 않는다 — 설치 후 `npx tsc --noEmit`이 0이면 채택, 아니면 어댑터 파일 상단의 로컬 선언으로 대체한다(어댑터 밖에는 matter 타입이 노출되지 않으므로 영향 범위가 파일 1개다).
- **matter 격리**: `matter-js` import는 `PhysicsAdapter` 파일 1개에만 존재한다. `Matter.Runner` 금지 — 고정 스텝 accumulator(1/120초, 프레임당 최대 4스텝)로 호출한다. 준수 여부는 D8(d)가 센다. `Matter.Render`는 `import.meta.env.DEV` 가드 안에서만 임포트한다 — D9의 `dist/` 부재 검사가 의미를 갖는 전제다. *부활 트리거*: 자체 루프가 D7을 못 맞추고 Runner가 맞춘다는 측정이 나오면 재검토.
- **대장 마커**: 각 표면을 구현하는 파일의 헤더 주석 첫 줄에 `// B<n> — <표면 이름>` 을 적는다. 이 규약이 D8(a)의 유일한 근거다.
- **기각 부활 트리거**(짧은 형태): 직접 물리 = D7 2회 연속 미달 또는 S6 불변식 실패 시 / 프레임워크 = 씬 6개 초과 시 / WebGL = 렌더 프레임 예산 초과 측정 시 / 서버 저장 = 계정·랭킹 요구 발생 시 / 런타임 fetch = 무배포 스테이지 갱신 요구 발생 시.
- **보증-커맨드 대응**: TypeScript ↔ D1, 픽스처 물리 ↔ D2, 결정성 ↔ D3, 스펙 요구 ③ ↔ D4, 콘텐츠 10종 ↔ D2 + D8(b), 폴리시·별 확정 ↔ D8(a)(c), matter 격리 ↔ D8(d), Vite 정적 산출물 ↔ D9.
- **`[초기값]` 항목은 S10 종료 시 전부 확정값 + 근거 한 줄로 교체된다.** 교체되지 않은 항목이 남으면 릴리즈 게이트(S11) 미통과다.

## Frame deviations & habit regressions

- **반사적 습관**: 이 과제를 받으면 나는 "아키텍처(엔진·렌더·상태 머신) → 기능"의 순서로 쓰려는 관성이 있다. 그 순서는 스펙에 없는 표면(사운드·파티클·저장)을 자연스럽게 뒤로 미루고 끝내 증발시킨다. 그래서 §1 대장을 먼저 쓰고 스택(§4)을 그 뒤에 뒀다.
- **가장 약한 절은 §5의 별 점수 칸**이다. 10행 전부가 "S9에서 확정"이며, 이 문서 안에는 숫자가 없다. 저작 전에 점수를 박는 것이 더 나쁘다고 판단해 자리표시자 + 확정 규칙(중앙값, ×1.25[임의]) + 잔존 검사(D8(c))로 닫았지만, ×1.25라는 배수 자체에는 근거가 없다 — 임의다.
- **직접 고친 것 두 건**: (1) settle 임계·터널링 스텝·별 규칙을 "나중에 정한다"로 남기려던 상태에서 V13·V25·§5로 각각 확정 규칙 또는 유도 근거를 붙였다. (2) D8을 "사람이 목록을 눈으로 대조"로 두려던 것을 카운트 4종(마커 25 / 스테이지 10 / 자리표시자 0 / matter 격리 1·0)으로 바꾸고, 그 근거가 되는 헤더 주석 규약을 §12에 넣었다. 다만 여기서 "자기충족 가능하던 완료 조건이 사라졌다"고 썼던 것은 **틀렸다**: 배선 감사가 D8(c)의 grep 패턴(`'"two": *1, *"three": *2'`, JSON 따옴표 키)이 §5가 지시한 TS 리터럴과 어긋나 언제나 0을 반환한다는 것 — 즉 자기충족 조건이 그대로 남아 있었다는 것 — 을 찾아냈고, (c)를 형식 비의존 값 단언으로 교체했다. 같은 감사에서 D8(a)의 `sort -u`가 선언("정확히 한 번씩")을 측정하지 못한다는 것, Vite·matter 격리 보증에 대응하는 커맨드가 아예 없다는 것도 나와 D8(a) 수정·D8(d)·D9로 닫았다.
- **배선 감사 후 닫은 것(내가 스스로 찾은 것이 아니다)**: §8 홉 2·5의 조건 단위 앵커 2건(`validateStage`, `turnStartedAt`), 콜드 스타트 표의 누락 행 2건(`turnStartedAt`·`validateStage`), S2 산출의 `inputEnabled`+진입/이탈 액션(홉 3이 S5에서 닫히려면 그 플래그를 만드는 단계가 S7이 아니라 S2여야 한다 — S7은 오버레이 가드만 확장하고 B24 마커도 S7이 갖는다), S4 어댑터의 `stepCount()`(D4(a)가 읽을 수단이 없었다).
- **프레임 대신 관례를 택한 곳**: §4 스택은 전부 도메인 관례(TS+Vite+Canvas 2D+matter)다. 관례가 파생을 끝내지만 명세를 끝내지는 않으므로, 각 항목에 "무엇을 사려고 샀는가"와 그 보증을 증명할 커맨드(D1·D2·D9)를 붙였다.
- **차용 기록**: §4.1은 dialectic 차용이며, 그 산출은 승자 선택이 아니라 승자에게 붙은 제약(`Matter.Runner` 금지 + 어댑터 1파일 격리)이다. 차용이 아무 결정도 바꾸지 못했다면 삭제했을 것이다.
- **프레임 구성요소가 실제로 뒤집은 결정**(존재 자체는 적용이 아니므로 1:1로 남긴다):
  - 무단 누락 금지 대장 → 사운드·파티클·저장을 "스펙 밖"으로 잘라내려던 것을 build로 되돌림(B20–B22).
  - 표면별 품질 바닥 → B3를 "스테이지 선택 화면 있음"에서 "잠금/해금/별이 구분됨"으로 승격, `isUnlocked` 술어와 D6의 판정 대상이 됨.
  - 배선된 load-bearing path → `collisionHandlerRegistered`·`inputEnabled`의 최초 값이 어느 단계에도 없던 것을 발견해 S4 말미·S2 진입 액션으로 배치했고, 홉 2의 해금 조건이 스키마에 없는 필드를 가리키던 것을 `isUnlocked(def, save)` 파생 술어(S8 산출)로 교체했다.
  - 콘텐츠 축 → "로더 + 스테이지 1개"로 끝낼 뻔한 계획을 §5의 10행 저작표 + 스테이지별 픽스처(S9)로 바꿈.
  - 얇은 종단 슬라이스 + 명명된 폴리시 단계 → 일시정지(S7)를 S5 안에 섞으려던 것을 분리하고, S10을 삭제 불가능한 단계로 고정.
  - 이유를 밝힌 스택 → "Canvas 2D로 한다"만 쓰려던 것을 D1·D7의 커맨드와 묶음.
- **내가 리뷰어라면 공격할 곳**: §11 D7이다. 기준값(4ms)의 교체 규칙이 "구현자 자기 장비 실측 중앙값의 1.5배"여서, 기준을 만족시켜야 할 사람이 기준을 다시 쓴다. 외부 기준(예: 대상 브라우저 최저 사양 기기 1대)을 못 박는 편이 낫지만, 그 기기가 무엇인지는 A2 수준의 정보로는 정할 수 없어 임의값을 세우지 않고 이 구조를 남겼다.
