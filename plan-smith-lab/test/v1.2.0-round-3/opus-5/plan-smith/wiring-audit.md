## Q1. 홉 ≤5의 하중 경로 사슬 / 모든 홉에 통과 조건 + "처음 참이 되는 지점"

**판정: 홉 단위로는 통과, 조건 단위로 2건 결함.**

§8은 5홉(메뉴 클릭 → 스테이지 로드 → 드래그·릴리즈 → 충돌·제거 → settle·클리어 오버레이)이며,
**5개 홉 전부가 "통과 조건" 칸과 "처음 참이 되는 지점" 칸을 비우지 않았다.** 즉 "칸이 통째로 빈 홉"은 없다.
그러나 규칙은 "Every 'passes only if' condition needs a 'first becomes true at'"이므로 조건 단위로 본다.

| 홉 | 통과 조건 중 3열 앵커가 없는 항목 | 판정 |
|---|---|---|
| 1 | 없음(assetsReady·stageDefs·gameState 3건 모두 앵커됨) | 통과 |
| 2 | **`validateStage(def) 통과`** — 3열은 `isUnlocked`/`save`/`engine·pigsAlive·birdsRemaining`만 앵커. 검증기가 언제 어디서 통과 상태가 되는지(S3 산출) 지목 없음 | **결함** |
| 3 | `gameState === 'PLAYING'`은 홉 2의 관측 효과로 연쇄되어 허용. 드래그 길이 ≥ 8px은 사용자 입력이라 앵커 대상이 아님 | 통과(주1) |
| 4 | 없음(rafId·collisionHandlerRegistered 앵커됨, gameState는 연쇄) | 통과 |
| 5 | **"턴 경과 6초"** — 3열은 `turnPhase`·`settleFrames`만 앵커. 턴 경과 시계는 이름조차 없다 | **결함** |

- 주1: `pigsAlive === 0`은 조건이 아니라 홉의 **판정 결과**로 쓰여 있어(“판정 결과 `pigsAlive === 0`”) 앵커 요구 대상에서 제외했다.
- 주2: 홉 3의 `inputEnabled === true`는 3열 앵커가 **있으나 그 앵커가 사실과 어긋난다** → Q3에서 다룬다.

## Q2. 콜드 스타트 표가 홉 조건을 전부 덮는가 / 빈 칸

**판정: 빈 칸(공란)은 0. 그러나 표의 자기 선언("위 통과 조건에 등장한 모든 상태")을 어긴 누락 행 2건.**

표는 17행이며 모든 셀이 채워져 있다(공백 셀 없음). 누락은 "행 자체가 없는" 형태다.

1. **턴 경과 시계 행 없음.** 홉 5의 통과 조건에 "턴 경과 6초"가 있고 V13도 "턴 시작 후 6초"를 쓰는데,
   `turnStartedAt`/`turnElapsed`에 해당하는 상태가 표에 없다 → 최초 값·바꾸는 주체·언제 실행되는가가 전부 미정.
   `settleFrames`는 행이 있으므로 대칭 누락이다.
2. **`validateStage` 행 없음.** 같은 성격의 파생 술어 `isUnlocked(def, save)`는 행을 받았는데(“술어 자체는 불변, 입력 save가 바뀜”),
   홉 2에 함께 등장하는 `validateStage`는 행이 없다. 표의 포함 기준이 일관되지 않다.

부수 관찰(결함 아님): `dragActive`·`accumulator`는 어떤 홉 통과 조건에도 등장하지 않는 여분 행이다. 규칙은 과잉을 금하지 않으므로 통과.

## Q3. 사슬이 가리키는 심볼·단계가 다른 곳에서 만들기로 약속된 것인가 (고아)

**판정: 결함 2건. 그중 1건은 경로가 "약속된 위치에서 닫히지 못하는" 순서 모순이다.**

1. **`inputEnabled` — 블로커.**
   - 콜드 스타트 값 `false`. 홉 3은 `inputEnabled === true`를 요구하고, 3열은 "S2 상태 머신의 PLAYING 진입 액션"이라고 앵커한다.
   - 그런데 §7 S2의 **산출**은 `gameState` 전이 표 / `assetsReady` / `SaveStore.load()` / 메인 메뉴 / 로딩 화면뿐이다.
     진입·이탈 액션도, `inputEnabled`도 산출에 없다(B24는 S2의 **서비스** 칸에만 등장).
   - "상태별 입력 가드(B24)"를 **산출**로 약속한 유일한 단계는 **S7이며 S7의 선행은 S5**다.
   - 반면 S5의 검증은 "§8 홉 5개가 전부 닫히는 것을 픽스처 1개로 통과"다.
     → S5 시점에는 `inputEnabled`를 true로 바꾸는 주체가 아직 만들어지지 않았으므로, 플랜 자신의 서술대로면 홉 3은 S5에서 닫힐 수 없다.
2. **`physicsStepCount` — 접근 경로 미약속.**
   §7 S4가 약속한 어댑터 API는 `create/step/onCollision/destroy/bodyCount`다. 여기에 스텝 카운터 노출이 없는데,
   S7 검증과 §11 D4(a)는 `physicsStepCount` 증분을 단언한다. 읽을 수단이 어느 단계의 산출에도 없다.

고아 아님으로 판정한 것(근거 명시): `assetsReady`(S2), `stageDefs`(S3), `validateStage`(S3), `SaveStore.load()`(S2),
`isUnlocked`(S8·§5), `loadStage()`·`engine`·`pigsAlive`·`birdsRemaining`·`adapter.onCollision`(S4),
`rafId`/고정 스텝 루프(S5, B25), `collisionHandlerRegistered`(S4 "충돌 구독 등록까지 수행"),
`loadNextBird()`·`turnPhase`(S5의 장전 B14 / 정지 감지 B13) — 심볼 이름이 §8에만 있어도 **표면 자체는 다른 절에서 build로 약속**되어 있으므로
"플랜이 결코 도입하지 않는 심볼"에 해당하지 않는다.

## Q4. `build` 요구마다 표 밖 동사 문장이 있는가 (행 수 vs 문장 수)

**판정: 통과. 결함 없음.**

- §1 원장 총 29행 = build 25(B1–B25) / defer 3(D1–D3) / n-a 1(N1). §1 하단 자기집계("build 25 / defer 3 / n-a 1") 및 D8(a)의 기대값 25와 일치.
- §6에 표 밖 문장 V1–V25가 **25개**, 각 문장이 `V<n>(B<n>)`로 원장 행과 1:1 결속. 누락 0, 잉여 0.
- 형식 검사: 25건 모두 ⟨행위자⟩–⟨행동⟩–⟨관측 가능한 결과⟩ + "부재 증상"을 갖는다. 부재 증상이 결과의 단순 부정에 그친 행은 없다
  (경계선인 V8도 "방향을 눈대중해야 한다"라는 사용자 결과를 덧붙여 규칙을 만족).
- defer 3건은 트리거를, n-a 1건은 사유를 갖는다(문장 의무 대상 아님).

## Q5. 구현자 계약 — 부활 트리거 / 해석 가능한 고정 버전 / "done"의 명령과 종료 코드

**판정: 결함 4건(블로커 1건 포함).**

갖춰진 것:
- 부활 트리거: §9의 7개 기각 항목 중 6개가 수치·관측 조건부 부활 트리거를 가지며, §12에 축약 재수록. "점수 임계 판정"만 "부활 없음"이나,
  기능(B15)으로 살아 있고 D8이 검사한다는 근거를 함께 적어 "설명 없는 금지"가 아니다. → 통과.
- 고정 버전: `typescript@5.6.3` / `vite@5.4.10` / `matter-js@0.20.0` / `vitest@2.1.8` + `npm view … version` 종료코드 0 게이트.
  존재하지 않는 버전을 못 박는 실패를 게이트가 설치 시점 이전에 잡는다. `@types/matter-js`만 의도적 비고정이며 대체 규칙과 영향 범위(파일 1개)를 명시. → 통과.
- 종료코드 있는 완료 명령: D1(`npx tsc --noEmit` 0), D2(`npx vitest run` 0), D8(grep 카운트 3종을 vitest/스크립트 종료코드로 판정). → 형식 충족.

결함:

1. **D8(c)의 grep 패턴이 대상 파일 형식과 어긋나 항상 0을 반환한다 — 블로커.**
   패턴은 `'"two": *1, *"three": *2'`(JSON 따옴표 키)인데, §5는 자리표시자를 `starScore = {two: 1, three: 2}`(따옴표 없는 TS 리터럴)로 저작하라고 지시하고,
   §9는 런타임 JSON fetch를 기각해 빌드타임 임포트(TS 모듈)를 강제한다. 게다가 스테이지 파일의 형식이 문서 어디에도 명시되지 않았다.
   TS 모듈로 읽으면 패턴은 결코 매치되지 않아 카운트는 무조건 0 = 무조건 통과. 자리표시자 잔존을 막는 **유일한 자동 검사**(§5 마지막 문장, §10 "별 임계 자리표시자 잔존" 완화 칸, S9 검증이 모두 여기로 수렴)가 자기충족 조건이 된다.
2. **Vite가 산 것("정적 산출물")을 증명하는 명령이 완료 기준에 없다.**
   §11 D1–D8 어디에도 번들 빌드 명령이 없고(D1은 `--noEmit`이라 산출물을 만들지 않는다), §12의 "보증-커맨드 대응"표에서 Vite 행 자체가 빠져 있다.
   같은 공백이 §4 렌더 행의 "`Matter.Render`는 프로덕션 빌드에서 제외" 주장도 미증명 상태로 남긴다.
3. **§12 matter 격리 규약을 증명하는 명령이 없다.**
   "`matter-js` import는 `PhysicsAdapter` 파일 1개에만", "`Matter.Runner` 금지"는 §4.1 dialectic 차용의 **유일한 산출물**(승자에 붙은 제약)인데,
   §11의 어떤 D도 이를 단언하지 않는다. D3(결정성)은 격리를 증명하지 못한다 — 전 파일에서 matter를 import해도 결정적일 수 있다.
4. **D8(a)의 `sort -u`가 선언한 판정("정확히 한 번씩")을 측정하지 못한다.**
   `grep -rho 'B[0-9]\+' src/ | sort -u | wc -l` 은 중복을 제거한 **고유 ID 개수**다. 같은 마커가 3개 파일에 있어도 1로 세므로 "한 번씩"은 검증 불가이고,
   B1이 누락되고 오타 `B26`이 있어도 25가 나와 통과한다.
