## Q1 — 하중 경로 사슬 (홉 ≤5, 통과 조건 + 최초 참 지점 완비 여부)

**판정: 부분 결함.** 사슬은 5홉으로 상한을 지켰고, 홉 5의 "—"는 템플릿이 종점(관찰 가능한 효과)에
허용하는 형식이므로 결함이 아니다. 홉 2·3·4는 두 열이 모두 채워져 있고 지점이 단계 번호로 특정된다.

- **홉 1 결함**: 통과 조건은 "상태가 STAGE_SELECT이고 n ≤ 해제 스테이지"인데, "최초 참" 열은
  상태 **초기값 MAIN**과 전이 함수의 소재(S2), 해제 기본값(S7)만 답한다. 조건의 앞절인
  "상태 = STAGE_SELECT"가 **최초로 참이 되는 호출자** — S8 메인 화면의 "게임시작" 버튼 —
  는 이 셀에 없다. 규칙의 열 정의는 "the step (or caller) that sets it"이므로, 초기값과
  전이 기계의 소재는 설정자의 답이 아니다.

## Q2 — 콜드 스타트 표의 커버리지

**판정: 결함 2건.** 표의 기존 9행에는 빈 칸이 없다. 그러나 규칙은 "passes only if 셀에 등장하는
**모든** 상태·플래그·큐·전제조건"을 표에 요구한다.

- **누락 행 3개**: 홉 3의 전제 "`collisionStart` 핸들러가 등록돼 있음"과 "바디에 내구도 필드가
  있음", 홉 4의 전제 "`judgeTick()`이 매 틱 실행됨"은 통과 조건 셀에 등장하는 전제조건인데
  콜드 스타트 표에 행이 없다. 홉 표의 "최초 참" 셀이 지점(S6/S4)을 말하고는 있으나, 규칙상
  최초값·변경 주체·실행 시점 3열은 콜드 스타트 표가 지는 의무다.
- **"입력 상태" 행 자기모순**: "누가 바꾸나 = 포인터 다운/업 핸들러(S5)"라고 유일 변경자를
  선언해 놓고, "언제" 열은 "새 장착 시 조준 가능으로"라고 쓴다. 새 장착은 포인터 이벤트가
  아니다(`mountNextBird`, S4/S6). 장착 시점에 조준 가능으로 바꾸는 주체가 표 안에서 미명명.

## Q3 — 홉이 가리키는 심볼·단계의 존재 (고아 열거)

**판정: 고아 1건.** `loadStage(n)`(S4), `mountNextBird()`(S4), `collisionStart` 핸들러(S6),
`judgeTick()`(S6), 상태 머신·전이 함수(S2), 저장 모듈(S7)은 모두 플랜이 해당 단계 본문에서
만들기로 약속한 심볼이다.

- **고아: "오버레이 골격은 S6"(홉 5)**. S6 본문이 약속하는 것은 CLEAR/FAIL **판정과 상태 전이**
  ("돼지 0마리 → CLEAR … → FAIL", 검증 "클리어와 실패가 각각 재현")까지다. 오버레이 UI 골격의
  생성은 S6 산출 목록에 없고, 오버레이는 S7("다음" 버튼)과 S8("FAIL 오버레이에도 같은 두 버튼")
  에서 이미 존재하는 것으로 전제된 채 등장한다. 홉 표만이 골격의 출생지를 S6이라 주장한다 —
  사슬이 가리키는데 본문 어디도 만들기로 약속하지 않은 지점.

## Q4 — build 요구별 표 밖 동사 문장

**판정: 통과.** 원장 28행 = build 25 / defer 1(L25, 트리거 명시) / n-a 2(L16·L28, 이유 명시).
"요구별 동사 문장" 절에 표 밖 문장 정확히 25개(L1~L15, L17~L24, L26, L27) — build 행과 1:1.
각 문장은 actor-action-result 형태이고, "없으면" 절이 단순 부정 재진술이 아니라 가시적 증상
(예: L1 "어느 번호를 골라도 같은 배치", L20 "복귀 시 판이 달라져 있다")을 말한다. 결손 없음.

## Q5 — 구현자 계약 (부활 트리거 / 해석 가능한 핀 / done의 명령·종료 코드)

**판정: 부분 결함.**

- 부활 트리거: 기각 5건 전부에 트리거가 있고 계약 절에 요약돼 있다. 통과.
- 스택 핀: `matter-js@0.20.0`, `@types/matter-js@^0.19.0`, `typescript@~5.6.2`, `vite@^5.4.0` —
  전부 실재하는, 해석 가능한 버전 표기. 통과.
- 명령과 종료 코드: TypeScript의 보증 → `npx tsc --noEmit` exit 0, Vite의 보증 →
  `npm run build` exit 0이 done 1에 있다. 통과.
- **결함: Matter.js의 보증에는 증명이 없다.** 계약 절은 "Matter.js는 스태킹·충돌 해석을 위해
  샀다"고 주장하면서 그 보증의 확인을 **부활 트리거(지터 미해소 시 회수)로만** 처리한다.
  트리거는 보증이 깨졌을 때의 탈출구이지 보증이 성립함의 증명이 아니다. done 3~6은 수동 절차
  문장이고, 스태킹 보증에 가장 가까운 서면 기준(S4 검증 "진입 후 구조물 정지 유지")은 done에
  승격되지 않았다. "산다고 주장한 것을 증명하는 기준이 완료 기준에 없음"에 해당.
