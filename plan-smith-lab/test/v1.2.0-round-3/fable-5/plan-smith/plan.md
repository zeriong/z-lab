### 표면별 품질 바닥선 (사용자 대면 표면당 한 문장)

- **메인**: 타이틀·시작 버튼이 있고 클릭 1회로 선택 화면에 도달하면 완성.
- **스테이지 선택**: 10개 버튼이 잠금 상태와 획득 별 수를 함께 보여주면 완성.
- **인게임**: 모든 파괴가 눈(파티클)과 귀(효과음)와 숫자(점수)로 동시에 피드백되면 완성.
- **일시정지 오버레이**: 뒤 화면이 정지된 채 흐리게 남고 두 버튼이 즉답하면 완성.
- **클리어/실패 오버레이**: 점수·별과 다음 행동(다음/다시하기/메인으로)이 한 화면에 있으면 완성.
- **진행 저장**: 새로고침·브라우저 재시작 후에도 잠금과 별이 유지되면 완성.

## 요구별 동사 문장 (build 25행 = 25문장)

- **L1**: 플레이어가 선택 화면에서 1~10 중 한 번호를 고르면 그 번호 고유의 배치(블록·돼지·새 수)가 로드된다; 없으면 어느 번호를 골라도 같은 배치가 나온다.
- **L2**: 메인에서 "게임시작"을 누르면 10개 버튼 그리드(잠금·별 표시 포함)가 뜬다; 없으면 항상 1스테이지로만 진입하게 된다.
- **L3**: 스테이지 n을 클리어하면 선택 화면에서 n+1 버튼의 자물쇠가 풀린다; 없으면 클리어해도 다음 버튼이 회색으로 남는다.
- **L4**: 클리어 오버레이에서 "다음"을 누르면 `loadStage(n+1)`이 실행돼 새 배치가 뜬다; 없으면 오버레이만 닫히고 이전 스테이지 잔해가 그대로 남는다.
- **L5**: 플레이어가 새총 위의 새를 누르고 끌면 새가 포인터를 따라오되 당김 반경(80px)에서 걸린다; 없으면 새가 화면 끝까지 끌려간다.
- **L6**: 모바일에서 손가락 드래그로 같은 조작이 되고 그동안 페이지는 스크롤되지 않는다; 없으면 조준할 때마다 화면 전체가 딸려 움직인다.
- **L7**: 당기는 동안 예상 포물선이 점 10개 내외로 그려진다; 없으면 발사각을 감으로만 잡아 초탄이 번번이 빗나간다.
- **L8**: 새를 놓는 순간 당김 벡터 × 계수 k의 속도로 발사돼 중력 포물선을 그린다; 없으면 새가 제자리에 떨어지거나 직선으로 날아간다.
- **L9**: 새·잔해가 임계 이상의 충격으로 블록에 닿으면 블록 내구도가 깎이고 0이 되면 소멸한다; 없으면 구조물이 영구히 서 있어 어떤 스테이지도 클리어할 수 없다.
- **L10**: 임계 이상의 충격이 돼지에 닿으면 돼지가 터져 사라지고 점수가 오른다; 없으면 정확히 명중해도 돼지가 멀쩡하다.
- **L11**: 마지막 돼지가 사라지면 1초 안에 CLEAR 오버레이(점수·별·다음)가 뜬다; 없으면 돼지를 다 잡고도 게임이 하염없이 계속된다.
- **L12**: 새가 소진되고 정착 대기가 끝나도 돼지가 남아 있으면 FAIL 오버레이(다시하기·메인으로)가 뜬다; 없으면 빈 새총 앞에서 화면이 멈춘 채 방치된다.
- **L13**: 인게임 좌상단에 남은 새 아이콘 열과 점수가 상시 표시된다; 없으면 남은 기회를 알기 위해 발사 횟수를 머리로 세야 한다.
- **L14**: 블록 파괴·돼지 제거·잔여 새가 정해진 배점으로 합산돼 HUD에 실시간 반영된다; 없으면 클리어 화면의 별이 근거 없는 숫자가 된다.
- **L15**: 클리어하면 잔여 새 규칙에 따라 별 1~3개가 표시되고 저장된다; 없으면 이미 깬 스테이지를 다시 할 이유가 사라진다.
- **L17**: 인게임 **우측 상단**의 버튼을 누르면 상태가 PAUSED로 전환되고 오버레이가 뜬다; 없으면 모바일에서는 게임을 멈출 수단 자체가 없다.
- **L18**: 일시정지 오버레이에서 "다시하기"를 누르면 같은 스테이지가 초기 배치·초기 새 수로 재로드된다; 없으면 한 발 실수를 되돌리려 메인까지 나갔다 와야 한다.
- **L19**: "메인으로"를 누르면 물리 월드가 파기되고 메인 화면으로 전환된다; 없으면 일시정지에서 나가는 길이 재개뿐이다.
- **L20**: PAUSED인 동안 물리 스텝 호출이 0회가 된다; 없으면 오버레이 뒤에서 구조물이 계속 무너져 복귀 시 판이 달라져 있다.
- **L21**: 접속하면 타이틀과 "게임시작" 버튼이 뜨고 클릭 시 선택 화면으로 간다; 없으면 사용자가 맥락 없이 물리 월드 한가운데에 떨어진다.
- **L22**: 발사·파괴·클리어/실패 때 각각 구별되는 효과음이 난다(첫 사용자 입력에서 AudioContext 재개); 없으면 파괴 피드백이 시각에만 의존해 타격감이 죽는다.
- **L23**: 블록·돼지가 소멸하는 순간 파편 파티클(도형 6~10개)이 튄다; 없으면 객체가 소리·흔적 없이 증발해 무엇이 부서졌는지 보이지 않는다.
- **L24**: 클리어하면 잠금 해제와 별점이 localStorage에 저장돼 새로고침 후에도 유지된다; 없으면 브라우저를 닫을 때마다 처음부터다.
- **L26**: 하늘 그라데이션과 지면 띠가 그려져 월드에 상하 방향감이 생긴다; 없으면 흰 배경에 도형만 떠 있어 낙하 방향을 읽기 어렵다.
- **L27**: 창 크기가 바뀌면 960×540 월드가 종횡비를 유지한 채 화면에 맞춰지고 입력 좌표가 역변환된다; 없으면 작은 화면에서 게임 일부가 잘리고 클릭 위치가 어긋난다.

## 문제 정의 / 목표

정적 호스팅 가능한 브라우저 게임 1종. 요구 3건(10스테이지, 슬링샷 물리 게임플레이, 우측 일시정지+다시하기/메인으로)을 전부 충족하고, 위 원장의 build 25행이 모두 존재하는 상태가 목표. 서버·계정·멀티플레이는 범위 밖.

## 명시적 가정 (각각 "틀리면"의 영향 포함)

1. **아트 자산 없음 — 모든 시각 요소는 Canvas 도형(원·사각형·다각형)과 색으로 그린다.** 틀리면(스프라이트 요구가 있으면): 이미지 로더·에셋 파이프라인이 S1에 추가되고 L23 파티클이 스프라이트 시트로 교체된다. 렌더 함수가 바디 타입별로 분리돼 있어 교체 비용은 렌더 계층에 국한.
2. 대상은 데스크톱·모바일의 에버그린 브라우저 최신 2버전. 틀리면: Pointer Events 폴리필과 ES 타깃 하향이 필요 — S1의 빌드 타깃 설정 한 줄로 흡수.
3. UI 언어는 한국어. 틀리면: 문자열 상수 모듈(S2)만 교체.
4. **⟨하중 가정⟩ Matter.js의 `collisionStart` 이벤트에서 충돌 강도(두 바디의 상대속도 크기)를 읽어 파괴 판정에 쓸 수 있다.** 전체 파괴 시스템(L9·L10)이 이 위에 선다. 최저비용 조기 검증: S1에서 바디 2개를 떨어뜨려 충돌 이벤트의 pair 속도를 콘솔로 확인하는 10분 스파이크. 폴백: 이벤트 pair가 강도를 주지 않으면 충돌 직전 프레임의 두 바디 속도 차분으로 근사(정확도는 낮지만 판정엔 충분).
5. localStorage 사용 가능. 틀리면(사생활 모드 등): 메모리 폴백으로 세션 내 진행만 유지 — L24 위험 절 참조.

## 접근과 단계

의존성 순서로 정렬(각 단계: 전제 → 산출 → 검증 → 봉사하는 원장 행). **S1~S6이 스테이지 1 하나를 관통하는 얇은 끝-대-끝 슬라이스**이고, 그 뒤에 폭(콘텐츠·화면), 마지막에 폴리시가 온다. S8은 S2에만 의존하므로 S7과 병렬 가능하다 — 번호는 사다리지만 순차 강제가 아니다.

- **S1 스캐폴드 + 스택 확정** (전제: 없음/독립) — Vite + TypeScript 프로젝트, `matter-js` 설치, 960×540 캔버스 마운트, requestAnimationFrame 루프에서 Engine.update 호출, 하중 가정 4의 충돌 강도 스파이크 수행. 검증: `npx tsc --noEmit` exit 0, `npm run build` exit 0, 스파이크 로그로 가정 4 판정. (전 행의 기반)
- **S2 상태 머신 + 씬 라우터** (전제: S1) — 상태 MAIN → STAGE_SELECT → PLAYING ⇄ PAUSED, PLAYING → CLEAR | FAIL. 상태는 단일 판별 유니언 타입, 전이는 전용 함수로만. PAUSED 진입 시 물리 스텝을 건너뛰는 분기(L20)를 루프에 지금 심는다. 검증: 타입 체크 + 전이 함수 외 상태 대입이 컴파일 에러. (L17~L21, L20)
- **S3 스테이지 스키마 + 스테이지 1 데이터** (전제: S1; S2와 병렬) — 스키마: 새 수, 돼지 배열(위치·반지름), 블록 배열(위치·크기·재질 wood|stone|glass), 선택적 별점 규칙 오버라이드. 저작 규칙: 모든 좌표는 960×540 내부(L16의 n-a를 성립시키는 규칙). 검증: 스키마 위반 데이터가 컴파일 에러. (L1, L16)
- **S4 월드 조립 `loadStage(n)`** (전제: S2+S3) — 지면·경계벽 정적 바디, 새총 앵커 좌표, 스테이지 데이터로 블록·돼지 바디 생성(내구도는 바디 커스텀 필드), 새 대기열 생성 후 `mountNextBird()`로 첫 새를 앵커에 장착. 상태를 PLAYING으로 전이. 검증: 스테이지 1 진입 시 구조물이 무너지지 않고 정지 상태 유지. (L1, L4, L8 기반)
- **S5 입력·발사** (전제: S4) — Pointer Events(마우스·터치 통합, `touch-action: none`)로 장착된 새를 드래그: 앵커 기준 최대 80px로 클램프, 놓으면 당김 벡터 × k를 초기 속도로 부여하고 궤적 점선은 같은 공식의 등가속 시뮬레이션 점 10개로 표시. 발사 후 상태는 사격 불가(비행 관찰)로. 검증: 드래그-발사-포물선이 눈으로 재현, 모바일에서 스크롤 미발생. (L5, L6, L7, L8)
- **S6 충돌·파괴·판정** (전제: S5) — `collisionStart` 핸들러를 `loadStage` 말미에 등록: 상대속도 ≥ 임계 v_break면 블록 내구도 차감(재질별 배수), 0이면 소멸+파티클 훅; 돼지는 임계 이상 1회로 소멸. 매 틱 `judgeTick()`: 돼지 0마리 → CLEAR; 새 대기열 소진 + 마지막 새 발사 후 정착 대기(모든 바디 속도가 하한 미만이거나 타임아웃) 경과 + 돼지 잔존 → FAIL. 판정 시 CLEAR/FAIL 오버레이 골격을 표시한다(내용물 — 점수·별은 S7, 버튼 완성은 S7·S8). 다음 새 장착은 현재 새가 정착하면 `mountNextBird()`. 검증: 스테이지 1에서 클리어와 실패가 각각 재현 — **관통 슬라이스 완성점**. (L9, L10, L11, L12)
- **S7 점수·별·저장·전환** (전제: S6) — 배점: 블록 파괴 500, 돼지 제거 5000, 클리어 시 잔여 새 1마리당 10000 (원작 관례에서 가져온 값 — 도메인 관례 유래). 별: 클리어=1, 잔여 새 ≥1=2, ≥2=3 (선언적 임의값 — S9 저작 중 스테이지별 오버라이드로 대체될 수 있는 수명부 초기값). localStorage 키 1개에 { 해제 스테이지, 스테이지별 별 } JSON 저장. CLEAR 오버레이의 "다음" → `loadStage(n+1)`. 검증: 클리어 → 새로고침 → 잠금 해제 유지. (L3, L4, L13, L14, L15, L24)
- **S8 화면 완성: 메인·선택·일시정지 오버레이** (전제: S2 — S7과 병렬 가능) — 메인(타이틀+게임시작), 선택 화면(10버튼 그리드, 잠금·별 표시), 인게임 우측 상단 일시정지 버튼, PAUSED 오버레이(다시하기 = 현 스테이지 `loadStage(n)` 재호출, 메인으로 = 월드 파기 후 MAIN 전이), FAIL 오버레이에도 같은 두 버튼. 검증: 요구 3의 문구 그대로 — 우측 버튼 클릭 시 다시하기/메인으로 두 버튼 표시. (L2, L17, L18, L19, L21)
- **S9 스테이지 2~10 저작 + 계수 캘리브레이션** (전제: S3 스키마 + S6 판정 완성) — 아래 난이도 곡선 표대로 9개 데이터 파일 작성. 저작하면서 k·v_break·재질 배수를 확정해 임의값의 수명을 끝낸다(각 스테이지는 "의도한 해법 1개 + 우연 해법 여지"로 튜닝). 검증: 저작자가 각 스테이지를 주어진 새 수 안에서 클리어 가능. (L1, L15, L25 트리거 판정 지점)
- **S10 폴리시(명명된 단계): 효과음·파티클·배경·스케일링** (전제: S6; S9와 병렬 가능) — 효과음은 Web Audio 오실레이터 합성(파일 자산 불필요, 가정 1과 일관)으로 발사/파괴/클리어/실패 4종, 첫 입력에서 AudioContext resume; 파괴 파티클(수명 0.5초 내외 도형 파편); 하늘 그라데이션+지면 띠; 리사이즈 시 종횡비 유지 fit과 입력 좌표 역변환. 검증: L22·L23·L26·L27의 동사 문장이 각각 성립. (L22, L23, L26, L27)

## Load-bearing path (하중 경로)

실패하면 산출물 전체가 무의미해지는 단일 경로: **게임시작 → 스테이지 진입 → 드래그 발사 → 충돌 파괴 → 클리어 판정.**

| 홉 | 이름 | 통과 조건(passes only if) | 그 조건이 최초로 참이 되는 곳 |
|---|---|---|---|
| 1 | 메인 "게임시작" → 선택 → `loadStage(n)` | 상태가 STAGE_SELECT이고 n ≤ 해제 스테이지 | 상태 초기값 MAIN·전이 함수는 S2, STAGE_SELECT를 최초로 참으로 만드는 호출자는 S8 메인 화면의 "게임시작" 버튼, 해제 기본값 1은 S7의 저장 모듈 초기화 |
| 2 | 드래그 → 발사 | 장착된 현재 새가 존재하고 입력 상태가 조준 가능 | `loadStage`가 새 대기열 생성 후 `mountNextBird()` 호출 — S4 |
| 3 | 충돌 → 내구도 차감·소멸 | `collisionStart` 핸들러가 등록돼 있고 바디에 내구도 필드가 있음 | 핸들러 등록은 `loadStage` 말미(S6에서 구현), 내구도 필드는 S4 바디 생성 시 |
| 4 | 돼지 0 → CLEAR / 새 소진+정착 → FAIL | `judgeTick()`이 매 틱 실행되고 돼지 목록·정착 타이머가 관리됨 | `judgeTick` 루프 편입과 정착 타이머는 S6, 돼지 목록은 S4 |
| 5 | CLEAR 오버레이(점수·별·다음) 표시 + n+1 해제 저장 | — (관찰 가능한 종점) | 오버레이 골격은 S6, 점수·별·저장은 S7 |

**콜드 스타트 표** — 위 통과 조건에 등장하는 모든 상태의 최초 진입값:

| 상태/플래그 | 최초값 | 누가 바꾸나 | 언제 실행되나 |
|---|---|---|---|
| 게임 상태 | MAIN | S2의 전이 함수만 | 부팅 직후 초기화(S2) |
| 해제 스테이지 | 1 (localStorage 부재 시 기본값) | S7 저장 모듈(클리어 시 +1) | 부팅 시 로드, 클리어 시 기록 |
| 현재 스테이지 n | null | `loadStage(n)` | 선택 화면 버튼 클릭(S8) |
| 새 대기열 | 스테이지 데이터의 새 수만큼 생성 | `mountNextBird()`가 하나씩 소비 | `loadStage` 내부(S4), 이후 정착 시마다(S6) |
| 현재 새 | null → 첫 새 | `mountNextBird()` | `loadStage` 말미(S4) |
| 입력 상태 | IDLE | 포인터 다운/업 핸들러(S5); `mountNextBird()`(S4/S6)도 장착 시 조준 가능으로 설정 | 새 장착 시 조준 가능으로 |
| `collisionStart` 핸들러 등록 | 미등록 | `loadStage` 말미의 등록 코드(S6) | `loadStage(n)` 실행 시 |
| 바디 내구도 필드 | 부재(바디 생성 전) | S4 바디 생성 시 부여, 충돌 핸들러가 차감(S6) | `loadStage` 내부(S4) |
| `judgeTick` 루프 편입 | 미편입 | S6에서 메인 루프에 등록 | 등록 후 매 틱 실행 |
| 돼지 목록 | 스테이지 데이터로 채움 | 충돌 핸들러가 소멸 시 제거(S6) | `loadStage` 내부(S4) |
| 정착 타이머 | null | 마지막 새 발사 후 시작(S6) | `judgeTick` 내부 |
| 일시정지 플래그 | false | 우측 버튼/오버레이 버튼(S8) | 루프의 물리 스텝 분기(S2)가 소비 |

## 대안과 기각 근거 (각 기각에 부활 트리거)

- **물리 직접 구현** — 기각: 스태킹 안정성·회전 충돌 해석·수면(sleeping) 처리는 검증된 엔진의 핵심 가치이고 직접 구현 비용이 게임 전체보다 큼. 부활 트리거: 번들 크기 상한(예: 100KB 미만)이 새 하드 제약으로 등장하거나, Matter의 스태킹 지터가 S9 캘리브레이션으로도 해소되지 않으면 재개.
- **Phaser 등 게임 프레임워크 전체 도입** — 기각: 씬·에셋·애니메이션 관리가 이 범위(단일 물리 씬 + DOM 오버레이)에 과잉이고 학습·번들 비용만 추가. 부활 트리거: 스프라이트 애니메이션·다중 씬 요구가 확정되면 재개.
- **Matter.Render(내장 렌더러) 사용** — 기각: 디버그용이라 재질별 색·HUD·파티클을 얹을 수 없음. 부활 트리거 겸 허용 예외: S1~S4 개발 중 디버그 시각화로는 사용 가능, 출하 렌더는 커스텀 Canvas 2D.
- **DOM/SVG 렌더링** — 기각: 수십 개 바디의 매 프레임 변환에서 Canvas 대비 이점이 없고 파티클에 불리. 부활 트리거: 접근성(스크린리더로 게임 오브젝트 노출) 요구가 등장하면 오버레이 계층에 한해 재검토.
- **서버 저장/계정** — 기각: 요구에 없고 정적 호스팅 제약을 깨뜨림. 부활 트리거: 기기 간 진행 동기화 요구가 명시되면 재개.

물리엔진을 Matter.js로 두는 것은 도메인 정석의 재도달이며, 이 플랜에서 그 선택이 사는 이유는 스택 절에 명시했다(정석이라는 말로 명세를 생략하지 않는다).

## 위험과 완화

- **스태킹 지터로 구조물이 저절로 무너짐** → 정적 지면 마찰·iteration 수 상향, 블록에 수면 허용, S4 검증 항목("진입 후 정지 유지")으로 조기 검출.
- **임계값(v_break, k) 오조정으로 난이도 붕괴** → 두 값 모두 수명부 임의값으로 선언하고 S9 저작 플레이에서 확정하는 것이 단계에 내장됨.
- **모바일 드래그가 스크롤/제스처와 충돌** → 캔버스에 `touch-action: none` + Pointer Events 단일 경로(S5). L6 동사 문장이 검증 기준.
- **오디오 autoplay 차단** → 첫 사용자 입력에서 AudioContext resume(S10에 내장).
- **localStorage 불가 환경** → 읽기/쓰기를 저장 모듈 1곳으로 격리하고 실패 시 메모리 폴백(세션 내 진행만 유지, 시작 시 1회 안내).
- **정착 판정이 끝나지 않음(미세 진동)** → 속도 하한 판정에 상한 타임아웃을 병행(둘 중 먼저 오는 쪽) — S6에 명시.

## Definition of "done"

1. `npx tsc --noEmit`이 exit 0, `npm run build`가 exit 0. (스택을 산 이유에 대한 증명 명령 — 구현자 계약 참조)
2. 스테이지 데이터 파일이 정확히 10개이고 각각 스키마 타입 체크를 통과한다(1의 명령이 겸증명).
3. **저장소를 비운 새 브라우저 프로필에서: 메인 → 게임시작 → 스테이지 1 → 드래그 발사만으로 모든 돼지 제거 → CLEAR 오버레이(점수·별 표시) → 새로고침 → 선택 화면에서 스테이지 2가 열려 있다.** 이 문장 전체가 한 번의 절차로 재현되면 통과, 어느 고리든 끊기면 실패. 또한 스테이지 1 진입 직후 발사 전 구조물이 정지 상태를 유지한다(S4 검증의 승격 — Matter.js 스태킹 보증의 서면 확인 기준).
4. PLAYING 중 우측 상단 버튼 클릭 → 물리 정지 + "다시하기"/"메인으로" 두 버튼 표시; "다시하기"는 같은 스테이지 초기 배치, "메인으로"는 메인 화면 도달.
5. 새를 전부 소진하고 돼지를 남기면 FAIL 오버레이가 정착 대기 후 표시된다.
6. 저작자 기준 스테이지 1~10 각각이 주어진 새 수 이내로 클리어 가능함을 S9에서 스테이지당 1회 이상 확인(측정자: 저작자, 도구: 실제 플레이, 기록: 스테이지별 클리어 시 잔여 새 수 메모).

## Implementer contract

- **스택 핀(전부 해석 가능한 버전)**: `matter-js@0.20.0`, `@types/matter-js@^0.19.0`, `typescript@~5.6.2`, `vite@^5.4.0`. 렌더링은 Canvas 2D 직접 드로우, UI 오버레이는 DOM.
- **스택을 산 이유와 증명 명령**: TypeScript는 스테이지 스키마와 상태 머신의 오기를 컴파일 시점에 잡기 위해 샀다 → 그 보증은 `npx tsc --noEmit` exit 0으로 증명한다(done 1). Vite는 정적 번들 산출을 위해 샀다 → `npm run build` exit 0(done 1). Matter.js는 스태킹·충돌 해석을 위해 샀다 → 그 보증의 성립은 done 3의 정지 유지 기준으로 확인하고, 깨지는 조건(스태킹 지터 미해소)은 위 부활 트리거로 회수된다.
- **기각 부활 트리거 요약**: 직접 물리 = 번들 상한 등장 또는 지터 미해소 시 / Phaser = 스프라이트·다중 씬 요구 시 / Matter.Render = 출하 금지·디버그만 / DOM·SVG = 접근성 요구 시 오버레이 한정 / 서버 저장 = 기기 간 동기화 요구 시.
- **수치 태그 총람**: 당김 반경 80px·발사 계수 k·파괴 임계 v_break·재질 배수 = 선언적 임의값, S9 캘리브레이션이 수명 종점 / 배점 500·5000·10000 = 원작 관례 유래 / 별점 규칙(잔여 새 1·2) = 임의 초기값, 스테이지별 오버라이드 필드가 대체 경로 / 캔버스 960×540 = 16:9 관례 + 임의, 변경 시 L16 저작 규칙과 L27 스케일링만 영향 / 정착 타임아웃 = 임의값, S6에서 속도 하한과 병행 선언.

## Frame deviations & habit regressions

- **별점 규칙의 일괄 적용(§S7, §수치 태그 총람)**: 잔여 새 기준 별점을 전 스테이지 공통 규칙으로 뒀다. 새 수가 3~5로 다른 난이도 곡선(§10스테이지 표)에서 이 규칙은 후반 스테이지의 별3을 상대적으로 어렵게 만든다. 스키마에 오버라이드 필드를 넣는 것으로 한 번 직접 수정했지만, 어떤 스테이지가 오버라이드를 받아야 하는지는 S9로 미뤄져 있다 — 리뷰어라면 여기를 공격할 것.
- **가장 얇은 표면은 L27 모바일 스케일링**: 동사 문장 1개와 S10의 "종횡비 유지 fit + 입력 좌표 역변환" 한 구절이 전부다. 좌표 역변환의 구체 절차(캔버스 CSS 크기 대 내부 해상도 비율)는 미지정이라, 커버리지 우선 습관이 깊이를 여기서 희생했다.
- **안전 수렴 의심 지점**: 효과음을 오실레이터 합성으로 정한 것(§S10)은 "자산 없음" 가정과 일관되지만, 합성음 4종의 실제 타격감은 검증 없이 낙관한 값이다. 구조적 답(짧은 무료 샘플 번들) 대신 마찰 없는 기본값을 골랐을 수 있다 — L22의 품질 바닥선("귀로 피드백")이 성립하는지의 판정은 S10 검증 문장에 걸려 있다.
- **사다리 번호의 순차 인상(§접근과 단계)**: S7과 S8, S9와 S10이 각각 병렬 가능함을 본문에 명시했지만, 번호 체계 자체는 여전히 시간축 오름차순으로 읽히기 쉽다. 의존성 그래프 그림 대신 문장 주석으로 때운 것은 관행에 기운 선택이다.
- **배선 감사 반영(round-3 수정)**: 지적 5건 전부 수용 — 기각 없음. 홉 1 설정자 지목, 콜드 스타트 3행 추가, 입력 상태 변경자에 `mountNextBird` 병기, S6 산출에 오버레이 골격 명시, S4 정지 유지 검증의 done 3 승격.
