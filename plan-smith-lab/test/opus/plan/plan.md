# 웹 브라우저 앵그리버드 게임 — 구현 플랜

## 1. 목표 요약

새총으로 발사체를 당겨 쏘아 포물선 궤적·중력·충돌·구조물 파괴로 돼지(목표물)를 제거하는 물리 기반 슬링샷 게임을 웹 브라우저에서 동작하게 만든다. 스테이지는 10단계이며, 인게임 우측에 일시정지 버튼이 있고 클릭 시 "다시하기 / 메인으로" 오버레이가 뜬다. 데스크톱 브라우저를 1차 타깃으로 하고 모바일 터치는 여력이 되면 대응한다.

## 2. 기술 선택

**물리 엔진: Matter.js 라이브러리를 채택한다.** 앵그리버드류는 강체(rigid body) 충돌, 마찰, 복원, 제약(constraint) 기반 새총, 스택된 구조물 붕괴가 핵심인데 이걸 직접 구현하면 충돌 해상(broad/narrow phase), 접촉 임펄스, 안정적 스태킹까지 몇 주가 든다. Matter.js는 이 전부를 검증된 형태로 제공하고 `Matter.Events`로 충돌 콜백(`collisionStart`)을 쉽게 받을 수 있어 파괴·데미지 로직을 붙이기 좋다. 직접 구현은 "학습 목적"이 아니면 비용 대비 이득이 없다.

**렌더링: Canvas 2D를 채택한다.** 물체 수십 개 수준의 2D 게임이라 WebGL까지 필요 없다. 다만 Matter.js 내장 렌더러(`Matter.Render`)는 디버그용에 가까우므로, 물리는 Matter.js로 계산하되 화면 그리기는 별도의 커스텀 Canvas 2D 렌더 루프에서 담당한다. 이렇게 분리하면 스프라이트·배경·궤적 가이드·UI를 자유롭게 그릴 수 있다. 초기 개발 단계에서는 `Matter.Render`로 물리 형상을 그대로 띄워 검증하고, 이후 스프라이트 렌더러로 교체한다.

**스택: TypeScript + Vite.** 타입 안정성으로 스테이지 데이터/상태 머신 구조의 실수를 줄이고, Vite로 빠른 HMR 개발 루프를 확보한다. 외부 상태관리 라이브러리 없이 단순 클래스/모듈로 게임 상태를 관리한다(단일 페이지, 단일 캔버스라 오버엔지니어링 불필요).

## 3. 상태 머신

게임 전체를 하나의 상태 머신으로 관리한다. 상태는 다음과 같다.

- `MENU` (메인 화면, 스테이지 선택)
- `PLAYING` (인게임, 물리 시뮬레이션 및 입력 활성)
- `PAUSED` (일시정지, 물리 정지 + 오버레이 표시)
- `CLEAR` (스테이지 클리어)
- `FAIL` (발사체 소진 후 돼지 잔존)

전이 규칙:
- `MENU → PLAYING`: 스테이지 선택/시작
- `PLAYING → PAUSED`: 우측 일시정지 버튼 클릭 (물리 스텝 루프 정지)
- `PAUSED → PLAYING`: (오버레이 밖 클릭 또는 재개) — 요구사항엔 없지만 다시하기/메인으로만으로도 성립
- `PAUSED → PLAYING(재시작)`: "다시하기" → 현재 스테이지 리셋
- `PAUSED → MENU`: "메인으로"
- `PLAYING → CLEAR`: 돼지 전멸 감지
- `PLAYING → FAIL`: 새 소진 + 물체 정지 + 돼지 잔존
- `CLEAR/FAIL → PLAYING`: 다시하기 / 다음 스테이지
- `CLEAR/FAIL → MENU`: 메인으로

상태별로 "물리를 업데이트하는가 / 입력을 받는가 / 무엇을 그리는가"를 명확히 분리한다. `PAUSED`에서는 물리 `Engine.update` 호출을 건너뛰되 마지막 프레임을 계속 그려 화면을 정지시킨다.

## 4. 10개 스테이지 시스템

각 스테이지는 순수 데이터(JSON 또는 TS 객체 배열)로 선언한다. 코드와 데이터를 분리해 스테이지 추가/수정을 데이터 편집만으로 가능하게 한다. 한 스테이지 데이터가 담는 것:

- `id`, `name`
- `slingshot`: 새총 앵커 좌표
- `birds`: 사용 가능한 발사체 수와 타입(초기엔 기본 새 1종)
- `pigs`: 돼지 배열 (좌표, 크기, 체력)
- `blocks`: 구조물 배열 (좌표, 크기, 회전, 재질 — 나무/돌/유리로 밀도·내구도 차등)
- `ground`/`background`: 지형·배경 식별자
- `starThresholds`: 점수 기반 1~3성 기준(옵션)

로딩/전환은 `StageManager`가 담당한다. 현재 스테이지 인덱스를 들고, `loadStage(i)`가 이전 스테이지의 모든 Matter body를 `World.clear` 후 새 데이터로 body를 생성한다. 클리어 시 `currentIndex+1`로 다음 스테이지를 로드하고, 10번째 클리어 시 엔딩/메인 복귀를 처리한다. 스테이지 진행 상태(클리어 여부·최고점)는 `localStorage`에 저장해 재방문 시 복원한다.

## 5. 슬링샷 게임플레이

**입력(드래그·조준·발사):** 새총 앵커 근처의 새를 포인터로 누르면 드래그 시작. 드래그 중에는 앵커에서 포인터까지의 벡터를 계산하되, 최대 당김 거리(`maxPull`)로 클램프한다. 포인터를 놓으면 당김 벡터의 반대 방향으로 세기에 비례한 초기 속도를 `Body.setVelocity`로 부여해 발사한다. 발사 후 새가 정지하거나 화면 밖으로 나가면 다음 새를 앵커에 장전한다.

**궤적 예측 UX:** 드래그 중 발사 예상 경로를 점선 점(dot)들로 미리 보여준다. 실제 물리 스텝을 여러 번 미리 돌리는 대신, 초기 속도 `v0`와 중력 `g`로 등가속도 포물선 공식(`p(t) = p0 + v0·t + ½·g·t²`)을 이용해 일정 간격 `t`마다 점을 찍는다(충돌 전까지의 근사). 점 개수를 8~12개로 제한해 "겨냥은 되지만 정답을 다 알려주진 않는" 밸런스를 맞춘다.

## 6. 충돌·파괴·점수·클리어 규칙

**충돌/파괴:** `Matter.Events.on(engine, 'collisionStart')`에서 충돌쌍과 충격량(상대 속도)을 읽는다. 각 body에 커스텀 데이터(`gameType`, `hp`, `material`)를 붙여, 충격량이 재질 임계값을 넘으면 데미지를 준다. 돼지는 hp가 0이 되면 제거(월드에서 body 삭제 + 파괴 이펙트/사운드). 블록은 hp 소진 시 제거하거나 파편으로 대체한다. 유리는 낮은 임계값, 돌은 높은 임계값으로 재질별 파괴 난이도를 만든다.

**점수:** 돼지 처치 기본 점수 + 블록 파괴 점수 + 미사용 새당 보너스. 점수는 별 등급(`starThresholds`) 계산에 사용한다.

**클리어/실패 판정:**
- 클리어: 스테이지의 살아있는 돼지 수가 0이 되는 순간 `CLEAR`.
- 실패: 남은 새가 0이고, 발사된 마지막 새·모든 물체의 속도가 임계값 이하로 "정지"했으며(월드가 안정됨), 돼지가 1마리 이상 남아 있으면 `FAIL`. "정지" 판정은 매 프레임 전체 body의 최대 속도가 임계값 미만인 상태가 일정 시간(예: 1.5초) 지속되는지로 확인한다(무한 대기 방지).

## 7. 일시정지 오버레이 (우측)

인게임 화면 **우측 상단**에 일시정지 아이콘 버튼을 고정 배치한다. 클릭하면 `PAUSED`로 전이하며 반투명 딤 위에 오버레이 패널을 띄우고 **"다시하기"**, **"메인으로"** 두 버튼을 노출한다.
- **다시하기:** 현재 스테이지를 `StageManager.reload()`로 리셋 → `PLAYING` 복귀.
- **메인으로:** 월드 정리 후 `MENU`로 전이.

UI 구현은 Canvas 위에 HTML/CSS 레이어를 오버레이하는 방식을 택한다(버튼 히트 영역·접근성·스타일링이 캔버스 내부 그리기보다 쉽고 안정적). 일시정지 버튼과 오버레이는 `PLAYING`/`PAUSED` 상태에 따라 DOM 표시를 토글한다.

## 8. 구현 단계

1. **프로젝트 스캐폴딩** → 검증: Vite+TS 실행, 빈 캔버스에 Matter.js 바닥+낙하 박스 1개 렌더.
2. **슬링샷 코어** → 검증: 드래그로 새를 당겨 발사하면 포물선을 그리며 날아간다.
3. **궤적 예측 + 충돌/파괴** → 검증: 조준 점선 표시, 충돌로 블록/돼지 hp 감소·제거.
4. **상태 머신 + 클리어/실패 판정** → 검증: 돼지 전멸 시 CLEAR, 새 소진 시 FAIL 전이.
5. **일시정지 오버레이(우측) + 다시하기/메인으로** → 검증: 각 버튼이 정확한 상태 전이 수행.
6. **10개 스테이지 데이터 + StageManager 로딩/전환** → 검증: 10개 스테이지 순차 진행·리셋 정상.
7. **점수·별 등급·localStorage 저장, 사운드/이펙트, 폴리시** → 검증: 재방문 시 진행 상태 복원.
8. **밸런싱 + 성능 튜닝 + 크로스 브라우저 확인.**

## 9. 리스크

- **파괴 임계값 밸런싱:** 재질 임계값이 잘못되면 너무 쉽거나 안 부서짐. → 값을 데이터로 빼고 반복 튜닝.
- **스택 안정성(지터):** Matter.js 스택이 미세하게 흔들려 오판정 가능. → `sleeping` 활성화, 속도 임계값·지속시간으로 정지 판정.
- **궤적 예측 정확도:** 공식 근사가 충돌 후 실제 경로와 달라짐. → 충돌 전 구간만 표시로 한정.
- **스테이지 전환 누수:** body/이벤트 리스너 미정리 시 메모리·중복 충돌 발생. → `loadStage`에서 월드·리스너 일괄 정리.
- **모바일 대응:** 좌표 스케일·터치 이벤트 차이. → 1차는 데스크톱, 포인터 이벤트로 추상화만 확보.

## 10. 완료 판정 기준

다음을 모두 만족하면 "된 것"으로 본다.

1. **(측정 가능)** 10개 스테이지 전부가 오류 없이 로드되고, 각 스테이지를 정상 조작으로 클리어할 때 콘솔 에러 0건.
2. **(측정 가능)** 데스크톱 Chrome 최신 버전에서 발사·충돌·파괴가 진행되는 인게임 상황에서 평균 55fps 이상(초당 프레임 계측 기준)을 유지한다.
3. 슬링샷 드래그→조준 점선→발사→포물선 비행→충돌 파괴가 모든 스테이지에서 동작한다.
4. 우측 일시정지 버튼 클릭 시 오버레이가 뜨고, "다시하기"는 현재 스테이지를 초기 상태로 되돌리며, "메인으로"는 메인 화면으로 전이한다.
5. 상태 머신 전이(메인 → 인게임 → 일시정지 → 클리어/실패)가 각 트리거에서 의도대로 일어난다.
