# 웹 브라우저 앵그리버드 게임 — 구현 플랜

- 추론 프레임: backward (완료 기준 역방향 연쇄) / 스타일: opus
- 한 줄 요약: 검증 가능한 완료 기준 5개를 문서 최상단에 못 박고, 물리엔진·렌더링·스테이지 구조·상태머신을 그 기준에서 역산해 도출한다.

## 의도 패킷 (증류 요약)

- **목표(성공의 정의):** 새총 슬링샷 물리(중력·포물선·충돌·구조물 파괴)로 돼지를 제거하는 앵그리버드형 게임이 웹 브라우저에서 플레이 가능하고, 서로 다른 10개 스테이지를 클리어할 수 있으며, 인게임 우측의 일시정지 버튼으로 다시하기/메인 이동이 가능하다.
- **하드 제약:** ① 스테이지 정확히 10개 (5개로는 불충족 — 사용자가 못 박은 수치). ② 스크립트 가짜 궤적이 아닌 실제 물리 기반 슬링샷. ③ 일시정지 버튼은 인게임 **우측** 배치 + 오버레이에 다시하기/메인. ④ 상태 흐름 메인→인게임→일시정지→클리어/실패.
- **기각 대안(요지):** 손수 구현한 물리엔진, WebGL/Pixi 렌더러, 스테이지별 하드코딩, 엔진 정방향 시뮬레이션 기반 조준 프리뷰 — 각 기각 사유와 부활 조건은 후단 참조.

## 프레임 선정 근거

네 술어로 라우팅한다. **① 불확실성 위치**가 결정타다 — 미지의 대상이 원인도(진단 계열 불필요), 시장 반응도, 실행자 자신도 아니다. 검증 가능한 *기능* 기준이 주어진 순수 그린필드 빌드다. 이 사실이 "게임→emotion-curve/failure-first" 도메인 힌트를 기각한다: 스펙은 *느껴야 할 경험 곡선*이 아니라 *기능 기준*을 준다. emotion-curve를 얹으면 frames.md가 경고한 "곡선이 장식이 되고 논의가 메커니즘으로 회귀"가 그대로 재현된다. api-first도 부적합 — 여기서 "사용자"는 코드를 치는 개발자가 아니라 플레이어다. **② 자원 경직성**·**③ 인지 여유**·**④ 척도 합의**는 지배 술어가 아니다(자원 갈등 없음, 인시던트 아님, 클리어 판정 척도는 합의 가능). 남는 것은 Backward/Form 계열이고, 요구사항 세 항목이 곧 검증 가능한 완료 기준이므로 **backward**가 최적이다.

**정직성 단서(canon 지배):** Matter.js + Canvas 2D는 이 브리핑의 업계 표준 답이다. backward의 watch-out대로, 표준이 지배하는 곳에서 이 프레임의 가치는 *답을 생산*하는 데 있지 않고 *표준이 강제되지 않는 경계를 긋는* 데 있다. 이 플랜의 비표준 설계 노동은 앵커 교차점 세 곳 — 스키마 키스톤(A1×A4), 멱등 리셋 생명주기(A5×A1), 해석적 프리뷰(A2×A1) — 이며, 기술 스택 선택 자체는 canon 재도착으로 정직하게 기입한다.

## 완료 기준 앵커 (프레임 지정 출발점)

앵커 자격 시험: *실패 시 재작업 비용이 최대*인 조건만 앵커다. 장식성 요구는 탈락시킨다.

- **A1 물리 충실도** — 발사체가 중력 포물선을 그리고, 구조물과 충돌해 넘어뜨리거나 파괴하며, 돼지를 제거한다. (실패 = 앵그리버드 시스템 부재 → 코어 루프 전면 재작업.)
- **A2 슬링샷 입력** — 당김 벡터가 발사 속도·각을 결정하고 궤적 프리뷰가 표시된다. *이 앵커는 오직 A2×A1의 "해석적 프리뷰" 아키텍처 분기로만 자격을 얻는다*; 입력 자체는 아키텍처와 분리되어 있어 그 분기가 없으면 off-anchor로 강등한다.
- **A3 클리어/실패 판정** — 돼지 전멸 시 클리어, 새 소진 + 돼지 잔존 + 월드 정지 시 실패. (실패 = 게임이 아니라 샌드박스.)
- **A4 10개 데이터 주도 스테이지** — 스테이지가 데이터 스키마로 표현되고 깔끔히 로드/전환된다. (실패 = 콘텐츠 확장 불가 → 로딩 재설계 = 최대 재작업.)
- **A5 상태머신 + 리셋 생명주기** — 메인→인게임→(일시정지: 다시하기/메인)→클리어/실패가 명시적 FSM이고, 물리 월드가 깔끔히 정지·재초기화된다.

**off-anchor 요구의 자격 박탈:** 사운드, 파티클 파괴 이펙트, 리더보드, 모바일 터치 패리티, 화려한 셰이더는 기준에 없으므로 아키텍처를 움직일 권리가 없다. "일시정지 버튼 우측 배치"는 하드 요구이지만 *배치(cosmetic)* 문제이지 최대 재작업 앵커가 아니다 — 완료 기준에만 남기고 아키텍처로 분식하지 않는다.

### 각 앵커가 죽이는 대안 (역연쇄, 예정 결론 방지)

- A1은 "스크립트 가짜 궤적"을 죽인다 → 실제 엔진 필요. A1+A4(10개 다양한 구조물의 검증된 충돌)는 시간 제약 빌드에서 "손수 물리"를 죽인다 → **Matter.js**(canon 재도착).
- A2×A1은 "엔진 정방향 시뮬레이션 프리뷰"를 죽인다 → 충돌 무시 **해석적 포물선 샘플링**(값싸고 결정적)이 프리뷰 라인.
- A3은 "점수 임계 클리어"와 "렌더 루프에 판정 결합"을 죽인다 → 돼지 개수 == 0 이벤트 기반 판정.
- A4는 "스테이지별 하드코딩"을 죽인다 → JSON 스키마(지면/블록[모양·재질]/돼지 좌표/새 수/새총 위치).
- A5는 "불리언 플래그 난립"과 "캔버스 숨기기 = 일시정지"를 죽인다 → 명시적 FSM + 월드 폐기/재생성.

### 앵커 교차 통과 (충돌점·상호지지·의존성 발견)

- **A1×A4 (키스톤):** 10개 스테이지를 값싸게 저작하려면 구조물이 재사용 가능한 물리 프리미티브(블록 모양·재질) 소어휘로 구성돼 스키마로 표현돼야 한다. 상호지지 — "엔진이 데이터를 읽는" 구조면 *스테이지 추가 = 데이터 추가*(코드 무변경). **이 의존성이 나머지를 지붕처럼 덮어 실행 순서를 지정한다.**
- **A5×A1:** 물리엔진은 누적 상태를 지닌다. 월드를 폐기·재생성하지 않는 "다시하기"는 바디 누수·디싱크를 부른다. 해소 — 다시하기 = 스테이지 데이터로부터 월드 티어다운 후 재초기화(멱등 로드). 이로써 A4의 "깔끔한 로드"와 A5의 "다시하기"가 *같은 로더*가 된다(상호지지).
- **A2×A1:** 정확한 프리뷰는 충돌을 시뮬레이션해야 해 비싸고 비결정적이다. 앵그리버드 관례인 충돌 무시 해석적 호로 해소; 프리뷰가 장애물을 무시하는 작은 발산은 의도된 것으로 수용.
- **A3×A5:** 클리어/실패는 FSM의 전이이며 월드 이벤트로 발화한다. 공유 조건 — "월드 정지"(모든 바디 속도 < ε가 T ms 지속)가 실패 조기 판정을 막는다.

## 명시적 가정 (틀리면 어떻게 되나)

- **[핵심] Matter.js가 스테이지당 바디 수를 대상 브라우저에서 60fps로 처리한다.** 틀리면: 스테이지당 바디 수 축소 또는 렌더러 교체. *가장 값싼 조기 검증 = 0단계 스파이크*; 폴백 = 바디 상한/구조 단순화.
- 데스크톱 포인터(마우스 드래그)가 1차 대상. 틀리면(터치 필요): Pointer Events가 이미 통합 처리 → 소폭 재작업.
- "앵그리버드 같은"이 단일 새 타입·특수능력 없음을 뜻한다. 틀리면: 스키마에 bird-type 필드 추가(가산적).

## 접근 & 단계 (의존성 순서, 연대기 아님)

- **0단계 물리 스파이크 (독립/병렬):** 임펄스로 발사한 바디를 블록 더미에 던져 전복·파괴 감이 수용 가능하고 프레임이 유지되는지 확인. → A1. 검증: 목표 바디 수에서 60fps, 포물선 육안 정합. 큰 베팅을 정보 구매로 전환.
- **1단계 키스톤 — 스키마 + 멱등 로더:** 데이터로부터 월드 생성, 월드 폐기. → A4(+A5/A3 토대). 선행: 0단계 엔진 선택 소비. 검증: 데이터 로드 시 정확한 바디 생성; **로드 2회 호출 시 누수 바디 0(바디 수 동일).**
- **2단계 물리+렌더 동기화 + 수직 슬라이스 1스테이지:** → A1. 선행: 1단계 로더. 검증: 발사→호→블록 이동/파괴→돼지 1마리 제거.
- **3단계 슬링샷 입력 + 궤적 프리뷰:** → A2. 선행: 2단계. 검증: 드래그가 당김 벡터 생성, 릴리스가 당김 비례 속도(상한 클램프)로 발사, 점선 프리뷰가 실제 초기 호와 허용오차 내 일치.
- **4단계 FSM + 일시정지 오버레이(우측 버튼; 다시하기/메인) + 클리어/실패 판정:** → A5+A3. 선행: 1단계(다시하기=재로드), 2단계(돼지 계수). 검증: 일시정지가 시뮬레이션 정지 + 다시하기/메인 노출; 다시하기가 동일 스테이지 재초기화; 마지막 돼지 제거 시 클리어; 새 소진+월드 정지+돼지 잔존 시 실패.
- **5단계 나머지 9개 스테이지를 순수 데이터로 저작 + 스테이지 전환:** → A4(+A1). 선행: 1~4단계 안정(스키마 동결). 검증: 10개 모두 로드·클리어 도달 가능; **스테이지 추가가 데이터만 건드리고 엔진 코드 0줄.**

## 대안 & 기각 근거 (부활 조건 포함)

- **손수 구현 물리** — 기각(A1+A4가 검증된 광역 충돌을 요구, 시간 비용). 부활: 무의존/초소형 번들 제약 등장, 또는 결정적 리플레이 필요 시(Matter.js는 버전 간 비결정적).
- **WebGL/Pixi 렌더링** — 기각(off-anchor; 이 규모엔 Canvas 2D로 충분). 부활: 스테이지가 수백 개 동적 스프라이트 또는 무거운 시각 FX 요구 시.
- **스테이지별 하드코딩** — 기각(A4가 죽임; 10개 값싸게 확장 불가). 부활: 없음.
- **엔진 시뮬레이션 프리뷰** — 기각(A2×A1: 비싸고 비결정적; 관례는 해석적 호). 부활: 장애물 인지 조준 보조가 설계 요구가 될 때.

## 리스크 & 완화

- **터널링**(빠른 발사체가 얇은 블록 관통): 연속 충돌 활성화 / 발사 속도 상한 / 최소 블록 두께.
- **월드 정지 전 조기 실패 판정**: 정지 감지(모든 바디 속도 < ε가 T ms 지속)가 실패 전이를 게이트.
- **다시하기 상태 누수/디싱크**: 멱등 로더가 월드 폐기; 1단계 바디 수 동일성으로 검증.
- **클리어 불가 스테이지**(돼지가 도달 불가 위치에 낌): 각 스테이지는 주어진 새로 클리어 가능해야 함 — 출하 전 플레이테스트 게이트.

## 수치 태깅

- 60fps = **(a) 파생**: 웹 애니메이션 표준 프레임 예산(16.7ms).
- 발사 속도 상한 / 최소 블록 두께 = **(b) 수명 한정**: 0단계 스파이크가 터널링 없는 최소값을 첫 측정으로 확정(측정자: 구현자).
- 정지 감지 ε(속도 임계) / T(지속 ms) = **(b) 수명 한정**: 4단계 플레이테스트가 "정지처럼 보이는데 아직 안 멈춤" 오판이 사라지는 값을 확정(측정자: 구현자/플레이테스터).
- "3회 연속 다시하기" = **(c) 임의 선언**: 누수는 회차에 누적되므로 3회는 누수 노출용 최소 반복치; 누수 발견 시 상향.

## "완료"의 정의

- **실측 가능 문장:** "10개 스테이지 각각을 주어진 새로 클리어하고, 각 스테이지에서 일시정지→다시하기를 눌렀을 때 스테이지가 동일 엔티티 집합(바디 수·위치 동일)으로 재초기화되며 여전히 클리어 가능하다. 10/10 통과, 3회 연속 다시하기 후 누수 바디 0." — 바디 수·위치·통과 수로 측정 가능하고, 어떤 블로커도 자동 충족시키지 못한다(로더가 실제로 누수하면 실패).
- 일시정지 버튼이 우측에 있고 오버레이가 다시하기/메인을 노출하며, 클리어/실패에서 메인 복귀가 가능하다.
- **측정 저항 범주(측정 편향 스윕):** "게임 필"(슬링샷이 만족스러운가)은 결정적이나 실측 불가 — 앵커가 포착 못 하는 범주로 명시하고, 지표 대신 플레이테스트 게이트를 프록시로 둔다.

## Frame deviations & habit regressions

- **canon 재도착을 backward 도출로 분식할 위험:** 기술 스택 앵커(A1→Matter.js, 렌더링→Canvas 2D)는 도메인 canon으로 수렴했다. 즉 이 부분의 역방향 도출은 예정된 선택을 사후 합리화한 측면이 있다("역연쇄가 예정 결론으로" — backward의 명명된 실패 모드). 도출이 값을 번 곳은 앵커 교차점 세 곳(스키마 키스톤 §A1×A4, 리셋 생명주기 §A5×A1, 해석적 프리뷰 §A2×A1)뿐이다. 리뷰어라면 나는 "완료 기준 앵커" 절의 A1/렌더링 도출을 canon 강제 여부로 공격하겠다 — 그래서 그 절에 canon 재도착을 명기했다.
- **A2의 앵커 자격이 가장 약하다:** 입력은 아키텍처와 분리돼 있어, A2×A1 해석적 프리뷰 분기가 없었다면 off-anchor 강등이 옳았다. 본문에서 그 조건을 명시했으나, 5개 앵커 중 A2가 앵커 문턱에 가장 가깝게 걸쳐 있음을 인정한다.
- **수렴 본능 점검:** 5단계 "수직 슬라이스 후 9개 저작"은 opus 스타일의 안전한 점진 롤아웃 성향이 맞다. 다만 이 과제에선 스키마 동결이 실제 구조적 근거(A1×A4 키스톤)이므로 안전 기본값이 아니라 의존성이 강제한 순서다 — 회귀가 아니라고 판단한다.
