# 웹 앵그리버드 게임 구현 계획

## 기술 스택 선택

**물리 엔진:** Matter.js 라이브러리 사용. 슬링샷 기반 게임은 정확한 중력·충돌·회전 시뮬레이션이 중요한데, 직접 구현하면 버그와 성능 문제가 크다. Matter.js는 검증된 2D 물리 엔진이고 앵그리버드 같은 게임에 충분하다.

**렌더링:** Canvas 2D를 사용해 게임 뷰포트를 그리고, HTML/CSS로 UI(일시정지 버튼, 오버레이)를 따로 관리. Canvas API는 충분히 빠르고 간단하다. Three.js 같은 3D 라이브러리는 과도하다.

**구조:** Vanilla JavaScript(or TypeScript) + Matter.js. 번들러는 간단하게 esbuild 또는 Vite만 사용.

## 10개 스테이지 시스템

스테이지 데이터를 JSON으로 정의하되, 각 스테이지는 다음을 포함:
- 구조물 배치(좌표, 회전, 몸체 타입: 나무/돌/유리)
- 목표 객체(돼지) 위치 및 개수
- 새 종류(보통 새, 특수 능력 새 등) 목록과 발사 순서
- 난이도 지표(예: 필요 별점)

초기 3-4개 스테이지는 간단한 구조물 1-2개로 시작해 학습 곡선을 만들고, 후반부는 복잡한 다층 구조로 난이도를 올린다.

데이터 로드 방식:
1. `stages.json` 파일에 모든 스테이지 정의
2. 스테이지 시작 시 해당 데이터를 파싱하고 Matter 월드에 리드바디 생성
3. 스테이지 완료/실패 시 월드를 초기화하고 새 스테이지 데이터 로드

## 슬링샷 물리 및 입력

**슬링샷 디자인:**
- 화면 좌측 하단 고정점에 슬링샷 렌더링
- 새(발사체)는 슬링샷 끝에서 시작, 플레이어가 드래그하면 뒤로 늘어남
- 최대 드래그 거리 제한(예: 100px) 이상으로는 늘어나지 않음
- 손가락 뗄 때 발사, 드래그 벡터를 초속도로 변환

**궤적 예측:**
플레이어가 드래그할 때 발사 후 몇 개 프레임의 궤적을 점선으로 미리 표시. 이는 선택사항이지만 UX 개선에 도움된다.

**발사 메커니즘:**
```
드래그 시작 → 슬링샷 늘어남
드래그 중 → 궤적 미리보기 갱신
드래그 끝 → 발사(Rigidbody에 속도 설정)
```

## 충돌·파괴·점수·클리어

**점수 시스템:**
- 목표 객체(돼지) 제거: 10점/마리
- 구조물 파괴(불필요한 경우): 5점/개(선택사항)
- 스테이지 클리어 보너스: 남은 새 개수 × 10점

**클리어 판정:**
- 모든 돼지가 월드에서 제거(충돌 또는 떨어짐)되면 스테이지 클리어
- 3초 대기 후 자동으로 다음 스테이지 전환 또는 "다음" 버튼 표시

**실패 판정:**
- 모든 새를 다 썼는데 돼지가 남아있으면 실패
- 실패 후 "다시하기" 버튼으로 재도전 가능

**구조물 파괴:**
- Matter.js 충돌 감지를 통해 일정 충격량(velocity) 이상이면 파괴 마킹
- 파괴된 바디는 회색으로 변환 후 일정 시간 후 제거(시각적 피드백)

## 상태 머신

게임 전체 상태:
```
MENU(메인) 
  ↓ 스테이지 선택 또는 새 게임 시작
INGAME
  ├─ AIMING: 슬링샷 조준 중, 드래그 대기
  ├─ FLYING: 새가 비행 중, 물리 시뮬레이션 실행
  ├─ PAUSED: 일시정지 상태, 물리 일시정지 + 오버레이 표시
  └─ RESULT: 클리어/실패 결과 화면
      ├─ 클리어 → 다음 스테이지로 전환
      └─ 실패 → 다시하기 또는 메인으로
```

**상태 전환:**
- INGAME 중 우측 일시정지 버튼 클릭 → PAUSED
- PAUSED에서 "다시하기" 선택 → INGAME(현재 스테이지 초기화)
- PAUSED에서 "메인으로" 선택 → MENU
- RESULT 클리어 후 자동 또는 수동 → 다음 INGAME

## 일시정지 오버레이

**UI 구성:**
- 오버레이: 반투명 배경(rgba 0 0 0 0.5) 전체 화면
- 중앙 모달: "게임 일시정지" 텍스트
- 버튼 2개: "다시하기", "메인으로"
- 버튼 스타일: 큰 터치 타겟(최소 50px), 호버 효과

**구현:**
HTML 요소로 모달 미리 생성하고 `display: none` 상태에서 대기. PAUSED 상태 진입 시 `display: block` 변경. Canvas 물리 시뮬레이션은 `paused` 플래그로 중지.

## 구현 단계

1. **프로젝트 구조 & Matter.js 초기화** (1-2일)
   - 번들러 설정(Vite 또는 esbuild)
   - Canvas 생성 및 기본 렌더 루프 구현
   - Matter.js 월드 초기화(중력 9.8)
   - 데이터 구조(스테이지, 객체) 정의

2. **슬링샷 입력 및 발사** (2-3일)
   - 마우스/터치 드래그 이벤트 처리
   - 슬링샷 원점 고정, 드래그 벡터 계산
   - 발사 시 Rigidbody에 속도 설정
   - 궤적 미리보기(선택)

3. **물리 & 렌더링** (2-3일)
   - Matter.js 월드 스텝 루프
   - Canvas 렌더: 바디 위치/회전으로 직사각형/원 그리기
   - 구조물(나무/돌/유리) 타입별 색상 구분
   - 새와 목표 객체 렌더링

4. **충돌 & 점수** (2일)
   - 충돌 이벤트 리스너 등록
   - 목표 객체 제거 감지 및 점수 업데이트
   - 구조물 파괴 조건(충격량) 계산

5. **상태 머신 & UI** (2-3일)
   - 상태 전환 로직 구현
   - 메인 화면(스테이지 선택)
   - 일시정지 오버레이 및 버튼
   - 결과 화면(클리어/실패)

6. **10개 스테이지 데이터 작성 & 테스트** (2-3일)
   - `stages.json` 작성(10개 스테이지)
   - 각 스테이지 난이도 균형 조정
   - 전체 플로우 테스트(메인 → 스테이지 1-10 → 클리어 화면)

7. **프로토타입 테스트 & 반복** (1-2일)
   - 물리 파라미터 조정(중력, 마찰, 반발력)
   - UX 개선(슬링샷 각도, 감도)
   - 버그 픽스

**예상 총 기간:** 약 12-18일(병렬 작업 시 단축 가능)

## 리스크 및 완화

**리스크 1: 물리 안정성** 
- Matter.js가 조금 무거울 수 있거나 성능 문제 발생 가능
- 완화: 초기부터 성능 측정(FPS), 필요 시 바디 개수 제한 또는 활성 범위 제한

**리스크 2: 슬링샷 감도** 
- 드래그 → 발사 속도 매핑이 어색하면 게임이 불쾌감
- 완화: 초기 튜닝 후 플레이 테스트 기반 파라미터 조정

**리스크 3: 스테이지 난이도 밸런스** 
- 처음엔 쉽고 나중엔 어려워야 하는데, 과도하게 어려워질 수 있음
- 완화: 각 스테이지 구조 설계 시 플레이 테스트 포함

## 완료 판정 기준

**실측 가능한 완료 기준:**
1. **메커니컬 완성**
   - 메인 화면 → 스테이지 1 진입 → 슬링샷 드래그/발사 → 새 비행 → 목표 제거 → 클리어 화면 → 메인으로 복귀
   - 전체 흐름을 한 번에 완료하는 엔드투엔드 테스트 통과

2. **10개 스테이지 로드 및 전환**
   - 모든 10개 스테이지가 `stages.json`에서 정상 로드되고, 스테이지 1~10을 순차 진행했을 때 오류 없이 완료

3. **상태 머신 검증**
   - MENU → INGAME → PAUSED(일시정지 버튼) → PAUSED 상태에서 "다시하기" 선택 시 현재 스테이지 초기화 → MENU로 복귀 모두 작동

4. **UI 및 입력**
   - 우측에 일시정지 버튼이 보이고, 클릭 시 모달이 뜨며, "다시하기"와 "메인으로" 버튼이 반응

5. **점수 및 결과**
   - 게임 완료(모든 돼지 제거 또는 게임 오버)가 되면 점수와 함께 결과 화면 표시, 클리어 또는 실패 정확히 판정

**검증 방법:** QA 체크리스트를 만들어 위 5개 항목 모두가 Pass되면 "완료"로 판정. 특히 1번 엔드투엔드 플로우는 회귀 테스트처럼 매번 점검.
