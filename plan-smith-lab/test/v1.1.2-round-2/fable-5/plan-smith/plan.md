- HUD: 남은 새·남은 돼지·점수가 플레이를 멈추지 않고 읽힌다.
- 일시정지: 우측 버튼, 정지 중 물리 틱 0, 오버레이 두 버튼이 각각 동작한다.

- 진행도: 브라우저 새로고침·재방문 후에도 유지된다.

## 물리 엔진 결정 — dialectic 차용 (매트릭스 셀 R2-a)

- 판정 함수(사전 고정): **실패 비용 비대칭** = 잘못 선택했을 때의 재작업 폭 × 회복 가능성. 두 사람이 독립 채점해도 같은 결론이 나오도록 조작화: "스택 물리(다층 구조물 안정·전도·연쇄 붕괴)를 처음부터 다시 짜야 하는가"가 유일한 축.
- 직접 구현 진영 최강 논거: 번들 제로, 거동 완전 통제, 학습 자산.
- 라이브러리(Matter.js) 진영 최강 논거: 안정적 강체 스택은 충돌 해소 반복·sleeping·마찰 튜닝의 누적 노하우이며, 직접 구현 실패 시 게임의 핵심 재미(구조물 붕괴) 자체가 죽는다 — 회복 불가능 쪽 실패.
- **판정: Matter.js.** 직접 구현의 실패는 프로젝트를 죽이고, Matter.js의 실패(거동 불만)는 튜닝으로 회복 가능하다.
- 패자 논거 승격(제약으로 전환): "통제" 논거 → 물리 호출은 얇은 어댑터 모듈 뒤에 격리한다(교체 가능성 보존). "번들" 논거 → 번들 상한 300KB gzip(임의값 — 수명: S8 빌드 실측으로 교체)을 리스크 표에 올린다.
- 재판정 트리거: S1에서 5단 블록 탑이 개입 없이 2초 내 정지하지 못하고 튜닝으로도 해소 안 되면 planck.js로 교체 검토(어댑터 덕에 국소 교체).

## 접근과 단계

의존성 순서. 각 단계: 선행조건 → 내용 → 검증 → 섬기는 매트릭스 셀.

- **S0. 스켈레톤** — 독립. Vite+TS+Matter.js 설치, 어댑터 모듈, 빈 캔버스 rAF 루프. 검증: 빌드 통과 + 빈 루프 60fps. (R2-a)
- **S1. 얇은 관통 슬라이스** — 선행 S0. 하드코딩 스테이지 1개: 슬링샷 드래그(당김 거리→초기 속도)·궤적 예측 점선(발사 전 시뮬레이션 스텝 샘플링)·발사·충돌·블록 내구도 감소·돼지 제거·클리어 판정까지 한 줄로 관통. 검증: 마우스만으로 클리어 가능 + **5단 블록 탑이 개입 없이 2초 내 정지(임의값 — 수명: S1 실측으로 교체)** — 가정 A1의 조기 검증. (R2-a·b·c·d)
- **S2. 상태 머신 + 일시정지** — 선행 S1. `main → ingame → paused → cleared | failed` 4상태(도메인 정석 채택). 우측 상단 일시정지 버튼(터치 타깃 ≥44px — 근거: 플랫폼 HIG 관례), 오버레이에 "다시하기"(현 스테이지 리셋) / "메인으로"(main 전이). paused 중 물리 스텝·타이머 호출 0회. 메인 화면에 스테이지 선택 그리드. 검증: 전이표의 모든 간선을 1회 이상 수동 워크스루 + paused 10초간 물리 틱 카운터 0. (R3-a·b·c, R1-d)
- **S3. 스테이지 시스템** — 선행 S1(확정된 바디 타입이 스키마의 입력). JSON 스키마(발사대 위치, 새 수, 블록 배열{재질·크기·위치·내구도}, 돼지 배열), 로더, 클리어→다음 전환. 스테이지 1–3 저작. 검증: 1–3 연속 클리어, 스키마 위반 데이터가 로드 시 명시적 에러. (R1-a·b)
- **S4. 판정·점수·HUD** — 선행 S1, S3과 병렬. 클리어 = 모든 돼지 제거. 실패 = 새 소진 후 모든 바디 sleep 또는 5초 경과(임의값 — 수명: S7 플레이테스트로 교체). 점수 = 블록 파괴 500·돼지 1000·잔여 새 보너스 5000(임의값 — 수명: 동일). 별 = 클리어 1개·점수 임계 2개·잔여 새 조건 3개(임계값 임의 — 수명: S7에서 스테이지별 실측 분포로 교체). HUD: 남은 새·남은 돼지·점수. 검증: 점수 규칙 표와 화면 표기 일치(수동 대조). (R2-e·f·g)
- **S5. 피드백 레이어** (명명된 단계 — 이름 없으면 일어나지 않는다) — 선행 S1, S3·S4와 병렬. 파괴 파티클, 효과음 4종(발사·충돌·돼지 제거·클리어), 브라우저 자동재생 정책 대응(첫 사용자 제스처에서 AudioContext resume). 검증: 이벤트 4종 각각에 피드백 발화 — 수동 체크리스트. (I-1·2)
- **S6. 저장** — 선행 S2·S3. localStorage에 해제 스테이지·별 기록. 검증: 새로고침 후 유지. (I-3, R1-d)
- **S7. 콘텐츠 저작** (명명된 단계) — 선행 S3·S4. 스테이지 4–10 저작, 난이도 곡선: 새 수는 비단조 허용하되 구조 복잡도(블록 수·층수)는 상승 축. S4의 임의 임계값들을 여기서 실측으로 교체. 검증: **저자가 아닌 1인이 각 스테이지를 10회 시도 내 클리어**(10회: 임의값 — 수명: 첫 테스트 세션 실측으로 교체). (R1-a·c)
- **S8. 폴리시 + 터치** (명명된 단계) — 선행 전체. PointerEvent 기반 터치 드래그 확인, 번들 실측, 시각 다듬기. 검증: 모바일 Chrome에서 드래그 발사 성공. (I-4)

S3·S4·S5는 상호 병렬(공통 선행: S1). 번호는 문서 편의이지 시간표가 아니다.

## 대안과 기각 근거

- **물리 직접 구현** — 기각: §물리 엔진 결정. 부활 조건: 번들 상한 300KB 초과 + Matter 거동이 튜닝 불능으로 판명되는 두 조건 동시 성립 시.
- **WebGL/Pixi 렌더링** — 기각: 바디 120개 규모에서 Canvas 2D로 충분, 파이프라인 복잡도만 증가. 부활 조건: S7 프로파일에서 스테이지 10이 30fps 미만.
- **React 등 UI 프레임워크** — 기각: 화면 4종·버튼 수 개에 과잉. 부활 조건: 설정·업적 등 UI 표면이 2배 이상 늘어날 때.
- **스테이지를 코드로 하드코딩** — 기각: 10개 저작·튜닝 반복에 데이터 파일이 압도적으로 싸다. 부활 조건: 없음(스키마가 실패하면 그것은 스키마 수정 사유).

## "완료"의 정의

실측 문장(전부 통과해야 완료):

1. 빌드 산출물을 정적 서버로 열어, **저자가 아닌 테스터 1인이 외부 설명 없이 스테이지 1→10을 연속 클리어한다**(각 스테이지 10회 시도 내 — 측정: 테스터 자기 기록, 시도 횟수 카운트).
2. 임의 스테이지에서 우측 일시정지 버튼 클릭 → 오버레이의 "다시하기"로 해당 스테이지 재시작 1회, "메인으로"로 메인 복귀 1회가 각각 성공하고, paused 상태 10초 동안 물리 스텝 카운터가 0이다(측정: 콘솔 카운터 로그).
3. 스테이지 3까지 클리어 후 브라우저 새로고침 — 메인 화면에 1–4 해제·별 기록이 유지된다(측정: 육안 + localStorage 키 확인).
4. 매트릭스의 build 셀 22개 전수에 대해 대응 산출물 존재를 체크리스트로 확인한다(측정: 셀별 스크린샷 또는 파일 존재).

## Frame deviations & habit regressions

- §접근과 단계: S3–S8 번호가 사다리로 읽힌다. 병렬성(S3·S4·S5)은 명시했으나 번호 체계 자체가 순차 인상을 남김 — 의존성 그래프 그림이 더 정직했을 것.
- §S4: 점수·별 임계값 전부를 "임의+수명"으로 처리했다. 규칙 문장(무엇이 점수를 내는가)은 고정했지만 별 3개 기준의 근거는 끝내 만들지 못했고, 수명 표기가 정의 의무의 세탁이 되지 않았는지 경계가 필요하다.
- 가장 약한 절: §S5 효과음 — 이벤트 4종의 이름만 있고 에셋 소싱(라이선스·생성 방법)이 가정 A4에 통째로 얹혀 있다. 리뷰어라면 여기를 공격할 것.
- §S2의 4상태 머신은 프레임(매트릭스)이 강제한 것이 아니라 도메인 정석을 그대로 채택했다 — 본문에 표기했으나 관습 선택임을 여기 재확인한다.
- 수렴 본능 점검: 터치(I-4)를 S8로 미룬 것은 커버리지 판단이라기보다 "데스크톱 먼저"라는 안전 기본값일 수 있다. build 판정은 유지했으나 완료 정의 1–4에 터치 항목이 없다 — 모바일이 실제 소비 채널이면 완료 정의가 구멍이다(가정 A2에 걸어둠).
