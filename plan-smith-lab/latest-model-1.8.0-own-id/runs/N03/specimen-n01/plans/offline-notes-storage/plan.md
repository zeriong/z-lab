# 오프라인 메모 저장 결정
- 프레임: backward / 스타일: opus
- 권고: 조건부 JSON.

## 수용 기준
- 가: 오프라인에서 제목·본문이 재실행해도 동일하다. 구현자가 단절·왕복 검증한다. 원격 의존을 배제한다.
- 나: 저장 중 종료해도 기존/새 전체문서가 복구된다. 구현자가 저장경계별 종료·비교한다. 직접 덮어쓰기를 배제한다.
- 다: 기존 런타임으로 단일사용자를 구현한다. 구현자가 의존성·실행을 검증한다. 추측한 확장성은 SQLite 근거에서 배제한다.

## 목표·적격성
목표는 단순성이다. 가·나는 저장경로, 다는 통합 재작업을 유발하므로 적격이다. 전체문서 비교면 충분하다. 데이터베이스부터 고르는 습관을 버렸다.

## 가정·미지수
**런타임·파일시스템이 안전한 교체를 지원한다.** 실패하면 SQLite다. 규모·검색·정렬·마이그레이션·언어와 호스팅 제외이유는 미지정이다.

## 교차·실행·핵심 경로
- 독립: 실환경에서 임시파일 쓰기→영속화→교체→재실행을 종료 시험으로 검증한다(나·다). 실패하면 SQLite 트랜잭션도 검증한다.
- 통과가 전제: 제목·본문 JSON 기록→오프라인 왕복검증(가). 나가 가를 지탱한다. 다보다 복구를 우선한다. 가·다는 오프라인을 공유한다.
- 기준 밖 요구도 구현하되 구조를 바꾸지는 않는다. 단일사용자·동기화없음·동시성없음까지 원문과 대조한다. 유예는 없다.

## 대안·위험
SQLite 재검토: 교체 실패·실규모의 전체파일 저장 부적합·검색요구 확정. 호스팅 재논의: 오프라인 제약 변경. 손상은 종료·정상본복구로 검증한다.

## 완료·구현 계약
시험 통과·전환조건 기록으로 완료한다. 저장스택: 런타임 표준 파일 API·JSON; 언어 미정. 문법검증: `python3 -m json.tool notes.json`, 복구증명: 종료시험.

## Frame deviations & habit regressions
‘가정·미지수’의 런타임 미정이 약점이다. 리뷰대상은 ‘교차·실행·핵심 경로’의 영속화다. 관행인 표준 API 선호는 지원시험으로 뒤집는다. 측정하기 어려운 사용편의는 근거에서 빠졌다.
