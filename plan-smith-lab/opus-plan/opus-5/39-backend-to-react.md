# 백엔드 개발자의 React 8주 학습 계획 — 간섭 오개념 교정표

- 추론 프레임: misconception-first
- 한 줄 요약: React를 난이도순으로 배우지 않고, 백엔드 멘탈모델(요청-응답·동기 흐름·상태는 DB에)이 React에서 오작동하는 6개 지점을 발화 시점 순으로 배치해 예측→배신→재구성으로 교정하며, 도피로가 되는 라이브러리는 봉인한다.

## 프레임이 요구하는 시작점 — 간섭 지도

**선행지식 점검(프레임 적용 조건).** 이 프레임은 간섭할 선행지식이 있을 때만 작동한다. 학습자는 서버 코드를 직업으로 쓰는 사람이므로 조건은 성립한다고 **가정**하되, 주0의 진단으로 실측한다(가정 섹션 참조). 백지 상태면 이 계획은 무력하다.

간섭 오개념 6개. 각 항목은 "발화 시점"(오개념이 실제로 틀린 결과를 내는 순간)에 배치되며, 학습 시점과 다르다.

| # | 오개념 (백엔드 출처) | 발화 시점 · 기폭제 | 예측 → 배신 | 2차 오개념(과교정) |
|---|---|---|---|---|
| M1 | 렌더는 그리기다, 그리기는 비싸다 (응답 생성 비용 → 캐시 습관) | 즉시. 300행 목록 + 입력창 1개 | "한 글자마다 다시 그리면 느리다" → Profiler는 1ms대 | "최적화는 하면 안 된다" |
| M2 | `setState`는 변수 대입이다 (동기 흐름) | 즉시. 한 핸들러에서 2회 갱신 + 직후 값 읽기 | "2 증가, 콘솔에 새 값" → 1 증가, 옛 값 | "React는 못 믿는다" → ref 남용 |
| M3 | 상태는 저장소에 있고 화면은 그것을 복사해 온다 (DB = 단일 진실, 비정규화 컬럼) | 서버 호출 등장 시. 지연·간헐 실패 목업 API + 합계·필터 | "응답과 합계를 state에 두면 일치한다" → 요청 역전, 합계 불일치 | "모든 상태는 서버/URL에" → 모달 열림까지 서버로 |
| M4 | `useEffect`는 요청 핸들러/수명주기 훅, 즉 절차 실행 지점 | M3 교정 후. StrictMode ON + 이펙트에서 파생값 계산 | "마운트 시 1회" → 2회 실행, 체인 무한 루프 | "useEffect는 나쁘다" → 구독까지 핸들러로 |
| M5 | 렌더는 요청 1회 처리이고 값·인스턴스는 시간상 하나다 (요청 스코프) | 잠복. (a) 인터벌·디바운스 콜백 (b) 편집 중 입력값을 든 행의 재정렬·중간 삽입 | (a) "최신 값을 읽는다" → 그 렌더 값에 고정 (b) "편집값은 제 행에" → 다른 행으로 | "의존성에 다 넣으면 된다" → 매 렌더 재구독 |
| M6 | 데이터는 어디서든 서비스 레이어를 호출해 가져온다 (DI 컨테이너) | 3번째 화면 + prop 전달 깊이 발생 시 | "전역 하나면 끝" → 변경 출처 추적 불가 | "전역은 악이다" → 공유 상태도 손으로 릴레이 |

**긍정 전이 자산(충돌 과제를 배정하지 않는 영역).** 비동기·경쟁 조건 감각, 캐시 무효화/stale 개념(HTTP → 서버 상태 캐시), 멱등성(이펙트 2회 실행 이해에 직결), 스키마·타입 사고, 에러 분류, 테스트 습관(컴포넌트 테스트는 봉인하지 않고 주5부터 이 채널로 활용), 정규화 감각(→ 상태 정규화). 여기에 충돌을 설계하면 시간 낭비이고 사기를 떨어뜨린다.

**비간섭 화물(별도 채널).** JSX 문법, Vite/TS 설정, props 타입, 라우터 API, 폼·브라우저 이벤트 기본, 접근성 기본. 오개념을 유발하지 않으므로 충돌 설계 없이 **매일 30분 레퍼런스 읽기 채널**(30분은 임의 초기값)로 분리한다. 교정 주차 진도와 무관하게 진행한다.

**판정자는 런타임이다.** 자기 학습자는 문제를 스스로 내면 답을 이미 안다. 그래서 (1) 과제는 제3자(멘토 또는 AI)가 공급하고 해설은 같은 응답에 담지 않도록 요구하며, (2) 학습자는 실행 **전에** 예측을 append-only 노트에 시각과 함께 적고, (3) 배신 여부는 브라우저 화면·Profiler 수치·콘솔이 판정한다. 사람이 채점하지 않는다.

## 문제 정의 / 목표

8주 뒤 목표는 "React를 안다"가 아니다. **백엔드 멘탈모델이 React에서 만드는 6개 오작동을 스스로 감지하고, 관련 버그를 새 표면에서도 재현·수정할 수 있다.** 문법 숙련·생태계 폭·실무 투입 속도는 목표가 아니다.

## 명시적 가정

- **학습자가 백엔드 멘탈모델을 실제로 활성 사용 중이다(계획 전체가 이 가정에 걸린다).** 틀렸을 때 영향: 프레임이 무력해지고 교정표는 낯선 개념 목록으로 전락 → 표준 커리큘럼으로 전환. 가장 싼 조기 검증: 주0에 1시간(임의 초기값), 위 표에서 뽑은 예측 문항 8개. 5개 이상이 표의 예측대로 틀리면 계획 유지(임의 초기값 — 과반 기준). 대체 경로: 표에서 불발 항목을 삭제하고 남은 항목만으로 주차를 압축한다.
- 제3자 과제 공급원이 8주간 유지된다. 틀렸을 때: 충돌이 예측 확인 놀이로 퇴화 → 배신 0건 감지 규칙(완료 기준 3)이 먼저 울린다.
- 주당 학습 시간 10시간(임의 초기값 — 주1 실투입 기록으로 주2 초에 대체, 기록자는 학습자). 틀렸을 때: 주차가 밀리며, 밀리면 주차를 줄이지 않고 **뒤 항목을 삭제**한다(교정 순서가 깨지면 오염이 남는다).
- 8주 동안 업무에서 React 산출물을 요구받지 않는다(외생 제약: 기간 8주는 사용자 지정). 틀렸을 때: 봉인이 붕괴 → 대안 3의 부활 조건 발동.
- 환경은 React 18+ / StrictMode ON. 틀렸을 때: M4의 기폭제(이펙트 2회 실행)가 사라져 충돌 불발.

## 접근 및 단계

**순서 축 = 오염 전이.** 인접 쌍마다 "앞을 교정하지 않으면 뒤 학습이 이렇게 오염된다"를 적는다. 난이도순이 아니다 — M4는 흔히 초급에 놓이지만 5번째다.

- M1→M2: 재렌더가 비싸다고 믿는 동안 배치 갱신은 "성능 트릭"으로 오해되고, 대입이 아니라는 진짜 원인이 가려진다.
- M2→M3: 갱신이 즉시 대입이라고 믿으면 서버 응답 복사가 "동기화 가능한 설계"로 보여 불일치가 버그로 인식되지 않는다.
- M3→M4: 서버 데이터의 소유 위치를 정하지 않으면 이펙트가 곧 "데이터 가져오는 곳"으로 굳고, 그 뒤엔 이펙트 = 절차가 실무 습관이 된다.
- M4→M5: 이펙트를 절차로 보는 동안 스테일 클로저는 "React 버그"로 읽히고 의존성 배열이 미신이 된다.
- M5→M6: **오염 전이가 성립하지 않는다 — 임의 순서로 선언한다.** 배치 근거는 발화 시점(3번째 화면이 생기는 시점)뿐이다.

단계는 오염 의존으로 정렬했고, 주차는 그 투영이다.

- **S0 (주0) 진단 · 환경 · 봉인 선언.** 선행: 없음. 예측 문항 8개, 목업 API(지연 3초·간헐 실패 20% — 두 값 모두 임의 초기값이며 주3 관찰 후 조정. 하한만 도출됨: 지연은 사람 조작 왕복 ≈1초보다 길어야 로딩·경쟁 상태가 눈에 보인다), 300행 시드(임의 초기값 — 주1 Profiler에서 프레임 예산 초과가 보일 때까지 행 수를 2배씩 올려 대체), 편집 중 값을 가진 행·정렬·중간 삽입이 가능한 데이터. 검증: 진단 8문항 중 표의 예측대로 틀린 개수 기록.
- **S1 (주1–2) M1·M2 교정.** 선행: S0의 시드·목업. 검증: Profiler 수치를 노트에 붙이고, "느려진 원인"을 재렌더가 아닌 다른 문장으로 쓸 수 있는가. 서비스: 완료 기준 1·2의 전제.
- **S2 (주3) M3 교정.** 선행: S1(대입 오개념 제거). 검증: 서버 응답을 담은 `useState`가 화면당 1개 이하(임의 초기값)이며 파생값 state가 0개.
- **S3 (주4) M4 교정 + S1 간격 재검사.** 선행: S2. 재검사는 원 과제 재실행이 아니라 다른 표면(비동기 응답 후 연속 갱신)으로 낸다. 새 재료가 적은 주차다 — 회귀 처리 주차이므로 진도가 줄어드는 것이 정상이다. 검증: 무한 루프를 스스로 만들고 원인을 이펙트 체인으로 설명.
- **S4 (주5) M5(a) 스테일 클로저.** 선행: S3(의존성 의미 확립). 검증: 인터벌 콜백이 옛 값을 읽는 재현을 만들고, 고치기 전에 원인을 예측 노트에 먼저 적는다.
- **S5 (주6) M5(b) 목록 정체성 + S2 간격 재검사.** 선행: S4. 같은 오개념의 두 번째 표면이 곧 간격 재검사를 겸한다. 검증: 완료 기준 2.
- **S6 (주7) M6 교정 + 과교정 회복 패스.** 선행: S5, 그리고 **봉인 해제는 도피 없이 겪은 기록이 있을 때만**. 회복 패스: (a) Profiler 수치를 근거로 한 memo 1건, (b) "이펙트가 정답인 사례 3개" 목록, (c) 서버로 밀지 말아야 하는 UI 상태 3개. 검증: 각 항목에 수치나 사례가 붙어 있는가.
- **S7 (주8) 판정 전용.** 새 개념 0건. 사양서 1장으로 3화면 앱, 완료 기준 전체 측정. 실패 항목은 해당 주차를 재실행한다.

## 봉인 목록 (해제 조건 포함)

1. 전역 상태 라이브러리(Redux/Zustand/Jotai) — 주0~6 봉인. 해제: prop 전달 깊이 4단계 이상 + 3개 화면이 같은 데이터를 요구하는 사례를 실제 코드에서 2회 기록(임의 초기값 — 주6에 실제 코드로 재도출). 근거: 도피로가 있으면 M6 충돌이 일어나지 않는다.
2. 서버 상태 라이브러리(React Query/SWR) — 주0~5 봉인. 해제: 직접 만든 fetch 훅에서 중복 요청·무효화·요청 역전을 각 1회 이상 겪고 기록.
3. 메타 프레임워크(Next.js/서버 컴포넌트) — 8주 전체 봉인. 근거: 서버에서 렌더한다는 감각이 M3·M5 교정을 되돌린다. 해제: 주8 종료 후.
4. `useMemo`/`useCallback`/`React.memo` — 주0~6 봉인. 해제: Profiler 수치 첨부 시에만(M1 과교정 회복 패스와 짝).
5. 커스텀 훅 추상화 — 주1~3 봉인. 해제: 동일 로직 3회 중복 시(min-diff 프레임의 "3의 법칙" 차용).

## 누락 범주 점검 스윕

간섭 지도에 안 잡혀 빠질 뻔한 범주와 착지점: **인증·토큰 저장**(세션 미들웨어 감각 → localStorage 토큰. 진짜 간섭 오개념이지만 렌더 모델과 무관 → 주7 별도 채널 + 지도 부록), **폼·유효성·접근성**(비간섭 채널), **CSS·디자인**(계획 밖 — 오개념 근거가 없어 봉인 목록에서 제외했다), **팀 컨벤션·코드 리뷰**(업무 코드는 읽기 전용 관찰만), **건강·시간 예산**(가정 3), **실무 조기 투입 압박**(가정 4 + 대안 3).

## 대안과 기각 사유

- **표준 커리큘럼(문법→컴포넌트→훅→상태관리).** 기각: 오개념은 문법 학습으로 발화하지 않아 발견이 실무 배포 뒤로 밀린다. 부활 조건: 주0 진단에서 표의 예측대로 틀린 문항이 4개 이하일 때.
- **튜토리얼 클론 코딩.** 기각: 예측 단계가 없어 배신이 발생하지 않는다(설명 소화 ≠ 교정). 부활: 비간섭 화물 채널 한정으로는 채택한다.
- **전역 상태 라이브러리 조기 도입(실무 관행).** 기각: M6의 도피로를 만든다. 부활 조건: 업무 투입 시점이 4주 이내로 확정되면 주4에 조기 해제하고, M6 교정은 사후 회고로 대체한다.
- **난이도순 정렬.** 기각: 이 프레임의 실패 모드 자체다. 부활 조건: 주0 진단에서 인접 쌍의 오염 전이가 어느 쌍에서도 관찰되지 않을 때.

## 리스크 & 완화

- 예측 노트의 사후 수정(자기 채점 오염) → append-only + 시각 기록, 판정은 런타임 산출물로. 잔여 위험: 집행자가 학습자 자신이다.
- 과제 공급 품질 붕괴(해설이 같이 나와 배신이 미리 소거되거나, 기폭제 없는 과제가 온다) → 요청 시 "해설·정답 금지" 규칙과 위반 과제 폐기 + 완료 기준 3의 감지 규칙.
- 봉인이 업무·구직 압박으로 붕괴 → 봉인은 학습 저장소에만 적용.
- 교정 후 재발(가장 흔한 결말) → 간격 재검사를 다른 표면으로, 2회 연속 재발 시 주차 재실행(임의 초기값).
- 지도 자체가 이 학습자에게 틀림 → 주0 진단으로 항목 삭제 가능하게 설계.

## "완료"의 판정 기준

1. **(대표 실측 문장)** 주6 산출물의 모든 `useState` 선언에 두 질문을 적용한다 — "지우고 렌더 시 계산할 수 있는가", "서버 응답의 복사본인가". 해당하는 선언이 **0개**. 판정자는 학습자가 아닌 제3자가 파일을 훑어 카운트한다. 1개 이상이면 S2 재실행. (봉인은 라이브러리를 막을 뿐 state 복사를 막지 않으므로 이 기준은 자동 충족되지 않는다.)
2. 한 행이 편집 중인 상태에서 목록을 재정렬하고 중간에 행을 삽입한다 — 편집 중 값이 자기 행에 그대로 남는다. 런타임이 판정하므로 린트를 끄는 방식으로 우회되지 않는다.
3. 예측 노트에 **2주 연속 배신 0건**이면 과제 은행에 기폭제가 없다고 판정하고 공급원을 교체한다(작은 표본에서 비율은 못 쓰므로 방향 판정 — 관측 프레임의 "크기 대신 방향 일치" 차용).
4. 목업이 응답에 요청 순번을 넣는다. 주8 산출물에서 같은 조작을 빠르게 5회(임의 초기값) 반복한 뒤, 화면에 표시된 순번이 **마지막으로 발행된 요청의 순번과 일치**한다. 판정은 화면의 숫자가 하고, 학습자의 눈대중이 하지 않는다.
5. 봉인 5항목 중 해제된 것은 모두 해제 조건 충족 기록을 가진다. 무기록 해제가 1건이라도 있으면 미완이다.

## 프레임 이탈 / 관성 회귀

- **주차 사다리.** S3·S5는 앞 교정의 재검사이고 S7은 새 재료 0인데도, 문서는 주1→주8 사다리로 읽힌다. 각 단계에 선행 항목을 붙였지만 주차 라벨의 상승 인상을 지우지 못했다.
- **가장 약한 섹션은 리스크 & 완화**다. 다섯 항목 중 넷의 집행자가 학습자 자신이어서 구조적 봉쇄가 아니라 규율에 가깝다. 내가 리뷰어라면 이 섹션을 먼저 친다.
- **근거 없는 수치가 남았다.** 봉인 1의 "깊이 4단계 + 3화면"은 재도출 시점만 붙었을 뿐 근거가 없고, 2회 연속 재발 규칙도 임의다.
- M5를 스테일 클로저와 목록 정체성의 합본으로 묶은 것은 오개념 6개 상한을 지키려는 편의에서 나왔다. 두 표면의 기폭제가 달라 재검사 설계에는 유리했지만, 실제로 하나의 오개념인지는 검증하지 않았다.
