# 앱 7개짜리 개인 생산성 시스템 다이어트

- 추론 프레임: delete-first
- 한 줄 요약: 앱을 하나씩 깎지 않고 "저장 포맷"과 "할 일의 단일 원천"이라는 두 결정으로 여러 앱을 동시에 처형하되, 왕복 테스트를 통과한 대체재가 서기 전에는 어떤 삭제도 집행하지 않는다.

## 프레임이 요구하는 시작점 — 후보 전량, 한 문장 목적, 유죄추정 심문

현재 스택(피고 전원): ① Notion(위키·프로젝트 DB) ② Todoist(할 일) ③ Obsidian(노트) ④ Fantastical(캘린더 클라이언트) ⑤ Raindrop(북마크·읽을거리) ⑥ Toggl(시간 추적) ⑦ Readwise(하이라이트 동기화). 그림자 피고 ⑧ 기본 미리알림/메모 — 설치한 적 없을 뿐 캡처는 여기로도 들어온다. 명단에서 빠지면 심문도 못 하므로 함께 세운다.

**한 문장 목적:** "다음에 무엇을 할지를 매일 5분 안에 확정한다 — 그 결정의 근거를 나중에 되찾을 수 있는 범위에서."

여기서 한 번 갈렸다. 초안은 "결정하고, 그리고 3년 뒤에도 찾을 수 있게 한다"였다. 접속절로 목적이 둘이면 수집·보존 계열(⑤⑦, Notion 위키)이 전원 무죄가 된다. 그래서 보존을 목적이 아니라 **결정의 제약**으로 내렸다. 결과: ⑦ Readwise가 무죄 → 조건부 유죄로 뒤집혔다(근거 보존은 인용이 실제 결정에 쓰일 때만 필요조건이므로).

**세는 단위 — 유지보수 표면.** 앱 개수는 지표가 아니라 부산물이다. 4축으로만 센다. ① 유료 구독 건수(잔여 개월 포함) — 카드·앱스토어 구독 목록 12개월 조회. ② 계정·동기화 경로 수 — 각 앱 설정에서 켜져 있는 동기화 대상 1개 = 1경로, 로그인 계정은 별도 계상. ③ 백업 대상 저장소 수 — "이 서비스가 죽으면 데이터가 사라지는가"가 예인 저장소 = 1. ④ 주간 손질 시간(분) — 정리 목적으로 앱을 연 직후 "앱명, 분" 한 줄 기록, 7일 합.

축이 하나도 줄지 않는 변경은 삭제가 아니라 **이동**이다. 독에서 아이콘을 숨기는 것도 삭제가 아니다.

**유죄추정 심문(피고가 필요조건임을 입증해야 한다).**

| 피고 | 없으면 목적 문장이 깨지는가 | 1차 판결 |
|---|---|---|
| ① Notion | 아니다. 결정은 여기서 나지 않고, 근거 보존은 포맷 문제다 | 유죄 |
| ② Todoist | 부분적. 원천이지만 캘린더와 이중 | 유죄(원천 중복) |
| ③ Obsidian | 아니다 — 단, 폴더 위의 뷰어라 저장소를 잡고 있지 않다 | 무죄(뷰어로 존속) |
| ④ Fantastical | 캘린더는 필요조건, 이 클라이언트는 아니다 | 유죄(구독축만 −1) |
| ⑤ Raindrop | 아니다 | 조건부 유죄(백업축 확인) |
| ⑥ Toggl | 아니다. 시간 데이터가 어떤 결정을 갈랐는지 불명 | 조건부 유죄(S0 검색으로 판정) |
| ⑦ Readwise | 아니다(제약으로 강등된 뒤) | 조건부 유죄 |
| ⑧ 기본 앱 | 진입점으로는 유용, 원천으로는 중복 | 유죄(진입점 통합) |

개별 심문에서 ②⑤⑥⑦이 "고유 기능"을 들고 반쯤 빠져나갔다. 프레임의 지시대로 피고를 한 단계 올린다: 앱 → **저장 포맷 / 원천 개수**.

## 삭제 지렛대 (한 결정이 여러 앱을 동시에 처형)

- **L1 — 저장 포맷: 로컬 마크다운 폴더 1개(원격 git 백업 1경로).** 처형: ① Notion, ⑤ Raindrop, ⑦ Readwise의 저장 역할. ③은 이 폴더의 뷰어로 남는다. 표면 감소는 **백업 대상 저장소 축**에서 발생한다(사유 DB 3건 → 폴더 1건). 앱 개수 감소로 이중 계상하지 않는다.
- **L2 — "다음에 무엇을"의 단일 원천: 시간이 붙은 것은 캘린더, 안 붙은 것은 `next.md` 한 파일.** 처형: ② Todoist, ⑧ 기본 미리알림, ① Notion 태스크 DB. 아침 5분의 필요조건이다 — 원천이 둘이면 확정 전에 대조가 필요하다.
- **L3 — 기각한 지렛대: "구독 0원".** 비용은 목적 문장의 필요조건이 아니고, 이 지렛대는 목적을 해치는 삭제를 정당화한다. 부활 조건: 월 구독 합계가 실제 예산 상한을 넘을 때 제약으로 승격.

이동 vs 삭제 판정:
- ④ Fantastical → 기본 캘린더: 구독 −1, 동기화·백업축 불변. **클라이언트 교체이므로 다이어트 성과로 세지 않는다.**
- ⑤ Raindrop → 브라우저 북마크: 백업 대상이 사라지지 않고 브라우저 프로필로 옮겨질 뿐이다. 따라서 대체재는 브라우저가 아니라 **`reading.md` 한 파일**(URL + 한 줄 이유)이며, 이유를 못 쓰는 링크는 저장하지 않는다.

## 문제 정의 / 목표

아침에 무엇을 할지 확정하려면 앱 3~4개를 대조해야 하고, 6개월 전 결정의 근거가 어느 앱에 있는지 모른다. 목표는 앱 수 감축이 아니라 **원천 1개 + 저장소 1개**이며, 성과는 표면 4축의 변화로만 주장한다.

## 명시적 가정

- **개인 단독 사용이며 이 스택에 타인과 공유 중인 문서·보드가 없다.** ← 전체가 걸린 가정. 틀리면 L1이 무효(Notion 삭제 불가)이고 범위는 ②⑥⑦로 축소된다. 가장 싼 조기 검증: S0에서 Notion 공유 페이지 목록·초대 이력 확인(10분). 붕괴 시 경로: 공유 문서만 무료 워크스페이스에 격리하고 나머지는 예정대로 처형.
- 모바일에서 마크다운 캡처·편집이 가능하다. 틀리면 왕복 테스트 (2)가 실패하고 삭제는 보류된다.
- 노트에 규제·비밀 정보(고객 자료, 자격증명)가 없다. 틀리면 원격 git 백업이 새 리스크가 되며 해당 파일은 폴더 밖 암호화 보관으로 분리한다.
- 시간 추적 데이터가 지난 3개월 어떤 결정에도 인용되지 않았다. 틀리면 ⑥은 무죄. 검증은 기억이 아니라 노트·주간 리뷰 파일 전문 검색(시간 수치 인용 문장 유무)이며, S0에서 실행한다.

## 접근 및 단계

- **S0 기준선 실측(7일).** 선행: 없음. 산출: 표면 4축 숫자(현재는 공백 — 추정치를 적지 않는다) + 아침 결정 소요 7일치 + Notion 공유 페이지 목록 + 노트·주간 리뷰 전문 검색 결과(시간 수치 인용 문장 건수 = ⑥ 판결 입력). 검증: 4축 각각에 숫자와 계수 방법이 적혀 있고, ⑥의 조건부 유죄가 유죄/무죄로 확정된다.
- **S1 캡처 진입점 감사(7일, S0과 병렬).** 새 항목이 어느 앱으로 들어왔는지 항목마다 한 줄. 검증: 진입점별 건수 표.
- **S2 중단 게이트(S0·S1 소비, 기본값=중단).** 진입점이 이미 2개 이하이고 아침 결정이 이미 5분을 만족하면 문제는 도구가 아니라 루틴이므로 **이 계획을 중단한다.** 통과 시에만 다음으로.
- **S3 지렛대 확정(S2 소비).** L1·L2를 못 박고 각 지렛대의 처형 명단을 적는다. 검증: 명단에 없는 앱은 이후 단계에서 삭제 불가.
- **S4 대체재 구축 + 왕복 테스트(S3 소비).** 폴더 구조, `next.md`, `reading.md`, 내보내기 실행. 3종 전부 통과해야 삭제 자격: (1) 6개월 전 항목 3건을 새 저장소에서만 30초 내 재발견, (2) 모바일 캡처 → 데스크톱 편집 왕복, (3) 폴더를 다른 기기에 복사해 동일 검색 성공. 실패 시 삭제로 넘어가지 않고 S4 재작업. 작업 총량 상한 6시간, 초과 시 범위를 L1만으로 축소.
- **S5 병행 2주(S4 통과 소비).** 신규 항목은 새 경로만, 구 앱은 읽기 전용. 2주는 주간 리뷰가 2회 도는 최소치라서 정한 값(파생). 검증: 병행 중 구 앱 신규 생성 0건.
- **S6 집행(S5 소비).** 순서: 원본 내보내기 zip 보관 → 구독 해지 → 1결제주기(1개월) 후 계정 삭제. 대기창은 결제 주기에서 파생.
- **S7 재진입 게이트(S6 이후 상시).** 생존 컨테이너(폴더+Obsidian)에 기본거부: 새 플러그인·앱 후보는 "현 구조에서 실패한 시도 1건"을 적어야 심리 대상. 플러그인 7개 설치는 다이어트가 아니라 이동이다.
- **S8 30일 재판(S6 +30일).** 표면 4축 재측정(S0과 동일 방법) + 미련 로그 심리.

## 대안과 기각 사유

1. **개수 쿼터(7→3)를 먼저 정한다** — 기각: 목적 심문이 개수를 결정한다. 쿼터는 천장이지 목표가 아니며, ④ 같은 이동을 성과로 계상하게 만든다. 부활: 외부 제약(예산 상한)이 실제로 걸릴 때 제약으로 승격.
2. **Notion 하나로 전부 통합** — 기각: 표면은 1로 보이지만 사유 포맷이 남아 근거 재발견 제약을 보증하지 못한다(병합 위장). 부활: 무손실 마크다운 내보내기가 S4 3종을 통과할 때.
3. **아무것도 삭제하지 않고 루틴만 고친다** — 기각하지 않고 S2 게이트의 기본값으로 채택. 도구 무죄 가능성을 표에서만 다루면 발화하지 않는다.
4. **스크립트로 자체 통합** — 기각: 표면에 "내가 만든 코드" 축이 추가된다. 부활: 왕복 테스트 (2)가 기성 도구로 3회 연속 실패할 때.

|---|---|
| 이사 자체가 취미가 됨 | S4 6시간 상한(임의값, S8에서 실측 교체) 초과 시 범위 축소 |
| 내보내기 손실(DB 관계, 하이라이트 메타) | 원본 zip 영구 보관, 삭제는 S6에서만 |
| 3주 후 캡처가 기본 앱으로 다시 샘 | S1 로그를 월 1회 재실행, 진입점 2개 이상이면 재판 |
| 파일 수 증가로 검색 실패 | 검색 실패 한 줄 로그, 월 3건(임의) 이상이면 구조 재설계 |
| 공유 요청 발생 | 단건 링크/PDF 공유 → 불가 시 무료 워크스페이스 격리 |
| 세무·업무 보존 의무가 걸린 자료 | 삭제 전 분리, 이 계획 범위 밖으로 |
| 기기 분실 시 단일 폴더 소실 | git 원격 1경로가 곧 백업(백업축 1은 0이 아니다) |
| 부활이 정치화(그냥 다시 깔기) | 미련 로그 `regret.md`: 같은 앱 30일 내 3건(임의) + 각 건에 현 구조 실패 시도 기재 시에만 심리. 측정자 본인 |

## "완료"의 판정 기준

- **실측 문장:** S6 +30일에 표면 4축을 S0과 동일 방법으로 재측정해 **주간 손질 시간(분)이 S0 기준선보다 작다.** 앱을 지우면 자동 만족되지 않는다 — 새 구조의 손질 시간이 이 숫자에 포함되므로.
- 무작위로 뽑은 6개월 전 노트 5건을 새 저장소에서만 각 30초 내 재발견한다(30초·5건은 임의값, S8에서 실측 분포로 교체. 측정자 본인, 타이머).
- 아침 결정 소요가 7일 연속 5분 이하(5분은 목적 문장이 선언한 임의값 — S0 실측값을 기록하고 S8에서 교체).
- 재설치 횟수 0. 부활 심리를 통과한 건은 실패로 세지 않고 별도 계상한다.
- 앱 개수는 완료 기준이 아니다.

## 프레임 이탈 / 관성 회귀

- 가장 약한 곳은 S4의 **6시간 상한**이다. 근거가 없는데도 삭제 범위를 실제로 자를 권한을 갖는다. 리뷰어라면 여기를 먼저 친다.
- ⑤ Raindrop의 "조건부 유죄"는 유예의 변형일 수 있다. ⑥은 S0의 검색으로 판결이 발화하지만 ⑤는 대체재 설계(`reading.md`)로 옮겨 판결을 뒤로 미룬 모양이 남았다.
- S0~S8 번호가 사다리처럼 읽힌다. S4 실패 → S4 재작업 루프를 구조가 아니라 문장으로만 처리했다.
- 표면 4축 기준선을 공백으로 둔 대가로, 이 문서만 읽는 사람은 다이어트의 크기를 알 수 없다. 추정치를 적지 않기로 한 선택이지만 비용은 실재한다.
