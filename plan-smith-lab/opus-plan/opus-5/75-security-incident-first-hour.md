# 보안 침해 신고 접수 후 첫 1시간 대응 런북
- 추론 프레임: triage / 스타일: opus
- 한 줄 요약: 90초 안에 읽을 수 있는 신호 3개로 오탐/실제/불명을 가르고, 불명은 "전원 유지 + 네트워크 격리"를 기본 트랙으로 자동 진입시켜 차단 속도를 사면서 휘발성 증거는 지키는 첫 1시간 카드.

## 프레임이 요구하는 시작점 — 시간 계층과 각 행동의 부작용·발화 조건

### T0 — 0~90초: 분류 (예산 상한 90초)
쿼리 콘솔 없이, 신고 원문과 화면만 보고 읽을 수 있는 신호 셋:

1. **신고 경로** — 인증된 내부 채널/티켓인가, 외부 제보인가, 자동 알림 단독인가.
2. **자격증명·권한 언급** — 계정 탈취·토큰·관리자 권한·MFA 우회가 문장에 나오는가.
3. **현재 진행 중 징후** — 알 수 없는 활성 세션, 랜섬 노트, 외부인이 우리 내부 데이터를 실제로 보여줌, 관리자 콘솔 접근 불가.

판정: (2) 또는 (3)이 참 → **실제**. 셋 다 아니고 자동 알림 단독 + 기록된 오탐 패턴 일치 → **오탐**. 그 밖의 모든 경우, 그리고 **90초 소진 자체** → **불명**.

부작용 주석: 이 분류는 진단이 아니다. **오탐 트랙**도 무행동이 아니다 — 판정 근거 한 줄 기록 → 2인 확인 후 종료 → 새 오탐 서명을 패턴 목록에 추가(다음 90초를 싸게 만드는 유일한 경로)까지가 오탐 카드다.

### 불명의 기본 트랙 — 되돌릴 수 있는 쪽, 그리고 지불하는 비용
기본 트랙 = **전원 유지 상태의 네트워크 격리 + 관측**. 되돌리기 비용이 비대칭이라서 이쪽이다.
- 잘못 격리했을 때: 호스트 1대의 업무 중단, 해제는 스위치 원복(수십 초 규모). **되돌릴 수 있다.**
- 잘못 관측만 했을 때: 유출·암호화가 그 시간만큼 계속된다. **되돌릴 수 없다.**

기본 트랙이 태우는 것(알고 지불한다): ① 격리된 사용자·서비스의 가동 시간, ② 공격자에게 "탐지됐다"는 신호가 갈 가능성 — 파괴적 전환을 유발할 수 있는 비가역 리스크이며, 그래서 격리 사실은 사내 공지가 아니라 지휘자 채널에만 남긴다, ③ 오탐일 때의 격리 피로.

오분류 복구 장치: T1 종료(5분)와 T2 중간(접수 후 30분)에 **재분류 게이트**. 승격 신호는 "다른 호스트에서 동일 지표" 또는 "격리 후에도 계정 활동 지속", 하향 신호는 "격리 후 지표 정지 + 알려진 오탐 서명 일치". 격리 해제는 2인 확인(비가역 조치에만 2인을 붙인다).

## 문제 정의 / 목표
첫 1시간의 목표는 사건 해결이 아니라 **① 확산 정지, ② 사라질 증거의 확보, ③ 통지 시계 시작 시각의 기록** 셋이다. 원인 규명·복구·근절은 범위 밖. 판단력이 가장 낮은 사람(야간 온콜, 첫 인시던트)이 카드만 들고 여기까지 도달하면 성공이다.

## 명시적 가정
- **[전체가 걸린 가정] 온콜이 90초 안에 단독 발동할 수 있는 격리 스위치가 실재한다.** 틀리면 기본 트랙이 문장으로만 존재하고 런북이 붕괴한다. 최저가 검증: 다음 근무일에 스테이징 호스트 1대를 실제 격리·해제하고 소요 시간 기록. 대체 경로: 권한자 2명 전화번호를 카드 첫 줄에 박고 기본 트랙을 "권한자 동시 호출 + 계정 단위 세션 차단"으로 강등.
- 신고 접수 창구가 하나로 수렴한다. 틀리면 접수 시각이 여러 개 생겨 시계 계산이 무효 → T2에 채널 전수 확인.
- 통보 채널(사내 메신저·메일)이 공격자 통제하일 수 있다. 이 가정은 **틀린 쪽이 안전**하며, 대역외 브리지를 상시 자산으로 요구하는 근거다. 틀렸을 경우(채널이 안전했을 경우) 지불하는 비용은 대역외 브리지 상시 유지 공수뿐 — 그래서 이 방향으로 고정한다.
- 로그 보존 기간이 첫 1시간보다 길다. 틀리면 대응 중 증거가 소멸 → T2 보존 홀드가 대비.

## 컴파일 타임 자산 목록
| 자산 | 리허설 확인 | 없을 때의 강등 경로 |
|---|---|---|
| 호스트/계정 격리 스위치 | 분기 1회 실제 격리·해제, 소요 시간 기록 | 권한자 2인 전화 호출 |
| 휘발성 수집 수단(메모리·세션·연결 스냅샷) | 훈련 시 1회 실행, 산출물 존재 확인 | 화면 촬영 + 연결 목록 출력 텍스트 보존 |
| 대역외 브리지(사내 채널과 무관한 통화/방) | 반기 1회 소집 테스트 | 개인 전화 회의, 명단 수기 |
| 지휘자·권한자·법무 연락 카드 | 분기 1회 최신성 확인 | 조직도 인쇄본 |
| 로그 보존 홀드 절차 및 대상 목록 | 대상별 보존 기간 확인(값은 확인 대상, 추정 금지) | 담당자에게 즉시 수기 홀드 요청 |
| 금지 조치 목록 배포 대상 명단 | 신규 임원·온콜 합류 시 갱신 | — |
| 오탐 서명·패턴 목록 | 사후 리뷰마다 신규 서명 반영 여부 확인 | 목록 부재 시 T0 오탐 트랙을 봉쇄하고 전건 불명 처리 |

## 접근 및 단계 (계층별, 각 단계에 선행조건·검증)

### T1 — 5분 카드 (항목 상한 6, 휘발성 × 비가역성 순)
1. **접수 시각·신고 원문 확보** — 선행: T0. 스크린샷·원본 메시지·제보자 연락처 별도 저장. 검증: 저장 경로에 파일 존재. *1번인 이유는 관례를 뒤집은 결과다 — 통상 문서화는 후순위지만, 신고가 온 채널은 삭제 가능한 최고 휘발성 증거다.*
2. **지휘자 1명 지명** — 선행: 없음(병행). 검증: 이름이 브리지에 기록됨. 지휘자는 조치자가 아니다.
3. **기본 트랙 발동(또는 실제 판정 시 격리)** — 선행: 1. 전원 유지. 검증: 격리 후 해당 지표 정지 여부.
4. **휘발성 스냅샷** — 선행: 3(격리 후, 전원 유지 상태). 검증: 산출물 크기 > 0.
5. **대역외 브리지 개설** — 선행: 2. 검증: 지휘자 외 1명 이상 접속.
6. **로그 보존 홀드 요청 발신** — 선행: 없음(병행). 검증: 수신 확인 회신.

카드 종료 조건: 6항목 완료 또는 5분 소진 시 **재분류 게이트 1회** — 승격/하향/유지 중 하나를 근거 신호와 함께 브리지에 기록해야 T2로 넘어간다. 항목이 아니라 카드를 닫는 조건이므로 상한 6에 포함되지 않는다.

### T2 — 60분 카드 (항목 상한 7)
선행 사슬:
- ① 범위 판정(동일 지표 타 호스트 검색) — 선행: T1 3(격리 발동 후). 검증: 검색 대상 자산 수와 히트 수 기록.
- ② 재분류 게이트 **(접수 후 30분 시점)** — 선행: ①. 검증: 판정과 근거 신호가 브리지에 기록.
- ③ **자격증명·토큰 회전 결정 게이트** — 선행: ①(범위 판정에서 계정·토큰 관여 확인). 검증: 회전 대상 목록 또는 "회전 없음" 사유 기록.

병행군(①~③ 결과에 의존하지 않음 — 사람이 남으면 동시에 착수):
- ④ 통지 시계 확인 소유자 지명 — 선행: 없음(병행), 단 **T2 진입 직후 지명·질의 발신**(이 발신 시각이 아래 40분 기본 행동의 기준선이다). 검증: 소유자 이름 + 질의 발신 시각 + 회신 시각.
- ⑤ 신고자 재인터뷰 — 선행: 없음(병행). 검증: 최초 관측 시각·경로가 기록에 추가.
- ⑥ 외부 포렌식 벤더 호출 판정 — 선행: 없음(병행). 검증: 호출 여부와 사유 한 줄.
- ⑦ 제3자·SaaS 계정 점검 — 선행: 없음(병행). 검증: 점검한 서비스 목록.

통지 시계는 값이 아니라 소유자로 처리한다(이 문서는 법정 시간 수치를 주장하지 않는다). **접수 후 40분까지 ④의 회신이 없을 때의 기본 행동**: 접수 시각을 시계 시작으로 확정 기록하고, 알려진 요건 중 최단 기한을 가정해 통지 초안만 착수한다 — 발송은 금지 조치 1번의 2인 승인 대상.

*여기서 관례가 두 번째로 뒤집힌다*: 전사 비밀번호 강제 재설정과 전체 세션 무효화는 "빠를수록 좋다"는 직관과 달리 **게이트 뒤**다. 비가역이고(세션 증거 소멸), 공격자에게 탐지를 알리고, 대량 문의로 인력을 잡아먹는다. 범위 판정에서 계정·토큰이 관여로 확인될 때만 발동하며, 그때도 대상 한정 회전이 먼저다.

### T3 — 이후 (포인터 3개 상한)
① 포렌식·근절 이관, ② 사후 리뷰(오분류 사례 포함), ③ 자산·금지·오탐 서명 목록 갱신. 그 외 후속은 별도 백로그로 나간다. 계층 간 무게 점검: T1 6 / T2 7 / T3 3 — 꼬리를 막은 대가가 중간 계층으로 옮겨가는 것을 상한으로 막았고, T2가 7을 넘기면 초과분은 T3 백로그로 간다.

## 금지 조치 (유혹 문법 → 실제 비용 → 지정 대체 → 구조적 집행)
1. **성급한 전체 공지.** "빨리 알려야 책임을 다한 것 같다" → 공격자에게 대응 상황 노출, 오탐일 때 신뢰 손실, 법무 검토 전 문구의 대외 유출. 대체: 대역외 브리지에 지휘자 + 영향 조직장만. 집행: 전사 발신은 2인 승인, 금지 목록을 **CEO·CTO·홍보 담당에게 사전 배포**(공지를 지시할 사람이 그들이므로).
2. **서버 재시작·전원 차단.** "일단 끄면 멈춘다" → 메모리 상주 악성코드·활성 세션·연결 정보 영구 소멸, 되돌릴 수 없다. 대체: 전원 유지 네트워크 격리 + 스냅샷. 집행: 인시던트 선언 중 해당 호스트 재시작 권한 잠금, 온콜 카드 첫 줄에 명시, 지시 주체(SRE 온콜·인프라 리드)에게 배포.
3. **악성 파일 삭제·정리.** "치우면 깨끗해진다" → 유일한 표본 소멸. 대체: 격리 보관 후 보존. 집행: 삭제는 포렌식 이관 후로만, 2인 확인.
4. **공격자에게 회신·역스캔.** "확인해보고 싶다" → 법적 노출, 자극. 대체: 법무·벤더 위임. 집행: 대외 접촉 권한을 지휘자 단일 창구로 잠그고, 이 조항을 온콜·개발자 카드에 배포.
5. **로그 회전 방치·티켓 정리.** "평소 하던 정리" → 증거 소멸. 대체: 보존 홀드 우선. 집행: 인시던트 선언 시 정리·배포 작업 동결을 T1 6번 요청문에 포함.

## 대안과 기각 사유
- **불명의 기본을 "관측 우선"으로**: 기각 — 오분류 비용이 비가역(유출 지속) 쪽이다. 부활 조건: 격리 최소 단위가 서비스 전체이고 격리 1회의 매출·안전 영향이 관측 지연 손실을 넘길 때 → 기본을 "관측 + 계정 단위 차단"으로 교체.
- **온콜이 분류하지 않고 즉시 전문가 에스컬레이션**: 기각 — 호출 응답까지 무행동 구간이 생기고 그것이 첫 1시간의 대부분이다. 부활 조건: 24/7 응답 SLA가 계약된 SOC 보유 시(T0을 "호출 + 기본 트랙"으로 축약).
- **자동 격리(탐지 즉시 무인 차단)**: 기각 — 사람 확인 없는 오탐 격리가 누적되면 런북 신뢰가 먼저 죽는다. 부활 조건: 리허설 3회 연속 오탐 0.

## 리스크 & 완화 (+ 누락 범주 스윕)
- 격리 피로로 온콜이 기본 트랙 회피 → ① 사후 리뷰에서 오탐 격리 건수·원인을 공개하되 개인 책임으로 다루지 않음, ② 오탐 서명 목록 갱신으로 같은 오탐이 두 번 격리를 유발하지 않게 함, ③ 회피 탐지 지표: 불명 판정 대비 격리 발동 비율이 1 미만이면 사후 리뷰 필수 안건.
- 지휘자 부재(연휴·야간) → ① 지명 실패 시 접수자가 임시 지휘자, 30분 내 인계, ② 인계 실패 시에도 카드는 계속 진행(지휘자 공백이 T1을 멈추는 조건이 아니다), ③ 연락 카드에 백업 지휘자 2순위까지 명시.
- 내부자·계정 탈취로 통보 채널이 공격자 통제하 → ① 대역외 브리지가 유일 채널, ② 브리지 참가자 신원은 음성 확인으로 검증(초대 링크 전달만으로 신뢰하지 않음), ③ 브리지 자체가 열리지 않으면 개인 전화 회의로 강등(자산 표 3행).
- 제3자·SaaS·클라우드 콘솔에는 격리 스위치가 닿지 않음 → ① T2 ⑦번 점검, ② 각 서비스의 세션 무효화·API 키 회수 경로를 자산 표 갱신 시 함께 기록, ③ 닿지 않는 범위는 "격리 불가"로 명시 기록해 범위 판정이 이를 커버로 오인하지 않게 함.
- 스윕에서 확인한 범주: 법무·규제 통지, 개인정보 주체, 홍보, 계약상 고객 통지, 물리 보안, 인력 교대 피로, 보험. 이 중 **보험 신고 요건**은 첫 1시간에 자리가 없어 T3 백로그로 명시 이월한다(누락이 아니라 결정).

## "완료"의 판정 기준
- **실측 문장**: 인시던트 경험이 없는 온콜 1명에게 런타임 카드만 주고 모의 신고를 던졌을 때, 90초 안에 분류를 산출하고 5분 카드 6항목을 **외부 질문 0회·즉흥 판단 0회**로 마친다(질문 수를 세어 기록. 이 완료 문장 형식은 `checklist` 프레임의 완료 규범에서 차용했다).
- 격리 스위치 리허설이 분기 1회 실행되고 실측 소요 시간이 기록돼 있다.
- 금지 목록이 지시 주체 명단 전원에게 배포돼 있고 신규 합류자 갱신 이력이 있다.
- 최근 3건의 인시던트에서 접수 시각과 통지 시계 회신(또는 무회신 기본 행동 발동 기록)이 모두 존재한다.

수치 태그: 90초·5분·60분은 **과제 스펙 지정값**으로, 실전·훈련 3회 분류 소요의 중위값으로 대체한다(측정·기록: 지휘자). T0 신호 개수 3은 90초 예산 안에서 읽을 수 있는 항목 수로 잡은 **임의 선언값** — 리허설 실측 분류 소요로 2개 또는 4개로 재조정(측정·기록: 지휘자). T3 상한 3은 프레임 기본값이고, T1 6·T2 7·리허설 주기(분기·반기)·30분 인계·재분류 30분·통지 회신 40분·"3회 연속 0"·"최근 3건"은 모두 **임의 선언값**으로 첫 사후 리뷰에서 지휘자가 재조정한다. 2인 확인은 "비가역 조치에만"이라는 규칙에서 **유도**됐다. 격리 해제 소요는 추정값이며 리허설 실측으로 대체된다 — 대체 전까지 기본 트랙의 가역성 논거는 조건부다.

## 프레임 이탈 / 관성 회귀
- T2 ③번의 발화 조건이 "계정·토큰이 관여로 확인될 때"로 남았다. 검증 문장은 붙였지만 이 조건은 여전히 판단을 요구한다 — 감각적 발화 조건(무엇을 보면 참인가)에 도달하지 못했고, 프레임의 판단어 감사를 통과하지 못한 문장이다.
- T0에서 신호를 셋 선언했는데 (1) 신고 경로는 오탐 판정에만 소비되고 실제·불명 판정식에는 기여하지 않는다. 판정식을 다시 짜야 하는 결함이라 이 판본에서 열어 둔다.
- 계층을 T1→T2→T3 번호로 매긴 탓에 상승 사다리처럼 읽힌다. T1의 1·2·6, T2의 ④⑤⑥⑦은 독립·병행이다. 두 층위 모두 선행 표기와 병행군 분리는 넣었으나 번호는 관성대로 남겼다 — T2는 ①~⑦ 원번호를 유지한 탓에 병행군이 여전히 "뒤 순번"으로 읽히는 잔여가 있다.
- 완료 실측 문장이 여전히 "5분 카드 6항목"만 센다 — T1 카드 종료 조건으로 추가한 재분류 게이트는 완료 판정에 반영되지 않았다.
