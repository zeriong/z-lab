# 엑셀 파워유저의 SQL 전환 — 8주 오개념 교정 플랜
- 추론 프레임: misconception-first / 스타일: opus
- 한 줄 요약: 셀·절차 멘탈모델이 집합·선언 질의와 충돌하는 지점을 먼저 확정하고, 그 충돌이 실제로 터지도록 데이터에 뇌관을 심어, 8주 뼈대를 난이도 순서가 아니라 교정 순서로 세운다.

## 프레임이 요구하는 시작점 — 간섭 목록과 발화 시점

**선지식 간섭 전제 점검(1주 첫날, 90분).** 제3자 출제 예측 시험 12~16문항. 예측을 먼저 파일에 적고 실행해, 어긋난 문항만 "활성 오개념"으로 확정한다. 이 점검이 죽이는 것: (a) 활성 3개 미만이면 플랜 폐기, A1로 전환 — 8주에서 7주(회복)·8주(판정)를 빼면 충돌 슬롯 6개이고 절반이 비면 교정 골격이 성립하지 않는다(derived). (b) Power Query/DAX 상시 사용자면 5주 M4 충돌을 삭제하고 그 슬롯을 M5 심화로 돌린다.

**충돌을 걸지 않는 긍정 전이 자산**(매주 1개 회수): SUMIFS → GROUP BY+HAVING, 자동필터 → WHERE, IF → CASE, 피벗 값 영역 → 집계함수, 다중조건 INDEX/MATCH → 복합키 조인.

| 코드 | 간섭 | 발화 시점 | 뇌관 |
|---|---|---|---|
| **M3** | VLOOKUP식 사고: 한 행당 값 하나, 없으면 #N/A, 여럿이면 첫 값 | 1주 — 매일 쓰는 도구라 즉시 | 조인키 중복 2행 + 미매칭 키 |
| **M1** | 행 순서 신앙: 결과 순서가 저장 순서를 반영 | 2주 — 대조 쿼리 작성 시 | 동순위 다수 + LIMIT |
| **M5** | NULL = 빈 셀(0/""처럼 동작) | 4주 — LEFT JOIN이 NULL을 만든 뒤 | 집계 열 NULL, 서브쿼리 NULL |
| **M4** | 절차 신앙: 단계 시퀀스 가공 / 행별 반복 | 5주(집계 필터), 6주(갱신) | 별칭 참조, 1만 행 갱신 |
| M2 | 셀 좌표 지목 → 조건·키로만 식별 가능 | 3주 | PK 없는 중복 행 |
| M7 | 엑셀식 형변환(문자 날짜, 선행 0) | 1주 데이터 게이트 | 문자열 날짜 열 |
| M8 | 결과는 눈으로 스크롤해 검증 | 2주 | 습관 항목 |
| M9 | 틀리면 Ctrl+Z | 지연 발화 — 쓰기 권한 획득 시 | 커밋된 UPDATE |

**순서축 = "미교정 X가 Y 학습을 오염시키는 경로."**
- **M3을 1주로 당김**(관례는 3주차 조인): 미교정 M3는 모든 다중표 집계 합계를 조용히 틀리게 하므로, 뒤로 밀면 틀린 결과를 신뢰하는 습관이 여러 주 누적된다.
- **M3 → M8**: 금액이 틀린 직후가 눈검증을 버릴 유일한 동력. 관례는 검증을 마지막 주 "베스트 프랙티스"에 둔다 — 그 배치를 죽였다.
- M8 → M2: 대조 쿼리로 중복을 세면 "중복 한 행만 삭제"가 불가능함이 드러나고, 키 부재가 1주 뇌관의 원인이었음이 연결된다.
- M2 → M5: 대조 쿼리의 건수·합계가 NULL에서 깨진다. **다만 이 쌍은 관례 순서와 같은 답이다** — 오염 논거와 난이도 논거가 일치하므로 축이 일했다는 증거가 아니다.
- M5 → M4: fan-out의 정본 해법(선집계 CTE)은 GROUP BY와 논리적 처리 순서 교정 뒤에만 쓸 수 있다. 그래서 M3은 한 오개념인데 충돌(1주)과 재구성(5주)이 4주 떨어진다.
- M1과 M7의 선후: **임의 선언** — 오염 경로가 서로 없어 정당화 불가. 1주에 같이 처리한다.

## 문제 정의 / 목표

8주 후 실무 조회·집계·검증 자립. 목표는 문법이 아니라 간섭 제거 — 엑셀과 SQL이 다른 답을 낼 때 어느 쪽이 틀렸는지 스스로 판별하는 상태다. 성능 튜닝·스키마 설계는 제외(봉인 목록).

## 명시적 가정

- **실무 데이터 사본(또는 구조가 같은 위장 사본)과 쓰기 가능한 로컬 DB가 있다.** 틀리면 뇌관을 심을 수 없어 모든 충돌이 해설로 붕괴한다. 최저가 조기 검증 — 1주 첫날 30분, 1테이블 적재 성공 여부. 폴백 — 중복키·NULL·문자 날짜가 든 공개 dirty 데이터셋 + 문제은행으로 대체, "본인 데이터가 배신한다" 효과 상실을 기록하고 8주 이관 과제만 실무 데이터로.
- 출제·채점은 제3자(멘토·문제은행·AI). 틀리면 예측 시점에 답을 이미 알아 배신이 없다. 폴백 — 예측 파일 선봉인 + 데이터만이라도 타인 제작.
- 학습자는 진짜 파워유저다(피벗·SUMIFS·INDEX/MATCH 상시). 틀리면 간섭할 선지식이 없어 프레임 부적합 → A1.
- 사본 반출·개인정보 마스킹 승인이 있고 1~5주는 읽기 전용 계정. 틀리면 게이트 통과 불가 → 폴백 데이터셋, 6주 쓰기는 로컬 사본만.
- 주당 5시간. (b) 1주차 실제 소요 로그로 교체, 기록자는 학습자.

## 봉인 목록과 해제 조건

봉인은 "아직 안 가르친다"가 아니라 관성을 강화하므로 차단한다는 뜻이다.
- **피벗/CROSSTAB 변환**: 봉인 — 엑셀 표 모양 재현 관성을 굳힌다. 죽인 것: 통상 커리큘럼의 "엑셀 피벗을 SQL로 옮기기" 단원. 해제 8주 이후.
- **윈도우 함수**: 봉인, 7주 부분 개방(순서가 의미론적으로 필요한 자리만). 죽인 것: 3~5주 누적합·순위 과제.
- **인덱스·실행계획·성능**: 봉인. 해제는 시간 임계가 아니라 사건 — 학습자 쿼리가 실무에서 취소·차단된 사건 1건.
- **격리수준·락**: 봉인, 6주에 BEGIN/ROLLBACK 안전벨트만 개방. 전체 해제: 동시 쓰기 환경 배정 시.
- **DDL·정규화**: 봉인. 해제: 테이블을 직접 만들어야 하는 과제 발생 시.
- **재귀 CTE·저장 프로시저**: 봉인, 해제 조건 없음(8주 범위 밖).

## 접근 및 단계

각 주는 예측 → 충돌 → 재구성 → 검증 한 사이클, 충돌은 **주 1건 상한**((c) 임의; 3주말 이월 빈도로 재조정 — 2주 연속 이월이면 유지, 이월 0이면 2건). 문법·도구는 간섭하지 않는 화물이라 **별도 채널**: 주 30분 드릴 + 치트시트((c) 임의; 2주말 "구문 오류로 충돌이 막힌 횟수"로 교체).

**1주 — 뇌관 게이트 + 진단 + M3 충돌.** 선행: 없음(독립). 게이트 기준(모두 derived — 각 수치는 해당 예측을 반증 가능하게 하는 최소값): 같은 조인키 2행 이상 ≥1쌍(1행이면 fan-out 미발생), 미매칭 키 ≥1건(INNER 소멸 관측 최소), 집계 열 NULL ≥1건(AVG 분모 차이 최소), 문자열 날짜 ≥1열(정렬 붕괴 최소). 충돌: 제3자가 쓴 조인 쿼리를 주고 **행 수와 금액 합계를 먼저 적게 한다** — 학습자는 기준 표 행 수를 쓰고 실제는 더 크며 합계가 부푼다. 예측 과제는 작성 능력을 요구하지 않으므로 문법을 기다릴 필요가 없다. 재구성: 조인은 값 조회가 아니라 카디널리티 곱 + LEFT/INNER 미매칭 대조. 검증: fan-out 발생 행을 지목하는 쿼리 제출.

**2주 — M8 + M1.** 선행: 1주의 금액 오류. 충돌: ORDER BY 없는 LIMIT 쿼리를 두 번 실행해 순서 변동 확인. 재구성: 모든 산출 쿼리에 **검증 쿼리 짝**(행수·합계 대조, anti-join 미매칭 건수). 검증: 1주 과제 재시험(데이터만 교체) — 첫 간격 재시험.

**3주 — M2.** 선행: 2주 대조 쿼리. 충돌: PK 없는 중복 2행 중 하나만 삭제하라는 불가능 과제. 재구성: 행 식별은 좌표가 아니라 키 → 1주 뇌관의 원인 연결. 검증: 2주 항목 재시험.

**4주 — M5.** 선행: 1주 LEFT JOIN의 NULL, 2주 합계 대조. 충돌: NULL 한 건이 든 `NOT IN`이 0행 반환, `COUNT(*)` vs `COUNT(열)` vs AVG 분모. 재구성: 결측을 0으로 바꾸는 것은 데이터 변경이다. 검증: 3주 재시험.

**5주 — M4(1차) + M3 재구성.** 선행: 4주까지 전부. 충돌: `SELECT amount*0.1 AS fee … WHERE fee > 100` 오류, HAVING/WHERE 혼동. 재구성: 논리적 처리 순서 + **fan-out 정본 해법 = 선집계 CTE**(DISTINCT 봉합과 구분). 검증: 1주 과제를 선집계로 재작성해 합계가 엑셀 원본과 일치.

**6주 — M4(2차 발화) + M9.** 선행: 5주. 트리거: 쓰기 권한 획득(없으면 로컬 사본, 그래도 없으면 M9 봉인 유지 + 트리거만 기록). 충돌: 1만 행 등급 갱신을 행별로 하려는 시도 vs 단일 `UPDATE … CASE`; 커밋된 UPDATE에는 Ctrl+Z가 없다. 재구성: BEGIN/ROLLBACK 안전벨트 + 동일 WHERE로 SELECT 예행. 검증: 4주 재시험.

**7주 — 과교정 회복.** 선행: 5·6주 제출물. 진입 시 제출 쿼리의 `DISTINCT`·`COALESCE(…,0)`·서브쿼리 내 `ORDER BY`·`ROW_NUMBER` 출현 횟수를 센다(임계 없음 — 1기 관측으로 설정). 예측된 2차 오개념: DISTINCT 방어벽(정당한 중복 손실), COALESCE(0) 남발(AVG 왜곡), 순서 부정 과잉(누적 계산을 앱으로 반출), ROW_NUMBER로 좌표 복원. 재구성: 윈도우 함수 부분 개방 — `OVER(ORDER BY …)`는 논리적 순서 지정이며 저장 순서와 무관. 검증: 5주 재시험.

**8주 — 무예고 재시험 + 실무 이관 판정.** 선행: 전 주.

## 대안과 기각 사유

- **A1 난이도순 표준 커리큘럼.** 기각: 발화 시점과 무관해 fan-out을 배운 시점과 실제로 틀리는 시점이 어긋난다. **부활: 활성 오개념 3개 미만** — 간섭이 적으면 표준 순서가 싸다.
- **A2 엑셀 → Power Query → SQL 다리.** 기각: 절차 멘탈모델(M4)을 굳힌다. 부활: 조직 표준이 Power Query이고 SQL은 읽기만 필요할 때.
- **A3 오개념 사전 강의.** 기각: 예측이 오염돼 배신이 없다(프레임 실패 모드). 부활: 이미 쓰기 권한이 있어 사고 위험이 학습 효과를 넘을 때 — M9·M2만 해설 선행.
- **A4 BI 도구·ORM 우회.** 기각: 간섭이 남은 채 잘못된 리포트를 더 빨리 만든다. 부활: 8주 후에도 fan-out 문항이 계속 실패하고 조직이 검증된 템플릿을 제공할 때.

## 리스크 & 완화

- 충돌 불발(뇌관 없는 데이터) → 1주 게이트를 승인 게이트로 운영, 미달 시 폴백 데이터셋.
- 반복 실패로 사기 저하 → 주 1건 상한, 매주 긍정 전이 자산 1개 회수, 2건 이상 붕괴 시 이월.
- 예측 회피 → 예측 파일 제출 전 정답 잠금(제3자 운영).
- 과교정을 성과로 착각 → 7주 고정 + 8주 재시험에 과교정 탐지 문항.
- 지연 발화 미실현 → M9 봉인 유지, 완료 판정에서 미교정으로 명시.
- 개인정보 노출 → 마스킹 사본만, 1~5주 읽기 전용 계정.
- 1주 과부하 → 게이트 실패 시 진단만 하고 M3 충돌을 2주로 이월, 8주 판정일 고정.

## "완료"의 판정 기준

1. **(실측)** 8주차에 실무에서 쓰던 엑셀 리포트 1건을 SQL로 재현하고 ① 행 수 ② 핵심 금액 합계 ③ 미매칭 건수를 엑셀 산출물과 대조한다. **세 지표가 모두 일치하거나 불일치 원인이 엑셀 쪽 오류로 규명되면 통과.** 대조 쿼리는 학습자가 쓰고 제3자가 재실행해 확인한다(자가 채점 불가).
2. **(실측)** 무예고 재시험 — 활성 오개념당 2문항, 데이터만 교체. 전체 5/6 이상 정답 + fan-out 문항(1:N 조인의 행 수·합계 예측)은 무관용 전부 정답. 근거: 1문항 오차 허용은 구문 실수 여지이고 fan-out만이 금액을 조용히 틀리게 하므로 허용 대상이 아니다. (b) 1기 종료 후 오답 분포로 합격선 교체.
3. 봉인 항목 각각이 "봉인 유지" 또는 "해제 사유+날짜"로 기록돼 있다. 공란은 결손.
4. 미교정으로 끝난 오개념(예: 권한 미발생에 따른 M9)이 명시적으로 목록화돼 있다.

## 프레임 이탈 / 관성 회귀

- **순서축이 일하지 않은 구간을 본문에 남겼다.** §시작점의 M2 → M5 쌍은 오염 논거와 난이도 논거가 같은 답을 낸다. 축이 실제로 결정을 뒤집은 곳은 M3의 1주 배치, M8의 2주 배치, M3의 충돌/재구성 분리, M9의 사건 트리거 — 네 곳뿐이다.
- **§접근·7주의 2차 오개념 4건은 근거 표기 없는 내 추정이다.** 검출기(키워드 출현 횟수)는 넣었으나 **임계를 만들지 못했다** — 임계 없는 검출기는 게이트가 아니라 관찰이다.
- **가장 약한 절: §봉인 목록의 DDL·정규화.** 해제 조건이 "과제 발생 시"라 8주 내내 발생하지 않을 수 있고, 그러면 스키마 감각 없이 조회만 하는 상태로 종료된다. §완료 3·4는 그 사실을 기록하게 할 뿐 결손으로 판정하지 않는다.
- **리뷰어라면 §접근·1주를 공격하겠다.** 게이트·진단·충돌 셋을 한 주에 넣어 부하가 두 배인데, 일정 복구는 리스크의 이월 규칙 한 줄뿐이다.
- **관습을 택한 곳: 8주라는 달력 단위.** 발화 시점 기반이면 사건 경계(권한 획득, 첫 리포트 요청)가 옳았고 M9만 그렇게 했다. 같은 편의로 7주(회복)·8주(판정)를 뒤에 몰아 상승 곡선을 만들었지만 과교정은 5·6주 중에도 발생한다.
