# 사내 모놀리스 마이크로서비스 전환 — 18개월 부검에서 역산한 플랜
- 추론 프레임: premortem
- 한 줄 요약: 18개월 후 부검이 지목한 7개 사인을 차단하는 순서로 이관을 재배열하고, 완료를 "이관한 서비스 수"가 아니라 "모놀리스에서 삭제된 코드 경로 수"로 판정한다.

## 프레임이 요구하는 시작점 — 부검 보고서 (2028-01-31)

**고지: 이하 서사의 날짜·수치는 전부 서사 장치다.** 실측이 아니며 추정치로 인용·유통되면 안 된다.

**사망 선언.** 2028-01-31, CTO가 전사 공지로 "플랫폼 현대화 프로그램 종료"를 선언했다. 이 문장이 18개월 만에 나온 **첫 판정**이라는 것이 문제다. 실제 사망 시점은 12개월 차의 조용한 정체였다. 아무도 죽었다고 말하지 않았고 로드맵에는 "잠시 보류"라고 적혔으며, 그 상태로 6개월간 이중 인프라 비용만 지불됐다. **선언자도 순간도 없었다는 사실 자체가 사인 D4다.**

**서사 (시간순).**

*0~4개월.* 아키텍처 위원회가 도메인 12개를 그리고 "1년 내 12개 서비스"를 로드맵에 박았다. 첫 대상은 가장 중요한 주문 도메인이었다 — 중요하니 먼저 한다는 논리였다. 관측성·배포·온콜은 "서비스가 나오면 붙인다"로 미뤄졌다.

*5~9개월.* 주문과 재고가 분리되자 한 커밋에 들어가던 쓰기가 두 서비스로 갈렸다. 사가·보상 트랜잭션을 직접 구현했고, 보상이 실패하는 경로가 다시 보상을 필요로 했다. 재고 음수, 중복 주문, 수복용 수동 스크립트가 쌓였다(**D1 분산 트랜잭션 지옥**). 재무팀이 월마감을 못 하기 시작했다.

*10~13개월.* 장애가 서비스 사이에서 났고 어느 팀 것인지 정하는 회의가 열렸다. 분산 추적이 없어 한 요청의 전 구간을 아무도 재구성하지 못했다. 야간 페이지가 늘고 두 명이 번아웃으로 이탈했다(**D2 운영 복잡도**).

**D3 조직 미성숙**은 별개 사슬로 진행됐다. 스키마 변경 승인 권한이 이관 전과 동일하게 중앙 DBA 조직에 남아 있어서, 서비스는 독립 배포가 가능해졌는데 그 서비스의 테이블은 여전히 남의 결재를 받았다 — 분리의 목적이 첫 서비스부터 소멸했다. 팀 편성 권한도 없었다: 조직 개편은 반기 인사에만 열리고 프로그램은 그 사이에 시작했으므로, 4개 서비스를 기존 2개 팀이 겸업 온콜했다. 온콜 과부하가 없었더라도 "승인은 중앙, 책임은 팀"이라는 배치만으로 이관은 멈췄을 것이다. 12개월 차에 실제로 멈췄으나 아무도 멈췄다고 쓰지 않았다.

*14~18개월.* 모놀리스는 그대로 살아 있었고, 분리한 3개 서비스의 원본 코드 경로도 남아 이중 유지보수가 됐다. 종료 후 2개는 되돌렸고 1개는 좀비로 남았다.

### 사인 체크리스트 스윕

범주 목록은 **서사를 쓰기 전에** 고정했다(서사에서 뽑으면 커버리지 보증이 순환한다): 규제·법무 / 돈 / 보안 / 테스트 / 조직 / 건강 / 사용자.

| 범주 | 서사에 있었나 | 판정 |
|---|---|---|
| 규제·법무 | **없음** | **신규 사인 D5** — 감사로그와 개인정보 처리 이력이 서비스별로 흩어져, 외부감사의 "특정 고객 데이터에 누가 접근했나"에 단일 답을 제출할 수 없었다. 분리마다 처리위탁 범위 재심사가 재발했다. 단독으로 프로그램을 정지시킬 힘이 있다. |
| 사용자(사내) | **없음** | **신규 사인 D6** — 스키마가 갈리며 정산·리포팅 배치가 조인을 잃었다. 재무·CS가 엑셀 우회로 옮겨갔고 그 우회가 업무 정본이 되어 되돌릴 수 없었다. 사내 사용자는 티켓이 아니라 우회로 불만을 표현한다. |
| 돈 | 부분(이중 인프라만) | **신규 사인 D7** — 관측성 SaaS·라이선스·런타임이 서비스 수에 선형으로 붙고, 병행 기간이 길수록 성과와 무관하게 비용이 늘었다. 예산 회수 요구가 종료 선언의 방아쇠였다. |
| 보안 / 테스트 / 조직 / 건강 | 있음 | 각각 D2(서비스간 인증·시크릿), D1(경계 넘는 시나리오 검증 불가), D3, D2(온콜 번아웃)에 흡수 |

스윕 결과: **D5·D6은 서사에 완전 부재, D7은 부분만 존재** — 통과 기준(서사 부재 사인 ≥1건) 충족. 흡수 위치: D5→S1·S2·S4, D6→S2·S4, D7→S0·S2·S5.

## 문제 정의 / 목표

사내 모놀리스의 배포·소유권 병목을 줄인다. 목표는 "마이크로서비스화"가 아니라 **위 7개 사인이 발생하지 않는 조건에서 분리 가능한 경계만 분리하는 것**이다. 기본 착지 지점은 전면 분해가 아니라 **소수 서비스 + 모놀리스 잔류 확정**이다.

## 명시적 가정

- **경영진이 18개월 내내 "이관 서비스 수"를 성과지표로 요구하지 않는다** — 틀리면 플랫폼 선행(S2)과 잔류 착지가 무력화되고 부검 서사가 그대로 재생된다. 가장 싼 확인: S0에서 스폰서에게 "판정 지표 = 삭제된 코드 경로 수"가 적힌 한 장에 서명을 받는다(2주 내 가능). 서명이 안 나오면 대체 경로 — 이관을 취소하고 모놀리스 내부 모듈 경계 정리로 범위를 재정의한다.
- 쓰기 트랜잭션 경계를 코드·DB 로그에서 정적으로 열거할 수 있다 — 틀리면 S1 인벤토리가 부정확해져 D1이 재발한다. 완화: 열거 불가 영역은 "분리 금지" 목록으로.
- 정산·리포팅이 단일 DB 조인에 의존한다 — 틀리면 D6 대비가 과투자다(손해는 작다).
- 스키마 승인 권한을 서비스 소유팀으로 이전할 수 있다 — 틀리면 D3가 구조적으로 확정되므로 S4를 통과할 수 없고 플랜은 S0 기본값으로 착지한다.

## 접근 및 단계

단계는 의존 순서다(달 표기 없음). 각 단계는 어느 사인을 막는지 명시한다.

- **S0. 사망 선언 규칙과 착지 규칙.** 선행조건: 독립. 산출물 (a) 분기마다 판정 회의를 강제하는 규칙, (b) **기본값 있는 게이트** — 미통과 시 자동으로 "이관 중단 + 잔류 확정 + 이관분 유지"로 착지한다("재검토"는 기본값이 아니다), (c) CFO 오피스가 직전 12개월 청구서로 기입한 비용 상한. 검증: 규칙 문서에 스폰서·CFO 서명. 막는 사인: D4, D7.
- **S1. 트랜잭션 경계·감사 인벤토리.** 선행조건: 독립(S0과 병렬). "같은 커밋에 들어가야 하는 테이블 집합"과 "감사·개인정보 이력이 걸린 테이블"을 열거한다. 검증: 후보 경계를 가로지르는 쓰기 트랜잭션 = **0건**(DB 로그 표본으로 확인, 표본은 월마감 주간을 포함해야 한다). 0이 아니면 그 경계는 후보 탈락. 감사 걸린 테이블은 영구 제외가 아니라 **S2의 중앙 감사 싱크 가동 후 재심** 대상으로 표시한다. 막는 사인: D1, D5.
- **S2. 플랫폼 선행.** 선행조건: S0(비용 상한 기입 완료). 분산 추적·중앙 감사로그 싱크·배포 파이프라인·정산용 읽기 전용 통합 뷰(CDC 또는 리플리카)를 **서비스보다 먼저** 세운다. 검증: ① 모놀리스 단독 상태에서 추적으로 실패 요청 1건의 전 구간 재구성 ② 정산 배치를 통합 뷰 기준으로 재작성해 기존 결과와 대조 일치 ③ 감사 질의("특정 고객 데이터 접근자")에 단일 응답 제출 ④ S2 실지출을 S0 상한 대비로 기록 — 상한 초과 시 S3 착수 금지. 막는 사인: D2, D5, D6, D7.
- **S3. 첫 서비스 1개.** 선행조건: S1(경계 통과) + S2(검증 4항 통과). 대상은 "중요한 도메인"이 아니라 **경계가 깨끗한 도메인**이며, 스키마 승인 권한을 소유팀으로 이전한 상태여야 한다. strangler 프록시로 트래픽을 옮기고 원본 경로를 삭제한다. 검증: 원본 코드 경로 삭제 커밋 존재 + 소유팀 단독 스키마 변경 1건 성공. 막는 사인: D1, D3.
- **S4. 확장 게이트.** 선행조건: S3 이후 1개 운영 주기. 전부 충족 시에만 다음 서비스 착수 — 야간 페이지 주 2건 이하 / 감사 질의 단일 응답 유지 / 정산 결과 불일치 0 / 소유팀 단독 온콜 가능. 하나라도 미달이면 S0의 기본값으로 착지. 막는 사인: D2, D3, D5, D6.
- **S5. 비용 게이트.** 선행조건: S3 이후 청구서 3건. 월비용 증가율이 S0 상한을 넘으면 이관 정지. 막는 사인: D7.
- **S6. 잔류 확정.** 선행조건: S4 또는 S5의 정지 판정. 남은 영역을 "분리하지 않음"으로 문서화하고 좀비 서비스는 되돌린다. 검증: 소유팀 없는 서비스 0건 + 잔류 문서에 스폰서 서명. 막는 사인: D4.

수치 태그 — 야간 페이지 **주 2건**: 임의 선언, S2 이후 3개월 온콜 리포트 실측 중위값으로 교체(측정: 플랫폼팀). 비용 상한: **본문에 숫자를 두지 않는다** — 현재 청구서를 보지 않은 숫자는 잘못된 앵커다. 소유자·자료·시점을 S0에 고정했다. 서비스 수 상한: 파생 — 한 팀이 2개 이상을 온콜하면 D2가 재발하므로 1팀=1서비스.

## 대안과 기각 사유

- **도메인 전면 분해 로드맵(12개 서비스)** — 기각. D1·D2·D3가 모두 여기서 출발했다. 부활 조건: S2가 서 있고 온콜 가능 팀이 도메인 수만큼 실재할 때.
- **팀별 자율 분해(플랫폼 없이)** — 기각. 감사로그·추적이 팀별로 갈리면 D5가 구조적으로 확정된다. 부활 조건: 중앙 감사 싱크를 강제하는 표준 템플릿 배포 후.
- **그린필드 재작성** — 기각. 이중 정본 기간이 D6(엑셀 우회 고착)을 최대화한다. 부활 조건: 모놀리스가 지원 종료 런타임에 묶여 잔류 자체가 위험일 때.
- **모듈러 모놀리스(분리 없음)** — 기각하지 않는다. S0 기본값이 실질적으로 이 상태이며 S4·S5 미통과 시 여기로 착지한다.

## 리스크 & 완화

| 리스크 | 완화 |
|---|---|
| S2가 "성과 없는 기간"으로 보인다 | S2 검증을 모놀리스 단독 상태의 가시적 개선(추적·정산 대조·감사 질의)으로 정의 |
| 게이트가 정치적으로 우회된다 | 기본값이 "정지"이고 통과에만 서명이 필요 |
| 이관됐지만 원본이 남아 이중 유지보수 | 완료 판정을 삭제 커밋 기준으로 고정 |
| 감사 제외가 넓어 분리 후보가 남지 않는다 | 제외를 S2 가동 후 재심 조건부로 전환(S1) |

## "완료"의 판정 기준

1. **(필수·실측) 모놀리스 저장소에서 이관 대상 코드 경로가 삭제되어 있다.** 측정: 이관 서비스 목록의 각 항목에 원본 경로 삭제 커밋 해시를 대응시킨다. 대응 실패는 **0으로 센다** — 서비스가 떠 있어도 원본이 남으면 완료가 아니다. 측정자: 릴리스 엔지니어, 저장소 이력으로, 분기 판정 회의에서.
2. 소유팀이 아닌 엔지니어 1명이 온콜 문서만으로 실패 요청 1건의 전 구간을 재구성한다(외부 질문 0회). 측정: S2 이후 게임데이 1회, 소요 시간을 기록해 첫 실측치로 삼는다. 시간 상한은 이 실측 전에 정하지 않는다.
3. 분기 판정 회의가 매 분기 열렸고 각 회의에 "계속 / 정지·잔류 확정" 중 하나가 기록됐다. 기록 없는 분기가 1개라도 있으면 미완(D4 재발).

## 프레임 이탈 / 관성 회귀

- **이미 분리한 서비스를 되돌리는 경로가 S6 하나뿐이다.** S4·S5 미통과는 "다음 서비스 착수 정지"까지만 가고 기존 이관분은 유지된다. 부검은 "2개를 되돌렸다"를 기록했는데, 되돌리기가 정상 운영 경로라는 사실이 단계 구조에 들어가지 못하고 종점으로 밀렸다.
- **S1의 표본 창을 "월마감 주간 포함"으로만 규정했다.** 대상 시스템의 마감 주기를 모르는 상태에서 근거 있는 기간(1주/1개월)을 정할 수 없었고, 조건부 규정이 상한선이었다.
- **관행 채택:** strangler 프록시·CDC 읽기 뷰는 부검에서 도출한 것이 아니라 업계 정석이다. 부검이 결정한 것은 *순서*(플랫폼 선행), *탈락 규칙*(S1), *착지 지점*(잔류 확정)이다.
