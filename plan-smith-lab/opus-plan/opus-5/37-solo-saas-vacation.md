# 1인 SaaS 4주 여행 중 무인 운영 계획
- 추론 프레임: safety-net
- 한 줄 요약: 28일간 성장을 포기하고, 앱 바깥의 스위치로 어디서든 도달하는 폴백 상태 하나와 등급별 자동 대응으로 하한선 4항목의 붕괴를 막는다 — 무발동은 성공이 아니라 감지 실패로 분류한다.

## 프레임이 요구하는 시작점 — 하한선과 폴백 상태

### 하한선 4항목 (하나라도 붕괴하면 여행은 실패다)

| # | 하한선 | 라이브 디텍터 | 최대 무지 시간 |
|---|---|---|---|
| 1 | 기존 고객 데이터 유실 0 | 일일 백업 성공 + 주 1회 복원 해시 비교 | 24h |
| 2 | 결제·갱신·독촉이 계속 돈다 | 일별 결제 성공 건수·금액이 실측 하한 밖이면 알람 | 24h |
| 3 | 로그인 + 핵심 작업 1개 가용 | 외부 스케줄러의 합성 트랜잭션 | 6h |
| 4 | 법·계약 기한 무위반 | 하강 가격표(단계 1)의 만료 알람 | 만료 14일 전 |

무지 시간이 24시간을 넘는 디텍터는 부적격이다. 창이 끝난 뒤에야 아는 항목은 하한선이 아니라 부검 항목이다.

### 폴백 상태 F = "동결 운영" (단 하나, 어디서든 도달)

- **스위치는 앱 배포 밖에 둔다**(프로바이더 환경변수 + CDN 규칙): 앱 프로세스가 전부 죽은 상태에서도 F 진입이 가능해야 한다.
- 켜진 것: 기존 유료 고객 전 기능, 결제·갱신·독촉, 상태 페이지, 데이터 내보내기.
- 꺼진 것: 자동 배포(main→prod 거부), 배치·캠페인·리포트·재색인, 큐 소비자 정지, 워커 동시성 상한, 유료 API 하드 캡, 수동 승인이 필요한 신규 가입(대기명단).
- 바뀐 것: 지원 SLA 72시간 회신, 월 요금 이하 환불은 자동 승인.

### 전 창 거주성 계산 — 28일 내내 F에 있어도 죽지 않는가

기존 MRR은 100% 유지(청구는 동결 대상이 아니다), 신규는 0. 손실 = 월 신규 MRR + F 기간 이탈.
판정 규칙: **신규 MRR 비중이 30% 이상이면 F 정의에서 '신규 가입 차단'을 뺀다** — 셀프서브 결제 가입은 유지하고 수동 승인 플랜만 대기명단으로 돌린다. (30%: 준비 착수 시 대시보드 실측으로 확정 — 측정자 운영자, 직전 3개월 신규/총 MRR.) 이 계산이 반사적으로 넣었던 "신규 가입 전면 차단"을 기각했다.

### 동결로 수렴하지 않는 손해 — 예외 경로

확산성 3종: (a) 침해·크리덴셜 유출, (b) 쓰기 루프에 의한 데이터 오염(큐 재시도·웹훅 리플레이), (c) 비용 폭주. (b)(c)는 F 안에서 멈춘다 — 큐 소비자 정지와 하드 캡이 F의 구성요소인 이유가 이것이다.
(a)는 F로 멈추지 않는다. **격리**(키 회전·세션 무효화·통합 차단)는 F보다 공격적이므로 자동 실행을 금지하고 인간 승인 전용으로 둔다. 승인자 부재 확정(호출 후 12시간 무응답 — 임의 선언, 여정 실측 최장 무연락 구간으로 대체) 시 사전 확약된 조치는 F 유지 + 전면 공지 + 청구 일시정지다. 이는 하한선 2를 깨는 것이 아니라 **조정**이며, 값을 미리 계산해 둔다(일 매출 × 잔여일수).

## 문제 정의 / 목표

28일간 운영자에게는 판단 자원이 없다(시차·이동·오프그리드). 목표는 성장이 아니라 하한선 4항목이 한 번도 붕괴하지 않았음을 귀국 후 로그로 증명하는 것이고, 여행 중 개입은 성과가 아니라 설계 실패로 센다. 범위 밖(선언): 프로바이더·리전 전면 장애, 사업의 법적 분쟁 — F는 커버하지 않으며 조치는 상태 페이지 + 청구 일시정지뿐이다. 이 선언이 틀렸다면(즉 F가 커버한다고 믿으면) 해당 항목에 디텍터가 없어 무방비가 된다.

## 전환 비대칭 — 등급과 이동 규칙

출발과 동시에 L1로 내려간다. "여행 중 정상"은 평시 정상이 아니다.

| 등급 | 자동 트리거 | 자동 조치 |
|---|---|---|
| L1 여행 정상 | 출발(단계 7) | 배포 잠금, SLA 72h, 오토스케일 상한 |
| L2 열화 | 에러율·응답시간·큐 적체가 직전 4주 p99 초과 30분 지속 | 비필수 기능 차단, 캐시 TTL 확대, 상태 페이지 자동 갱신 |
| L3 = F(폴백) | L2 조치 후 30분 미회복, 또는 즉시 트리거(비용 캡 80% 도달, 5xx 임계, DB 연결 실패, 하트비트 48시간 부재) | F 정의 전체 + 영향 고객 자동 공지 |

**격리는 등급이 아니라 승인 게이트다** — 표 밖에 있고 자동 트리거가 없다.

- 하강: 즉시·자동·무조건. 어느 지점에서든 L3 직행이며, L3는 사다리의 끝이 아니라 어디서나 닿는 바닥이다.
- 상승: L2→L1은 프로브 3회 연속 정상(18시간) 후 자동 — L2는 열화이고 바닥이 아니다. **L3→L1은 자동 상승이 없다**: 손으로만, 귀국 후, 2시간 연속 확보 + 복귀 체크 통과 시. 창 중 예외는 거주성 예외 1건뿐이다.
- 숫자 태그: p99·30분 지속 = 출발 전 실측 분포에서 유도. 하드 캡 = 월 실측 평균의 2배(배수 2는 임의 선언), 그 80% 도달에서 L3(80%도 임의 선언 — 캡 도달 전 여유 확보 목적). L2→L3의 30분 = 임의 선언, 직전 4주 사고 로그의 자기해소 시간 중간값으로 대체(운영자, 준비 단계). 48시간 = 임의 선언, 여정 실측 최장 오프그리드 구간 + 12시간으로 대체. SLA 72시간 = 임의 선언, 귀국 첫 주 실제 회신 지연 분포로 대체(운영자, 티켓 로그).

## 명시적 가정

1. **운영자는 24시간에 1회, 5분, 폰으로 대시보드 1화면을 읽고 알람을 수신한다.** 틀리면 등급 전환·격리 승인·계획 재검토가 전부 무주공산이 되고 F 안착을 아무도 모른다. 최저비용 검증: 여정의 무연락 구간 최댓값 측정 → 48시간 초과 구간이 있으면 그 구간만 대리인 유상 온콜. 폴백: 하트비트 48시간 부재 = 자동 L3 하강 + '제한 운영' 공지. 운영자 부재 자체를 하강 트리거로 배선한다.
2. 백업·인증서·도메인 자동 갱신이 켜져 있고 복원이 실제로 된다. 틀리면 F가 28일을 못 버틴다(데이터 손상은 회복 불가) → 단계 4가 유일한 검증.
3. 주간 티켓량이 자동 응대로 견딜 규모다. 틀리면 SLA·환불 규칙이 무너져 이탈과 평판 손실 → 직전 8주 중간값·최댓값 실측으로 임계 확정.
4. 결제 파이프라인은 무인으로 돈다. 틀리면 매출 하한이 조용히 붕괴한다 — 디텍터 2가 유일한 방어선.

## 접근 및 단계 (의존 순서. 날짜 표기 없음 — 순서는 소비 관계에서만 나온다)

1. **하한선 확정 + 하강 가격표**(선행 없음). 위 4항목 표를 채우고 만료·기한 인벤토리를 만든다: TLS, 도메인, 프로바이더별 결제수단·카드 만료, 결제 분쟁 응답 7~10일, 개인정보 요청 30일, 세무 기한. 검증: 여행 창 + 2주 안에 만료되는 항목 0건, 남는 항목은 대리인 위임 문서로 처리. 이 표가 없으면 "즉시·자동 하강"은 허구다 — 제도적 기한은 동결되지 않는다.
2. **F 스위치를 앱 밖에 구현**(1 소비). 검증: 앱 프로세스를 강제 종료한 상태에서 스위치를 켜 상태 페이지·읽기 경로·결제 웹훅이 살아 있음을 확인. 실패면 출발 전 조치가 미완이다.
3. **프로브·주입기·하트비트를 외부 스케줄러에 배선**(2 소비 — F가 워커를 줄이므로 앱 안의 프로브는 F 진입과 함께 죽는다. F 스위치와 같은 바깥에 둔다). 합성 트랜잭션은 하한선 3의 무지 한계와 같은 6시간 주기, 주 1회 합성 장애 자동 주입, 하트비트 침묵 자체가 경보. 검증: 주입 1건 → L2 자동 전환 → 폰 알람 도달 → 18시간 후 자동 복귀가 로그에 남는다. 왕복이 기록되지 않으면 단계 3은 미완이다.
4. **복원 리허설**(1 소비, 2·3과 병렬). 백업에서 별도 환경으로 복원, 해시 비교 + 소요시간 기록. 이 시간이 데이터 오염 예외 경로의 예산이 된다.
5. **대리인 계약 + 최소 권한 역할**(1·3 소비). 격리 스위치만 실행하는 역할, 스테이징 1회 리허설, 알람 왕복 수신 확인.
6. **복구 수단 물리 분리**(3 소비, 5와 병렬). TOTP/하드웨어 키와 종이 백업 코드를 노트북·폰과 다른 가방에 — 기기 도난은 알람 채널과 승인 권한을 동시에 앗아간다. 여행지 IP에서의 콘솔 계정 잠금도 여기서 사전 확인.
7. **출발 동결**(1~6 전부 소비). 배포 잠금 + L1 진입. 검증: main→prod 자동배포가 거부된 로그 1건.
8. **창 중 운영**(7 소비, 반복). 하루 5분 읽기만 — 읽고 손대지 않는 것이 규칙이다. 주간 주입은 자동 발생하고 사람은 도달 여부만 본다. F 누적 체류가 14일(창의 절반 — 조치가 아직 의미 있는 마지막 시점)에 이르면 계획 재검토 알람이 뜨고, 기본값은 전면 공지 + 청구 일시정지 + 대리인 유상 발동이다. 이 기본값은 지금 확정한다. 바닥 안착 함정의 차단기가 이것이다.

## 대안과 기각 사유

- **창 중 핫픽스 허용** — 기각: 배포는 F의 도달성 기준선을 흔든다(스위치 경로가 변경된 코드 안에 있을 수 있다). 부활: 무인 카나리 + 자동 롤백이 검증되고 알람 왕복이 4주 연속 100% 도달할 때.
- **전면 유상 위임(외부 온콜)** — 기각: 4주짜리 도메인 지식 이관 비용이 회수되지 않고, 프로덕션 권한 부여가 침해 표면을 늘린다. 부활: MRR이 대행 비용의 20배 초과(임의 선언 — 귀국 후 운영자 정산에서 실측 대체) + 최소 권한 역할 준비 완료.
- **예고 휴업(청구 일시정지)** — 기각: 하한선 2·3을 스스로 깨며 F보다 손실이 크다. 부활: F의 28일 유지비(하드 캡 + 대리인 비용)가 4주 MRR을 초과할 때, 또는 침해 의심 + 승인자 부재.
- **자동 대응 없이 알람만 강화** — 기각: 가정 1을 정면으로 위반한다. 창 중의 판단은 최악의 판단이며, 알람은 대응이 아니다.

## 리스크 & 완화 (누락 범주 스윕: 돈·보안·데이터·법규·서드파티·신뢰·인적·알람·남용·계정)

- 프로바이더 계정 정지(결제수단 만료) — 가장 조용한 죽음. 여분 결제수단 + 만료일을 단계 1 인벤토리에.
- 알람 채널 단일 장애점 — 푸시 + SMS 2채널, 침묵도 경보로 취급.
- 오탐 피로로 F에 안착 — 단계 8의 14일 재검토가 유일한 차단기.
- 무료 티어 남용에 의한 비용 폭주 — F의 하드 캡이 구조적 차단.
- 개인정보 열람·삭제 요청 30일 — 28일 창과 겹친다. 자동 회신의 접수 확인 + 대리인 위임.
- 서드파티 API deprecation 공지 — 창 중 도착하면 대응 불가. 구독 메일을 대리인에게도 전달.
- 평판 — 상태 페이지와 자동 회신에 '제한 운영 기간'을 날짜로 명시. 침묵이 아니라 예고된 제한이어야 한다.
- 운영자 건강·기기 도난 — 단계 6의 물리 분리 + 하트비트 부재 자동 하강.

## "완료"의 판정 기준

1. **(실측 판정)** 귀국 후 전환 로그에 자동 주입된 합성 장애가 4건 이상, 각각 폰 알람 도달 시각과 함께 남아 있다. L1·L2에서 주입된 건은 "L2 이상 자동 전환 → 알람 도달 → 18시간 후 자동 복귀"까지 요구하고, **이미 L3(F)에 있는 동안 주입된 건은 알람 도달 기록만으로 충족**한다(F에는 자동 복귀가 없으므로 면제). 4건은 왕복이 아니라 **알람 도달 건수**로 센다. 0건이면 '하한선 미붕괴'를 주장하지 않고 감지 실패로 분류한다. '사고 0건'은 F가 사고의 매질을 없애 자동 충족되므로 판정에 쓰지 않는다.
2. 28일 전 구간에서 하한선 디텍터에 붕괴 구간이 없다: 일별 결제 성공 로그 28일 전부 존재, 합성 트랜잭션 완료율이 정한 값 이상, 복원 해시 비교 통과, 기한 위반 0건.
3. 단계 2·4의 리허설 통과 기록이 출발 전에 존재한다. 미통과면 여행을 미루거나 예고 휴업으로 간다 — 이 분기는 지금 확정한다.
4. 측정하지 않는 것: 고객 만족도, 창 중 성장, F 기간 이탈의 인과.

## 프레임 이탈 / 관성 회귀

- **F의 바닥이 높다.** §시작점에서 F를 '기존 고객 전 기능 유지'로 넉넉히 정의했다. 거주성을 사는 대가로 F 자체의 장애 표면을 남겼고, 더 낮고 단단한 바닥(읽기 전용)을 계산해 보지 않았다. 채택 가능성 쪽으로 기운 관성이며, 리뷰어라면 여기를 먼저 팔 것이다.
- **승인자 부재 조치가 하한선과 충돌한다.** §예외 경로의 청구 일시정지는 하한선 2와 부딪힌다. '조정'으로 재정의하고 계산식을 넣어 봉합했지만 그 값은 출발 전 실측까지 비어 있다.
- **임의 숫자가 다섯이다.** §숫자 태그의 30분·48시간·72시간·하드 캡 배수 2·80%. 이 중 SLA 72시간의 대체 측정(귀국 후 회신 지연)은 F 기간의 적정 SLA를 직접 재지 않는다.
- **표와 단계 번호가 사다리로 읽힌다.** §전환 비대칭의 표는 L1→L2→L3 오름차순이고 "어디서든 L3 직행"은 표 아래 산문에만 있다. 단계 1~8도 소비 관계로 적었으나 결과적으로 준비→출발→창 중의 시간 순과 일치한다.
- **대리인 한 사람에게 격리 승인 전체가 걸린다**(가정 1, 단계 5). 굵은 가정에 검증과 폴백을 붙였지만, "무인"의 예외를 사람 하나로 메운 형태다.
