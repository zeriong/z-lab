# 실시간 협업 텍스트 에디터 (웹) — 수렴 인수조건 역산 플랜

- 추론 프레임: backward / 스타일: opus
- 한 줄 요약: 인수조건 5개를 먼저 못박고, A2×A4 교차가 OT를 배제해 시퀀스 CRDT로 착지시키며, 앵커 밖 요구는 아키텍처를 못 구부리되 전부 출하한다.

## 프레임이 요구하는 시작점 — 인수조건 5개

| 앵커 | 판정 문장 (무엇을 어떻게 재는가) | 이 조건이 죽이는 대안 |
|---|---|---|
| **A1 수렴** | 같은 연산 집합을 받은 두 클라이언트의 **정규화 해시**(문자 시퀀스+속성 맵)가 동일 | 문서 전체 LWW 덮어쓰기, 3-way 텍스트 병합, "충돌 시 병합 UI" |
| **A2 오프라인 재접속** | 허용 창 이내 단절 후 재접속 시 수렴 + 단절 중 입력 문자 **100% 잔존** | 구간 락, 서버 변환 히스토리에 의존하는 OT |
| **A3 커서 의도 보존** | 원격 삽입/삭제 후 로컬 커서·선택이 **같은 문자**에 붙어 있음 | 정수 오프셋 커서 프로토콜 |
| **A4 서버 무지** | 편집 중 서버 kill → 재시작 → 재접속 시 손실 0, 수렴 유지 | 서버 권위 변환(OT), sticky session 전제, 서버 측 문서 모델 |
| **A5 규모 예산** | 10만자 × 10만 연산 픽스처에서 로컬 반영 p99 ≤ 1프레임, 메모리 상한 이내 | 무제한 tombstone, 전체 이력 재생 로드 |

**자격 심사(무엇이 탈락했는가).** 앵커는 실패 시 재작업이 최대인 조건만 받는다. *프레즌스 아바타*는 손상이 UI에 국소적이라 탈락(출하는 한다). *자동 저장*은 A4 영속 계약의 부산물이라 독립 조건이 아니다. *충돌 병합 UI*는 탈락이 아니라 **소멸**이다 — A1이 성립하면 보여줄 충돌이 존재하지 않는다.

**해상도 감사.** A1을 "사람 눈에 같아 보임"으로 잡으면 속성 맵 발산을 놓치고 발산은 다음 편집에서 증폭된다 → 정규화 해시로 고정(더 거친 해상도는 목적 미달). 반대로 A5는 의도적으로 거칠게 — 상시 게이트가 아니라 주문형 벤치 1회.

**앵커 교차(쌍별 겹침).**
- **A2 × A5 충돌** — 오프라인 클라이언트가 아직 못 본 삭제를 tombstone GC가 지우면 재접속 시 조용히 발산한다. 이 지점이 핵심 결정을 낳는다: **오프라인 허용 창을 명시 파라미터로 두고, 창 초과 클라이언트는 오류가 아니라 정규 경로인 "재동기화 강등"**(스냅샷 재수령 + 로컬 편집을 신규 삽입으로 재적용)으로 보낸다.
- **A1 × A4 상호지지** — 서버가 내용을 몰라야 한다는 요구가 수렴을 클라이언트 대칭 알고리즘으로 밀어붙인다.
- **A3 × A1 상호지지** — 커서용 안정 식별자는 수렴 코어의 위치 ID를 재사용해 해결(별도 매핑 계층 불필요).
- **의존 → 실행 순서.** A4가 나머지의 지붕이다. 서버 무지를 먼저 못박으면 A1·A2·A3의 구현 위치가 클라이언트로 확정된다 → A4 → A1 → A3 → A2 → A5.

**측정 저항 스윕.** 결정적인데 앵커가 없는 범주: **서식 병합의 의미적 정합성**(같은 구간에 각각 bold와 링크 → 수렴하지만 사람에게 납득 가능한가). 해시로 판정 불가, 앵커 승격 불가. 대체물은 사람 검토 픽스처 10건 회귀뿐이며 앵커보다 약한 장치다.

## 문제 정의 / 목표

두 사용자가 같은 텍스트를 동시에 편집해도 어느 쪽 입력도 잃지 않고 한 문서로 수렴하는 웹 에디터. "충돌 없음"은 충돌을 숨기는 것이 아니라 **충돌이라는 상태가 생기지 않는 것**이다.

**역산 결과.** A2(장기 오프라인 병합)와 A4(서버 무지)를 동시에 만족하면 변환 권위를 가진 중앙 서버가 성립하지 않는다 → **시퀀스 CRDT**. 이는 도메인 정석과 일치하므로 프레임이 생산한 답이 아니다. 프레임이 한 일은 경계 그리기다: 정석이 **강제되는** 구간은 A2+A4 조합, **강제되지 않는** 구간은 라이브러리 채택 여부·서식 모델·인증이다.

**전달 스택(정석 채택이지만 무엇을 사는지 명시).** TypeScript / 시퀀스 CRDT 라이브러리(Yjs 계열, A1 구현과 A5의 런렝스 인코딩을 산다) / CodeMirror 6 또는 ProseMirror 바인딩(A3의 상대 위치) / 문서를 해석하지 않는 WebSocket 릴레이 + append-only 업데이트 저장 + 주기 스냅샷(A4의 재시작 무손실) / 클라이언트 IndexedDB.

## 명시적 가정

- **편집 대상은 단일 선형 텍스트 시퀀스(+인라인 서식)이고, 트리형 블록 문서·표는 범위 밖이다.** 틀리면 위치 식별자와 GC가 전면 재작업(A3·A5 재도출). 가장 싼 조기 검증: S0 착수 전 실제 사용 문서 20건에서 표·중첩 블록 비율을 세는 반나절 작업. 폴백: 2계층 CRDT(블록 리스트 + 블록 내부 텍스트) — 앵커 5개는 유지하고 S2·S3만 블록 경계에서 재정의.
- 동시 편집자는 ≲10명. 틀리면 팬아웃·GC 빈도 재설계 + A5 예산 재도출.
- 서버는 신뢰 가능(업데이트 위조는 다루지 않음). 틀리면 서명·권한 계층이 필요하고 A4의 "내용을 모른다"와 충돌 → 앵커 재판정 사안.
- 클라이언트에 로컬 영속이 있다. 틀리면 A2 경로가 탭 새로고침을 못 견딘다.

## 접근 및 단계

- **S0 앵커 계측 하네스** (선행: 없음). 고정 seed 편집 스크립트, 2클라이언트 시뮬레이터, 해시 비교기, 오프라인 창 주입, kill 스위치. *검증*: 깨진 LWW stub을 끼우면 A1 판정이 **실패해야 한다**(못 잡으면 하네스가 고장). 서비스: 전체.
- **S1 전송·영속 계약** (선행: S0 민감도 통과). 방 단위 불투명 바이너리 릴레이 + append-only + 스냅샷. *검증*: 편집 중 `kill -9` → 재시작 → 해시 일치, 손실 0. 서비스: **A4**.
- **S2 수렴 코어** (선행: S1 계약). 텍스트 CRDT 결선 + 로컬 우선 적용. *검증*: 각 1,000연산 교차 후 해시 일치. 서비스: **A1**.
- **S3 커서·프레즌스 위치** (선행: S2의 위치 ID). *검증*: 커서 앞 원격 삽입 → 오프셋 보정, 선택 내부 삭제 → 선택 축소. 서비스: **A3**.
- **S4 오프라인 경로 + GC 창** (선행: S1·S2 / A2×A5 교차의 산물). *검증*: 창 이내·초과 두 케이스, 초과 시 로컬 편집이 신규 삽입으로 생존. 서비스: **A2·A5**.
- **S5 규모 판정** (선행: S2·S4의 GC 정책). *검증*: 픽스처 벤치의 p99와 메모리 실측. 서비스: **A5**.
- **S6 앵커 밖 표면 출하** (선행: S2·S3 / **S4·S5와 병렬**). *검증*: 표면별 완성 문장 + **A1 회귀 재실행**. 서비스: 앵커 없음 — 출하 의무.

### 앵커 밖 요구 원장 — 아키텍처는 못 구부린다, 그러나 전부 출하된다

| 요구 | 판정 | 완성 문장 / 유예 트리거 |
|---|---|---|
| 프레즌스(이름·색·원격 커서) | build | 없으면 수렴해도 제품이 고장난 것처럼 보인다 |
| 연결 상태 UI | build | 이 표시 없이는 A2 경로를 사람이 검증할 수 없다 |
| IME(한글 조합) | build | 조합 확정 시점에만 CRDT 트랜잭션 발행 |
| 접근성(스크린리더·키보드) | build | 원격 편집이 포커스를 훔치지 않는다 |
| 서식(bold/heading/list) | build | 속성이 정규화 해시에 포함된다 |
| 협업 undo | build | 내 undo가 남의 편집을 되돌리지 않는다 |
| 문서 목록·공유 링크 권한 | build | 읽기 전용 링크의 쓰기 업데이트를 서버가 거부한다 |
| 모바일·터치 | defer | 트리거: 파일럿 접속의 20% 이상이 모바일 |
| 이미지·첨부 | defer | 트리거: 텍스트 앵커 5개 전부 통과 후 |
| 버전 이력·복원 UI | defer | 트리거: 요청 1건(S1의 append-only가 이미 이력 보유) |
| 감사 로그 | defer | 트리거: 조직 고객 유입 |

**IME는 특수 사례다** — 앵커에 없으면서 아키텍처를 건드릴 후보였다. 격리로 처리했으나 격리를 약속으로 두지 않는다: **S6의 IME 픽스처에서 확정 음절 1개당 CRDT 연산이 1개를 넘으면**(중간 자모마다 발행 → tombstone 폭증 → A5 역류) **IME를 앵커 A6로 승격하고 S2를 재도출한다.**

**숫자 태깅.** 로컬 반영 p99 ≤ 1프레임(≈16ms) = **파생**(화면 갱신 주기). 10만자×10만 연산 = **수명 상한**(S5 착수 전 파일럿 문서 길이 p95로 대체, 측정자 구현자). 오프라인 창 7일 = **임의 선언**(파일럿 재접속 간격 p95로 대체). 원격 반영 200ms = **임의 선언**(파일럿 RTT 분포로 대체). 메모리 상한 = **정직한 공백**, S5가 첫 측정. 그 밖의 수치(1,000연산·픽스처 10건·문서 20건·≲10명·모바일 20%)는 전부 **임의 선언**된 표본 크기이며 앵커 판정 자체를 바꾸지 않는다.

## 대안과 기각 사유

1. **OT(서버 권위 변환)** — A2와 A4를 동시에 만족 못 함. *부활*: A4가 요구에서 빠지고 오프라인 창이 초~분으로 축소되거나, **S5에서 CRDT 메타데이터가 메모리 상한을 초과하면** 재심(OT엔 tombstone이 없다).
2. **구간 락** — 충돌을 해결하지 않고 회피하며 A2·A3를 함께 죽인다. *부활*: 대상이 동시 편집 금지 문서(서명본·규제)로 바뀌면.
3. **저장 시 3-way 병합** — 충돌 마커가 나올 수 있어 A1 정의상 수렴이 아니다. *부활*: 요구가 실시간을 포기하고 체크인 모델이 되면.
4. **CRDT 자체 구현** — 초기 기각(A1 재검증 비용). *부활*: S5 미달 + 프로파일이 라이브러리 인코딩을 원인으로 지목할 때.

## 리스크와 완화

| 리스크 | 완화 |
|---|---|
| 메타데이터 팽창으로 A5 미달 | GC 창 + 스냅샷 + 강등 경로(S4); 미달 시 대안 1·4 재심 |
| GC 창과 오프라인 창 불일치 → **조용한 발산** | 창 파라미터를 양쪽이 단일 출처에서 읽고, 창 초과를 정규 경로로 |
| 서식 병합이 수렴하지만 납득 불가 | 앵커 불가 — 사람 검토 픽스처 10건 회귀(약한 대체물) |
| IME가 아키텍처로 역류 | 바인딩 격리 + 음절당 연산 1개 초과 시 앵커 승격 |
| 하네스 무감각 / 앵커 밖 작업이 수렴을 깸 | S0 민감도 검증 + S6 표면별 A1 회귀(각 단계 검증란과 동일) |

## "완료"의 판정 기준

1. **(실측 판정)** 고정 seed 각 1,000연산을 두 클라이언트에 서로 모르는 상태로 적용하고, 도중 서버를 1회 `kill -9`하고, 한 클라이언트를 창 이내로 오프라인 처리한 뒤 재접속시킨다 → **두 문서의 정규화 해시가 동일하고, 오프라인 중 입력한 문자 전부가 최종 문서에 존재한다.** (뒷절이 필수: 해시 일치만 보면 "양쪽 모두 비었음"으로 자동 만족되는 순환 판정이 된다.)
2. 창 초과 케이스에서 재동기화 강등이 발동하고 로컬 편집이 신규 삽입으로 보존된다.
3. A3 두 케이스 통과(S3 검증과 동일).
4. S5 벤치 수치가 기록된다 — 통과·미달 무관하게 기록이 완료 조건이고, 미달이면 대안 1·4 재심을 연다.
5. 원장의 build 7개 항목이 각자의 완성 문장을 만족하고, 그 직후 A1 회귀가 통과한다.

## 프레임 이탈 / 관성 회귀

- **가장 약한 곳은 숫자다.** 앵커 관련 수치 4개 중 2개(창 7일, 200ms)가 근거 없는 임의값이고, 표본 크기 5개는 임의 선언으로 묶어 처리했다. 수정 시도는 했다 — 반영 예산은 화면 주기에서 파생시켰고, 문서 규모엔 실측 대체점을 박았고, 메모리 상한은 추측 대신 공백으로 남겼다. 창 7일만 파생 경로를 찾지 못했다.
- **정석 착지.** "역산 결과" 문단은 발견이 아니라 확인이다. 그렇다면 프레임의 순가치는 경계선 한 줄 + 교차 결정 하나 + 원장 하나로 좁게 계산돼야 한다.
- **측정 저항 범주 처리가 약하다.** 픽스처 10건은 선정 자체가 저자 취향이다. 리뷰어라면 "측정 저항 스윕"과 그것을 받는 리스크 행부터 친다.
- **유예 4건.** 모바일의 20%는 근거가 없고, 트리거의 존재가 유예를 정당화하는 것처럼 보이게 배치됐다.
