# 팀 공용 디자인 시스템 컴포넌트 라이브러리 설계

- 추론 프레임: api-first / 스타일: opus
- 한 줄 요약: 소비자가 실제로 타이핑하는 10줄을 계약으로 동결하고, 그 10줄이 참이 되는 방향으로만 내부를 만든다 — 계약의 핵심은 컴포넌트 목록이 아니라 **오버라이드 경계와 잠김/자유 선언**이다.

## 프레임이 요구하는 시작점 — 소비자 코드 10줄 + 이스케이프 해치 1줄 (v1 = 가설 — 단계 0 실사 결과로 **교체 예정**, 현재 인용 없음)

반사적 습관은 토큰 → 프리미티브 → 컴포넌트 순의 계층 설계였고, 이 프레임은 그 순서를 금지한다. 그래서 토큰 레이어는 3단계로 내려갔다.

```tsx
// packages/ui/examples/consumer.tsx — 이 파일이 바뀌면 버전이 바뀐다
<Field label="이메일" error={form.errors.email} required>
  <TextInput {...form.register("email")} placeholder="you@corp.com" />
</Field>
<Select value={teamId} onChange={setTeamId} placeholder="팀 선택" emptyText="가입한 팀이 없습니다">
  {teams.map(t => <Select.Option key={t.id} value={t.id} disabled={t.archived}>{t.name}</Select.Option>)}
</Select>
<Button variant="danger" size="sm" loading={saving} disabled={!teamId} onClick={remove}>삭제</Button>
<Button variant="ghost" className="ms-auto w-full md:w-auto">취소</Button>
<Button asChild variant="primary"><Link href={`/teams/${teamId}`}>팀으로 이동</Link></Button>
<Button variant="danger" style={{ background: "#f00" }}>위반 예시 — dev throw</Button>
{/* 유일한 합법 탈출구. 이 주석(이슈 링크)이 없으면 lint 실패 — ISSUE-1234 */}
<Button variant="danger" unsafeStyle={{ background: "#f00" }}>해치 예시 — 사용 건수는 기준선 지표(기준 5)</Button>
```

**기존 세계가 죽인 결정:** 2행의 `{...form.register()}` 스프레드는 내가 반사적으로 잡았을 `<TextInput value onChange>` 제어 전용 시그니처를 폐기시킨다(제품 코드는 이미 react-hook-form을 쓴다). 1행의 `Field`가 `id`/`aria-describedby`를 주입한다는 사실은 "소비자가 `htmlFor`를 직접 연결한다"는 현행 관행을 계약 위반으로 만든다.

**예시가 전제하는 외부 의존 = 픽스처 목록(완료 기준 2는 이 목록만 깔린 앱에서 실행된다):** react-hook-form(`form` = `useForm()` 결과 — 예시의 `errors` 접근 경로는 설치 버전 기준으로 단계 1에서 확정. v7+는 `form.formState.errors`다), 라우터의 `Link`(`next/link` 또는 동일 시그니처 스텁), 지역 바인딩 `teams` / `teamId` / `setTeamId` / `saving` / `remove`. 이 목록 밖의 의존이 예시에 들어오면 그것은 계약이 아니라 앱 코드다.

### 에지 케이스 — 계약에 박음 (각 행 = 이름 붙은 테스트)

| 행 | 확정하는 분쟁 | 테스트 |
|---|---|---|
| 1–3 | Field가 label/error/id/required를 자식에 주입. 자식이 2개 이상이면 dev throw | `contract/field-injection` |
| 2 | 비제어 스프레드 허용. `value`만 주고 `onChange`가 없으면 dev warn(읽기전용으로 바꾸지 않음) | `contract/uncontrolled-spread` |
| 4–6 | `teams`가 빈 배열/undefined면 `emptyText`. `disabled` 옵션은 선택 불가하나 기존 값은 유지 | `contract/select-empty` |
| 7 | `loading`이면 disabled 자동 + `aria-busy` + onClick 억제. loading·disabled 동시 지정 시 표시는 disabled 우선. 미지의 variant는 **타입 에러**(런타임 폴백 없음) | `contract/button-state` |
| 8 | `className`은 외곽 박스의 **논리 스페이싱·폭·정렬·position**만(`ms-*`,`me-*`,`margin-inline-*`,`w-*`,`flex/grid` 배치). 물리 방향(`ml/mr`) 금지 — RTL을 깨므로 | `contract/override-allowlist` |
| 9 | `asChild`: 스타일·상태는 Button, 시맨틱·라우팅은 자식. onClick은 자식 먼저 후 Button. 인터랙티브 중첩(a 안의 button)은 throw | `contract/as-child` |
| 10 | `style` prop과 색·타이포·radius·shadow 계열 className: dev throw / prod 무시 + 1회 warn + 이스케이프 해치 안내 | `contract/override-violation` |
| 11 | `unsafeStyle`은 경계를 넘는 **유일한 합법 경로**: 임의 CSS를 통과시키지만 이슈 링크 주석이 없으면 lint 실패, prod 빌드에서 사용 건수를 집계 파일로 배출 | `contract/unsafe-escape` |
| 1–11 (전 행) | 포커스 순서는 DOM 순서와 일치, Field는 라벨→입력→에러를 한 탭스톱으로 묶음 / Select는 키보드만으로 열기·선택·닫기·포커스 반환 가능 | `contract/focus-order`, `contract/keyboard-nav` |

### 잠김 / 자유 선언 (계약의 범위)

| 잠김 — 변경은 major | 판정자 | 자유 — 예고 없이 바뀜 |
|---|---|---|
| 공개 prop 이름·타입·필수성 | **기계** — 공개 `.d.ts` diff | 내부 DOM 구조·클래스명·래퍼 개수 |
| 합성 구조와 부모의 주입 사실 | **리뷰** — 소유자 | 토큰 값(hex, px), 애니메이션 시간 |
| 접근성 계약: role, accessible name의 출처 prop, 상태 노출(`aria-invalid`/`busy`/`expanded`), 라벨–입력–에러 연결 | role·aria 상태·연결은 **기계**(a11y 스냅샷) / accessible name의 **출처 prop**은 **리뷰** | 기본 문구·아이콘(예: 닫기 aria-label 기본값) |
| 오버라이드 경계와 위반 시 동작 | **기계** — `contract/override-*` 테스트 | 옵셔널 prop 추가(기본값이 기존 동작과 동일할 때) |
| `variant`의 **의미**(danger = 파괴적 행동) | **리뷰** — 소유자 | `variant`가 참조하는 토큰 값 — 다크모드에서 달라도 계약 위반 아님 |
| `onChange`가 받는 값의 형태(값 vs 이벤트) | **기계** — 타입 diff | 접근성 계약을 깨지 않는 내부 노드 순서 |
| 이스케이프 해치의 이름(`unsafeStyle`)과 필수 주석 규칙 | **기계** — 타입 diff + lint 규칙 diff | 해치 **내부에 적는 값** 자체(소비자 소유, 계약 밖) |

픽셀 스냅샷은 계약으로 쓰지 않는다. 자유 층까지 잠그면 모든 개선이 파괴적 변경으로 읽힌다 — 시각 회귀 테스트는 계약 밖의 참고 신호로만 돌린다.

## 문제 정의 / 목표

팀마다 같은 버튼을 다시 만들고, 공용 컴포넌트를 쓸 때는 `!important`와 래퍼로 비틀어 쓴다. 목표는 컴포넌트 개수가 아니라 **분쟁 종결**이다: 무엇을 오버라이드할 수 있고 무엇을 바꾸면 major인지가 문서가 아니라 타입·테스트로 답해지는 상태.

## 명시적 가정

1. **소비 스택이 단일(React + TypeScript)이고 렌더러도 웹 DOM 단일(React Native·웹뷰 전용 앱 없음)이며, 기존 콜사이트를 grep으로 광산할 수 있다.** 틀리면 10줄 예시가 단일 헌법이 될 수 없어 프레임 자체가 무효다 → 공용 층을 토큰/CSS로 내리고 컴포넌트 계약은 웹 React 범위로 명시 축소. 가장 싼 검증: 실사 첫날 제품 저장소 `package.json`의 프레임워크 집계 + `react-native`/`react-native-web` 의존 grep(반나절 이내).
2. 오버라이드 채널은 `className`(유틸리티 CSS 또는 CSS Modules)이다. 틀리면(styled-components 테마) 허용 목록이 prop 화이트리스트로 바뀌지만 경계 원칙과 잠김/자유 표는 그대로 산다.
3. 라이브러리 팀이 제품 저장소에 lint/CI 규칙을 강제할 권한이 있다. 틀리면 오버라이드 경계는 예의 수준으로 떨어지고 이 계획은 계약이 아니라 측정 도구만 남는다 — 그 경우 완료 기준 5만 유지한다.
4. Figma variant 이름과 코드 variant가 1:1이다. 틀리면 이름 드리프트가 잠김 항목을 흔든다 → variant 이름 변경을 major로 취급하는 규칙(단계 5)으로 흡수.

## 접근 및 단계

**0. 실사 (독립).** 전 제품 저장소 콜사이트 전수 grep으로 ① 컴포넌트 빈도 순위 + 컷라인(= v1 범위, 취향이 아니라 실사 산출물) ② 실제 데이터 형태와 인용(`file:line`) ③ 오버라이드 해킹 census(`!important`, `styled(...)`, 로컬 래퍼 수). **거부 게이트:** 전수 콜사이트 중 위 예시로 표현 불가한 비율이 20%를 넘으면 v1을 패치하지 않고 폐기·재작성한다. (20% = 임의 초기값, 파일럿 실측 이탈률로 대체.)

**1. 계약 동결 (0 소비).** 예시의 각 행을 광산 인용으로 교체하고 잠김/자유 표를 확정. 구현 없이 타입 선언만 작성. 검증: 예시 파일이 `tsc` 통과 + 모든 행에 인용이 붙음(빈 인용 = 미완) + 조항 표에 남은 `TBD-실사` 표기가 0.

**2. 에지 케이스 테스트 (1 소비).** 위 조항 표 9행(접근성 행의 `contract/focus-order`·`contract/keyboard-nav` 포함) + `contract/ssr-portal`(Modal 포털의 하이드레이션)을 이름 붙은 테스트로 작성. 검증: 산문 조항 표에 테스트 id 빈칸이 0인지 CI 스크립트가 확인. **유예 규칙:** 실사 전에는 대상 컴포넌트가 미확정인 조항의 id를 `TBD-실사`로 표기할 수 있고, 이 표기는 단계 1 종료 시점에 0이 되어야 한다 — CI 게이트의 판정 시점은 단계 1 종료 이후다. **2는 3보다 반드시 앞선다** — 구현이 먼저면 테스트가 구현을 기술하게 되고 계약이 사라진다(메커니즘이지 취향이 아니다).

**3. 내부 구현 (2 소비).** 토큰 레이어, 슬롯/컨텍스트 합성, variant 해석 함수 1개, 오버라이드 경계 검사. 검증: 1·2 테스트 전부 녹색 **+ 테스트 파일 diff 0**(테스트를 고쳐 통과시킨 흔적이 없음).

**4. 파일럿 이관 (3 소비).** 실사에서 콜사이트 밀도 상위 3화면. 검증: 아래 완료 기준의 계수.

**5. 거버넌스 (1과 병행 가능, 독립).** 계약 변경 절차(RFC + codemod 의무), 코퍼스 상한(컴포넌트당 예시 ≤3 = 정상 1 + 에지 2), 은퇴 규칙(타입으로 불가능해진 에지 예시는 타입 테스트로 강등), 버전 규칙(잠김 변경 major / 옵셔널 추가 minor / 자유 변경 patch).

예시 밖 컴포넌트는 빈도 순위대로 배치 2·3에서 같은 0→3 절차를 반복하고, 배치마다 추가 예시는 코퍼스 상한 안에서만 늘린다. Modal의 키보드·포커스 트랩 계약은 배치 2에서 같은 방식으로 행이 된다.

## 대안과 기각 사유

- **토큰 우선(Figma 토큰 → 프리미티브 → 컴포넌트).** 기각: 팀이 실제로 피 흘리는 곳은 토큰 값이 아니라 오버라이드 분쟁이고, 토큰은 그 분쟁에 판정을 주지 못한다. 부활 조건: 실사에서 프레임워크가 2개 이상으로 확인되면 공용 층은 컴포넌트가 아니라 토큰/CSS여야 하므로 즉시 전환.
- **`className`을 제한 없이 머지해 주는 관행(현행 공용 컴포넌트의 기본값이자, 프레임 없이 썼다면 이 문서가 갔을 자리).** 기각: 색·타이포까지 열리면 잠김 층이 사실상 사라지고 계약은 문서로 퇴화한다 — 그래서 8행이 허용 목록, 10행이 위반, 11행이 유일한 해치가 됐다. 부활 조건: 없음. 열어야 하면 `unsafeStyle`을 통과해 건수가 세어져야 한다.
- **벤더 헤드리스 API를 그대로 계약으로 채택(Radix/MUI 등).** 내부 구현으로는 채택, **계약으로는 기각**: 벤더의 파괴적 변경이 우리 major가 되고 잠김/자유 선언 권한을 잃는다. 부활 조건: 실사 결과 v1 예시가 벤더 API와 prop 이름 기준 80% 이상 일치하거나 유지 인력이 1명 이하이면 벤더 API를 계약으로 채택하고 우리는 토큰만 소유한다. (80% = 임의 초기값, 실사 diff로 대체.)

## 리스크 & 완화

- 예시가 광산 결과가 아니라 작성자 취향(이 프레임의 고유 실패 모드) → 단계 0 거부 게이트 + 단계 1의 인용 의무.
- 코드로 표현 못 하는 조항이 산문으로 새어 방치됨 → 조항 표의 테스트 id 빈칸 0을 CI에 넣음(단계 2, 판정 시점은 단계 1 종료 후).
- 이스케이프 해치가 기본 경로가 됨 → `unsafeStyle`은 계약 11행·`contract/unsafe-escape`로 박혀 있고, 이슈 링크 주석 없으면 lint 실패, 사용 건수를 소유자가 월 1회 읽음(단계 5). 임계는 기준선 측정 전까지 공백.
- 채택 실패(팀들이 로컬 컴포넌트 유지) → 파일럿을 실사 밀도 상위로 고정하고, 로컬 중복 컴포넌트 수를 이관 전후로 센다.
- 접근성 계약이 role/name만 잠가 얕음 → 조항 표의 `contract/focus-order`·`contract/keyboard-nav`를 단계 2에 포함. 파일럿에서 키보드 결함 1건이라도 나오면 배치 2 최우선으로 승격.
- 번들 크기(배럴 임포트) → 이연. 트리거: 파일럿 화면 gzip 번들이 이관 전보다 +10KB 이상이면 배치 2에서 엔트리 분할. (+10KB = 임의 초기값, 이관 전 실측으로 대체.)
- 모바일/RN → 범위 밖(n-a): 가정 1의 "렌더러도 웹 DOM 단일" 조건에 근거하며(검증: 실사 첫날 `react-native`/`react-native-web` 의존 grep), 깨지면 재판정.
- 별도 문서 사이트 → 이연: 코퍼스가 문서다. 트리거는 소비 팀 4개 이상(임의 초기값 — 단계 4 이후 "온보딩 1건당 질문 수 × 소비 팀 수" 추이로 대체: 팀 수가 늘 때 온보딩당 질문 수가 함께 오르는 지점).

## "완료"의 판정 기준

1. **(측정)** 파일럿 3화면 이관 중, 제품 화면을 풀기 위해 `packages/ui/**`를 수정해야 했던 PR이 2건 이하이고, 각 건은 누락된 계약 조항 이름을 PR 본문에 남긴다. (≤2 = 임의 초기값, 파일럿 실측으로 대체. 측정: 소유자가 라벨로 집계.) lint·타입 검사가 자동 충족할 수 없는 지표다.
2. **(측정)** `packages/ui` + react-hook-form + 라우터 스텁만 설치된 **픽스처 앱**에서 예시 코퍼스 파일이 **수정 라인 0**으로 `tsc` + 계약 테스트 전부 통과. 픽스처가 제공하는 것은 §시작점의 픽스처 목록과 동일: `useForm()`(→ `form`), `Link` 스텁, 더미 `teams`/`teamId`/`setTeamId`/`saving`/`remove`. 그 밖의 앱 코드는 없다. (단계 1에서 예시의 `errors` 접근 경로를 설치 버전에 맞춰 동결한 뒤부터 이 기준이 판정 가능해진다.)
3. **(측정)** 조항 표의 테스트 id 빈칸 0, 그리고 잠김 표에서 **판정자가 기계인 항목**(공개 타입/`.d.ts` diff, a11y 스냅샷, lint 규칙 diff)을 바꾼 PR 중 major 표기 누락 0 — 둘 다 CI가 판정. **리뷰 판정 항목**(주입 사실, `variant`의 의미, accessible name의 출처 prop)은 CI 범위 밖이며 판정자는 소유자 리뷰다: 릴리스 노트에 판정 근거를 남기지 않은 major/minor 결정은 소유자가 반려한다.
4. **(측정)** 라이브러리를 처음 쓰는 개발자가 예시 코퍼스만 보고 설정 폼 화면을 완성 — 공용 채널 질문 0건(0건 = 임의 초기값, 첫 온보딩 실측으로 대체. 질문 수를 센다).
5. **(기준선)** 이스케이프 해치(`unsafeStyle`) 사용 건수 / 100 콜사이트 — 목표치 없음. 기준선만 기록하고 2회 측정 후 목표를 세운다.

## 프레임 이탈 / 관성 회귀

- **시작점의 10줄은 아직 내 추측이다.** `form.register` 스프레드와 Field 주입은 흔한 관행에서 끌어온 것이고 인용 칸은 비어 있다. 프레임의 1번 부품을 절차(단계 0 게이트)로 만족시킨 것은 규정된 대응이지만, 이 문서를 읽는 시점에 계약의 근거는 없다. 리뷰어라면 여기를 먼저 친다. 실제로 1행의 `form.errors`는 react-hook-form v7의 실제 경로(`formState.errors`)와 다르다 — 가설이 실물과 어긋나는 지점을 픽스처 목록에 적어 두었다.
- 단계 번호가 오름차순으로 읽히지만 실제 하중이 걸린 순서는 2→3 하나다. 0은 독립, 5는 1과 병행이라고 적었어도 4가 3 뒤일 수밖에 없어 결국 절반은 연대기다.
- 파일럿 3화면 + 배치 1·2·3은 조직 소화를 위한 안전한 기본값이다. 구조적 답은 오버라이드 경계와 잠김/자유 표인데 문서의 무게중심은 점진 도입 쪽으로 기울었다.
- 접근성 조항은 `contract/focus-order`·`contract/keyboard-nav`로 이름은 붙였으나(초안에서는 이름 없이 산문으로만 있었다), 대상 컴포넌트 목록이 실사 전이라 통과 조건의 범위는 단계 1에서 확정된다 — 이름은 있고 판정 범위는 아직 없다.
- 벤더 헤드리스를 "내부 구현으로는 채택"이라고 처리한 것은 관행 선택이다. 자유 층이므로 내 표와는 일관되지만, 실제로는 벤더 API가 우리 prop 이름을 끌어당길 것이고 이 문서에는 그 인력을 막는 장치가 없다.
- 20% / ≤2 / 80% / +10KB / 소비 팀 4개 / 질문 0건은 전부 임의 초기값이며 태그를 붙였다. 태그는 근거가 아니다.
