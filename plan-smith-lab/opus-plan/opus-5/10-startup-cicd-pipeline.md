# 스타트업 초기 CI/CD 파이프라인 구축
- 추론 프레임: dialectic
- 한 줄 요약: 소급이 불가능한 것만 지금 만들고, 나머지는 숫자로 된 재판정 트리거에 넘긴다.

## 프레임이 요구하는 시작점 — 판정 전에 판정 함수를 고정한다

반사적으로 쓰려던 것은 "1단계 테스트 / 2단계 자동배포 / 3단계 스테이징"이라는 도입 로드맵이었다. 프레임은 그것을 금지한다 — 쟁점마다 승패를 내라고, 그리고 **어떤 판정보다 먼저** 두 사람이 독립 채점해도 같은 답이 나오는 함수를 고정하라고 요구한다. 그래서 이 문서의 첫 산출물은 파이프라인 그림이 아니라 채점표다.

**판정 함수: 소급난이도 R을 먼저 보고, 같은 R 안에서만 순유지비용 W를 본다.** 사전편찬식이며 R이 W를 지배한다(W는 R2 이슈만 가른다). 이 선언이 없으면 두 번째 채점자가 내 판정을 재현할 수 없다.

- **R3** — 지금 안 하면 *그 기간의 것*을 나중에 만들 수 없다. (히스토리에 들어간 자격증명, 잘못 움직인 돈, 남지 않은 배포 아티팩트, 기록 안 된 운영 접근)
- **R2** — 나중에 새 산출물에만 적용 가능, 과거는 방치 가능. (테스트, IaC, 린트)
- **R1** — 도입 시점과 총비용이 무관. (스테이징 복제, 카나리, 빌드 캐시)
- **W** = 주당 유지 시간 − 그것이 없애는 주당 수동 작업 시간. 음수면 지금, 양수면 나중. 두 항 다 1주차 실측 가능(파이프라인 담당 1명이 수기 기록: 배포 1회 실측 × 주간 배포 횟수).

판정 규칙: R3 → 지금파 승(W 무관). R1 → 후회파 승. R2 → W의 부호.
타이브레이크(채점 불일치 또는 W ≈ 0): **되돌림 비대칭** — 과하게 만든 것은 삭제로 되돌아오지만 만들지 않은 기간은 되돌아오지 않는다 → 지금파. 이슈당 1회만.
분할 탐지: 양 진영이 서로 다른 하위 대상에서 각자 정당하게 이기면 이슈가 잘못 묶인 것이다 — 판정 말고 쪼갠다.

## 문제 정의 / 목표

3~6명 팀이 검증 안 된 제품을 주 1회 이상 배포한다. 목표는 좋은 파이프라인이 아니라 **12주 뒤 되돌릴 수 없는 상태가 되지 않는 최소 구조**다. 파이프라인 자체가 유지 대상이라는 사실을 비용에 계상한다.

## 명시적 가정

- **이 팀은 이미 되돌릴 수 없는 것을 다룬다 — 돈 이동, 고객 데이터, 외부 자격증명 중 최소 하나.** 틀리면 R3 항목이 사라져 판정이 전부 후회파로 기울고 이 플랜의 절반이 과잉이 된다. 가장 싼 조기 검증: 결제·인증·개인정보 저장 지점을 한 번 훑는다(30분, S0 포함). 폴백: R3가 0건이면 S1·S4·S6을 보류하고 S2+S3만 실행.
- 관리형 CI 러너 사용 가능. 틀리면 W가 2~3배로 커져 R2 판정 다수가 후회파로 뒤집힌다.
- 채점자 2명 이상. 틀리면 함수가 자기 확인이 되고 논쟁이 연극이 된다 → 외부 엔지니어에게 R 채점만 위임.
- 4주 안에 제품이 죽지 않는다. 틀리면 S2 외 전부 보류.

## 쟁점별 논쟁과 판정

### A — 지금 파이프라인을 만드나, 손으로 버티나
- 지금 필요파: "손 배포는 배포 빈도를 떨어뜨린다. 배포 단위가 커지면 사고 때 원인 후보가 20개가 된다."
- 나중에 후회파: "3명이 YAML 디버깅에 주 3시간 쓴다. 제품이 안 팔리면 그 3시간은 전액 손실이다."
- 채점: R2. W 부호가 범위에 따라 갈린다 — 최소형(푸시 → 빌드 → SHA 태그 아티팩트 → 1명령 배포)은 수동 절차 약 15분 × 주 5회를 없애 음수, 전체형(스테이징+카나리+매트릭스)은 유지가 절약을 넘어 양수.
- **판정: 최소형 지금파 승, 전체형 후회파 승.** 범위 축소는 취향이 아니라 W의 부호가 바뀌는 지점이다.
- 패자 논거 승격 → 제약: 유지 시간을 매주 W 표에 기록한다. CI 설정은 스크립트로 분리하고 YAML은 호출만(디버깅 대상 축소).
- 재판정 트리거: 유지 시간 4주 이동평균 > 절약 시간이면 A를 다시 판정. (4주 = 재판정 주기, 임의값 — 런웨이 대비 짧게 잡음)

### B — 테스트를 CI 게이트로 지금 세우나 (분할된 이슈)
- 지금 필요파: "결제·권한이 조용히 깨지면 돈과 신뢰는 되돌아오지 않는다."
- 나중에 후회파: "주마다 바뀌는 화면에 테스트를 붙이면 코드가 아니라 테스트를 리팩터링하며 산다."
- 분할 탐지 발동 — 두 주장이 각자 다른 대상에서 옳다. 판정 전에 쪼갠다.
  - **B1 돈·권한 경로**(과금·환불·권한 상승): R3 → 지금파 승. 케이스 수는 임의값이 아니라 *돈이 움직이는 엔드포인트 전수*로 정의(현재 추정 4~6개).
  - **B2 그 외 기능·UI**: R2, W 양수 → **후회파 승.** 게이트 목록에서 빠진다.
- 패자 논거 승격 → 제약: B1 테스트도 소모품이다 — 스펙이 바뀌면 고치지 않고 삭제할 수 있다(삭제 시 B1 목록에서도 지운다). 게이트 대기 시간은 W의 유지 항목으로 계상하고, 늘어나면 케이스를 줄이는 대신 병렬 실행을 손본다.
- 재판정 트리거: 같은 경로에서 동일 버그 2회 재발 → 그 경로에 회귀 테스트 1개 강제. B2 판정을 뒤집는 유일한 경로다.

### C — 시크릿과 자격증명 분리
- 지금 필요파: "시크릿이 히스토리에 한 번 들어가면 로테이션·히스토리 정리·노출 기간 감사가 필요하고, 외부 유출 여부는 영원히 알 수 없다."
- 나중에 후회파: "볼트 운영은 3명 팀에 과하다. 지금은 환경변수로 충분하다."
- 채점: R3 → **지금파 승, W 무관.** 단 승리 형태는 최소형이다: 저장소에 시크릿을 넣지 않기 + CI 시크릿 스토어 + 운영/개발 자격증명 분리. 볼트는 R2이므로 도입하지 않는다.
- 패자 논거 승격 → 제약: 시크릿 항목은 목록 파일 1개로만 관리하고, 추가는 그 파일 수정과 같은 PR에서만(운영 부담을 구조 하나로 고정).
- 재판정 트리거: 팀 6명 초과 또는 고객 데이터 자체 보관 시작 → 단기 자격증명(OIDC) 재판정.

### D — 롤백 가능성: 불변 아티팩트와 태그
- 지금 필요파: "롤백이 'revert 후 재빌드'면 장애 중 5분이 30분이 된다. 게다가 지난주 아티팩트는 지금 만들어둘 수밖에 없다."
- 나중에 후회파: "블루/그린과 카나리는 지금 인프라 비용과 복잡도다."
- 채점: 두 항목의 R이 다르다 — 아티팩트 불변성·태깅 R3, 카나리·블루그린 R1. → **태깅은 지금파 승, 배포 전략 고도화는 후회파 승.**
- 패자 논거 승격 → 제약: 롤백은 별도 스크립트가 아니라 *배포와 같은 명령에 이전 태그를 넣는 것*이다. 복잡도 논거를 "경로를 늘리지 않는다"는 규칙으로 승격.
- 재판정 트리거: 롤백 리허설 3회 중 1회라도 실패 → 배포 전략 재판정. (표본 3 = 리허설 부담에서 정한 임의값)

### 나머지 쟁점 일괄 판정

| 쟁점 | 채점 | 판정 | 패자 논거 → 제약 | 재판정 트리거 |
|---|---|---|---|---|
| DB 마이그레이션 | R3(스키마는 코드와 함께 롤백되지 않는다) | 지금파 — 파괴적 DDL은 배포와 같은 커밋에 넣지 않는다 | "매번 두 배 일"을 피하려 삭제 예정 컬럼은 대기열에 모아 격주 일괄 처리 | 스키마 변경 포함 롤백 리허설 실패 시 |
| 오류 수집 + 배포 마커 | R3(수집 안 켠 기간의 데이터는 존재하지 않는다) | 지금파 — 수집기와 배포 마커만. 대시보드·SLO는 R1이라 나중 | 알림은 하루 1건 이하 유지, 초과 시 규칙 삭제(임의값, 2주 실측 후 교체 — 측정자: 온콜 담당) | 사고 인지가 3회 중 2회 "고객 제보"였을 때 |
| 스테이징 환경 복제 | R1 | **후회파** — 내 반사는 "지금"이었고 R1 규칙이 뒤집었다 | 대신 데이터 마이그레이션은 읽기 전용 사본에서 1회 예행 | 고객 데이터 이동 변경이 월 1건 이상 |
| IaC | R2, W 양수 | 후회파 | 손으로 만든 리소스는 목록 파일에 기록(나중 임포트 비용을 유한하게) | 환경이 2개 초과 |
| 운영 접근 권한 | R3(접근 로그는 소급 생성 불가) | 지금파 — 운영 배포 권한은 CI에게만, 사람 자격증명 제거 | 긴급 우회 경로 1개는 남기되 사용 시 자동 기록 | 우회 경로 월 2회 이상 사용 |
| 브랜치 전략 | R1, W ≈ 0 | 타이브레이크로 지금파 — trunk + 짧은 브랜치 | 규칙은 문서 1줄까지만 | 팀 6명 초과 |

## 접근 및 단계

- **S0 (독립).** 2인 독립 채점: 각자 R/W를 적고 불일치 이슈만 재논의한 뒤 채점표를 파일로 고정. 가정 검증(결제·인증·개인정보 지점 훑기) 포함. 검증: 불일치 이슈 수 기록(0이면 "자명해서 함수가 불필요했다"는 뜻이며 그것도 기록 대상).
- **S1 (S0 소비 · S2의 선행).** 시크릿 회수: 히스토리 전체 스캔 → 노출 자격증명 로테이션. 파이프라인이 생기면 시크릿 사용처가 늘기 때문에 먼저 한다. 검증: 스캔 0건 + 로테이션 완료 목록. 집행: C.
- **S2 (S1 소비).** 최소 파이프라인. 검증: 같은 SHA로 두 번 배포해 산출물 동일(재현성). 집행: A, D.
- **S3 (S2 소비).** 롤백 경로 = 이전 태그 배포. 검증: 운영에 실제로 1회 롤백하고 소요 시간 기록. 집행: D.
- **S4 (S2와 병렬).** 돈·권한 스모크 게이트. 검증: 결제 성공 경로를 의도적으로 깨서 파이프라인이 막는지 확인(깨는 사람은 게이트 제작자가 아니다). 집행: B1.
- **S5 (S2 소비 후 상시).** 오류 수집기 + 배포 마커. 검증: 의도적 예외 1건 → 알림 도달 시간 기록.
- **S6 (S3 소비).** 마이그레이션 규율. 검증: 스키마 변경 포함 상태에서 롤백 리허설 통과.
- **S7 (S2 착수 시점부터 4주 주기 상시 병렬).** 재판정 회의: W 표와 트리거 실측치를 읽고 판정 갱신. 검증: 트리거 표 전 행에 숫자가 있다.

## 대안과 기각 사유

1. **PaaS의 git-push 배포만 쓰고 파이프라인을 만들지 않는다.** 기각: 아티팩트 불변성과 롤백은 얻지만 돈 경로 게이트와 마이그레이션 규율(둘 다 R3)은 얻지 못한다. 부활 조건: 백엔드 상태를 팀이 소유하지 않게 되면(관리형 DB + 마이그레이션 위임) 이 대안이 우세.
2. **승인 없는 완전 자동 CD.** 기각: 사고 인지 경로(S5)와 롤백 신뢰도(S3)가 검증되기 전에는 속도 이득이 인지 지연 비용에 잠식된다. 부활 조건: 롤백 리허설 3/3 성공 + 사고 인지 중위 시간이 정상 배포 시간 이하로 2주 연속.
3. **커버리지 목표치를 게이트로 세운다.** 기각: R2이고 무엇도 구조적으로 막지 못한다(커버리지는 돈 경로를 지목하지 않는다). 부활 조건: 계약·감사에서 수치가 요구될 때.

## 리스크 & 완화

- **파이프라인 우회(로컬에서 직접 운영 배포).** 문장으로 못 막는다 → 사람 자격증명 제거로 구조로 막고, 우회 경로 1개만 남겨 사용 시 자동 기록.
- **판정 함수가 사후 정당화 도구가 된다.** → S0에서 채점을 판정 전에 파일로 고정, 이후 수정은 S7 회의에서만.
- **트리거 숫자를 아무도 읽지 않는다.** → 트리거 표에 측정자 이름 칸 + S7을 주기 항목으로.
- **버스 팩터 1.** → 롤백 리허설을 제작자가 아닌 사람이 수행하도록 검증에 내장.
- **벤더 요금·종속.** → 무료 티어 초과 청구 알림, CI 설정을 스크립트로 분리(이전 비용 축소).

**누락 범주 점검 스윕** — 아예 언급하지 않은 범주: 백업·복구 리허설(롤백과 인접하나 별 계열 — 범위 밖으로 선언하고 고객 데이터 자체 보관을 진입 트리거로), 의존성 취약점 스캔(R2 → 나중, 단 lockfile 커밋은 지금), 온보딩 문서(S3·S4 검증이 사실상 대체), 모바일 배포·다중 리전(해당 없음), 계약상 SLA(현재 없음 — 생기면 관측성 판정이 R3로 승격).

## "완료"의 판정 기준

1. **파이프라인을 만들지 않은 팀원 1명이 지난 2주 중 지정된 임의 커밋 SHA를 운영에 배포하고 직전 버전으로 되돌린다. 판정: 복귀 소요 시간 ≤ 같은 날 실측한 정상 배포 소요 시간.** 파생 근거 — 롤백이 배포보다 비싸면 장애 중에 아무도 롤백하지 않는다.
2. 결제 성공 경로를 의도적으로 깨서 푸시하면 파이프라인이 배포를 차단하고 알림이 도달한다(1회 실측). 게이트가 스스로 충족할 수 없는 검증이다.
3. 히스토리 전체 시크릿 스캔 0건 + 로테이션 완료 목록 파일 존재.
4. 4주 뒤 표에 실측 숫자 3개 존재: 주간 배포 횟수, 주간 유지 시간, 사고 인지 중위 시간. 값의 크기는 조건이 아니다 — 원지표가 없으면 재판정 트리거가 작동할 수 없으므로 존재 자체가 조건이다.
5. 재판정 트리거 표 전 행에 현재 실측치와 측정자 이름이 있다.

## 프레임 이탈 / 관성 회귀

- **W축은 실측 가능하게 정의됐지만 쟁점 A의 판정은 실측 전 추정치(15분 × 주 5회) 위에 서 있다.** 부호가 반대로 나오면 A가 뒤집히고 S2가 근거를 잃는다. S0에 실측을 넣었어도 문서 순서상 판정이 측정을 앞선 사실은 남는다.
- **판정 13건 중 6건이 R3 라벨로 지금파에 갔다.** 함수의 결과일 수도, "일단 최소형으로 시작하기"라는 내 안전 기본값이 R3라는 이름을 얻은 것일 수도 있다. 구분법은 제3자가 각 R3 근거가 정말 "그 기간의 것을 못 만든다"를 만족하는지 재채점하는 것뿐이다(S0가 그 역할이지만 나는 이미 판정을 알고 있다).
- **패자 논거 승격 2건이 제약이 아니라 규칙 추가로 변질됐다** — C의 시크릿 목록 파일과 마이그레이션의 격주 일괄 처리는 승자를 묶기보다 실행자에게 일을 더한다. 형식은 갖췄고 방향은 뒤집혔다.
- 리뷰어라면 나는 **잔여 쟁점 표**를 친다. 대화를 생략해 최강 논거가 판정 칸으로 압축됐고, 브랜치 전략 행은 타이브레이크로 통과해 실질 논쟁이 없다.
