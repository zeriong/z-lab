# 대형 프로모션 당일 트래픽 폭주 대응 런북
- 추론 프레임: triage / 스타일: opus
- 한 줄 요약: 90초 분류 뒤 되돌릴 수 있는 유입 제어를 기본 경로로 고정하고, 캐시 전체 퍼지와 무분별 스케일아웃은 문장이 아니라 권한·설정으로 막는다.

## 1. 프레임이 요구하는 시작점 — 시간 계층과 초저가 분류

반사적 습관은 "원인부터 찾는다"다. 관측→가설→조치는 평시의 정답이고 프로모 3분 뒤에는 사치다. 배치 축은 원인이 아니라 **쓸 수 있는 시간**: **즉시(0~5분 = 이하 "즉시 계층 예산" 300초, 판단 불필요)** / **30분(전부 게이트)** / **사후(포인터, 상한 3건)**. 이 문서에서 90초는 항상 **T0 분류 상한**을, 300초(5분)는 항상 **즉시 계층 예산**을 뜻한다 — 두 예산을 섞어 쓰지 않는다.

**T0 분류 — T0 분류 상한 90초, 지표 3줄 한 화면**

| 읽는 것 | A 용량 포화 | B 의존 정지 | C 변경 유발 |
|---|---|---|---|
| 앱 CPU·스레드 | CPU 높고 스레드 소진 | CPU 낮고 스레드 대기 | 무관 |
| 오류 분포 | 전 경로 균등 지연 | 특정 다운스트림 타임아웃 | 특정 경로·버전 |
| 최근 변경(창 30분) | 없음 | 없음 | 배포·플래그·설정 있음 |

- 3줄 중 2줄이 한 열이면 그 열, 아니면 **D(판별 불가)**.
- **T0 분류 상한 90초 만료도 유효한 분류다 → D 확정, 기본 경로로 간다.** 더 보는 것은 선택지가 아니다.
- T0 분류 상한 90초 도출(가정 2 종속): 집계 지연 30초 × 관측 2점 + 판독 30초. 변경 창 30분은 임시값 — **D-3 리허설에서 배포 전파 시간 실측으로 교체, 측정자 릴리스 담당.**
- 기본 경로 = **엣지 유입 제어 1단**. 근거는 되돌릴 수 있음 — 토글로 원복되고 피해가 대기 사용자 수로 계량된다. 알면서 태우는 비용: 대기 이탈에 따른 전환 손실, 재고 소진 지연. 스케일아웃·퍼지·롤백은 이 시험에 탈락한다.
- **오분류 회복 장치**: G1이 한 번은 반드시 재분류를 판정한다 — 라벨 무관 관측 기반이며 D·C 진입 시의 트리거를 따로 둔다(§5 G1·G1a·G1b).

**정렬 규칙 — 안정화는 증거를 지운다.** 사라지는 속도 × 되돌릴 수 없음 순. 인스턴스 로컬 상태(스레드 덤프·커넥션·in-flight)가 가장 먼저 사라지므로 조치와 **동시에** 자동 캡처한다(사람 시간 0). 되돌릴 수 없는 조치는 전부 게이트 뒤다.

## 2. 문제 정의 / 목표

무중단이 목표가 아니다. (a) 부분 지연을 전면 장애로 승격시키지 않기, (b) 증거 남기기, (c) 여유 없는 당번이 문서만으로 다음 한 수를 알기. 성공은 GMV가 아니라 "되돌릴 수 없는 수를 게이트 없이 두지 않았음"이다.

## 3. 명시적 가정

1. **엣지에서 경로별·비율별 유입 제어를 90초 내에 켜고 끌 수 있다.** 기본 경로 전체가 걸린다. 틀리면 D 분기가 공백이 되고 손이 금지 조치로 간다. 최저가 검증: D-3 리허설 발화·원복(§8). 대체 경로: 미들웨어 비율 차단을 프로모 전 배포에 심고, 없으면 LB 가중치로 정적 대기 사이트 전환.
2. 집계 지연 ≤30초. 틀리면 T0 분류 상한 90초 무효 → (실측 지연 × 2 + 30초) 재도출.
3. 트래픽이 소수 URL(상세·장바구니·주문)에 집중. 틀리면 경로별 감속 무력 → 전역 비율 감속.
4. 당일 DB 확장·리플리카 추가 불가. 틀리면 옵션이 늘지만 승격은 게이트 뒤.
5. 결정권자 5분 내 응답. 틀리면 G5 위임 규칙이 발동한다.

## 4. 즉시 계층 (0~5분 = 즉시 계층 예산 300초, 판단 불필요)

| # | 조치 | 발화 조건 | 부작용 | 효과 확인 |
|---|---|---|---|---|
| I1 | 스냅샷 번들 1커맨드 | 경보 즉시, 무조건 | 대상에 수초 부하 → 2대만(도출: 2개면 한 대 특이현상 구분) | 번들 생성 |
| I2 | 지휘 선언(지휘관·대리·기록자) | 경보 즉시, I1과 동시 | 없음(사전 배정표) | 이름 3개 게시 |
| I3 | **기본 경로**: 유입 제어 1단(전환 20%) | D, A, 또는 T0 분류 상한 만료 | 대기 이탈로 전환 손실, 재고 소진 지연 | 오리진 요청 감소 |
| I4 | 회로 차단기 강제 개방 + 축퇴 응답 | B 확정 | 그 기능(추천·리뷰) 비활성 노출 | 스레드 대기 감소 |
| I5 | 30분 내 변경 플래그 되돌리기(롤백 아님) | C 확정 & 후보가 플래그 | 그 플래그 의존 기능 정지 | 해당 경로 오류율 하락 |

I3의 20%는 **임시값, D-3 리허설로 교체** — 확정값은 "오리진 요청 감소가 관측되는 최소 비율", 측정자는 당번 SRE.

**거절 방식은 규정이다.** 429/503을 반환하지 않는다 — 모바일 SDK·브라우저 재시도가 증폭한다. CDN에 캐시된 **정적 대기 페이지를 200으로** 준다. 부작용이 "오류가 아니라 대기 화면"으로 한정되고 오리진 요청 감소가 즉시 관측된다.

## 5. 30분 계층 (전부 게이트)

| 게이트 | 내용 | 부작용 |
|---|---|---|
| **G1 재분류(필수)** | I3 후 **라벨과 무관하게 관측으로만** 판정한다. ① 오리진 요청 감소 관측 + p99 미회복 → B로 재분류(다운스트림 타임아웃 지표가 확인되면 I4) ② 오류가 특정 경로·버전에 편중 → C로 재분류(I5) ③ 둘 다 아니면 D 유지 + 유입 제어 단계 상향. 기준: 리허설 실측 "발화→효과 지연" × 2 (그 전 임시값 120초, 측정자 당번 SRE) | 재분류 동안 유입 제어 유지 |
| **G1a D 진입 트리거** | T0 분류 상한 만료로 D 확정→I3인 경로(가장 흔한 경로)에서는 기준 시간 경과 시 G1의 ①②③을 그대로 적용하고, ③이 두 번 연속이면 G2·G3를 게이트 큐에 올린다 | 판단 지연 |
| **G1b C 진입 트리거** | C 확정→I5 후 해당 경로 오류율이 하락하지 않으면 = C 오분류 → G1 ①③으로 재배정(되돌린 플래그는 원복 상태 유지) | 그 플래그 의존 기능 정지 지속 |
| **G2 스케일 스텝** | `ASG max = (DB 커넥션 예산 − 배치·관리 예약) / 인스턴스당 풀 크기`를 프로모 전 계산해 설정 고정, 당일 상한 내 1스텝 | 콜드 캐시가 오리진·DB 부하 일시 상승 → 워밍 후 LB 편입 |
| **G3 읽기 축퇴** | 개인화·추천·실시간 재고 문구 off, 상품 카드는 사전 계산 캐시 | 재고 표시 부정확 → 초과판매 방지선은 주문 API 검증에 남긴다 |
| **G4 롤백(2인 확인)** | C 확정 & I5 무효일 때만 | 프로모 페이지가 그 배포에 있으면 프로모가 사라진다 → 배포 범위 확인 선행 |
| **G5 축소·연장** | 지휘관은 제안, 결정은 사전 지정 결정권자. **5분 무응답 시 기본값 = 축소 없이 유입 제어 단계만 상향**(5분 = 즉시 계층 예산 종료 시점) | 상향분의 전환 손실 |
| **G6 고지** | 기록자가 상태·대기 페이지 문구 갱신, 원인 추정 금지. 간격 10분은 임의값(문의 유입 간격 실측으로 교체) | 문구가 원인으로 인용될 위험 |

G1a·G1b는 G1의 하위 트리거이며 별도 게이트로 세지 않는다(게이트 수는 6).

## 6. 금지 조치

**① 캐시 전체 퍼지**
- 유혹: "재고·가격 표시가 틀렸다. 캐시가 오래됐다. 퍼지가 한 방이다."
- 비용: 히트율 0에서 오리진 동시 폭주. 재구축 중 DB 커넥션 고갈로 부분 지연이 전면 장애로 승격하고, 회복 시간이 캐시 워밍 속도에 종속된다.
- 대체: 프리픽스 단위 무효화 + 만료값 제공하며 뒤에서 갱신, 정확도 필요한 값만 실시간 엔드포인트로 분리.
- 집행: 프로모 기간 퍼지 토큰 회수, 2인 확인 콘솔만. 금지 목록은 **지시할 수 있는 사람 전원**(마케팅 리드·CTO·CDN 벤더)에게 D-1 배포 — 실행자만 알면 지시가 들어온다.

**② 무분별 스케일아웃**
- 유혹: "인스턴스를 늘리면 대기가 풀린다. 돈으로 사는 해결이다."
- 비용: 커넥션 = 인스턴스 × 풀 크기. 포화된 DB에 더 꽂으면 앱은 살고 DB가 죽는다. 콜드 인스턴스는 캐시 미스로 오리진 부하를 더 올린다.
- 대체: G2의 상한 내 1스텝. 집행: ASG max를 계산값으로 프로모 전 고정 — "무분별"이 설정상 불가능해진다.

| 나머지 금지 | 유혹 | 비용 | 대체 | 집행 |
|---|---|---|---|---|
| 즉시 롤백 | "배포 탓이겠지" | C 미확정이면 되돌릴 수 없는 시간 손실 | G4 | 2인 확인 |
| 조용한 중단 | "트래픽을 끄면 끝난다" | 신뢰·법무·마케팅 비용 | G5 | 결정권자 |
| 순차 재시작 | "재시작하면 풀린다" | 증거 소멸 + 잔존 인스턴스로 부하 이전 | I1 후 G2 | 없음(문장) |
| 타임아웃 상향 | "끊기지만 않으면" | 큐 적재·재시도 증폭 | 타임아웃 하향 + I4 | 없음(문장) |

뒤 두 항목은 권한·설정 집행이 없다. 문장은 압박받은 뇌를 막지 못하므로 **막힌 것으로 계산하지 않는다**(§11 제외).

## 7. 사후 계층 (포인터만)

상한 3건 — 근거: 다음 프로모 D-7 게이트까지 SRE 1명이 대응 외 시간으로 완료 가능한 수 추정(임시값 — **첫 사후 리포트 시 실제 소요 시간으로 교체, 측정자 당번 SRE**). 초과분은 별도 백로그로.

1. 증거 번들 첨부 사후 리포트 — 기한은 로그 보존 기간에 종속. 정책 미확인 상태의 숫자는 허위 근거이므로 **의도적 빈칸**이고, 정책 확인이 이 항목의 첫 작업이다.
2. ASG max·유입 제어 비율·G1 기준을 당일 실측으로 교체.
3. 금지 목록 갱신 + 거부 로그 검토(집행 없는 2종의 집행 수단 포함).

## 8. 사전 준비 자산 (D-7 ~ D-1)

런타임 계층은 사전 자산을 전제한다. **없는 자산에 의존하는 조치는 런북에서 삭제한다** — 있는 척이 가장 위험하다.

유입 제어 토글(단계값은 리허설로 확정) · CDN 정적 대기 페이지 · 축퇴 플래그 · 스냅샷 번들 · 3지표 단일 대시보드 · ASG max 계산값 · DB 커넥션 예산표 · 회로 차단기 강제 개방 스위치 · 로그인 사용자 우선 큐 · 사전 배정표(지휘관/대리/기록자/결정권자) · CDN·결제 벤더 연락처 · 금지 목록 배포 확인. (12종)

리허설(D-3): 가정 1을 검증하며 실측 두 값 — ① 오리진 요청 감소가 관측되는 최소 전환 비율(I3 교체) ② 발화→감소 관측까지의 초(G1 기준값).

## 9. 대안과 기각 사유

- **상시 3배 과다 프로비저닝**: 비용이 크고 병목이 DB·결제면 무효. 부활: 리허설에서 **발화→효과 지연이 150초를 초과**로 측정되면 사전 프로비저닝으로 대체. 150초 도출 = 즉시 계층 예산 300초 − T0 분류 상한 90초 − 조치 실행 여유 60초(**여유 60초는 임의값**, D-3 리허설에서 발화 커맨드 실행·전파 실측으로 교체, 측정자 당번 SRE). 즉 T0 분류 상한 90초가 아니라 즉시 계층 예산에 대는 기준이다.
- **당일 전면 정적화 + 주문 큐잉**: 재고 정확도·개인화를 잃고 리드타임이 D-7을 넘는다. 부활: 최근 2회 프로모에서 G3가 모두 발화했다면 상시 구조로 승격.
- **오토스케일 전면 신뢰(사람 없는 런북)**: 원인 무관 증폭기다 — B에서 커넥션을 더 꽂는다. 부활: DB 커넥션이 병목에서 제거되어 ASG max 계산이 불필요해질 때.

## 10. 리스크와 완화

| 리스크 | 완화 |
|---|---|
| 재시도 증폭 | 기본 경로를 정적 200 대기 페이지로 고정(§4) |
| 대기열 자체가 병목 | 대기 페이지는 CDN 정적, 오리진 무의존 |
| 봇·스캘퍼가 대기열 통과 우위 | 로그인·기존 고객 우선 큐 |
| 관측 도구 동반 과부하 | 대시보드를 별 경로·별 계정, 실패 시 LB 5xx 카운터로 판독 |
| 지휘권 충돌(마케팅 vs 엔지니어링) | G5의 제안·결정 분리 + 금지 목록 사전 배포 |
| 결제 파트너 rate limit | 축퇴 모드에 결제 재시도 간격 상향, 연락처 확보 |
| 오분류 고착 | G1 필수 통과 + D·C 진입 트리거(G1a·G1b) |

## 11. "완료"의 판정 기준

**리허설(조용한 날에도 판정 가능)**
- "D-3, 사전에 지정하지 않은 당번 1명이 이 문서만으로 유입 제어 1단을 발화하고 되돌린다 — 외부 질문 0건, 즉흥 판단 0건. 최소 전환 비율과 발화→감소 관측 초를 기록해 I3·G1에 기입한다."(판정문 형식은 checklist 프레임 차용)
- 자산 12종 각각에 존재 증거(커맨드 출력·스크린샷). 체크마크는 통과로 인정하지 않는다.

**당일**
- T0 분류 시각과 첫 조치 시각이 타임스탬프로 남고 차이가 T0 분류 상한 90초 이하.
- 집행 있는 금지 4종(퍼지 / ASG max 초과 스케일 / 즉시 롤백 / 조용한 중단)의 시도·거부 로그가 남는다. **거부 로그 0건은 무결이 아니라 기록 실패로 본다** — 압박 상태에서 지시 시도는 반드시 발생한다(해석 규칙은 min-diff 프레임 차용). 집행 없는 2종은 로그가 없어 판정 대상이 아니다.
- "금지 조치 0건 실행"은 권한 잠금이 매체를 없애 자동 충족되므로 쓰지 않는다.

## 프레임 이탈 / 관성 회귀

- §5가 게이트 6개로 커져 무게 중심이 중간 계층으로 밀렸다. 꼬리(§7)를 3건으로 묶은 대가이며, 실패 모드를 꼬리에서만 막은 셈이다.
- §6 표 뒤 두 금지에 집행 장치를 못 붙였다. 대체 지정에서 멈췄으니 "구조로 집행" 요구는 두 항목에 미충족이다.
- §7-1의 기한은 빈칸이다. 보존 7일을 가정해 채우려 했으나 근거 없는 숫자보다 빈칸을 택했다. 정당화했어도 결함이다.
- §8의 12종 중 회로 차단기 강제 개방과 우선 큐가 리허설에서 빠졌다. 검증이 유입 제어 하나에 몰려 있다 — 리뷰어라면 여기를 친다.
- §4의 I1~I5는 우선순위인데 I1·I2는 동시다. "동시"라 적고도 번호를 나눈 것은 사다리 습관이다.
