# 셀프호스팅 URL 단축 서비스 — 벽 안에서만 짓기
- 추론 프레임: constraint-first / 스타일: opus
- 한 줄 요약: 단일 $5 서버로는 무중단이 논리적으로 불가능하므로, 링크 해석을 "살아 있는 서버"가 아니라 "발행된 정적 아티팩트"로 옮기고, 서버는 죽어도 사용자에게 보이지 않는 컴파일러로 축소한다.

## 프레임이 요구하는 시작점 — 벽 세우기와 모순 판정

### 벽
- **벽1 예산**: 월 $5, 서버 1대.
- **벽2 인력**: 운영자 1인.
- **벽3 가용성**: 다운타임 허용 불가.
- **벽4 (숨은 벽 — 요구사항에 묻혀 있음)**: "단축" 서비스는 도메인 자체가 짧아야 값이 있다는 전제.
- **벽5 (숨은 벽)**: 단축 링크는 배포되면 회수 불가하다. 이 서비스에는 "종료" 출구가 없다.

### 각 벽이 실제로 무는 차원
- 벽1은 총액이 아니라 **분배**로 문다. VPS·도메인·백업·감시가 같은 $5를 나눈다. VPS $4를 쓰면 잔여는 월 $1 → 도메인 연 $12 이하, 백업·감시는 $0이어야 한다. (도출: $5 − $4 = $1/월 × 12)
- 벽2는 총 노동시간이 아니라 **대응 지연**으로 문다. 1인은 잠들고 여행한다. 수 분 내 수동 개입을 전제한 부품은 전부 벽 밖이다.
- 벽3은 **표면별로** 다르게 문다. 표면은 셋 — 링크 해석 / 링크 생성·차단 / 클릭 통계. 분리하지 않으면 판정 자체가 불가능하다.
- 벽4는 가격으로, 벽5는 시간(연 단위 갱신 의무)으로 문다.

### 후보 목록 (예산 초과 상태로 제출 — 도입부를 budget-allocation 프레임에서 차용)
이 프레임은 법정이지 아이디어 원천이 아니므로, 벽보다 큰 피고 목록을 먼저 세운다.

| 후보 | 판정 |
|---|---|
| 관리형 Postgres / Redis | 벽1 밖 기각. 읽기 전용 매핑에 DB 서버가 필요하지 않다 |
| 실시간 클릭 대시보드 | 벽1 밖 기각 (부활 조건: 아래 A5) |
| VPS 2대 + 플로팅 IP | 벽1 밖 기각 |
| 사용자 계정·멀티테넌시·웹 관리 UI | 벽2 밖 기각. 공개 표면은 곧 지원 부하 + 공격 표면 |
| 링크 만료·비밀번호 보호 | 동적 로직 필요 → 아래 완화 칸에서 사망 |
| 온콜·페이징 | 벽2 밖. 전제 깨기 1로 **필요 자체가 소멸** |
| 블루/그린 배포 | 불필요. 아티팩트 원자적 교체가 이미 그것이다 |
| 자동 악성링크 스캔 API | 벽1 밖 기각. 신고 채널로 대체 |
| QR 이미지, 감사 로그 | 인정. 발행 시 정적 생성 + append-only 파일의 무비용 부산물 |

### 모순 판정
- **모순 A (진짜 모순)**: {서버 1대} ∩ {해석 무중단} = ∅. 단일 VPS는 호스트 점검·커널 재부팅·디스크 장애로 반드시 정지하고, 벽2가 즉시 복구를 금지한다. 소프트웨어 품질과 무관한 물리적 단일 장애점이므로 요구를 깎아서는 해소되지 않는다.
- **모순 B (진짜 모순)**: {잔여 월 $1} ∩ {벽4 짧은 도메인} = ∅. 짧은 도메인은 연 $12를 크게 넘는 가격대가 흔하다.
- **벽 밖 요구 (모순 아님, 기각으로 충분)**: 실시간 통계, 멀티테넌시, HA DB. 벽과 논리적으로 충돌하는 것이 아니라 그냥 예산·인력 밖이다. 전제 깨기 대상이 아니다.

### 구조의 전제 깨기
- **전제 깨기 1 — "링크 해석에는 내 프로세스가 살아 있어야 한다."** slug→URL 매핑은 읽기 전용·추가 전용이다. 따라서 정적 리다이렉트 규칙 **아티팩트**로 컴파일해 발행할 수 있고, 내 서버는 컴파일러·발행자로 축소된다. 서버가 죽어도 사용자에게 보이지 않는다. 무중단 요구가 사람의 대기에서 구조로 이동한다 → 모순 A 해소.
- **전제 깨기 2 — "단축 서비스는 짧은 도메인이 필요하다."** 값은 도메인 길이가 아니라 **결과 URL 전체 길이**다. 중간 길이 도메인 + 4자 slug면 20자 내외이고 목적은 달성된다. 요구를 낮춘 것이 아니라 보호 대상("붙여넣기 가능한 짧은 문자열")을 특정한 것이므로 정제다 → 모순 B 해소, 프리미엄 도메인 후보 사망.

### 정제 / 완화 (정직 공개)
| 요구 | 판정 | 내용 | 이 판정이 죽인 것 |
|---|---|---|---|
| 다운타임 0 | 정제 | 해석(제3자 클릭, 통제 불가)은 무중단 / 생성·차단(운영자, 재시도 가능)은 중단 허용 | 상시 대기·페이징 체계, 관리 평면 HA 전부 |
| 짧은 도메인 | 정제 | 짧은 *결과 URL*로 재정의 | 프리미엄 도메인 구매안 |
| 생성 즉시 반영 | **완화** | 생성 후 발행 지연(초~분) 존재 | "만들면 즉시 유효"라는 약속. 생성 응답은 접수(202)로 명시한다 |
| 링크 만료·비밀번호 | **완화** | 동적 로직 불가 → 미제공 | 기능 자체. 대체물 없음 |
| 악성 링크 즉시 차단 | **완화** | 차단도 발행 지연에 종속 | "즉시 takedown" 약속. 신고→차단 시간은 사람 지연 + 발행 지연으로 재정의 |

### 벽에 낸 구멍 (선언 — 정제가 아니다)
- **구멍1**: 정적 리다이렉트를 제공하는 외부 호스팅의 **무료 등급에 의존**한다. 이는 벽1의 확장 해석이 아니라 벽에 낸 구멍이다. 상한: 무료 등급 내부. 요청량 또는 규칙 수가 한도의 80%에 닿으면 Step 7 트리거. 유료 전환으로 월 합계가 $5를 넘으면 **재스코프 또는 계획 무효**. 발행 저장소가 오프사이트 백업을 겸하는 것도 같은 구멍이며 같은 트리거를 공유한다.
- **구멍2**: 외부 무료 프로버 1개. 상한 $0. 유료화되면 감시를 일 1회 수동 확인으로 격하한다(비용 증액 금지).
- 80%의 근거(도출): 발행 대상 교체 리허설이 최대 1일이므로, 잔여 20%가 소진되는 데 1일 이상 걸려야 한다. 링크 증가율은 Step 7이 월 1회 기록하며, 첫 3개월 실측으로 이 퍼센트를 재산출한다(수명 상한).

## 문제 정의 / 목표
내가 발행한 단축 링크가 **영구히** 해석되는 서비스를 벽1~5 안에서 운영한다. 성공은 기능 수가 아니라 "벽을 넘지 않고 링크가 죽지 않았다"로 정의한다.

## 명시적 가정
1. **정적 리다이렉트 규칙 파일(HTTP 301/308)을 무료 등급으로 제공하는 호스트가 실재하고, 규칙 수 상한이 예상 링크 총량을 덮는다.** — 전체가 여기에 걸려 있다. 틀리면 전제 깨기 1이 무너지고 모순 A가 되살아나 계획 전체가 무효다. 최저비용 조기 검증: Step 0에서 후보 2곳의 한도 문서 확인 + 링크 3개 실측. 대체 경로: 키-값 저장소 기반 엣지 함수의 무료 등급(같은 구멍1 회계). 그것도 불가하면 벽3을 "월 99.9%"로 완화하고 대안 A1로 회귀한다.
2. VPS 월 $4 이하, 도메인 연 $12 이하로 실제 구매 가능. 틀리면 벽1 재분배 여유가 없으므로 도메인 등급을 낮추거나 계획 무효.
3. 링크 총량이 3년 내 무료 등급 규칙 상한의 절반 미만. 틀리면 Step 7 트리거로 키-값 방식 전환.
4. 운영자가 감당 가능한 정기 작업은 월 1시간 미만(임의값 — 1인 운영의 현실적 상한으로 선언, 첫 분기 실제 소요로 대체). 틀리면 드릴 주기를 늘리고 도메인 다년 선결제로 대체한다.
5. 링크 생성은 운영자 전용(공개 생성 없음). 틀리면 abuse 처리 부하가 벽2를 뚫는다 → 공개 생성은 범위 밖으로 고정.

## 접근 및 단계
각 단계는 선행조건 / 검증 / 어느 벽·전제 깨기에서 내려왔는지를 함께 적는다.

- **Step 0 — 벽 실측 게이트** (선행: 없음). VPS 요금, 도메인 가격, 무료 등급 한도(규칙 수·요청량·빌드 횟수) 세 숫자를 실제 화면에서 확인해 기록. 검증: 하나라도 벽 밖이면 **진행 금지**, 벽 재협상. ← 벽1, 벽4, 구멍1.
- **Step 1 — 무중단의 조작정의** (Step 0과 병렬, 독립). 표면 3분할을 문서화. 검증: 각 표면이 "30분 죽으면 실패인가?"에 예/아니오로 답할 수 있다. ← 벽3 정제.
- **Step 2 — 소스 오브 트루스 고정** (Step 1 소비). 단일 append-only 텍스트 파일: slug, 원본 URL, 생성시각, 상태(활성/차단). 검증: 파일만으로 아티팩트를 전량 재생성했을 때 기존 slug 전부가 동일 응답코드·동일 목적지. ← 전제 깨기 1, 벽5.
- **Step 3 — 컴파일 → 발행 경로 1개** (Step 0+2 소비). 파일 → 리다이렉트 규칙 아티팩트 → 원자적 교체 발행. 검증: 신규 slug 1개를 외부에서 301 확인하고 지연을 기록 — 이 값이 판정 기준선이 된다. ← 전제 깨기 1, 벽3.
- **Step 4 — 관리 평면 최소화** (Step 2 소비, Step 3과 병렬). 생성·차단은 VPS 로컬 CLI만. 공개 HTTP 관리 표면 0. 검증: 공개 도메인에 관리 엔드포인트 0건. ← 벽2, 벽3 정제.
- **Step 5 — VPS 소멸 드릴** (Step 3+4 소비). VPS를 삭제하고 발행 저장소만으로 재구축. 검증: 재구축 소요시간 실측 + 드릴 전 구간 기존 링크 실패 0건. ← 모순 A.
- **Step 6 — 부재 드릴** (Step 4 소비, Step 5와 병렬). 휴대폰만으로 악성 slug 1건 차단. 검증: 신고→차단 발행 완료까지 실측. ← 벽2.
- **Step 7 — 한도 감시와 사전확정 트리거** (Step 3 소비). 규칙 수·요청량을 월 1회 자동 기록, 80%에서 키-값 전환 착수. 검증: 두 숫자가 기록에 남는다. ← 구멍1, 벽1.
- **Step 8 — 카나리아 감시** (Step 3+7 소비). 외부 프로버가 카나리아 링크를 상시 확인하고 일 1회 요약 메일. 페이징 없음. 검증: 카나리아를 고의로 죽여 메일 도착을 확인한다 — 미발화는 감시 실패로 읽는다(safety-net 프레임의 '미발화 재해석'을 차용). ← 벽2, 벽3.

## 대안과 기각 사유
- **A1 정석 단일 VPS** (앱 + DB + 리버스프록시 + systemd 재시작). 기각: 모순 A 직격. **부활 조건**: 벽3이 "월 99.9%"로 완화되면 이것이 최선이다 — 외부 의존 0, 부품 최소.
- **A2 VPS 2대 + 플로팅 IP**. 기각: 월 $8~10, 벽1 위반. **부활 조건**: 예산이 월 $12로 오르고 "외부 무료 등급 의존 제거"의 가치가 그 비용을 넘을 때.
- **A3 서버 0대, 전부 관리형 무료 등급**. "1대"는 상한이므로 형식상 벽1을 통과한다. 기각: 소스 오브 트루스를 남의 DB에 두면 벽5와 충돌한다 — 이전 비용이 링크 수에 비례해 커지고 정책 변경 시 협상력이 0. **부활 조건**: 전량 export가 계약으로 보장되고 내가 그 export를 주기 보관할 때.
- **A4 레지스트라 URL 포워딩만**. 기각: slug 단위 매핑과 수천 건 관리가 불가. **부활 조건**: 총 링크가 20건(임의값 — 레지스트라 포워딩 규칙을 수동 관리 가능한 규모로 선언, Step 0에서 실제 규칙 수 상한 확인 시 대체) 이하로 고정된다면 이것이 최선(코드 0, 서버 0).
- **A5 실시간 클릭 통계 도입**. 기각: 벽1 밖. **부활 조건**: 통계가 요구로 확정되면 예산 벽을 먼저 재협상해야 하며, 클릭 로그는 규제 대상 개인정보를 함께 데려온다는 점을 같이 계산한다.

## 리스크 & 완화
- **R1 무료 등급 정책 변경·폐지 (최대 위험)**: 소스 오브 트루스는 내 파일로 유지, 발행 대상은 Step 3 한 곳에 격리, 연 1회(임의 주기 — 정책 공지가 통상 연 단위로 오는 것을 근거로 선언, 실제 공지 이력이 쌓이면 대체) 대체 타깃 발행 리허설.
- **R2 도메인 상실 (만료·계정 탈취·결제 실패)**: 배포된 전 링크의 영구 사망이며 복구 경로가 없다. 완화는 예방뿐 — 다년 선결제, 자동갱신, 2FA 백업코드 오프라인 보관, 만료 90/30/7일 알림(관행값 — 레지스트라 기본 알림 주기를 그대로 채택, 도출 아님), 결제수단 만료일 캘린더.
- **R3 abuse·법적 요구**: 공개 생성 미지원으로 표면 축소(가정 5), 신고 메일 별칭 공개, 차단은 상태 필드로 아티팩트에 반영. 처리 지연 상한은 Step 6 실측값.
- **R4 개인정보 규제**: 클릭 로그를 수집하지 않으므로 처리 대상 개인정보가 없다(설계 부산물). A5를 부활시키면 이 부담이 함께 돌아온다.
- **R5 버스 팩터 1**: 도메인·계정·복구 절차 1장을 신뢰 대상에게 봉인 전달, 연 1회 갱신.
- **R6 소스 파일 손상**: append-only + 발행 저장소 이력으로 되감기, Step 5가 복원 경로를 검증.
- **R7 slug 재사용 사고**: 삭제·차단된 slug는 영구 예약, 재발급 금지. ← 벽5.
- **R8 비용 잠식**: Step 0에서 확정한 두 요금 외 지출 금지. 초과는 증액이 아니라 기능 축소로 대응.

## "완료"의 판정 기준
- **(헤드라인, 실측 가능)** 3개월 연속 실제 청구 합계가 $15 이하다 — 도메인 연 요금의 3/12 안분 포함. (도출: 벽1의 월 $5 × 3.) 이 문장은 설계가 자동으로 만족시키지 못하며 실패할 수 있다.
- 발행 지연 p95가 Step 3 기준선의 2배 이내다. 외부 프로버의 30일 기록으로 판정. (계수 2와 창 길이 30일은 선언적 임의값이며, 첫 30일 실측 분포로 둘 다 대체한다.)
- 부재 드릴: 휴대폰만으로 신고→차단 발행이 완료된다. 1차 실측값을 목표로 고정하고, 2차 드릴이 그 값의 1.5배를 넘으면 절차 결함으로 판정한다(1.5는 임의값, 2차 실측으로 대체).
- 감시 발화: 카나리아를 고의로 죽인 뒤 24시간 내 요약 메일이 도착한다(도출: 일 1회 요약 주기 = 최대 지연 24시간). 미발화면 미완.
- 벽 재협상 트리거 3개(요금 초과 / 규칙 수 80% / 무료 등급 정책 변경) 각각에 담당 행동이 한 문장으로 적혀 있다.
- VPS를 삭제하고 24시간 방치해도 기존 링크가 전부 해석된다 — 이 항목은 **설계 적합성 확인**이다. 설계가 통과를 보장하므로 품질 판정의 근거로 쓰지 않는다.

## 프레임 이탈 & 관성 회귀
- **구멍1은 벽 준수가 아니다.** 이 계획의 무중단은 전적으로 외부 무료 등급 위에 서 있다. 상한과 위반 결과를 붙였지만(§벽에 낸 구멍, Step 0/7), "월 $5 서버 1대"의 문자를 만족한다고 주장할 수는 없다.
- **가장 약한 항목은 R2다.** 예방만 있고 복구 경로가 없다. 2차 도메인 병행 발행을 검토했으나 두 도메인 요금이 벽1에 들어가지 않아 접었다. 리뷰어라면 여기를 친다.
- **A5 기각의 근거가 예산뿐이다.** 사용자가 통계를 핵심 기능으로 볼 가능성을 요구 확인 없이 판정으로 밀어냈다.
- **품질 축 판정이 얇다.** 청구서 기준을 헤드라인으로 올려 순환을 피했지만, 청구서는 서비스 품질을 전혀 측정하지 않는다. 품질은 발행 지연 p95 하나에 얹혀 있고 그 기준선은 Step 3 실측 전까지 비어 있다.
- **관행 선택 1건**: Step 2의 텍스트 파일은 벽에서 도출된 것이 아니라 익숙함에서 왔다. SQLite도 같은 벽을 통과한다. 파일을 고른 실질 근거는 발행 저장소가 그것을 그대로 백업으로 겸한다는 점뿐이다.
