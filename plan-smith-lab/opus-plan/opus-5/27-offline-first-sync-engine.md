# 오프라인 우선 모바일 메모 앱 동기화 엔진 설계
- 추론 프레임: backward / 스타일: opus
- 한 줄 요약: 인수조건 5개를 최상단에 고정하고, "충돌 UX 없음 × 동시 편집 생존"에서 상태 기반 시퀀스 CRDT를, "장기 오프라인 ≡ 복원"에서 단일 재동기 경로를 역산한다.

## 프레임이 요구하는 시작점 — 인수조건 5개와 각 조건이 죽인 대안

반사적 습관은 "로컬 DB → 전송 큐 → 재시도 → 서버 API → 마지막에 충돌 처리" 순으로 쌓는 것이다. 그 순서의 종착지가 정확히 A5가 금지하는 화면("노트 (충돌 사본)")이므로, 조건을 먼저 고정하고 자료구조를 역산한다.

**앵커 자격 심사(탈락분).** 동기 지연 p95·배터리·노트당 서버 비용·메타데이터 오버헤드 비율은 실패해도 파라미터와 압축 튜닝으로 회수되고 자료구조를 바꾸지 않는다 → 앵커가 아니라 관측 지표. 아래 5개는 실패 시 병합 함수와 저장 포맷을 다시 쓰게 한다.

| 앵커 | 판정 명제 | 이 조건이 죽이는 대안 |
|---|---|---|
| A1 수렴 | 동기 정지 후 모든 기기의 콘텐츠 해시와 state vector가 동일 | 전체본 PUT 업로드(서버 권위), 적용 순서에 의존하는 비가환 연산 큐 |
| A2 동시 편집 | 오프라인 두 기기가 같은 문단을 편집해도 양쪽 입력이 생존 | 노트 단위 LWW, 공통 조상이 필요한 서버측 3-way diff3 |
| A3 장기 오프라인 | 최대 오프라인 창(180일) 뒤에도 재설치·초기화 없이 수렴 | OT(중앙 순서화·상시 온라인), 조상 보존형 머지, "N일 넘으면 강제 초기화" |
| A4 복원 | 앱 삭제·기기 교체 후 노트 전량과 본문 복구 | 로컬 전용 저장, **복원 전용 두 번째 코드 경로** |
| A5 충돌 UX 없음 | 병합은 사용자에게 아무것도 묻지 않고 항상 성공 | 병합 다이얼로그, 충돌 사본 생성, 사용자 선택 대기 큐 |

**해상도 감사.** A1을 "인코딩 바이트 동일"로 쓰면 과잉 해상도다 — 도착 순서와 로컬 압축 상태에 따라 바이트는 갈릴 수 있다. 판정은 콘텐츠 해시(본문+속성) + state vector 동일로 낮춘다. A3은 일 단위 해상도로 충분하다. A4는 도메인 정석이어서 파생은 끝나지만 명세는 남는다: A4의 값은 새 메커니즘이 아니라 **두 번째 코드 경로 금지**다.

## 앵커 교차 패스

| 쌍 | 발견 | 결정 |
|---|---|---|
| A2 × A5 | 물어볼 수 없으므로 병합 함수가 total해야 한다 | 본문은 시퀀스 CRDT — 블록(문단) CRDT 안에 텍스트 CRDT 중첩 |
| A3 × A1(GC) | 오래된 벡터 vs 서버 히스토리 정리가 정면 충돌 | **상태 기반(delta) 병합** — 누락 op 없이 스냅샷 병합 가능 → 히스토리 GC는 안전, 위험은 tombstone뿐 |
| A3 × A2 | 180일치 누적 업데이트가 로드 시간을 갉는다 | 스냅샷 압축은 하되 tombstone은 180일 + 유예 30일 보존 |
| A4 ≡ A3 | 빈 기기 = "epoch부터 오프라인인 기기" | 복원은 재동기의 특수 경우, 코드 경로 1개 |
| A1 지붕 | 나머지 넷이 모두 수렴 위에 얹힌다 | 수렴 퍼즈 하네스를 S0으로 |
| A5 × 삭제 | 삭제 vs 동시 편집도 물어볼 수 없다 | 규칙 선결: 삭제 승, 휴지통 30일, 편집분은 휴지통 사본에 보존 |

## 문제 정의 / 목표

단일 사용자가 2~4대 기기에서 쓰는 메모 앱. 네트워크는 없는 것이 기본이고 동기화는 사후 수렴 장치다. 목표는 위 5개 명제를 통과하는 엔진(자료구조 + 저장 포맷 + 델타 프로토콜 + 압축 정책)의 확정이다.

**스택(정석이지만 명시).** React Native + TypeScript, y-crdt(Yjs), 로컬 SQLite(스냅샷·미전송 업데이트·state vector), 서버 Node+TS와 Postgres(업데이트 blob·스냅샷), WebSocket에 HTTP 폴백. 무엇을 사는가: Yjs의 state vector·델타 인코딩 API는 A3의 "누락 구간 없는 재동기"를 직접 구현하지 않게 하고, SQLite는 앱 강제 종료 중 미전송 업데이트의 내구성을 산다.

## 명시적 가정

- **성숙한 CRDT 라이브러리의 수렴과 인코딩 호환성을 신뢰한다.** 틀리면 병합 계층 전체 재작성. 최저비용 조기 검증 = S0 퍼즈를 라이브러리에 직접 가함. 폴백 = 블록 단위만 CRDT, 문단 본문은 LWW로 후퇴하고 A2 등급 하락을 문서화.
- 노트는 단일 소유자 문서다(실시간 공동 편집 아님). 틀리면 권한 모델·presence 추가 — 병합 함수는 유지, 서버 인증 계층이 늘어난다.
- 노트 본문은 수만 자 이하다. 틀리면 메타데이터 팽창으로 로드가 느려짐 → 블록 분할 임계를 낮춘다.
- 서버는 평문을 볼 수 있다(E2EE 아님). 틀리면 서버측 압축 불가 → 압축을 클라이언트로 옮기고 A3 검증 재실행.

## 앵커 밖 요구 처리 원장

앵커에 없는 요구는 **병합 함수와 저장 포맷을 굽힐 수 없다. 그러나 범위에서 빠지지 않고 그대로 출하된다.** 침묵 칸은 결함이다.

| 요구 | 판정 | 근거 / 트리거 |
|---|---|---|
| 오프라인 전문 검색 | build (S7) | SQLite FTS를 CRDT 밖 파생 인덱스로 |
| 태그·폴더 | build (S4) | add-wins OR-Set, 별도 타입 |
| 핀·정렬 | build (S4) | LWW 레지스터(논리 시계) |
| 휴지통/복구 UX | build (S4) | A5×삭제 규칙의 사용자 표면 |
| 이미지 첨부 | build (S7) | 콘텐츠 주소 blob + CRDT엔 참조만(가산 채널) |
| 동기 상태 인디케이터 | build (S6) | "미전송 n건"만, 충돌 표시 아님 |
| 마크다운 렌더 | build (S7) | 블록 속성으로 표현 |
| 계정/로그인 | build (S2) | 토큰 만료 중에도 로컬 편집 큐잉 |
| 웹 클라이언트 | defer | 트리거: A1~A5 통과 + 동일 인코딩 웹 판독 스파이크 성공 |
| 노트 공유·협업 | defer | 트리거: 단일 소유자 가정 폐기 |
| 알림·리마인더 | defer | 트리거: 출시 후 문의 집계 상위 3위 |
| E2EE | defer | 트리거: 규제 요구 또는 서버 신뢰 폐기(A3 재검증 동반) |

## 접근 및 단계

- **S0 (독립).** 수렴 퍼즈 하네스: 가상 replica에 랜덤 편집·분단·중복 전달, 모든 순열에서 해시·벡터 일치 단정. 인코딩 버전 필드 동결. → 검증: 10,000 세션 0 실패. [A1]
- **S1 (S0과 병렬).** 로컬 저장 계층. 서버 없이 앱 완전 동작. → 검증: 서버 미배포 상태로 편집·강제종료·재시작 후 손실 0자. [A3·A4 준비]
- **S2 (S0·S1 의존).** 델타 프로토콜: 벡터 교환 → 누락분만 전송, 서버는 append + 스냅샷 보관. → 검증: 중복·역순 전달에서 멱등. [A1, A2]
- **S3 (S2 의존).** 압축·tombstone 정책 + 계정 하드 삭제 경로. → 검증: 압축된 서버에 180일 된 벡터를 붙여 수렴, 전량 재다운로드 0건. [A3]
- **S4 (S1 의존, S2와 병렬).** 메타데이터 CRDT(태그·핀·삭제·휴지통). → 검증: 삭제와 편집을 동시 인가해도 휴지통에 편집분 보존. [A5]
- **S5 (S3 의존).** 복원 = "epoch 벡터"로 S2 경로 재사용. → 검증: 초기화 후 노트 수·노트별 해시가 초기화 전과 일치. [A4]
- **S6 (병합 이상 검사는 S2와 동시 착수, 대시보드는 S4 의존).** 양측 삽입 문자 생존 검사를 S2 첫 왕복부터 켠다(나중에 붙이면 표본을 잃는다). 복구 편집률·미전송 큐 나이는 뒤에 합류. → 검증: S2 로그에 생존율 기록 + 대시보드 3지표 실데이터. [A5, A2]
- **S7 (S2 의존, 항목 간 병렬).** 첨부·검색 인덱스·마크다운 — 표면 완성 단계. → 검증: 각 표면이 오프라인에서 동작.

## 대안과 기각 사유 (부활 조건)

- **노트 단위 LWW + 서버 권위**: 가장 싸지만 늦게 저장한 쪽이 남의 문단을 지운다(A2 위반). 부활: 동일 노트 동시 편집이 월 0.1% 미만이고 A5를 "사본 허용"으로 완화할 때.
- **OT**: 중앙 순서화와 짧은 오프라인 전제 → A3에서 파산. 부활: 오프라인 요구가 사라지고 서버 권위가 필요할 때.
- **git 유사 3-way 텍스트 머지**: 쌍마다 공통 조상 보존이 필요해 압축 정책과 충돌하고, 자동 머지 실패 시 A5를 깨는 표면이 생긴다. 부활: tombstone 보존 비용이 서버 예산을 넘고 A5를 완화할 때.
- **자체 RGA 구현**: 의존을 없애는 대신 수렴 검증 비용을 전부 낸다. 부활: S0에서 라이브러리가 실패하거나 포맷 마이그레이션 정책이 없을 때.

## 리스크 & 완화

| 리스크 | 완화 |
|---|---|
| 메타데이터 팽창 | 블록 분할 + S3 압축(트리거 근거는 로드 시간 곡선) |
| interleaving으로 병합 결과가 안 읽힘 | 블록 경계로 교차 범위 제한 + 복구 편집률 관측 |
| 라이브러리 인코딩 breaking change | 포맷 버전 필드, 서버 버전 혼재 허용, 기기별 재인코딩 |
| 시계 skew | 논리 시계 + 기기 ID 타이브레이크, 본문엔 시계 미사용 |
| 미동기 기기 유실 = 영구 손실 | 구조적 완화 없음(서버 사본이 없다). 미전송 큐 나이를 노출해 손실 창을 줄이는 것뿐 |
| 계정 삭제 요청 vs tombstone 보존 | 개인정보 삭제가 우선 — 계정 하드 삭제 경로를 S3에 포함 |
| 서버 스토리지 비용 / 구버전 기기 | 앵커 아님(지표). 압축 주기로 조절, 구버전 인코딩 읽기 호환 1버전 유지 |

**측정 저항 범주 스윕.** 앵커가 모두 측정 가능한 조건이라 "병합 결과가 사람이 읽을 만한가(의도 보존)"가 빠졌다. CRDT는 수렴을 보장하지만 의미를 보장하지 않는다. 앵커로 올리지 않고 대리 지표로 둔다 — 병합 직후 5분 내 복구 편집률(측정자: 클라이언트 텔레메트리). 기준선은 정직하게 공란, 출시 후 4주 관측으로 채운다.

**수치 태그.** 최대 오프라인 창 180일 = 제품 선언값(임의), tombstone 보존 180일+유예 30일이 여기서 파생. 대체: 출시 후 8주, 서버 로그의 기기별 마지막 동기 시각 p99(측정자: 서버팀). 압축 트리거(미압축 업데이트 200건 또는 스냅샷 대비 델타 2배) = 임의 초기값, S3 벤치의 "노트 열기 100ms 초과 지점"으로 대체. 휴지통 30일 = 도메인 관행(임의). 수렴 60초 = 판정 하네스 상한(임의).

## "완료"의 판정 기준

1. 두 기기를 비행기 모드로 두고 같은 노트의 같은 문단을 각각 20자 이상 편집한 뒤 동시에 온라인 전환 → 60초 내 두 기기의 콘텐츠 해시와 state vector가 일치하고 양쪽 40자가 모두 존재한다(손실 0자). [A1, A2]
2. 180일 전 벡터를 가진 기기를 압축 완료된 서버에 붙이면 수렴한다. "초기화 이벤트 0건"만으로는 초기화 경로를 만들지 않았으니 자동 충족되므로, 함께 측정한다: 수렴까지 수신한 바이트 < 서버 전체 스냅샷 크기이고, 그 상태에서 노트별 콘텐츠 해시가 서버와 전부 일치. [A3]
3. 기기 초기화 후 재로그인 시 노트 수와 노트별 해시가 초기화 전과 전부 일치하며, 그 경로가 S2와 동일 코드 경로임을 커버리지로 확인. [A4]
4. A5는 "충돌 UI 노출 0건"으로 판정하지 않는다 — UI가 없어 자동 충족되는 순환 조건이다. 자동 병합 1,000건 표본의 양측 삽입 문자 생존율 100%, 그리고 복구 편집률이 기준선 대비 상승하지 않음을 판정으로 쓴다. [A5]

## 프레임 이탈 / 관성 회귀

- 180일은 근거 없는 선언값인데 tombstone 보존 기간이 전부 여기서 파생된다. 대체 시점을 붙였을 뿐 근거를 만들지 못했다.
- 「리스크 & 완화」가 가장 얇은 절이다. 완화 열이 한 줄 처방이고, "미동기 기기 유실"은 처음 인디케이터로 덮었다가 완화가 없다고 고쳐 적는 데서 끝났다. 리뷰어라면 이 칸을 먼저 찢을 것이다.
- 원장의 "알림·리마인더" 트리거("문의 집계 상위 3위")는 집계 규칙이 없어 사실상 제품 판단이다(웹 클라이언트 쪽은 스파이크 조건으로 고쳤다).

- S6 관측을 단계 목록 끝에 두었던 사다리 배치, 그리고 판정 기준 2의 순환 조건은 이 절을 쓰다가 잡아 본문을 고쳤다(편집 이력, 잔여 결함 아님).
