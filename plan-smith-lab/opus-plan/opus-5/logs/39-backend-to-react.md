# 로그 — 39 백엔드 개발자의 React 8주 (misconception-first) [Opus 5]

## 진입 시 사고

주제를 보자마자 떠오른 건 주차 커리큘럼이었다. 1–2주 JSX·컴포넌트, 3주 상태, 4주 이펙트, 5주 라우팅, 6주 상태관리 라이브러리, 7–8주 프로젝트. 이 배열의 축은 난이도이고, 난이도순 배열은 이 프레임의 실패 모드로 명시돼 있다. 프레임이 요구한 시작점은 커리큘럼이 아니라 "기존 지식이 간섭하는 지점의 목록"이었고, 그것을 먼저 쓰자 순서가 바뀌었다. 특히 `useEffect`가 5번째로 밀렸다 — 통상 초급 소재지만, 이펙트 오개념은 "서버 데이터를 어디에 두는가"가 정리되기 전에는 교정해도 되돌아간다.

두 번째 관성은 "8주니까 8개 주제"였다. 프레임은 단위를 주제가 아니라 오개념으로 잡게 했고, 그래서 주4와 주6이 새 주제 없는 재검사 주차가 됐다.

## 프레임이 만든 결정적 순간

세 번.

첫째, **발화 시점 규칙**이 M5(렌더 스냅샷·정체성)를 잠복 항목으로 분류하게 했다. 이 오개념은 즉시 배울 수 있지만 지연 콜백이나 목록 재정렬이 없으면 절대 틀린 결과를 내지 않는다. 그래서 교정을 주5–6으로 미루고, 대신 그 주차의 시드 데이터에 "행마다 편집 중 입력값 + 중간 삽입 가능"이라는 조건을 박았다. 기폭제가 없으면 예측이 배신당하지 않는다는 경고를 데이터 설계로 받은 결과다.

둘째, **봉인 목록**이 계획의 성격을 바꿨다. 처음엔 상태관리 라이브러리를 "6주에 다룸"으로 적었는데, 그러면 M6(데이터는 서비스 레이어에서 가져온다)의 충돌이 영구히 일어나지 않는다. 도피로가 열려 있으면 prop 전달의 불편이 오개념을 노출시키기 전에 해소된다. 그래서 봉인 5항목을 만들고 해제 조건을 코드에서 관찰되는 사건으로 적었다. `useMemo` 계열 봉인은 M1의 과교정 회복 패스와 짝을 이룬다 — 봉인이 곧 2차 오개념 관리 장치가 됐다. 반대로 컴포넌트 테스트는 봉인 후보에서 빼고 긍정 전이 자산 채널로 돌렸다.

셋째, **자기 학습자는 자기 문제의 답을 안다**는 경고가 판정 구조를 만들었다. "판정자는 런타임이다"를 본문 규칙으로 박고, 예측을 append-only 노트에 실행 전에 적고, 과제는 제3자가 해설 없이 공급하게 했다. 완료 기준 3(2주 연속 배신 0건 → 공급원 교체)은 이 구조가 실패했음을 감지하는 장치다. 처음엔 배신률 30%로 썼다가, 주당 3건이면 표본이 6건이라 비율이 아무것도 판정하지 못해 방향 판정으로 바꿨다(관측 프레임 차용). 같은 이유로 완료 기준 4도 "잘못된 데이터 0회"라는 눈대중 문장에서 목업이 넣은 요청 순번 비교로 바꿨다.

## 프레임 이탈 / 관성 회귀 지점

- **주차 라벨의 상승 인상.** S3·S5는 회귀 처리, S7은 새 개념 0인데도 문서는 주1→주8 사다리로 읽힌다. 본문에 "진도가 줄어드는 것이 정상"이라고 적은 것은 방어이지 구조 교정이 아니다.
- **상한을 지키려는 병합.** M5를 스테일 클로저와 목록 정체성 합본으로 묶었다. 재검사 표면이 두 개 나와 설계상 유리했지만, 실제로 하나의 오개념인지 검증하지 않았고 그 병합은 오개념 6개라는 상한을 지키려는 편의에서 나왔다.
- **관행을 프레임 옷으로 입힐 뻔했다.** CSS·디자인 봉인을 쓰려다 오개념 근거가 없다는 걸 확인하고 봉인에서 빼고 스윕으로 내렸다. M2→M3 인접 쌍은 논증을 밀었지만 M5→M6은 성립하지 않아 임의로 선언했다 — 여기서 억지 논증을 하지 않은 것이 프레임 문자를 따른 지점이다.
- **자기 집행 완화의 누적.** 리스크 완화 다섯 개 중 넷의 집행자가 학습자다. 규율을 구조로 바꾸지 못했고, 대안도 찾지 못했다.

## 방향성

교정표는 "무엇을 배우는가"가 아니라 "무엇이 언제 틀리는가"의 표다. 계획의 실행 가능성은 시드 데이터와 봉인이 지탱하고, 신뢰성은 예측 노트가 지탱한다.

## 자가 평가

충실도: 상. 근거는 본문 좌표다 — 필수 부품 4개가 각각 결정을 바꿨다. 선행지식 점검은 S0 진단과 대안 1의 부활 조건으로, 봉인 목록은 상태관리 라이브러리의 "6주에 다룸"을 폐기시켰고, 예측→충돌→재구성은 시드 데이터 조건과 완료 기준 2를 만들었고, 순서 축은 이펙트를 5번째로 밀고 한 쌍을 임의로 선언하게 했다.

흠: (1) 주차 사다리 인상을 못 지웠다. (2) 봉인 1의 임계값(깊이 4단계·3화면)에 근거가 없고 재도출 시점만 붙었다. (3) 리스크 섹션이 이 문서에서 가장 약하다. (4) 분량을 맞추려고 인증·토큰 저장 같은 실제 간섭 항목을 스윕 한 줄로 처리했다 — 지도의 부록으로 넘긴 것은 축소이지 해결이 아니다.
