# 신입 개발자 온보딩 "첫 2주" 프로그램

- 추론 프레임: backward / 스타일: opus
- 한 줄 요약: 2주 후 신입이 타인의 손 없이 해내야 하는 5가지를 판정 문장으로 먼저 고정하고, 커리큘럼·버디 시간·권한 프로비저닝을 그 5개에서만 역산한다.

## 프레임이 요구하는 시작점 — 인수조건 5개

모든 앵커는 "14일차에 신입이 대행자 없이 수행하며, 산출물이 시스템 기록으로 남는다"로 읽는다.

| # | 앵커 | 판정: 누가·무엇으로 | 실패 시 재작업 | 이 앵커가 죽이는 대안 |
|---|---|---|---|---|
| A1 | 로컬 개발 환경을 문서만 보고 재구축해 테스트를 통과시킨다 | 버디가 신규 clone에서 신입이 남긴 절차를 실행 → 통과 로그 | 부패한 setup 문서가 남아 이후 입사자와 본인이 매번 남의 시간을 산다 | 완제품 VM 지급, 세팅 화면공유 대행 — 문서 부패를 은폐한다 |
| A2 | 프로덕션까지 변경 1건을 스스로 배포한다 | 배포 기록의 actor가 신입 계정, 승인 외 타인 개입 0 | 릴리스 절차 학습이 이연되어 매 변경마다 대행자가 붙는다 | 샌드박스 리포 과제, 온보딩용 장난감 티켓, 리뷰 없는 push |
| A3 | 알람의 심각도를 판정하고 에스컬레이션 대상을 지목한다(수정 아님) | 리허설 알람(과거 인시던트 리플레이)의 판정 ↔ 런북 정답 일치 | 온콜 로테이션 진입 불가 → 기존 인원의 야간 부담이 고정된다 | 온콜 노출을 30일 이후로 미루기, 런북 통독으로 대체 |
| A4 | 막힘을 스스로 해소한다 — 정해진 형식으로 올바른 채널에 질문해 답을 얻는다 | 막힘 로그: 형식(시도 3줄 + 찾아본 곳) 충족 5건, 그중 3건이 버디 개입 없이 종결 | 버디가 상시 인간 검색엔진으로 고착되고, 버디 부재 시 신입이 정지한다 | 버디 DM 즉답 상시대기 — 즉답이 자립을 대체한다 |
| A5 | 백로그 티켓 1건을 스스로 분해·추정해 등록하고 착수한다 | 하위 작업·추정이 신입 작성, 매니저 수정 폭 ≤ 하위 작업 1개 | 매니저가 무기한 대신 분해하고, 작업 단위가 "지시받은 것"으로 굳는다 | 2주간 분해 완료된 티켓만 배정하기 |

**앵커 자격 시험.** 앵커는 "실패했을 때 되돌리는 비용이 최대인 조건"이다. 이 시험으로 두 개가 탈락했다. ① "코드 품질·설계 의도 이해" — 2주 해상도에서 판정자 두 명의 채점이 일치하지 않는다(측정 불가이므로 앵커 불가). ② "타인 PR 리뷰 1건" — 후보였으나 2주 내 미수행의 재작업 비용이 A5보다 뚜렷하게 작다. 둘 다 앵커에서 빠지되 **범위에서 빠지지 않는다**(아래 스윕 표). 해상도도 함께 감사했다: A2는 "배포 3건"(선호 해법에서 역류한 과잉)도 "PR 머지 1건"(배포 권한·롤백이 판정에서 빠짐)도 아닌 1건이어야 목적을 만족한다.

**측정 저항 스윕.** 심리적 안전(모름을 드러낼 수 있는가), 소속감, 잔류 의사는 결정적이지만 2주 안에 판정 불가라 앵커가 없다. A4가 대리 지표에 가깝다는 점을 명시하고, 30일차 관찰 항목(자발 질문의 채널 분포 추이)으로 이연한다.

## 앵커 교차 통과

- **지붕: A1 → A2·A3.** 환경이 안 서면 A2도 A3도 측정이 불가능하다. 실행 순서가 여기서 결정된다 — A1은 D1.
- **충돌: A2 × A3.** 신입 배포로 사고 확률이 오른 시점에 같은 사람이 1차 대응자면 위험이 겹친다. 결정: A3는 리허설·섀도로 강등(실제 응답 책임 없음), A2 배포는 오전 + 원클릭 리버트 경로로 한정.
- **충돌: A2 × A5.** 배포 대상과 분해 티켓이 같으면 한 산출물이 두 앵커를 통과시킨다. 결정: A2의 변경은 A1이 발견한 문서·설정 결함, A5의 티켓은 실제 백로그 항목이며 완료가 아니라 착수까지만 요구.
- **상호지원: A4 × A2.** 첫 배포 중 실제로 막히는 지점이 A4 훈련의 유일하게 진짜인 소재다 — 별도 질문 훈련 세션을 만들지 않는다.

## 문제 정의 / 목표

2주는 가르치는 기간이 아니라 **자립 여부를 판정 가능하게 만드는 기간**이다. 목표는 위 5개 판정 문장이 14일차에 산출물로 판정되는 것, 그리고 그 판정에 버디의 즉흥적 헌신이 아니라 예약된 시간과 사전 권한이 쓰이는 것.

## 앵커 밖 요구 스윕 (모두 처리, 침묵 금지)

| 요구 | 처리 | 근거·트리거 |
|---|---|---|
| 보안·개인정보 필수 교육, 인사 서류, 장비 수령 | build (D1 오후 고정 슬롯 / Step 0) | 조직이 명시한 요구. 앵커가 아니라고 일정을 굽히지 않는다 |
| 타인 PR 리뷰 1건 | build (2주차, 버디 코칭 30분) | 앵커에서 탈락했을 뿐 범위에는 남는다 |
| 팀원 1:1 라운드 4명 × 15분 | build (2주 분산) | 인원·시간은 임의값 |
| 성과·승급 기준 설명 | build (매니저 1:1, D8) | HR 명시 요구 |

| 제품 도메인 전체 교육 | defer | 트리거: 첫 도메인 티켓 배정(30일 내) |
| 아키텍처 전체 개요 세션 | defer | 트리거: 두 번째 서비스를 건드릴 때 |
| 사내 위키 기여, 접근성 규범 | defer | 트리거: 30일차 회고에서 재검토 |

## 명시적 가정

- **프로덕션에 2주 내 도달하는 배포 경로가 있고, 신입 계정에 그 권한을 줄 수 있다.** 틀리면 A2가 붕괴하고 커리큘럼 절반이 목적을 잃는다. 가장 싼 조기 검증: D-3에 신입 계정으로 스테이징 dry-run(권한 오류 0). 실패 시 대체: 앵커를 "스테이징 릴리스 1건 + 프로덕션 승인 배석"으로 하향하고 프로덕션 1건은 30일 앵커로 이월(이월 사실 기록).
- 버디가 2주간 예약 시간을 실제로 쓸 수 있다. 틀리면 A1·A2 검증이 지연된다 → 버디 시간을 스프린트 티켓으로 등록해 커밋에서 차감.
- 테스트 스위트가 로컬에서 돈다. 틀리면 A1 판정을 "앱 기동 + 스모크 절차 통과"로 교체.
- 런북과 온콜 로테이션이 존재한다. 없으면 A3를 "런북 초안 1건 작성"으로 교체(측정 대상이 바뀜을 기록).
- 신입이 해당 스택에 최소 노출이 있다. 틀리면 A2·A5 리드타임이 늘어 2주차가 A5만으로 찬다.

## 접근 및 단계

버디 체계도 앵커에서 역산한다. **역할 분리: 버디(일상 동반·A1·A3·A4) ≠ 리뷰어(A2 게이트)** — 조력자와 평가자가 같으면 신입이 모름을 숨긴다. 백업 버디는 같은 온콜 로테이션의 다음 사람으로 자동 지정.

버디 시간 예산은 앵커별 동승 항목의 합에서 도출한다: A1 막힘 회수 30분 + A2 페어 배포 90분·리뷰 2회 30분 + A3 섀도 2회 45분 + A4 막힘 회고 5회 15분 + A5 분해·리뷰 코칭 60분 ≈ 345분. A1·A2가 1주차에 몰리므로 1주차 45분/일, 2주차 25분/일(주차 편중은 지붕 구조에서 도출).

0. **Step 0 (D-3, 선행: 없음)** — 계정·배포 권한 프로비저닝, 앵커 5문장을 신입·버디·리뷰어·매니저가 같은 문서에서 확인. **A1이 말하는 "문서"를 여기서 팀 리포의 단일 진입점 파일 `docs/onboarding.md` 하나로 지정한다** — A1의 검증 대상이 곧 이 파일이므로 위키·개인 노트 등 다른 경로의 안내문은 판정에서 제외한다(진입점을 정하지 않으면 신입은 가장 덜 부패한 경로로 통과하고, 버디는 다른 산출물을 재실행한다). 검증: 신입 계정 스테이징 dry-run 통과, 현직 팀원 1명이 이 파일로 setup 소요시간을 실측(A1 기준값 — 초기값 90분은 이 실측으로 대체, 측정자는 버디).
1. **A1 (D1, 선행: Step 0)** — 신입이 `docs/onboarding.md`만 보고 환경 구축, 막힌 지점을 그 파일 수정 PR로 남긴다. 검증(1차): 신입 본인 실행이 기준값 이내 테스트 통과 + PR 1건. **14일차 판정은 버디의 재실행 결과를 쓴다**(신입 본인 실행은 진행 확인용).
2. **A2 (D2–D4, 선행: Step 0 권한 + Step 1 PR)** — 첫 배포 대상은 Step 1의 문서·설정 결함. 검증: 배포 기록 actor = 신입 계정, 롤백 절차를 신입이 말로 재현.
3. **A4 (D1부터 상시, 병렬)** — 막힘 로그 형식을 D1에 고정. 검증: 5건 중 3건 버디 개입 없이 종결(임의값 — 첫 코호트 2명의 실측 분포로 대체, 매니저가 30일차에 판정).
4. **A3 (D6–D9, 선행: Step 1)** — 리허설 알람 2회. 검증: 심각도·에스컬레이션 지목이 런북 정답과 일치. 판정 제한시간은 런북의 기존 1차 응답 SLA를 차용(런북에 없으면 30분 임의값 + 첫 실제 인시던트로 대체).
5. **A5 (D7–D12, 선행: Step 2)** — 배포를 한 번 겪은 뒤에야 작업 단위 감각이 생긴다. 검증: 매니저 수정 폭 ≤ 하위 작업 1개(임의값 — 첫 코호트 2건 실측으로 대체, 매니저 판정).
6. **14일차 (선행: 1–5)** — 앵커 판정 + 앵커 밖 스윕 표 결산. 미달은 30일 계획으로 이월하며 "불합격" 판정을 만들지 않는다.

## 대안과 기각 사유

- **4주 강의형 커리큘럼** — 기각: 앵커 5개 중 강의로 판정되는 것이 0개다. 부활 조건: 규제 도메인에서 인증 교육이 배포 권한의 법적 전제일 때(그러면 교육이 Step 0로 들어온다).
- **버디 1인 통합(동반자=리뷰어=온콜 페어)** — 기각: A2의 게이트와 A4의 안전한 무지 노출이 같은 사람에게 모인다. 부활 조건: 팀 상시 인원 4명 이하 또는 온콜 로테이션 3인 이하.
- **첫날 프로덕션 배포(업계 관행)** — 기각: 권한 발급 리드타임이 실제로 D+2~3이라 첫날 배포는 대행으로 위조되고 A2 측정이 오염된다. 부활 조건: 권한이 셀프서브(15분 내)이고 리버트가 원클릭인 팀.

## 리스크 & 완화

- **앵커 5개가 범위 목록으로 변질** — 앵커 밖 스윕 표를 14일차 결산 항목에 넣어, build 행 미이행을 앵커 미달과 동급으로 기록.
- **버디 소진** — 시간을 스프린트 티켓으로 가시화, 2주차 절반 축소를 사전 확정.
- **판정이 시험 스트레스가 되어 심리적 안전을 훼손** — 별도 시험을 만들지 않고 실제 산출물(배포 기록·PR·로그)로만 판정, 미달은 이월 처리.
- **신입이 판정 통과에만 최적화(체크박스 연기)** — 판정 근거를 자기보고가 아닌 시스템 기록으로 한정. A4의 막힘 로그는 자기 작성이라 이 완화가 닿지 않는 유일한 항목이며, 종결 3건은 채널 스레드로 교차 확인한다.

## "완료"의 판정 기준

- **(14일차 게이트, 실측) 이번 2주 동안 신입과 접점이 없던 다른 팀 엔지니어 1명이, 산출물 4종(배포 기록·PR 목록·막힘 로그·온콜 리허설 채점표)만 보고 앵커 5개 각각에 통과/미달을 표시할 수 있다.** 표시 불가 항목이 1개라도 있으면 그 앵커의 판정 문장이 실패한 것으로 보고 문장을 고친다(프로그램이 아니라 판정 설계의 결함).
- (14일차 게이트) 앵커 밖 스윕 표의 build 행 전부 이행, defer 행 전부에 트리거 기재.
- **(15~19근무일 사후 확인, 실측) 신입의 막힘 요청이 팀 채널의 막힘 티켓 형식으로 도착한다** — 버디 DM 비율이 그 기간 요청의 절반 미만(절반은 임의 기준 — 첫 코호트 실측 후 재설정). 침묵으로는 통과되지 않는다. 이 항목은 14일차 종료를 막지 않고 다음 코호트의 설계 입력이 된다.
- 신입 자기채점과 외부 판정의 불일치는 기록하되 게이트가 아니다(보정 관찰 항목).

## 프레임 이탈 / 관성 회귀

- 단계 0–6이 결과적으로 D-3→14일차 시간축으로 늘어섰다. A4만 병렬이고 나머지는 A1 지붕과 A2→A5 선행에서 나온 순서지만, A3의 D6–D9 배치는 의존이 아니라 "1주차는 이미 꽉 찼다"는 일정 감각으로 밀린 것이다 — 이 한 칸은 역산이 아니라 관례다.
- 버디 시간 345분은 항목 합으로 도출했지만 각 항목의 분 단위(90분, 45분)는 경험적 관례다. 합계만 도출된 것처럼 보이는 구조가 이 문서에서 가장 그럴듯하게 위장된 지점이다.
- 리뷰어라면 앵커 밖 스윕 표의 defer 3행을 공격할 것이다. 트리거가 "30일차 회고"처럼 사람이 기억해야 하는 형태라 조용히 사라지기 쉽다. 캘린더 이벤트나 티켓으로 물리적으로 만드는 것까지는 하지 않았다.
- 14일차 미달을 "불합격 없음, 30일 이월"로 처리한 것은 조직 소화 가능성을 택한 선택이다. 인수조건에 통과/미달 선을 긋고 미달의 결과는 비워둔 셈이며, 앵커가 판정 도구인지 게이트인지 이 문서는 결정하지 않았다.
