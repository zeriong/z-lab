# 개발자 컨퍼런스 200명 — D-day 역산 운영 계획

- 추론 프레임: critical-path
- 한 줄 요약: 지연이 전파되는 두 개의 제로슬랙 체인(해외 연사 비자, 조건부 업링크 회선)을 그래프로 먼저 확정하고, 캘린더는 그 그래프의 투영으로만 쓴다.

### 그래프의 실제 기여 (날짜와 분리해서 읽을 것)

- **제로슬랙 체인 2개.** C1 = N1→N2→N8→N9→N10→N11. 길이는 점이 아니라 **범위**다 — 비자 8주 분기에서 68일, 10주 분기에서 82일. 아래 캘린더는 **8주 분기 기준**이며, 10주 국가의 연사를 초청하면 최소 리드타임이 D-126으로 올라간다(그 경우 D-96 → D-110으로 이동). C2 = N1→N2→N3→N4→N5→N7 (조건부, 슬랙 7일). 두 체인은 D-day에서만 병합한다.
- **절단 가능 엣지 4개.** ① 티켓 오픈←아젠다: 트랙 구조만 있으면 열 수 있으므로 세션은 TBA로 남긴다. ② 배지 인쇄←최종 명단: 자재를 선인쇄하고 이름은 현장 라벨 프린터로 붙인다. ③ 지출 커밋←스폰서 입금: 예산은 스폰서 0으로 편성한다. ④ 초청장←최종 장소 계약: 초청장은 **날짜 홀드(N2)** 에만 걸리므로 계약(N3)보다 먼저 나간다 — 이 한 엣지가 C1을 5일 앞당긴다.
- **크리티컬 패스에서 이탈한 노드 3+1개.** CFP·아젠다(엣지 ①), 스폰서(③), 배지 이름(②), 그리고 N4 실측이 "기존 업링크로 충분"으로 나오면 N5·C2 전체가 이탈한다.

### 노드 분할 결과

- "아젠다 확정" → (트랙 구조/슬롯 수) / (세션 제목) / (연사명 붙은 최종표). 티켓 오픈은 첫째만 소비 → CFP 지연이 판매를 막지 못한다.
- "장소 확보" → (날짜 홀드) / (최종 계약서). 초청장은 앞쪽만 소비.
- "네트워크" → (업링크 회선) / (AP·스위치 구성) / (인증·게스트 정책). 외부 의존은 회선 하나뿐 → 나머지는 N5와 병렬.
- "예산 확정" → (지출 상한: 티켓 수입 하한 기준) / (스폰서 수입: 상향 항목 전용).

**숫자 출처 (임의값은 대체 시점을 함께 적는다).** 케이터링 하한 = 스태프·연사·스폰서 확정 인원 + D-30 시점 실판매수(산출식, 임의 계수 없음). 자원봉사 15명 = 필요 12명(등록 4·안내 4·세션 진행 2·물류 2 — 동선 기준 산출) + 예비 3명(임의 → D-21 모집 마감 시점의 사전확인 응답률로 재산정). 5G 라우터 8대 = 1대당 동시 25세션 가정(임의 → 벤더 실측치로 대체) × 200. 배지 자재 220부 = 좌석 200 + 스태프·연사 20(산출). 예비 세션 2건 = 트랙 2개당 1건(산출). PCO 부활선 "자금 하한의 2배" = 임의 → S8의 대행 수수료 실견적으로 대체. 재투영 임계 ±3일 = 임의(1회차 자체 데이터 없음).

## 문제 정의 / 목표

200명 규모 유료 개발자 컨퍼런스를 1회차로 개최한다. 목표는 "D-day에 프로그램이 예정대로 진행되고, 지연이 발생한 노드가 사전에 크리티컬 패스로 표시돼 있던 노드였다"는 상태다. 운영 인력은 코어 4명 + 자원봉사 12명, 예산은 티켓 수입 하한 기준.

## 명시적 가정

- **오늘로부터 D-day까지 112일 이상 남아 있다(비자 10주 국가면 126일).** 남지 않았다면 C1과 C2(회선 6주)가 동시에 성립하지 않아 이 문서의 역산 전체가 무효다. 가장 싼 검증: 오늘 후보 장소 8곳에 가용일을 문의(반나절)해 D-값을 확정한다. 폴백: 해외 연사 0명(국내 연사만) + 회선 증설 포기를 선언한 축소판으로 다시 투영한다 — 두 체인을 잘라내면 최소 리드타임은 약 D-56.
- 리드타임 6주(회선)·8~10주(비자)는 관례 기억값이며 견적이 아니다. 틀리면 D-70과 D-96이 이동한다: 회선이 8주면 신청이 D-84로(티켓 오픈과 같은 주), 비자가 10주면 초청장이 D-110으로 간다 → D-100까지 실견적으로 재투영(검증 스텝 S8).
- 장소가 200석 + 전원 + 기존 업링크를 함께 제공한다. 전원이 분리 계약이면 신규 노드가 C2에 삽입된다.
- no-show율 자체 데이터가 없다. 그래서 초과판매를 하지 않는다(정직한 공백). 틀리면 좌석이 남고, 케이터링 하한 방식이 손실을 흡수한다.

## 접근 및 단계

- **S0 목표일 확정** — 선행: 없음. 후보 8곳 가용일을 스캔해 **3곳 이상 비어 있는 날**을 목표일로 잡는다(날짜↔장소↔연사 순환을 여기서 끊는다). 검증: 홀드 3건 회신. 기여: C1·C2 공통 시작점.
- **S1 날짜 홀드 3건 + 운영 자금 하한 산정** — 선행: S0. 자금 하한 = 장소 예약금 + 회선 신청비 + 인쇄 선급금의 견적 합. D-100까지 세 견적 미확보면 G1을 조기 발동한다(예약금 지출 시점 D-91이 티켓 수입 시점 D-84보다 앞이므로, 이 하한은 판매와 무관하게 선확보해야 한다). 검증: 견적 3건 문서화.
- **S2 업링크 실측 + 키노트 접촉 + 비자 소요 조회(G3a 입력)** — 선행: S1. S2 이후의 S3·S4·S5는 서로 **병렬**이다(번호는 의존 순서 표기이며 실행 순서가 아니다). 검증: 후보 장소 현장 실측치 확보 → G2 분기 결정, 연사 국적별 표준 처리 기간 문서 확보. 기여: C2의 존재 여부와 C1의 길이를 판정.
- **S3 초청장·비자 트랙**(S4·S5와 병렬) — 선행: S2의 키노트 확정. 발송 근거는 날짜 홀드다. 검증: 접수 번호 확보, 주 1회 상태 기록. 기여: C1.
- **S4 장소 계약 → 티켓 오픈**(S3·S5와 병렬) — 선행: S1. 오픈에는 트랙 구조만 필요하며 세션은 TBA. 검증: 결제 1건 실거래 + 환불 1건. 기여: N14 하한 산정의 입력.
- **S5 회선·네트워크 구성**(S3·S4와 병렬) — 선행: S2 분기. 신청 후 개통 대기 중에 AP·게스트 정책을 병렬 구축. 검증: D-42 중간 확인 회신. 기여: C2.
- **S6 CFP·아젠다** — 선행: S4(오픈 이후). 크리티컬 패스 밖이므로 지연 시 TBA를 유지하고 판매를 멈추지 않는다. 검증: D-35 최종표 공개 + 예비 세션 2건.
- **S7 당일 운영 준비** — 선행: S4(명단), S5(네트워크). 스태프 브리핑, 등록 동선, 안전·보험·CoC 신고 절차, 배지 자재 선인쇄. 검증: D-2 등록 리허설.
- **S8 재투영 검증** — 선행: S1·S2의 견적. 실견적으로 그래프를 다시 투영해 D-값이 ±3일 넘게 움직인 항목을 문서에 반영한다. 기여: 관례 리드타임으로 관례 캘린더를 재생산하는 것을 막는 유일한 장치.

## 대안과 기각 사유

1. **관례 캘린더(D-90 장소 / D-60 CFP / D-30 아젠다) 채택** — 기각: 이 그래프에서 초청장(D-96)과 목표일 확정(D-112)이 관례 캘린더의 시작점보다 앞에 있다. 관례를 쓰면 C1이 시작 시점에 이미 늦는다. 부활 조건: 해외 연사 0명이고 장소가 업링크를 계약으로 보장하면 두 체인이 사라져 관례 캘린더가 그래프와 일치한다 — 그때는 관례를 쓴다.
2. **온라인·하이브리드 전환** — 기각: C2와 케이터링을 없애는 대신 스트리밍 벤더·이중 리허설이라는 새 제로슬랙 체인을 만들고, 코어 4명으로 현장과 온라인 두 행사를 운영해야 한다. 부활 조건: G2에서 회선 포기가 확정되고 **동시에** G1 기본값(2순위 계약)까지 실패하면 전환한다.
3. **대행사(PCO) 위탁** — 기각: 수수료가 스폰서 수입 0 가정 예산에 들어가지 않는다. 부활 조건: D-70까지 스폰서 입금이 자금 하한의 2배를 넘으면 등록·케이터링·인쇄 묶음만 위탁한다(크리티컬 패스에서 3노드 제거).

## "완료"의 판정 기준

1. **D-21 부하 리허설**: 실제 장소에서 동시 200 세션(스태프 단말 20대 + 트래픽 생성 스크립트) 조건에서 HTTPS 요청 실패율 2% 미만, 발표 스트리밍 업링크 5Mbps를 30분 연속 유지. 측정: 네트워크 담당이 iperf·요청 로그로 측정, 결과 파일 첨부. (5Mbps·2%는 임의값 → D-42 장소 실측치로 재산정.)
2. **D-2 등록 리허설**: 스태프 5명이 50인 모의 등록을 처리해 1인 중위 30초 이하, 최장 대기열 20명 이하. 측정: 타이머·계수기. (30초 = 200명을 개시 후 40분 안에 통과시키려면 데스크 5개 × 30초가 필요하다는 산출.)
3. **게이트 발동 기록**: G1~G6의 발동/미발동을 각 1행으로 기록한다. 전부 미발동이면 임계가 느슨했는지 점검한다(비발동 재해석 — safety-net 프레임에서 차용).
4. **그래프 자체의 판정**: D-day 이후 회고에서 실제로 일정을 밀은 노드를 이 그래프에 표시한다. 밀린 원인 노드가 전부 C1·C2 안이면 그래프는 유효했다. 하나라도 밖이면 "그래프가 틀렸다"를 명시적으로 기록하고 누락 엣지를 남긴다.
5. **재투영 이력**: S8 이후 실견적으로 갱신된 D-값 목록이 문서에 남아 있다(항목 0건이면 S8이 실행되지 않은 것으로 본다).

## 프레임 이탈 / 관성 회귀

- **CFP를 크리티컬 패스에서 이탈시킨 처리가 편의적이다.** "그래프의 실제 기여" 엣지 ①은 CFP 지연이 판매를 막지 못한다고 썼지만, 실제로는 아젠다 부재가 판매 속도를 떨어뜨려 G5를 통해 간접 전파한다. 그 간접 엣지를 그리지 않고 "이탈"로 처리했다 — 프레임을 느슨하게 쓴 지점이다.
- **좌석 노드에는 버퍼 통화가 하나도 붙지 않았다.** 초과판매를 정직한 공백으로 남긴 결과(가정 4), 판매 200 = 좌석 200이 되어 노쇼가 그대로 손실이다. 방향·수량 어느 통화도 붙이지 못했고, 대신 케이터링 하한으로만 우회했다.
- **리드타임 6주·10주는 출처가 없다.** 태그(견)를 붙이고 이동 방향까지 적었지만(가정 2), 그 두 숫자가 D-70·D-96을 결정하므로 캘린더 투영은 실견적(S8) 전까지 관례 재생산 위험을 표시만 한 상태다. 이 문서에서 가장 약한 부분은 캘린더 투영이다.
- **리스크 표의 항목 3개가 그래프에 통합되지 않았다.** 커버리지 스윕(돈/법/사람/보건/보안/커뮤니티/평판)에서 건진 법·보건·커뮤니티 3행은 완화 칸이 "문서 확보·담당자 지정" 수준이고 게이트 기본값이 없다. 노드·엣지로 내려가지 못하고 표에만 남았다. 내가 리뷰어라면 이 3행부터 공격한다.
- 관례 대비 새로 넣은 판단은 초청장을 계약 전에 보내는 엣지 절단과 비자 범위를 게이트로 분기시킨 것 두 개이며, 나머지 구조는 이벤트 운영의 정석과 대체로 일치한다.
