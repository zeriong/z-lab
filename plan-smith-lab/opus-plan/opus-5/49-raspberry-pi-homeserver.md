# 라즈베리파이 1대로 돌리는 홈서버 스택
- 추론 프레임: constraint-first
- 한 줄 요약: 벽 5개(RAM·SD 수명·전기·소음·가족 눈치)를 먼저 세워 교집합을 판정한 뒤, 살아남은 4개 서비스만 USB-SSD 위에 올리고 오프사이트 백업과 외부 감시는 숫자 한도가 붙은 클라우드 가정으로 명시 선언한다.

## 프레임이 요구하는 시작점 — 벽 세우기와 모순 판정

### 벽 5개, 그리고 각 벽이 실제로 물리는 차원

| 벽 | 선언값 | 실제로 무는 차원 |
|---|---|---|
| W1 RAM | 4GB 중 가용 = 4GB − OS 오버헤드 (잠정 3.2GB, **수명한정**: S0 `free -m` 실측으로 교체) | 총량이 아니라 **동시 활성 서비스 수** |
| W2 SD 수명 | 소비자용 카드 TBW 미공개 → 잠정 상한 1GB/일 (**임의 선언**, S3 24시간 실측으로 교체) | 총 쓰기량이 아니라 **쓰기 국소성**(어느 장치에 쓰는가) |
| W3 전기 | 월 3,000원 (**임의 선언** — 가족 눈치의 대용치. 위반 시 서비스 1개 정지) | 파이 본체(10W×720h≈7.2kWh, **파생**)가 아니라 **상시 회전 주변장치** |
| W4 소음 | 23~07시 청감 불가 | 절대 dB가 아니라 **가동부(팬·플래터)의 유무** |
| W5 가족 눈치 | — | 숨은 벽 3개: (a) **경로 의존성** — 가족 사용 경로가 파이를 통과하면 안 됨 (b) **시간대** — 19~23시 장애·재부팅 금지 (c) **나의 부재** — 가족이 할 수 있는 복구 동작은 전원 재인입 1개뿐 |

W5는 요구 안에 묻혀 있던 벽이다. 명시 전에는 "취향"으로 보이지만, 분해하면 아래 판정 3건 중 2건을 결정한다.

### 판정 대상 후보 목록 (budget-allocation의 오프닝을 차용 — 일부러 예산 초과로 작성)

이 프레임은 법정이지 아이디어 원천이 아니므로, 벽보다 큰 후보 목록을 먼저 세운다.
① Vaultwarden ② Immich 사진 백업 ③ 파일 공유(Samba)+원격접속 ④ Home Assistant ⑤ Pi-hole 가정 전체 DNS 광고차단 ⑥ Jellyfin 4K 트랜스코딩 ⑦ 3.5" HDD 4TB NAS + 3-2-1 백업 ⑧ Prometheus+Grafana+Loki ⑨ Minecraft 서버·Paperless OCR·다운로드 자동화 스택.

### 충돌 판정 3건 + 1

**V1 진짜 모순 — ⑤ Pi-hole.** 광고차단의 가치는 공유기 DHCP가 DNS를 파이로 지정할 때만 발생하는데, 그 순간 파이 장애 = 온 집 인터넷 사망(W5a)이고 복구자는 없다(W5c). "보조 DNS로 폴백"은 벽에 조용히 구멍을 뚫는 것이다 — 클라이언트가 두 DNS를 경합시키므로 차단이 무작위로 동작한다. 요구를 깎지 않고 **전제를 깬다**: "차단은 네트워크 계층에서 한다"를 버리고 기기 계층(내 기기 3대만 파이를 DNS로 지정)으로 옮긴다. 가족 기기의 보호는 실제로 사라지므로 **완화**로 신고한다.

**V2 벽 밖 요구(기각으로 충분) — ⑥ 4K 트랜스코딩.** Pi 4에는 HEVC 인코드 하드웨어가 없다. 모순이 아니라 능력 밖이므로 판정은 기각이면 끝난다. 정제하면 벽 안으로 들어온다: "거실 TV 앱이 직접재생하는 컨테이너·코덱만 서빙".

**V3 숨은 벽 사이의 진짜 모순 — ⑦.** 저장 매체 자체는 모순이 아니다. USB3 2.5" SATA SSD가 W2·W3·W4를 동시에 통과한다(무가동부, 약 2W). 여기서 모순을 선언하면 판정의 힘이 죽는다. 진짜로 교집합이 비는 것은 **오프사이트 사본**이다 — 3-2-1은 정의상 다른 장소를 요구하고, "1대" 제약 안에 다른 장소는 없다. 전제 깨기: "두 번째 사본을 내가 소유·운영해야 한다"를 버리고 클라우드 보조를 가정 A1로 정면 선언한다.

**V4 ⑧ 자기감시 역설.** 파이 위의 감시자는 파이가 죽으면 침묵한다. 그래서 감시는 성능 문제가 아니라 위치 문제이며, 반드시 파이 밖에 두어야 한다(A1의 두 번째 구멍).

### 정제 / 완화 대장 (정직 신고)

| 원 요구 | 처리 | 종류 |
|---|---|---|
| 가정 전체 광고차단 → 내 기기 3대 | 가족 기기는 실제로 무보호 | **완화** |
| 미디어 스트리밍 → 거실 TV 직접재생 코덱 한정 | 보호 대상을 TV로 명시, TV의 보장 불변 | 정제 |
| └ 같은 요구의 "외부에서 폰으로 시청" | 보호 대상에서 제외 | **완화** |
| 데이터 무손실 → SSD 원본 + 클라우드 오프사이트 | 사본 소유자를 분리 명시 | 정제(A1 조건부) |
| Home Assistant → 물리 스위치가 대체 가능한 기기만 등록 | 자동화 대상 축소로 경로 의존 0 | 정제 |

### 제약이 죽인 것 — 포기 목록

가정 전체 DNS 광고차단(W5a) / 4K 트랜스코딩·외부 원격 시청(W1·CPU) / 상시 가동 대용량 NAS(W3·W4) / Immich 얼굴인식 등 ML 기능(W1) / 자체 완결 오프사이트 백업(1대 제약) / 풀스택 관측(W1·W2) / Minecraft·Paperless·다운로드 자동화(W1 동시성·CPU·W5b) / **무인 자동 커널 업데이트**(W2 쓰기 + W5b 시간대에 동시 충돌 — 보안 패치만 자동, 재부팅은 월 1회 토요일 낮 수동).

## 문제 정의 / 목표

파이 1대로, 가족의 일상에 어떤 의존도 만들지 않으면서, 내가 잃으면 곤란한 데이터(비밀번호·사진·문서)를 보관·동기화하고 외부에서 접근한다. 스택은 Raspberry Pi OS Lite 64-bit + Docker Compose, USB-SSD 부팅(SD 슬롯 공백), 원격접속은 Tailscale 단독(포트포워딩 0), 백업은 restic → 클라우드.

## 명시적 가정

- **A1 (전체가 걸린 가정) 클라우드 보조가 허용된다.** 구멍 2개를 숫자와 함께 명시한다: ㉮ 오프사이트 백업 저장 — 월 5,000원 상한(**임의 선언**, S0의 현행 가족 클라우드 요금 확인 후 재산정) ㉯ 외부 하트비트 감시 — 무료 티어 한정. **어느 쪽이든 한도를 넘으면 계획 무효(재스코프)다.** 틀렸을 경우: 무손실 요구가 1대 제약과 다시 모순이 되어, 이 서버는 "원본 보관처"가 아니라 동기화·열람 노드로 축소된다. 최저비용 조기 검증 = S0에서 가족이 이미 쓰는 클라우드 용량·요금 10분 확인. 대체 경로 = 외장 SSD 두 번째 사본을 월 1회 사무실에 물리 로테이션(사람 의존이므로 보장 등급 하락을 신고).
- A2 하드웨어는 Pi 4B 4GB + USB3 SATA SSD, 팬 없음, 유선 이더넷. 틀리면(2GB·Wi-Fi 전용) S4 예산표 합이 깨져 서비스를 2개로 줄인다.
- A3 가족 중 누구도 파이를 운영할 수 없다. 틀리면 W5c가 풀려 복구 단일동작 제약이 완화되고 서비스 폭을 넓힐 수 있다.
- A4 라우팅·DHCP·DNS는 공유기가 전담하고 파이와 독립이다. 틀리면 W5a가 즉시 위반되고 S6 판정이 실패한다.
- A5 24시간 상시 가동이 필요하다. 틀리면(야간 정지 허용) W3·W4가 크게 풀리고 HDD 옵션이 부활한다.

## 접근 및 단계 (각 단계에 근거 벽/전제깨기를 태그)

- **S0 벽 실측** [W1~W5 전부] · 선행: 없음. 콘센트형 전력측정기 kWh, 유휴 `free -m`, 야간 소음(30cm 거리), 가족 2문항 인터뷰("무엇이 끊기면 화나는가" / "절대 금지 시간대"), 현행 클라우드 요금. 검증: 벽 표의 잠정값 잔존 0.
- **S1 부팅 매체를 SSD로 이전** [W2] · 선행: 없음(S0와 병렬). 검증: `lsblk` 루트가 SSD, SD 슬롯 물리적 공백(복구 이미지 카드는 서랍 보관, 쓰기 없음).
- **S2 복원 리허설을 먼저 세운다** [V3 전제깨기] · 선행: S1. 데이터가 쌓이기 전에 restic 저장소와 복원 경로를 검증한다. 검증: 더미 20개 왕복 후 sha256 전부 일치.
- **S3 쓰기 경로 격리** [W2] · 선행: S1. journald volatile, log2ram, tmpfs, 모든 볼륨·DB는 SSD, swap 1GB는 SSD. 검증: 24시간 후 SD 쓰기 0, SSD 일 쓰기 기준선 기록(이 값이 W2의 임의 상한을 대체).
- **S4 동시성 예산표** [W1] · 선행: S0. 서비스별 `mem_limit` 선언, 합 ≤ 가용 RAM × 0.8(0.8 = **임의 선언**, S6 이후 7일 실측 최저치로 재산정). 검증: 전 서비스 기동 후 available 최저 ≥ 400MB(**임의 선언**, 동일 대체), OOM 로그 0.
- **S5 서비스 4개 배치** [V1·V2 판정의 잔존물] · 선행: S3, S4. Vaultwarden / Immich(ML 비활성) / Samba+Tailscale / Home Assistant(등록 규칙 = 파이 전원을 뽑은 상태에서 물리 스위치가 동작하는 기기만).
- **S6 가족 경로 비의존 검증** [W5a] · 선행: S5. 전원 인출 30분(30분 = DNS 캐시 TTL과 모바일 앱 재연결 주기를 모두 넘기는 값 — **파생**). 이 테스트는 W5b와 충돌하므로, 저녁대는 가족 예고·동의 후 1회만 하고 이후 반복은 주말 낮에 한다. 같은 회차에 HA 등록 기기 전부를 물리 스위치로 재검증한다.
- **S7 외부 하트비트** [V4·W5a의 침묵 실패] · 선행: S2, S5(의존성상 S2 직후 가능). 백업·동기화 성공 신호를 파이 밖 무료 티어로 발신, 미수신 시 나에게 알림. 검증: 전원 인출 후 무료 티어 최소 주기 내(**파생**) 알림 도착.
- **S8 확장 게이트(기본값 = 거부)** [모든 벽] · 선행: S4, S6, S7. 신규 서비스 3조건: mem_limit 선언 / S6 재통과 / 일 쓰기 증가 ≤ 20%(**임의 선언**, 3개월 추이로 재산정).

## 대안과 기각 사유

- **파이 2대(감시·DNS 분리)** — 기각: "1대"는 하드 제약. 부활 조건: 가족이 실제로 파이 서비스를 쓰기 시작해 W5a가 이중화를 요구하면, 2대가 유일한 해다.
- **미니PC(N100)** — 기각: 주제 제약. 부활 조건: 트랜스코딩·ML 요구가 등장하면 파이는 구조적으로 불가이며, Compose 정의는 그대로 이식된다.
- **전부 VPS로 이전** — 기각: 로컬 네트워크·집 안 데이터라는 목적을 부정. 부활 조건: W3 월 상한이 3개월 연속 깨지면.
- **k3s** — 기각: control plane만으로 W1을 침식하고 W5c(복구 단일동작)를 깬다. 부활 조건: 노드 2대 이상.

## 리스크 & 완화

하드웨어: USB-SATA 어댑터 UASP 결함 → 검증된 모델 사용 + SD 복구 이미지 보관. 열: 팬 없음, 여름 실내 30도 → 주간 `vcgencmd get_throttled` 확인, 임계 시 서비스 1개 정지. 정전: UPS 없음 → 복전 자동 부팅 설정 + 보수적 쓰기 캐시. 보안: 포트 개방 0, Vaultwarden은 Tailscale 내부에만. 법·개인정보: 가족 사진의 사실상 관리자가 나 → 1회 서면 동의와 삭제 요청 창구 1개, 저작권 관련 다운로드 스택은 후보에서 배제. 측정 오염: 전기 판정을 청구서(누진·기후환경요금 혼입) 대신 콘센트 측정기 kWh로 한다.

누락 범주 점검 스윕에서 추가로 건진 것: SSD 폐기 시 데이터 파기 절차, ISP 약관·CGNAT(Tailscale 선택으로 이미 회피되어 별도 조치 불필요).

## "완료"의 판정 기준

1. **(필수 실측 판정) 월 1회 복원 리허설 — 클라우드 저장소에서 무작위 20개 파일을 복원해 sha256이 20/20 일치한다.** 측정자 = 나, 도구 = restic + `sha256sum`. 2회 연속 실패 시 A1 붕괴로 보고 계획 무효를 선언한다. (20개 = **임의 선언**, 첫 정기 리허설의 소요시간 실측 후 재산정.)
2. 30일 연속 가동 후 SD 슬롯 공백 유지 + SSD 일평균 쓰기 ≤ S3 기준선 × 1.2(**임의 선언**, 3개월 추이로 재산정). `smartctl` 총 기록량.
3. 7일간 available RAM 최저 ≥ 400MB, OOM 킬 0건(5분 간격 로그).
4. 전원 인출 테스트 통과 — 이 판정이 잡아내는 누출을 명시한다: 공유기 DHCP가 배포하는 DNS가 파이를 가리키게 된 경우 / HA 자동화가 조용히 필수가 된 경우. 판정 = 사후 질문에 이상 지목 0건 **그리고** S7 알림이 실제로 도착. 인출 창에서 드러나지 않는 잠식(가족이 Samba·Immich를 쓰기 시작)은 별도 측정: 지난 30일 접속 로그에 내 기기 외 클라이언트 0건.
5. 가족 1인이 문서 없이 전원 재인입만으로 15분 내(**임의 선언**, 첫 2회 실측 중간값으로 대체) 전 서비스 복귀, 2회 연속(2회 = **임의 선언**).
6. 콘센트 측정기 kWh × 한계단가 ≤ 월 3,000원.

## 프레임 이탈 & 관성 회귀

- W3의 3,000원과 판정 6의 상한은 근거 없는 임의값이고, 대체 트리거도 붙이지 못했다 — 가족 눈치를 숫자로 바꿀 대용치가 없어 골랐다. 실측으로 대체되는 것은 kWh 쪽뿐이다.
- S5의 HA 등록 규칙은 최초 등록 판단이 사람 몫으로 남는다. S6의 반복 재검증으로 지속성만 구조화했고, 첫 등록의 오판은 막지 못한다(보장 등급: 구조적 봉쇄가 아니라 예의 수준).
- 후보 목록 ⑨(Minecraft·Paperless·다운로드 스택)는 벽 이름만 붙인 한 줄 기각이다. 앞 8건과 판정 밀도가 다르다.
- 가장 약한 절은 리스크의 법·개인정보 한 줄이다. 내가 리뷰어라면 여기를 친다 — 가족 데이터 관리자 책임을 동의서 1장으로 처리했다.
- 최난 하위문제(오프사이트)를 가정 A1으로 수출했다. 굵게 표시하고 최저비용 검증과 대체 경로를 붙였지만, 수출 자체는 사실이다.
- 단계 태그 중 S5만 벽이 아니라 "판정의 잔존물"을 가리킨다 — 추적성이 가장 약한 지점이며, 서비스 4개 선정에 내 선호가 섞여 있다.
