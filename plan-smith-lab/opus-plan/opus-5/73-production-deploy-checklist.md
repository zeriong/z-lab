# 프로덕션 배포 전 체크리스트 설계
- 추론 프레임: checklist / 스타일: opus
- 한 줄 요약: 배포 당일에 남는 판단을 0으로 만들기 위해, 모든 판정을 "명령 출력 vs 미리 채운 기대값" 한 번의 비교로 압축하고 미분류 상황은 전부 배포 중단 한 갈래로 흘린다.

## 프레임이 요구하는 시작점 — 판단어 감사

내 반사적 습관은 "배포 전 확인 항목 20개"를 쓰는 것이다. 그 문장들은 전부 판단어로 끝난다 — 이 프레임이 정확히 금지하는 것이다. 그래서 먼저 쓰려던 표현을 압수하고 치환한다.

| 압수한 표현 | 나타나는 자리 | 치환 (감각/명령 조건문) |
|---|---|---|
| "헬스체크 확인, 이상 없으면 진행" | 기동 직후 (R2a) | `curl -sf $URL/healthz` 종료코드 0 **그리고** 출력에 `"status":"ok"` 포함 → 다음 줄. 둘 중 하나라도 아니면 폴백 |
| "확인한다" (전 항목) | 문서 전체 | 명령 출력을 `deploy-log.md`에 붙여넣는다. **붙여넣기 없는 줄 = 미통과** (체크마크는 판정이 아니다) |
| "지연이 증가하면" | 관측 | p99가 `클라이언트 타임아웃 ___ms`(C2에서 설정 파일에서 읽어 기입)를 넘는 샘플이 연속 2개 → 폴백. **2 = 반복의 최소 단위, 선언된 임의값**(1개는 단발 스파이크와 구별 불가) |
| "충분히 관측한 뒤 전환" | 카나리 | 카나리 요청 누적 500건 도달까지 대기. 500 = **초기 임의값**, 배포 3회 누적 로그로 재도출, 재도출 담당 = 릴리스 담당자 |
| "필요시 담당자에게 연락" | 협조 | C3의 이름표 순서 — 전화 벨 3회 무응답 → 대리자 → 대리자 무응답 → 실행자가 중단 권한 승계 |
| "신속히 롤백" | 사고 | 폴백 유형표의 명령 1줄. 그 외 어떤 명령도 금지 |
| "대부분 인스턴스가 올라오면" | 배포 후 | 버전 엔드포인트 카운트가 `기대 개수 ___`(C2 기입)와 **정확히** 일치, 아니면 폴백 |

## 문제 정의 / 목표

목표는 "좋은 배포"가 아니다. **배포 창구 안에서 사람이 새로 생각해야 하는 횟수를 0으로 만드는 것**이다. 대상은 HTTP 서비스 1개 + 관계형 DB 1개, 단일 리전, 트래픽 전환 수단이 존재하는 구성. 산출물은 두 문서다: 컴파일 문서(D-1까지, 심의를 여기서 다 태운다)와 런타임 문서(당일, 비교만 한다).

## 명시적 가정

- **트래픽을 새 버전에서 이전 버전으로 되돌리는 수단(플래그 또는 LB 가중치)이 한 명령으로 존재한다.** 틀리면 폴백에 도달할 수 없고 이 체크리스트 전체가 무효다. 가장 싼 조기 검증: C0에서 staging에 되돌리기 명령을 1회 실제 실행하고 출력을 붙여넣는다(문서 검토로 대체 불가). 깨진 세계의 대안 경로: 배포를 "점검 공지 + 정지 배포"로 재정의한다 — 다운타임을 대가로 폴백(이전 이미지 재기동)은 항상 도달 가능해진다.
- 배포 창구에 두 사람이 있다(실행자, 중단 선언 권한자). 틀리면 중단 권한이 실행자에게 승계되어 자기 작업을 자기가 죽여야 하고, 폴백 우회 확률이 올라간다.
- 스키마 변경을 두 번의 배포로 나눌 조직적 여유가 있다. 틀리면 제거형 변경을 한 배포에 담아야 하므로 C0②의 grep이 **항상** 걸려 컴파일이 실패하고, 이 체크리스트를 따르는 배포 자체가 성립하지 않는다(R1에 도달하지 못하므로 "비가역 R1"이라는 상태는 발생할 수 없다). 깨진 세계의 대안 경로: 이 문서를 버리고 "점검 공지 + 정지 배포 + 사전 백업 기반 복구 절차"로 전환한다 — 폴백의 단위가 초가 아니라 복구 시간(RTO)이 되므로, 그 값을 C2에 기입하고 공지 문안에 넣는 것이 조건이다.
- 관측 대시보드에 이전 배포 기준선 뷰가 저장돼 있다. 틀리면 R5의 비교 대상이 없어 판단이 되살아난다 → C2에서 뷰를 만들어 URL을 기입하는 것으로 흡수.

## 심의 섬 — D-1에서 태우고 런타임에는 비교 1개만 남긴다

배포일은 고민이 완전히 사라지지 않는 혼합 영역이다. 남는 고민 3개를 시간축으로 추방한다.

| 심의 섬 | D-1에 태우는 심의(산출물) | 런타임에 남는 비교 1개 |
|---|---|---|
| 오류율 상승이 우리 배포 탓인가 외부 탓인가 | 카나리군/기존군을 같은 시간축에 겹쳐 보는 대시보드 뷰 1개를 만들어 URL 고정 + 잡음 여유 `___pp` 기입 | 두 군의 오류율 차가 `___pp`(C2 기입)를 넘으면 폴백. 이 pp는 **초기 임의값**(잡음만으로 발화하는 것을 막는 여유), 배포 3회 로그의 무배포 구간 변동폭으로 재도출, 담당 = 릴리스 담당자. **두 군이 같이 올라도 폴백** (외부 장애 중 배포는 원인 분리가 불가능하므로 진행하지 않는다) |
| 마이그레이션 데이터가 맞게 들어갔나 | 신·구 컬럼 불일치 행 수를 세는 쿼리 1개를 확정 | 출력이 `0`이 아니면 폴백 |
| 일부 인스턴스만 새 버전인 상태를 용인할 것인가 | 용인하지 않기로 결정 + 카운트 명령과 기대 개수 확정 | 카운트 ≠ 기대 개수면 폴백 |

## 접근 및 단계

### 컴파일 창구 (D-1까지) — 의존 순서

- **C0. 폴백 도달 가능성 제작 (우선순위 0, 다른 모든 항목의 선행)**
  ① 되돌리기 명령을 staging에서 1회 실행 → 출력 첨부. ② 이번 배포의 마이그레이션에서 `DROP`/`RENAME`/`NOT NULL` 을 grep — 1건이라도 잡히면 컴파일 실패, 진행 금지. 추가(ADD COLUMN, NULL 허용)만 이번 배포에 넣고 제거는 다음 배포로 분리한다. ③ 이전 릴리스 이미지 태그를 고정하고 그 태그로 1회 기동. 검증: 세 명령의 출력이 `compile-log.md`에 존재.
- **C1. 폴백 유형 판별 파일** (C0 의존). 런타임 각 줄이 자기 이름을 `deploy-state`에 append하고, 전환 줄만 `SWITCHED`를 기록한다. 검증: staging 완주 후 `grep -c SWITCHED deploy-state` = 1.
- **C2. 감각 조건표의 빈칸 채우기** (독립·병렬). 타임아웃 ms, 기준선 뷰 URL과 p99 추출 쿼리/API 경로, 오류율 차 임계 pp, 정합성 쿼리, 인스턴스 기대 개수(신·구 각각), 폴백 도달 시간 상한 초, 폴백 비용 칸. 검증: 두 문서 전체에 `___` 문자열이 `grep -c` 0건.
- **C3. 사전 배정과 에스컬레이션** (독립·병렬). 실행자·중단 선언 권한자(실행자와 다른 사람)·각 대리자를 이름으로 고정. 런타임 협상 금지. 검증: D-1에 테스트 통화 1회, 통화 기록 캡처가 산출물(구두 합의는 산출물이 아니다).
- **C4. 리허설** (C0·C1·C2·C3 전부 의존). staging에서 런타임 문서만으로 완주 1회. 관찰자가 ⓐ 외부 질문 수 ⓑ 즉흥 판단 수를 센다. 이어서 관찰자가 임의 시점에 중단을 선언 — 유형 A 1회, 유형 B 1회 — 폴백 도달까지 초시계. 검증: 카운트 2개와 초 2개가 숫자로 기록.
- **C5. 리허설 무효 규칙** (C4 의존). 인프라 저장소에 커밋이 1건이라도 있거나 이미지 태그가 바뀌면 리허설은 무효 → C4 재실행. 날짜 유효기간을 쓰지 않는 이유: 날짜는 변경을 감지하지 못한다.

### 런타임 (배포 당일) — 비가역성 기울기 순서

시간순이 아니라 **되돌리기 비용이 낮은 것부터** 배열한다. R4가 경첩이고, 그 앞은 전부 사용자 무영향, 그 뒤는 전부 사용자 영향이다.

| 줄 | 명령 | 기대 출력 | 불일치 시 |
|---|---|---|---|
| R0 | 인프라 저장소 커밋 해시 비교 | C4 기록의 해시와 동일 | 폴백 A (리허설 무효) |
| R1 | 추가형 마이그레이션 실행 | 종료코드 0 | 폴백 A |
| R2a | 새 버전 기동(트래픽 0) 후 `curl -sf $URL/healthz; echo "exit=$?"` | `exit=0` **그리고** 출력에 `"status":"ok"` | 폴백 A |
| R2b | 새 버전 인스턴스 카운트 명령 (C2 기입) | 기대 개수와 일치 | 폴백 A |
| R3 | 정합성 쿼리 | `0` | 폴백 A |
| R4 | 카나리 → 누적 500건 → 전환(`SWITCHED` 기록) | 두 군 오류율 차 ≤ `___pp` | 폴백 A(전환 전) / B(전환 후) |
| R5 | 기준선 뷰의 p99를 쿼리/API로 추출 (C2 기입 경로, 예: `curl -s "$METRICS_API/query?q=___"`) | 타임아웃 `___ms` 초과 샘플이 연속 2개 미발생 | 폴백 B |
| R6 | 이전 태그 인스턴스 카운트 명령 (C2 기입, 예: `... --filter tag=$PREV_TAG --count`) | 이전 태그 기대 개수 `___`와 일치 (삭제는 다음 배포) | 폴백 B. 단 출력이 `0`이면 되돌릴 대상이 없으므로 C0③의 고정 태그로 재기동한 뒤 되돌리기 명령 |

## 미분류 상황 폴백 — 배포 중단 하나로 수렴

분류되지 않은 모든 상황(예상 밖 출력, 알 수 없는 알람, 사람 무응답, 시간 초과)은 예외 없이 **배포 중단**이다. 중단의 실행 형태만 두 가지이고, 유형 판별은 판단이 아니라 파일 읽기다.

`grep -c SWITCHED deploy-state`

- 출력 `0` → **유형 A: 정지**. 새 버전에 트래픽이 없으므로 아무것도 되돌리지 않고 멈춘다. 중단 비용 = 재배포 1회 `___분 × ___명` (C2 기입, 값의 출처는 C4 리허설).
- 출력 `1` → **유형 B: 되돌리기**. 되돌리기 명령 1줄. 중단 비용 = 되돌림 소요 `___초` (C4 초시계) + 재배포 1회.

비용을 이 표에 인라인으로 적는 이유는, "조금만 더 보자"의 유혹이 발생하는 지점이 바로 이 줄이기 때문이다.

## 대안과 기각 사유

- **자동 판정 게이트만 두고 사람 체크리스트를 없앤다.** 기각: 임계값 빈칸이 아직 하나도 측정되지 않았다 — 근거 없는 숫자를 자동화하면 오탐 중단이 사람 없이 반복된다. 부활 조건: 동일 체크리스트가 3회 연속 개입 없이 통과하고, 각 줄의 기대값이 쿼리로 표현된 상태 → 그 줄부터 자동화.
- **시니어 재량용 짧은 목록(5줄)으로 간다.** 기각: 판단어 감사가 압수한 표현이 전부 되살아난다. 부활 조건: 심의 섬 표의 3항목 중 하나라도 D-1로 옮기는 것이 원리적으로 불가능하다고 판명될 때 — 그 1항목에 한해 재량을 되돌린다.

## 리스크 & 완화

- 체크박스 극장(읽지 않고 체크) → 판정을 산출물 존재로 정의. `deploy-log.md`의 출력 블록 수가 런타임 줄 수와 다르면 배포는 미완이다.
- 폴백 우회 → 중단 선언 권한자를 실행자와 분리 + 비용을 폴백 표에 인라인 + R4 관측창을 시간이 아닌 요청 수로 고정(사람이 늘릴 수 없다).
- 임계값 오탐으로 무해한 중단 반복 → 연속 2회의 중단이 모두 사후 무해로 판정되면 해당 임계값 재도출(2회 근거: 1회는 우연과 구별 불가, 2가 반복의 최소 단위).
- 컴파일 문서 부패 → C5 무효 규칙(커밋 1건 기반).
- 다중 서비스·다중 리전 동시 배포 → 이 문서 범위 밖. 서비스 간 의존이 있으면 폴백 A가 상대 서비스에서 도달 불가일 수 있으므로, 그 경우 별 문서가 필요하다(측정하지 않은 영역).

## "완료"의 판정 기준

1. **이 서비스 배포 경험이 없는 엔지니어 1명이 런타임 문서만으로 staging을 완주한다 — 외부 질문 0회, 즉흥 판단 0회.** 관찰자가 세어 C4 기록에 숫자로 남긴다.
2. 유형 A·B 폴백 도달 시간이 각각 초 단위로 기록돼 있고, 두 값이 각각 C2에 기입된 고정 상한 `___초` 이하다. 상한은 최초 리허설 실측 + 여유로 조직이 **한 번** 정해 고정하는 값이며(이후 배포에서 실측값에 맞춰 올리지 않는다), 실측 > 상한이면 이 판정은 실패다 — C5 무효 시 재리허설의 실측값으로 다시 판정한다. 관측창은 요청 수로 고정돼 있어 소요 시간이 트래픽에 따라 변하므로 비교 대상으로 쓰지 않는다.
3. D-1에 실제로 채운 컴파일·런타임 두 문서(이 설계 문서가 아니라 그것을 서식으로 삼아 만든 배포용 문서)에 `___` 문자열이 0건이다(`grep -c`).
4. `deploy-log.md`의 출력 블록 수 = 출력을 내는 런타임 줄 수 = 8 (R0·R1·R2a·R2b·R3·R4·R5·R6 전부 명령 출력을 남긴다).

"배포 사고 0건"은 판정 기준으로 쓰지 않는다 — 폴백이 사고의 매체를 없애므로 정의상 자동 충족되는 순환 문장이다.

## 프레임 이탈 / 관성 회귀

- R5·R6은 비가역성 기울기가 아니라 순수 시간순이다(전환 이후에는 기울기가 평평해져 정렬 근거가 사라졌다). R0~R4의 정렬만 근거를 가진다.
- 가장 약한 곳은 C2의 검증 문장이다. 게이트가 `___`의 **개수만** 세기 때문에, 손으로 적은 그럴듯한 값과 C4 초시계가 만든 값이 똑같이 통과한다 — 숫자를 그 출처에 묶는 장치가 없다.
- 오류율 차 임계 `___pp`와 p99 연속 2개는 태그를 달았지만 태그의 내용이 "임의값 + 재도출 경로"다. 즉 첫 배포에서는 근거 없는 숫자로 작동한다는 사실을 감추지 못한다.
- 리뷰어라면 「리스크」의 마지막 항목을 공격할 것이다. 실제 조직에서 가장 흔한 배포는 다중 서비스 동시 배포이고, 거기서 폴백 도달 가능성이 서비스 간 의존으로 깨지는데 이 문서는 그것을 범위 밖으로 밀어냈다.
