# 순환 의존이 얽힌 백엔드 모듈 분리
- 추론 프레임: middle-out
- 한 줄 요약: "어떤 순환이 진짜 병목인가"를 8인일 캡의 분석 spike로 판정하고, 판정 전에는 어떤 분리 수술도 착수하지 않으며, 결과(A 코드 결합 / B 데이터·소유권 결합 / S 병목 아님 / U 판정 불가)에 따라 준비 단계와 수술 단계를 서로 다르게 실행한다.

## 프레임이 요구하는 시작점 — 판정 spike가 문서의 중앙이다

반사적 습관은 정적 분석으로 순환 목록을 뽑아 사이클 수를 0으로 만드는 일괄 제거 계획이었다. 사이클 개수는 고통과 비례하지 않으므로(사이클 하나가 파일 3개일 수도, 200개일 수도 있다) 이 프레임은 그 계획을 금지하고 문서 중앙에 **판정 장치**를 놓는다. 순환 목록은 산출물이 아니라 spike의 입력이다.

**진입 자격 게이트 — 둘 중 하나라도 실패하면 spike를 열지 않는다.**
1. **구속 합의**: 모듈 오너와 백엔드 리드가 "임계 미달이면 착수하지 않고 예산을 반환한다"에 서면 동의하고, 아래 임계표를 데이터 수집 **전에** 봉인한다(커밋 타임스탬프가 증거). 합의가 없으면 spike는 착수를 정당화하는 장식이 된다.
2. **측정 가능성**: 12개월치 git 이력·CI 로그·장애 티켓이 남아 있고 정적 분석 도구가 사이클을 출력한다.

**임계표(봉인 대상)**

| 항목 | 값 | 태그와 출처 |
|---|---|---|
| 착수 정당화선 | 후보 순환 1건이 **연 6인주 이상**의 낭비 | (a) 파생 — 승인된 분리 예산 6인주 ÷ 회수기간 12개월(회계연도). 둘 다 판정 대상 데이터와 독립인 재무 사실 |
| 낭비 추정식 | (경계 넘는 PR 수 × PR당 추가 시간) + (순환 때문에 재실행되는 CI 시간 × 월 머지 수) + 장애 복구 인시 | (a) 파생 — 세 항 모두 로그 실측 |
| PR당 추가 시간 | 경계 넘는 PR의 (첫 리뷰 요청→머지) 중위 시간 − 단일 모듈 PR의 동일 중위 시간. 변경 줄 수 3구간 층화, 동일 기간·동일 저자 풀 | (b) 수명 상한 — spike 중 구간별 5건 표본으로 확정 |
| 후보 진입 필터 | 경계 동시변경률 ≥ 30% | (c) 선언적, 근거 없음. 1차 사이클에는 근거 있는 값이 원칙적으로 불가. spike가 관측한 분포의 중위값으로 다음 사이클에 교체 |
| 우선순위 오버라이드 | 12개월 내 순환 기인 프로덕션 장애 ≥ 1건인 후보는 비용 순위와 무관하게 1순위이며 P1을 생략한다(존재가 이미 증명됨) | (a) 파생 — 비가역 피해 우선. 건수 1은 (c) 선언적 |
| spike 캡 | 2인 × 4영업일 = **8인일**. 초과는 실패가 아니라 "판정 불가(U)"라는 유효 결과 | (c) 선언적 — 분리 예산 30인일의 약 1/4. 실 소요를 기록해 다음 사이클에 교체 |

**감도(필수)**: 회수기간을 12→18개월로 늘리면 정당화선이 연 4인주로 내려가 2순위 후보가 착수선 위로 올라온다. 예산이 6→3인주로 깎이면 어떤 후보도 통과하지 못해 S가 기본이 된다. 진입 필터를 30→20%로 낮추면 후보 집합이 커져 순위를 재계산해야 한다 — 결론을 가장 크게 흔드는 숫자는 정당화선이 아니라 필터다.

## 문제 정의 / 목표

모놀리스 백엔드의 모듈들이 서로를 참조해 (1) 한 모듈만 고쳐도 상대 모듈이 함께 수정되고, (2) CI가 전체 테스트를 재실행하며, (3) 초기화 순서 의존 사고가 난다. 목표는 "순환 0"이 아니라 가장 비싼 결합 하나를 끊어 위 증상 중 실측된 것을 줄이는 것, 그리고 끊을 가치가 없다면 그 사실을 8인일 안에 확정해 6인주를 태우지 않는 것이다.

## 명시적 가정

- **(전체가 걸림) 순환의 비용을 12개월 사후 로그에서 읽어낼 수 있다.** 틀렸을 경우: 실제 병목이 있어도 후보가 임계 위로 못 올라가 S/U로 떨어진다. 가장 싼 조기 검증 = 0단계에서 커밋 30건 표본으로 동시변경 추출과 CI 로그 보존기간을 반일 확인. 폴백 = 전향 계측 2주(빌드 그래프 타이밍 + PR 라벨) 후 P1만 재실행, 그 기간 분리는 동결.
- DI 컨테이너·리플렉션·문자열 라우팅 등 정적 그래프에 안 잡히는 동적 의존이 소수다. 틀렸을 경우: 장애형 후보가 과소평가되어 오버라이드가 발동하지 않는다 → 장애 티켓 원인란을 별도 축으로 병행 검사.
- 분리 예산 6인주는 반환 가능한 성격이다. 틀렸을 경우: 중단 분기가 정치적으로 불가능해져 판정이 장식이 된다 → 진입 게이트 1 실패로 처리.
- 모듈 경계를 넘는 DB 트랜잭션이 존재한다. 틀렸을 경우: B 분기 비용이 크게 하락하고 준비 단계가 짧아진다.

## 접근 및 단계

### 0단계 — 진입 게이트 (선행: 없음, 반일)
서면 합의 + 임계표 봉인 + 측정 가능성 표본 + 후보 순환 목록 스냅샷 1개.
검증: 봉인 커밋과 스냅샷 파일이 둘 다 존재. 실패 시 spike를 열지 않고 가정 폴백으로 이동.

### 1단계 — 판정 spike (선행: 0단계 산출물, 캡 8인일) · 프로브 순서는 존재 → 효능
- **P0 지표 오염 점검(0.5인일)** — 포맷팅·자동생성·머지 커밋 제외 규칙 확정 후 재추출. 검증: 제외 전후 상위 5 후보의 순위가 바뀌면 오염이 지배한 것으로 보고 제외 후 값만 쓴다. (행 0 발상은 hypothesis-loop에서 차용)
- **P1 존재 검증(2인일, 값싸고 결정적)** — 후보별 낭비 추정 + 리드타임을 대기/리뷰/재작업으로 분해. **하드 게이트**: 모든 후보가 연 6인주 미달이고 오버라이드도 없으면 P2를 실행하지 않고 S로 직행. 오버라이드 발동 후보는 P1을 생략하고 P2로 보낸다.
- **P2 효능·절단 가능성(3인일)** — 1순위 후보 하나에 대해 폐기 예정 브랜치에서 경계 인터페이스 추출과 의존 역전만 시도(동작 변경 금지). 검증 = 상대 모듈 소스 트리를 빌드 컨텍스트에서 물리적으로 제거하고 컴파일·해당 모듈 테스트 실행. **이 결과가 A/B를 가른다**: 통과 → A(코드 결합), 공유 테이블 쓰기나 경계 트랜잭션 때문에 실패 → B(데이터·소유권 결합). 산출물에 끊는 비용(변경 파일 수, 경계 트랜잭션 수, 테스트 수정량)과 남는 결합을 적는다.
- **P3 판정문(0.5인일)** — 분기 1개 + 감도 1줄 + 캡 소진 기록. 브랜치는 폐기한다(정상 경로이며 손실이다).

### 2단계 — 분기별 앞단계·뒷단계 (선행: P3 판정문)

**A 코드 결합.** 앞: 빌드 시스템 레벨 모듈 경계 강제 도구 도입(검증: 고의 위반 커밋 1건이 빌드 실패로 잡힘) + 테스트 분할 기준선 실측. 뒤: 인터페이스 추출·의존 역전을 본선 반영(검증: 본선 소스 트리 제거 빌드 통과, CI 평균 대기 시간 비교).

**B 데이터·소유권 결합.** 앞: 테이블 × 모듈 쓰기 매트릭스와 경계 트랜잭션 목록(검증: 빈 칸 없음 — 모든 테이블이 단일 소유자 또는 '미결' 라벨). A 분기에는 이 준비가 필요 없다. 뒤: 쓰기 소유권 이전(읽기는 API/뷰, 쓰기는 소유 모듈만), 경계 트랜잭션을 단일 트랜잭션 재배치 또는 보상 경로로 전환(검증: 목록 전건 대조 + 비소유 모듈 쓰기 시도 차단).

**오버라이드 적용 시**: A/B와 무관하게 부팅 시 순환 감지를 즉시 삽입해 사고 경로를 부팅 실패로 전환(검증: 과거 사고 재현 시나리오가 부팅 단계에서 드러남).

**S 순환은 병목이 아니다.** 예산 반환 기록 + 신규 순환 동결 게이트만 설치. 리드타임을 지배한 실제 원인(대기·리뷰 단일 병목 등)은 별도 항목으로 이관.

**U 판정 불가(캡 소진).** 행동은 S와 같지만 이유가 다르다: 비가역성 비대칭에 따라 되돌리기 싼 쪽이 기본이다(모듈 분리는 API 경계·데이터 소유권·배포 단위를 바꿔 비싸고, 동결 게이트는 설정 한 줄 제거). 재판정 트리거: 전향 계측 2주 후 P1만 재실행.

## 대안과 기각 사유

1. **마이크로서비스 추출부터** — 비용 미측정 상태의 최대 비가역 선택. 부활: 오버라이드가 2회 이상 반복 발동하고 조직이 별도 배포 단위를 확정할 때.
2. **순환 전부 일괄 제거** — 사이클 수와 고통이 비례하지 않는다. 부활: P1에서 상위 3후보의 추정 비용 차이가 2배 미만이면 우선순위가 성립하지 않으므로 균등 처리가 합리적이다.
3. **spike 없이 리드 판단으로 1순위 지정** — 존재 검증 없는 효능 작업. 부활: 오버라이드가 이미 성립하고 절단 수단도 과거 유사 수술 기록으로 알려진 경우 — 그때는 spike 전체가 낭비다.
4. **지연 import로 순환 우회(현행 유지)** — 초기화 순서 폭탄을 늘린다. 부활: 해당 모듈이 6개월 내 삭제 예정일 때.

## 리스크 & 완화

- **경계 트랜잭션 정합성 붕괴**(B): 목록 전건에 재배치/보상 경로를 지정하기 전에는 소유권 이전을 시작하지 않는다.
- **순환 재유입**: 동결 게이트를 기본 거부로 설치, 예외는 기존 구조 내 시도 실패 기록 첨부 시에만 통과.
- **spike 정치화**: 임계표 선봉인 + 서면 구속 합의(0단계).
- **지표 오염**: P0.
- **동적 의존 미검출**: 장애 티켓 원인란 병행 검사. 테스트 코드에만 있는 순환은 후보에서 제외하되 목록에 기록.
- **배포 lockstep**(B): 소유권 이전 기간을 구·신 경로 병존 창으로 감싸고 종료일을 명시.

## "완료"의 판정 기준

- (측정 가능·필수) **본선에서** 대상 모듈의 상대 모듈 소스 트리를 빌드 컨텍스트에서 물리적으로 제거한 상태로 컴파일과 해당 모듈 테스트가 통과한다. P2 폐기 브랜치의 결과는 이 판정에 쓰지 않는다.
- (측정 가능) 수술 후 60일간, 대상 순환의 두 모듈 중 하나만 건드린 PR을 착수 전 12개월 표본과 **동일 추출 규칙**으로 20건 뽑았을 때 상대 모듈 파일 동시 수정 비율이 착수 전 실측 기준선보다 10%p 이상 낮다. 측정 주체 = 모듈 오너, 도구 = git 이력 스크립트, 기준선은 P1 산출물에 고정. 동결 게이트는 신규 순환만 막고 동시변경률을 자동 만족시키지 못하므로 이 판정은 자기충족되지 않는다.
- spike 자체: 캡 8인일 내에 분기 1개 + 감도 1줄 + 봉인 임계표 대조 기록이 산출됐다. 캡 소진도 완료로 센다(U).
- S/U: 예산 반환이 기록되고, 동결 게이트 설치 후 60일간 차단 0건이면 고의 위반 PR 1건으로 게이트 작동을 점검한다(무차단을 성공으로 읽지 않는다 — safety-net에서 차용).
- 위 60일·20건·10%p, 대안 2의 "2배", 대안 4의 "6개월"은 모두 **(c) 선언적** 값이다. 60일 측정에서 얻은 동시변경률 분산을 기록해 다음 사이클에 표본 수와 하락 폭을 교체한다.

## 프레임 이탈 / 관성 회귀

- **진입 게이트가 절반만 게이트다.** "고통의 출처가 코드가 아니라 조직(리뷰 단일 병목, 팀 경계)"인 세계는 0단계가 아니라 P1의 리드타임 분해에서야 드러난다. 0단계를 데이터 가용성 확인으로 축소하고 S를 P1 직후 하드 게이트로 올리는 것까지 했지만 그 세계에서도 2인일은 이미 태워진다. 남은 잔여물이다.
- **결론을 가장 크게 흔드는 숫자가 근거 없는 숫자다.** 임계표 4행의 진입 필터 30%는 후보 집합과 순위를 결정하는데 태그가 (c)다. 감도 문단에서 그 사실을 밝히는 것 외의 방어 수단은 만들지 못했다.
- **수단 자체는 프레임이 만든 것이 아니다.** 2단계의 의존 역전·쓰기 소유권 분리·부팅 감지는 전부 업계 정석이다. 프레임이 만든 것은 "무엇을 먼저 증명하고 어느 것을 언제 하는가"와 P2의 소스 트리 제거 판정뿐이며, 도출이 아니라 배치다.
- **후퇴가 단계로 적히지 않았다.** 2단계는 준비→수술→확장으로 단조 상승하는데, 정상 경로에 있는 P2 브랜치 폐기라는 손실은 P3의 한 문장으로만 처리했다.
- **리뷰어라면 공격할 곳**: 임계표 3행 "PR당 추가 시간". 중위값 차이와 줄 수 층화까지 정의했지만, 차이가 순환 때문인지 경계 넘는 PR이 애초에 더 어려운 일이기 때문인지는 분리하지 못한다. 연 6인주 정당화선 전체가 이 귀속 위에 서 있다.
