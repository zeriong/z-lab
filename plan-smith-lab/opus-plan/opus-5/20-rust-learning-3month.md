# 백엔드 개발자의 3개월 Rust 학습 계획

- 추론 프레임: misconception-first
- 한 줄 요약: GC·스레드·인터페이스·예외에 길든 멘탈모델이 Rust에서 **언제 발화하는지**를 지도로 그리고, 그 발화 시점에 충돌 과제를 배치해 커리큘럼의 뼈대로 삼는다.

## 프레임이 요구하는 시작점 — 간섭 지도

내 반사적 습관은 "The Book 챕터 순서 + 주차 배분"으로 시작하는 것이고, 이 프레임은 그것을 금지한다. 시작점은 목차가 아니라 **선행지식이 배신당하는 지점의 목록**이다.

**정밀 조건 검사(프레임 적용 자격).** 이 프레임은 간섭할 선행지식이 있을 때만 유효하다. 0주차에 **간섭 진단**: 코드 스니펫 15문항(임의 · 1주차 실측 소요시간으로 재조정)을 보고 "컴파일 여부와 출력"을 먼저 종이에 쓰고 그 다음 실행한다. 오답 패턴이 아래 목록과 매칭되는 비율로 분기한다 — ≥60% 이 플랜 그대로, 40~60% 목록을 진단 결과로 교체 후 진행, <40% 간섭 가설 실패이므로 이 플랜을 폐기하고 순차 교재로 전환(세 임계값 모두 **임의 선언** · 진단 자체가 첫 실측이므로 그 결과로 대체).

**긍정 전이 자산(충돌 과제를 낭비하지 않는 영역).** 타입 사고, 트랜잭션 경계, 타임아웃·백프레셔 감각, HTTP/직렬화, SQL, 테스트 습관, 컨테이너 배포. 여기는 그냥 옮겨온다.

| ID | 선행지식 → 오개념 | 발화 시점(뇌관) | 과교정(2차) → 회복 |
|---|---|---|---|
| M1 | GC/`free` → "소유권은 메모리 관리 기법" (실제로는 **별칭 제어 규칙**) | 첫 이동 후 사용 에러 | "clone은 죄악" → 라이프타임 곡예 (S2) |
| M2 | Java 참조/Go 포인터 → "`&`는 핸들" | 순회 중 수정, 두 번째 `&mut` | 전부 값 복사 → S2 |
| M3 | nullable → "`Option`은 그냥 null" (반쯤 맞아 위험) | `unwrap()` 남용 | `match` 남용·조합자 회피 → S2 |
| M4 | checked exception → "`Result`=예외, `?`=throw" | 서비스 계층에서 에러 타입 3종 합성 | 에러 enum 과설계 → S6 |
| M5 | interface → "trait=interface" (고아 규칙·정적 디스패치 부재) | 외부 타입에 외부 trait 구현, `Box<dyn>` vs 제네릭 | 제네릭 과다 → 컴파일 시간 폭발 (S6) |
| M6 | 스레드/고루틴 → "async task는 경량 스레드" (실제로는 폴링되는 상태기계) | 블로킹 호출을 executor에서, `.await` 없는 future | "전부 async화" → S6 |
| M7 | "`Send`/`Sync`는 컴파일러 잔소리" | non-`Send` 값을 `.await` across | 과도한 `Arc` 포장 → S6 |
| M8 | 동기화된 공유 가변 상태 → "`Arc<Mutex<T>>`가 정석" | `MutexGuard`가 `.await`를 넘음 | "채널만 옳다" → 액터 남용 (S6) |
| M9 | "라이프타임 애노테이션이 수명을 연장한다" (실제로는 기술만 함) | 구조체에 참조 필드를 넣을 때 — **발화가 늦거나 아예 안 남** | 참조 필드 강박 → S6 |

## 문제 정의 / 목표

3개월(주 10~12시간 · **임의 선언** · 1주차 3회 실측으로 대체) 안에 백엔드 개발자가 Rust로 작은 서버(HTTP + DB + 백그라운드 워커)를 **오개념 없이** 설계할 수 있게 만든다. 목표는 문법 습득이 아니라 위 9개 간섭의 소거다. 측정하지 않는 것: 실무 투입 가능성, 성능, 코드 품질 일반.

## 명시적 가정

- **주 10~12시간 중 절반을 "예측을 먼저 기록하는" 느린 방식에 쓸 수 있다.** 틀렸을 경우: 예측 없이 충돌만 하면 프레임 전체가 튜토리얼 따라하기로 붕괴하고 이 문서는 무의미해진다. 최저비용 조기검증 — 1주차에 예측 시트 작성 시간을 3회 실측(회당 15분 초과 시 문항 15→6). 폴백 — 시간이 없는 주는 충돌 과제를 다음 주로 밀고 화물 채널만 돌린다(진도보다 충돌 밀도를 보존).
- 주력 언어가 GC + 런타임 계열(Java/Kotlin/Go/TS/Python 중 3년 이상). 틀리면: C++ 출신은 M1이 "라이프타임=RAII"로 대체되고 M9가 조기 발화 → 0주차 진단이 잡는다.
- 충돌 과제 공급원이 정답을 선노출하지 않는다. 틀리면 충돌이 해설로 퇴화한다.
- 12주차 산출물 서버 스펙에 뇌관이 실제로 들어 있다. 틀리면 M6~M8이 발화하지 않는다 → 스펙을 뇌관 체크리스트로 검수.

## 접근 및 단계

**순서 축(조작적 정의): 오염 전파 + 발화 시점.** 인접 쌍은 "X를 교정하지 않으면 Y 학습이 이렇게 오염된다"로만 정당화하고, 그럴 수 없는 쌍은 임의로 선언한다(S5 내부 M8/M9 순서는 **임의 선언** — 발화 선후 판별 불가). 난이도 순서는 금지 — 이 축이 난이도 순서와 실제로 갈라지는 곳은 세 군데다.

- **M9 강등**: 교재는 라이프타임을 초중반에 둔다. 발화 시점 분석으로는 소유 DTO만 쓰는 백엔드에게 8주 이후이거나 끝까지 안 온다 → S5로 내리고, 미발화면 학습하지 않는다.
- **M7 승격**: "고급"으로 분류되지만 M6과 **동시 발화**한다 → 같은 단계에 둔다.
- **발화≠교정 분리**: async 호기심은 2주차에 발화하지만 교정은 S4다. 그 사이 `Pin`/`Future` 수동 구현은 봉인한다.

**봉인 목록(지금 손대지 않는 것) / 해제 조건**

| 봉인 | 이유 | 해제 조건 |
|---|---|---|
| `unsafe`·원시 포인터·FFI | M1/M2 미교정 상태의 탈출구가 된다 | M1·M2 재시험 적중 ≥90%(임의) + 실제 요구 발생 |
| `Pin`·수동 `Future`·GAT·HRTB | M6 교정 전 접촉 시 "async는 마법"으로 고착 | S4 재시험 통과 후 |
| 성능 최적화·벤치마크 | "Rust=빠름" 기대가 소유권 학습을 최적화 문제로 오독시킨다 | 8주차 이후 + 실측 부하 존재 |
| 매크로 작성, diesel DSL 심층 | 화물이지 간섭이 아니다 | 12주 이후 |

봉인 목록은 읽기 목록 필터로도 쓴다(블로그·커뮤니티 유입 차단).

**충돌 과제 공급 규칙.** 예측자가 스스로 문제를 만들면 이미 답을 안다. 과제는 제3자에서 온다: 문제 은행(rustlings / Exercism / Too Many Linked Lists)이 1차, 지도에 맞춘 맞춤 뇌관은 **매 과제마다 새 컨텍스트**에서 생성한다 — 함정을 만든 쪽은 예측 파일을 본 적이 없고, 진단은 예측을 그 컨텍스트에 붙여넣은 **뒤에야** 생성된다(정답이 예측 이전에는 존재하지 않으므로 구조). 등급은 2 — 학습자가 별도 세션을 열어 우회할 수 있으므로 "기록 없이는 불가능"까지만 보장된다. 뇌관 없는 데이터는 배신을 못 만들므로 데이터도 설계한다: 중복 키, 1:N, 순회 중 수정, 동일 키 동시 갱신, 자기참조 구조.

| 단계 | 대상 | 선행조건(소비하는 출력) | 검증 |
|---|---|---|---|
| S1 (1–2주) | M1·M2·M3 | 0주차 진단 결과 | 예측 적중률 기록 + 소유권 이동을 말로 설명 |
| S2 (3–4주) | M4 + M1/M2/M3 과교정 회복 | S1 — 별칭 규칙 미교정이면 에러 설계가 clone 우회로 붕괴 | 에러 타입 3종 합성 과제 + clone마다 근거 주석 |
| S3 (5–6주) | M5 | S2 — `?` 변환을 모르면 trait 경계 설계가 에러 전파와 뒤섞인다 | 외부 타입 확장 과제에서 고아 규칙을 **사전에** 예측 |
| S4 (7–9주) | M6·M7 | S3 — dyn/제네릭 미교정 시 async trait 장벽을 async 탓으로 오독 | 뇌관 심긴 async 코드에서 컴파일 전 지적 |
| S5 (10–11주) | M8·M9 | S4 — M6 미교정 시 `await` 넘는 락을 락 문제로만 읽는다 | 공유 상태 3안(채널/이동/`Arc<Mutex>`) 비교 근거 문서 |
| S6 (12주) | 간격 재시험 + 과교정 회복 | 전 단계 | 아래 완료 기준 |
| 화물 채널 (상시·**병렬**) | 문법, cargo, clippy, 모듈, 크레이트 탐색 | 독립 | 매일 20분, 충돌 설계 없음 |
| 간격 재시험 (**병렬**) | 각 오개념 교정 후 +2주, +6주 | 해당 단계 | 백지 예측 재시험 (파생: 다음 단계 진입 후 1회, 두 단계 뒤 1회) |

## 대안과 기각 사유

1. **난이도 순 순차 교재** — 기각: 발화 시점과 학습 시점이 어긋나 라이프타임·`Pin`을 잠복 상태에서 배우고, 배운 것이 발화할 때 이미 잊혀 있다. **부활 조건**: 0주차 진단 매칭률 <40%(간섭 없음 = 프레임 무효).
2. **프로젝트 몰입형(바로 실전 서버)** — 기각: 뇌관은 만나지만 `clone`·`unwrap`·`Arc<Mutex>`로 전부 우회 가능해 오개념이 화석화된다. **부활 조건**: 주 20시간 + 상주 리뷰어 확보 시 12주를 6주로 압축(리뷰어가 우회를 차단하므로).

## 리스크 & 완화

- **위조 진도(clone/unwrap 우회)**: 근거 주석 없는 `clone`이 3개(임의) 이상이면 M1 재시험 강제.
- **사기 저하**: 주간 에러 로그에 에러를 오개념 ID로 태깅. 태깅 불가한 에러 비율이 오르면 학습이 아니라 헤매는 중이므로 화물 채널로 후퇴.
- **목록 자체가 틀림**: 목록은 가설. 2주마다 "예측되지 않은 오개념" 칸을 채우고 3건 초과 시 순서를 재도출.
- **측정 오염**: 크레이트 버전은 단계 시작 시 고정. 버전 불일치로 생긴 에러는 오개념 태깅에서 제외.
- **12주 후 착지처 없음(기술 감쇠)**: 4주차까지 12주 산출물을 팀 내부 도구 후보 중에서 선정해 실제 사용자를 확보한다.

## "완료"의 판정 기준

- **(실측 판정 문장)** 12주차에, 제3자가 뇌관 6개(블로킹 호출, `await`를 넘는 `MutexGuard`, non-`Send` 홀딩, 순회 중 수정, 고아 규칙 위반, `?` 에러 타입 불일치)를 심어 넣은 처음 보는 async 서버 코드 300줄을 받아, **컴파일러를 실행하지 않고** 60분 내에 5개 이상을 위치와 이유까지 지적한다. 컴파일러 출력이 개입하지 않으므로 봉인·규칙이 자동 충족시킬 수 없다. (6/5·300줄·60분 모두 **임의 선언** · 0주차 축소 리허설로 기준선 측정 후 대체.)
- 0주차 15문항 재시험에서 구 문항 ≥13, 신규 15문항 ≥10 (임의 · 0주차 기준선으로 대체).
- 간격 재시험이 모든 오개념에 대해 2회 이상 기록되어 있다.
- 봉인 해제 회계 문서 존재: 무엇이 언제 왜 풀렸는지. `unsafe` 0줄은 **봉인 준수 증거일 뿐 학습 성과가 아니다**(봉인이 매체를 제거하므로 순환).

## 프레임 이탈 / 관성 회귀

- **가장 약한 곳: 「접근 및 단계」의 S1→S2→S3.** 오염 전파로 도출했다고 썼지만 결과가 교재 순서와 같다. 프레임이 순서를 실제로 뒤집은 것은 M9 강등과 M7 승격 두 곳뿐이고, 그 세 단계에서는 관습을 프레임 위에 둔 것에 가깝다. 임의 숫자도 많다(진단 60/40, 90%, 13/15·10/15, 5/6, clone 3개) — 태깅은 규칙 준수이지 해결이 아니며, 폐기를 결정하는 40% 임계에 중간대를 넣은 것이 유일한 직접 수정이다.
- **상승 서사 회귀**: 과교정 회복을 S6에 몰아넣었다. 회귀는 교정 직후에 일어나므로 각 단계 뒤에 흩어야 옳았고, S2에만 부분적으로 흩었다.
- **리뷰어라면 공격할 곳: 「충돌 과제 공급 규칙」.** 새 컨텍스트 규칙으로 공급자를 구조화했지만 등급 2에 머문다(별도 세션 우회). 또 분량 상한 때문에 리스크를 5개로 줄여, 망라성은 이 문서의 약한 축이다.
