# 간헐적 API p99 레이턴시 스파이크 조사

- 추론 프레임: hypothesis-loop / 스타일: opus
- 한 줄 요약: 수정이 아니라 **재현 레시피**를 산출물로 삼고, "숫자 자체가 계측 산물"이라는 0행이 정산될 때까지 다른 어떤 데이터도 해석하지 않는다.

## 프레임이 요구하는 시작점

이 과제를 받으면 내 반사 습관은 GC 로그와 플레임 그래프를 먼저 켜는 것이다. 프레임은 그것을 금지한다 — 계측 산물 가설이 정산되기 전의 프로파일링은 증거가 아니다.

- **관측 사실:** 대시보드 p99 시계열에 간헐적 상승 구간이 있다. 그것뿐이다.
- **추측(사실 아님):** 실제 사용자 지연이라는 것 / 단일 원인이라는 것 / 반복 가능하다는 것 / 그 구간에 부하가 높았다는 것.
- **정직한 공백:** 스파이크의 폭·빈도·지속시간·영향 요청 수는 0단계 산출물이 나오기 전까지 기입하지 않는다. 인테이크 대시보드 수치를 여기 옮기면 0행 정산 전에 그 숫자가 유통된다.

### 가설 원장 (기각·승격 조건 사전 등록)

행 순서는 과제가 열거한 순서를 따르고, **실행 순서는 비용 열이 정한다: A열(R0·R3·R4·R5·R6의 로그 재계산분)을 1차 병렬 배치로 전부 돌린 뒤** B·C·D를 게이트 뒤에 둔다. A = 기존 로그 재계산(추가 부하 0), B = 이미 켜진 지표의 상관 분석, C = 신규 계측 배포, D = 부하 유도·제거.

| # | 가설 | 사전 등록 기각 조건 | 승격 조건(상관만으로는 불가) | 비용 |
|---|---|---|---|---|
| **R0** | **숫자가 집계·정의·쿼리의 산물**(파드별 p99의 평균, 스크레이프 창 > 히스토그램 버킷, 클라이언트 타이머 vs 서버 타이머, 저빈도 구간에서 단일 요청이 p99 결정, LB 로그와 앱 로그의 시작점 차이) | 원시 요청 단위 로그(샘플 아님)로 재계산한 p99이 대시보드 p99과 상대오차 10% 이내, **그리고** 스파이크 구간 요청 수 ≥ 200 | 원시 재계산에서 스파이크가 사라지거나 위치가 옮겨감 | A |
| R1 | 런타임 일시정지(GC/컴팩션) | 스파이크 구간과 겹치는 STW 정지 총합이 스파이크 상승분의 20% 미만 | 홀드아웃 문장 적중 또는 힙/컬렉터 단일 토글로 3/3 소멸 | B→D |
| R2 | 커넥션 풀 고갈(DB 또는 상류 HTTP 풀) | 스파이크 시각의 풀 대기 큐 최대값이 0이고 획득 대기 p99이 평시 대비 1.5배 미만 | 풀 크기 단일 변경으로 유도된 스파이크가 3/3 소멸 | B→D |
| R3 | 이웃 소음(CPU steal, 공유 디스크 크레딧, AZ 경합) | 스파이크가 호스트·AZ 축에서 균등 분포(상위 1개 노드 점유율 < 30%) | 전용 노드 이주 시 서명 소멸 | A→C |
| R4 | 재시도 폭풍(클라이언트 재시도 × 서버 큐 증폭) | 스파이크 구간 요청 수가 평시 대비 1.2배 미만이고 중복 idempotency 키 비율 상승 없음 | 합성 부하에서 재시도 정책만 켜고/끄고 서명 재현·소멸 | A→D |
| R5 | 특정 페이로드(대용량 배열, N+1 유발 필드, 역추적 정규식) | 페이로드 크기 십분위별 지연이 단조 증가하지 않고, 스파이크 요청의 형태가 평시와 구분 불가 | 캡처한 실제 요청 본문 재생으로 단독 재현 | A→D |
| R6 | 스윕 산출: 배치·크론 위상, 사이드카/mTLS, DNS·인증 서비스 | 크론 위상 축 재집계에서 군집 없음 **그리고** 사이드카 구간 지연이 총지연의 5% 미만 | 해당 작업 일정 이동으로 서명이 함께 이동 | A |

임계값 태그: 표의 숫자(10%·200·20%·1.5배·30%·1.2배·5%)와 아래 60초·70%·5일은 전부 **임의 선언**이며 수명은 0단계 재계산까지다 — 재계산 후 각 값은 평시 분포의 (평균 + 2σ, 이 기준선 자체도 임의 선언)로 교체하고 교체 사실을 원장에 남긴다. "3회 중 3회"는 **파생** — 1회 소멸은 자연 소멸과 구분되지 않는다. **수정 프로토콜:** 임계값을 사후에 고치면 해당 가설은 자동으로 "보류"로 강등되고 수정 사유·시각·수정자가 원장에 기록된다.

### 좌표계 의심 — 재집계 축과 그 결과

| 재집계 축 | 군집이 보일 때 승격되는 행 |
|---|---|
| 배포 시각 기준 상대 분 | R1(워밍업·JIT), R2(풀 재생성) |
| 호스트·노드·AZ 식별자 | R3을 즉시 1순위로 |
| 테넌트·API 키 | R5, R4(특정 클라이언트 SDK) |
| 페이로드 크기 십분위 | R5 |
| 크론·배치 위상(15분·1시간·일 단위 접기) | R6 |
| 커넥션 연령 | R2 |
| 테넌트 로컬 시간(UTC 균등이 로컬에서 뭉칠 수 있다) | R4, R6 |

## 문제 정의 / 목표

산출물은 세 개다: (a) R0 정산 결과, (b) 승격된 원인 1개 또는 정식 "판정 불가", (c) 명령 한 줄 수준까지 적힌 유도 절차와 제거 변수. 수정은 이 조사의 후속 작업이며 범위 밖이다.

## 명시적 가정

- **[전체가 걸린 가정] 스파이크는 단일 현상이다.** 틀렸을 때: 원장 전체가 두 현상의 평균을 쫓아 모든 행이 "약한 상관"으로 끝난다. 최저비용 조기 검증 = 재집계 7축 중 3축(호스트·테넌트·크론 위상)을 0단계 직후 실행. 폴백 = 군집 ≥ 2면 가정 폐기, **군집별 원장 재작성**(게이트 G1).
- **[전체가 걸린 가정] 원시 요청 단위 로그가 스파이크 시각까지 보존되어 있다.** 틀렸을 때: R0을 정산할 수 없어 착수 불가. 최저비용 조기 검증 = 0단계의 첫 행동인 로그 덤프가 곧 이 가정의 검증이다. 폴백 = 0단계를 계측 구축으로 대체하고 조사는 다음 스파이크까지 연기.
- 관측 예산(엔지니어 시간, 스테이징)이 있다. 틀렸을 때: 진단은 사치다 — 즉시 타임박스 소진으로 간주해 기본 행동으로 간다.
- 스테이징이 프로덕션 서명을 재현할 수 있다. 틀렸을 때: 승격이 프로덕션 유도만으로 가능해지고 별도 승인 게이트가 필요하다.
- 스파이크가 사용자 영향을 갖는다. 틀렸을 때: 조사 우선순위가 내려간다 — 0단계 산출물에 영향 요청 수를 기입해 함께 판정한다.

## 접근 및 단계 (의존 순서 · 복귀 간선)

- **0단계 — 원시 데이터 스냅샷 + R0 정산.** 선행: 없음. 첫 행동은 보존 만료 전 로그 덤프. 검증: 재계산 p99 vs 대시보드 p99, 구간 요청 수. **게이트 G0:** R0이 승격되면 대시보드 기반 논의 전부를 폐기하고 원장을 다시 쓴다(복귀 간선 1). 정산 전에는 R1~R6의 데이터를 해석하지 않는다.
- **1단계 — 좌표 재집계 7축.** 선행: 0단계. 비용 A이므로 7축 **전부 병렬**. 검증: 축별 군집 집중도. 프로파일링보다 먼저인 이유는 비용이 아니라 순서다 — 군집을 모르면 원장의 대상 모집단이 틀린다.
- **2단계 — 원장 확정 또는 분할.** 선행: 1단계. **게이트 G1:** 군집 ≥ 2 → 단일 현상 가정 폐기, 군집별 원장 재작성 후 1단계 복귀(복귀 간선 2). 아니면 순위 확정.
- **3단계 — 홀드아웃 문장.** 선행: 2단계. 상위 2행에 대해 "아직 보지 않은 구간(직전 주 동일 요일)에서 무엇이 보일 것인가"를 **먼저 적고** 데이터를 연다. 불발 시 그 행은 "보류"이며 상관 데이터로 되살리지 않는다.
- **4단계 — 유도·제거.** 선행: 3단계에서 적중한 행만. 단일 변수 토글 3회. 검증: 3/3 소멸. 실패 시 2단계 복귀(복귀 간선 3).
- **5단계 — 재현 레시피 문서화.** 선행: 4단계. 검증: 미참여 엔지니어가 문서만으로 유도 성공.
- **소멸/판정 불가 기본 행동.** 타임박스 = 엔지니어 5일 또는 전 행 기각·보류. 사전 정의 출력: ① "판정 불가"를 정식 결론으로 승인, ② 원인 불명에도 되돌릴 수 있는 완화 1건(요청 단위 타임아웃 + 재시도 예산 상한)만 적용, ③ 다음 스파이크용 상시 캡처 트리거(서명 감지 시 요청 본문·풀 상태·STW 로그 동시 덤프). 완화를 원인 규명으로 기록하지 않는다.

## 대안과 기각 사유

1. **전면 계측 확충 후 관찰** — 기각: 가설 없는 계측 살포는 이 프레임의 실패 모드이고, 0행을 건너뛴 계측은 오염된 숫자를 더 정밀하게 만든다. **부활:** 0단계에서 원시 로그 부재가 확인되면 0단계가 계측 구축으로 대체된다.
2. **즉시 완화 동시 투입(풀 2배 + 힙 플래그 + 백오프)** — 기각: 원인이 소멸하면 재현 레시피가 영구 상실되고 어느 변경이 들었는지도 모른다. **부활:** SLO 위반·매출 손실 등급이면 triage로 전환 — 단 완화 전에 증거 스냅샷을 뜬다.
3. **클라우드 벤더 티켓 선행** — 기각: 이웃 소음은 7행 중 1행이며 근거 없는 티켓은 회신 대기로 타임박스를 먹는다. **부활:** 호스트·AZ 축에서 노드 점유율이 임계를 넘으면 R3을 1순위로 올리고 즉시 연다.

## 리스크 & 완화

- **조기 수렴(GC 편애):** 실행 순서를 비용 배치로 고정, 승격은 홀드아웃 또는 유도·제거만 인정.
- **loop가 사다리로 납작해짐:** 복귀 간선 1·2·3을 게이트로 명문화 — "loop" 라벨은 방지 장치가 아니다.
- **임계값 사후 조정:** 수정 프로토콜(강등 + 기록)로 집행.
- **조사 중 스파이크 자연 소멸:** "판정 불가" 기본 행동 + 상시 캡처 트리거.
- **유도 실험이 프로덕션 사고를 유발:** 스테이징 우선, 프로덕션 유도는 승인 게이트 + 즉시 중단 조건.
- **누락 범주 점검 스윕(작성 후 실행), 각 항목의 착지처:** 보안(WAF·TLS·인증) → R6 / 인프라 외부(DNS·사이드카) → R6 / 조직(배포 창·크론 일정) → 재집계 축 / 비용(APM 샘플링·로그 보존) → 0단계 스냅샷 범위 제한 / 법·규제(원시 로그 PII 접근 승인) → 0단계 선행 작업 / 사람(조사자 1인 병목) → 홀드아웃 문장을 제3자에게 봉인 보관.

## "완료"의 판정 기준

- **실측 판정 문장:** 스테이징에서 프로덕션 서명(스파이크 전후 60초 창의 p99 상승분이 관측치의 70% 이상)과 일치하는 스파이크를 유도하고, 명명된 단일 변수 하나만 토글해 **3회 중 3회** 소멸시킨다.
- 미참여 엔지니어가 재현 레시피만으로 스파이크를 유도한다(외부 질문 0회).
- R0 정산 결과가 "산물이었다/아니었다" 중 하나로 문서에 확정되어 있다.
- 금지: "N일간 스파이크 0"은 트래픽 변화만으로도 충족되므로 완료 기준이 아니다.
- 정당한 다른 완료: "판정 불가"가 기본 행동 3항목과 함께 기록된 상태.

## 미해결 질문

- **컨트랙트 충돌(연성):** 컨텍스트 패킷 경로가 전달되지 않아 호출 프롬프트를 패킷으로 취급했다. 실제 패킷의 제약(SLO 수치, 스택, 로그 보존 정책)이 이 계획과 충돌하면 0단계 전 재조정이 필요하다.
- 스파이크의 실제 폭·빈도·영향 요청 수는 공백이다 — 추정치를 채우지 않은 것은 결정이다.
- 프로덕션 유도 실험의 승인권자 미정. 4단계 착수 전 확정 필요.

## 프레임 이탈 & 관성 회귀

- 0~5 단계 번호가 사다리로 읽힌다. 실제 병렬은 1단계 내부(7축)뿐이고 나머지는 게이트 연결인데 문서 형태는 계단이다. 복귀 간선 명문화로 부분 보정, 형태는 미해결 — 가장 약한 지점.
- 원장 표의 임계값 전부가 단일 교체 시점(0단계)에 매달려 있다. 개별 근거를 세우려 했으나 실측 없는 근거는 위조가 되므로 태그 부착에서 멈췄다. 리뷰어라면 원장 표 하단을 먼저 때릴 것이다.
- R6이 세 범주(크론·사이드카·DNS)를 한 행에 묶어 다른 행과 대칭이 아니고 기각 조건도 뭉툭하다. 스윕 산출을 원장에 착지시키려다 행 단위가 커졌다.
- 완화안(요청 타임아웃 + 재시도 예산 상한)은 조직이 소화 가능한 관습적 선택이며 프레임이 도출한 결론이 아니다.
