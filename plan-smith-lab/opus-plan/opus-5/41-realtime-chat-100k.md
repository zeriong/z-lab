# 동시접속 10만 실시간 채팅 인프라 — 자릿수부터

- 추론 프레임: envelope / 스타일: opus
- 한 줄 요약: 전달 10^4/s·저장 10^2 GB/일·비용 10^3~10^4 $/월이 이 서비스의 자릿수이고, 그 안의 병목은 대역폭도 메모리 총량도 아니라 **재접속 순간의 수립률**이므로, 설계의 중심은 폭풍 생존 장치와 7개 재설계 트리거다.

## 1. 프레임이 요구하는 시작점 — 자릿수 계산

이 절에서는 제품명·구성요소명을 쓰지 않는다. 단위 명사(연결, 메시지, 방, 수신자, 바이트, 초, 코어, 행, 노드)만 쓴다.

**손으로 고른 입력 7개:** 동시 연결 10만(주어짐) · 발신율 1 메시지/분/연결 · 첨두 계수 3배 · 평균 팬아웃(수신자 수) 10 · 메시지 300 B 저장·400 B 전송 · 평균 세션 20분 · 계정당 발신 상한 30/분. 노드는 6대(대당 16,700 연결).

| 축 | 율(rate)로 읽으면 | 총량으로 읽으면 | 뒤집히는 판단 |
|---|---|---|---|
| 인바운드 | 10만/60 ≈ **1,700/s**, 첨두 5,000/s | 1.4억 메시지/일 | 수신은 한 자리 서비스 규모 — 인바운드 최적화는 범위 밖 |
| 전달(팬아웃) | 1,700×10 = **17,000/s**, 첨두 **50,000/s** | 15억 전달/일 | 전달이 인바운드의 10배 — 설계 하중은 여기 |
| 아웃바운드 전송 | 6.7 MB/s(≈54 Mbps), 첨두 160 Mbps → 노드당 27 Mbps | **17.4 TB/월** | 율로는 사소, 월 총량으로는 비용 1위와 동급 → 압축은 성능 대책이 아니라 **비용 대책** |
| 연결 유지 메모리 | — | 연결당 10 KB → 총 **1 GB**(노드당 167 MB). 버퍼 기본값 128 KB여도 노드당 2.1 GB | **노드당 8 GB에 닿으려면 480 KB/연결이 필요**하다 → 노드 수를 정하는 것은 메모리가 아니라 전달률과 장애 반경 |
| 연결 수립 | 정상 10만/1,200초 = **83/s** → 0.12 코어. 폭풍(30초 창) 3,300/s → **5 코어**. 무지터(5초) 20,000/s → **30 코어**. (수립 1회당 암호 협상 1.5 ms 가정) | — | 총량에서 사소했던 축이 율로는 지배적 → **지터가 필수 장치** |
| 이력 조회 | 정상 83×50행 = 4,200 행/s(쓰기의 2.5배). 폭풍 3,300×50 = **165,000 행/s**(쓰기의 100배) | 30일 핫 2.7 TB | 100배는 버스트에만 존재 → 상주 사본은 성능 개선이 아니라 **폭풍 생존 장치** |
| 저장 | 쓰기 1,700행/s, 첨두 5,000 | 43 GB/일 → 색인·복제 2배 = **90 GB/일**, 30일 2.7 TB, 3년 100 TB | 저장은 율 문제가 아니라 **보존 기간 문제** |

7축 중 5축만 양방향으로 읽힌다. 메모리에 율이 없고 수립에 총량이 없는 그 비대칭이 결론이다 — 같은 자원(연결)이 총량으로는 사소하고 율로는 지배적이다.

**월 비용:** 전송 17.4 TB × $0.09/GB ≈ $1,570 · 연결 노드 6대 ≈ $1,500 · 이력 저장 2.7 TB + 저장 노드 ≈ $1,000 · 상주 사본 1대 ≈ $250 → **합 ≈ $4,300/월(10^3.6)**. 전송과 연결 노드가 같은 자릿수다.

## 2. 문제 정의 / 목표

동시 연결 10만을 유지하며 방 단위 메시지를 첨두 5만 전달/s까지 p99 500 ms 이내로 넘기고, 30일 이력을 조회 가능하게 보관한다. 목표는 "빠른 채팅"이 아니라 **위 자릿수가 유지되는지를 스스로 감시하는 인프라**다.

## 3. 명시적 가정

| # | 가정 | 틀렸을 경우의 영향 |
|---|---|---|
| A1 | **평균 팬아웃은 10 자릿수이며, 1방 1만 명급 방송 트래픽은 없다** | 전달률이 두 자릿수 뛰어 설계 범주가 바뀐다(방 단위 소유 분할이 1일차 항목). 조기 검증: 방 정원 상한 1일 내 질의 + 파일럿 방 인원 히스토그램. 폴백: 방 식별자의 **단일 소유점**을 처음부터 유지해 방 단위 이전이 재작성 없이 가능하게 남긴다 |
| A2 | 텍스트 전용, 첨부는 별도 계열 | 평균 3 KB를 넘기면 저장·전송 결론이 10~100배로 무효 |
| A3 | 계정당 발신 상한 30/분 존재 | 없으면 인바운드에 수학적 상한이 없어 1,700/s 전제가 무의미 |
| A4 | 10만은 단일 리전의 최대 동시치 | 전 세계 합계면 리전당 자릿수가 내려가 노드·비용 과대 산정 |
| A5 | 평균 세션 20분 | 3분이면 정상 조회 7배(28,000행/s) — 상주 사본이 정상 경로에서도 필수 |
| A6 | 법정 보존 의무 없음(자율 30일) | 3년이면 100 TB — 콜드 계층이 1일차 항목 |
| A7 | 순서는 방 단위 단조, 중복 허용(수신 측 멱등 키) | "유실 0·중복 0"이면 발신 지연이 저장 지연에 종속 |

## 4. 접근 및 단계 (번호는 순서가 아니라 식별자 — 선행 표기를 따른다)

- **S0 입력 확정** (선행: 없음). 법정 보존·방 정원 상한·발신 상한은 질의로, 발신율·팬아웃·세션 길이·메시지 크기·첨두 계수는 계측 하니스로. *검증:* 7개 입력 중 5개가 실측/확답으로 교체됨.
- **S1 연결 유지 단층** (선행: 없음 — S0과 병렬). 1,000→16,700 계단 부하에서 연결당 상주 바이트 기울기 측정. *검증:* 실측 KB/연결이 10 KB의 2배 이내. 벗어나면 T2 발화.
- **S2 팬아웃 경로** (선행: S1의 KB/연결, S0의 방 인원 분포). *검증:* 합성 5만 전달/s를 10분 지속해 전달 p99 ≤ 500 ms, 그리고 방 식별자 단일 소유점이 코드 경계로 존재함을 확인(A1 폴백의 실체).
- **S3 영속화** (선행: S0의 메시지 크기 — S2와 병렬). *검증:* 5,000 쓰기/s를 30분 지속, 일 증가량이 추정 90 GB ±30% 내.
- **S4 폭풍 생존** (선행: S1·S2·S3). 재접속 지터, 수립률 게이트, 폭풍 시 이력 조회 축소 모드(50행→20행 자동 강등). *검증:* §10의 1번 문장. 이때 암호 협상 CPU를 실측해 §1의 1.5 ms를 교체한다.
- **S5 계기판·트리거 배선** (선행: S1~S4가 정의한 지표). *검증:* 7개 트리거에 합성 값을 주입해 알림 도달 + 착수 항목 링크 7/7.

## 5. 민감도 표 — 무엇이 결론을 뒤집는가

| 입력 | 기준 | 뒤집히는 지점 | 뒤집히는 결론 |
|---|---|---|---|
| 팬아웃 | 10 | **≥ 20** (첨두 10만/s) | 단일 소유 프로세스 팬아웃 폐기 → 방 단위 소유 분할 |
| 발신율 | 1/분 | **≥ 2.5/분** (저장 225 GB/일) | 핫 전량 30일 보존 폐기 → 콜드 이관 |
| 첨두 계수 | 3배 | **≥ 6배** | 팬아웃 20과 동일 결과 — T1 발화 |
| 연결당 상주 | 10 KB | **≥ 480 KB** (노드당 8 GB) | 노드 수가 메모리로 결정됨. 기본 버퍼로도 도달하지 않으므로 이 축은 감시만 하고 설계를 바꾸지 않는다 |
| 세션 길이 | 20분 | **≤ 5분** | 상주 사본이 정상 경로 필수 |
| 재접속 창 | 30초 | 수립률 **≥ 5,000/s** | 입장 대기열 도입 |
| 조회 깊이 | 50행 | **≥ 200행** | 폭풍 구간 즉시 불가 → 축소 모드 상시화 |
| 메시지 크기 | 300 B | **≥ 3 KB** | 전 자릿수 무효, 새 계열로 재작성 |
| *(비수치)* 보존 의무 | 없음 가정 | 법무 회신 | 계산과 무관하게 콜드 계층 1일차 확정 |
| *(비수치)* 유실 허용 | 중복 허용 | 품질 요구 확정 | 인바운드 경로가 저장 지연에 종속 |
| *(비수치)* 국외 이전·삭제권 | 미확인 | 규정 확인 | 리전 배치와 삭제 경로가 강제됨 |
| *(비수치)* 예산 승인 한도 | 미확인 | 재무 확정 | 계산은 $4,300/월을 내놓지만 승인선이 낮으면 보존 30일→7일이 먼저 잘린다 |

## 6. 재설계 트리거 (사전 확약)

| # | 발화 조건 | 착수 | 임계 근거 |
|---|---|---|---|
| T1 | 10분 지속 전달률 ≥ 100,000/s | 방 단위 소유 분할 | 도출 — 설계 첨두 5만의 2배(자릿수 여유 소진점) |
| T2 | 관측 상주 ≥ 40 KB/연결 | 버퍼 설정 회귀 점검, 필요 시 노드 증설(코드 최적화 금지) | 도출 — 설계 예산 10 KB의 4배, S1 검증선(2배) 초과점 |
| T3 | 저장 증가 ≥ 150 GB/일, 4주 연속 | 콜드 이관 | 도출 — 추정 90의 1.67배 |
| T4 | 월 전송 청구 ≥ $3,000 | 전송 압축 + 배치 전달 | 도출 — 추정 $1,570의 약 2배 |
| T5 | 관측 수립률 ≥ 5,000/s | 입장 대기열, 지터 폭 확대 | 도출 — 7.5 코어 소모점(1.5 ms 가정 위) |
| T6 **하향** | 동시 연결 p95 ≤ 10,000, 8주 연속 | 지속 연결 계열 **철수** → 주기 조회로 회귀, 노드 6→1 | 도출 — 그 규모에서 대안 A의 요청률이 5,000/s로 떨어져 지속 연결의 이점이 비용을 못 넘김 |
| T7 **하향** | 90일간 최대 방 인원 ≤ 50 | 방 분할 백로그 삭제 | 도출 — 팬아웃 20 미달이면 T1이 영구 미발화 |

관측 창(4주·8주·90일)은 **임의값**이다 — 계절성 1주기를 못 봤다. 첫 분기 리뷰에서 실측 주간 변동계수로 재도출한다.

## 7. 손으로 고른 값의 수명

| 입력 | 계측 | 시점 | 담당 |
|---|---|---|---|
| 발신율·팬아웃 | 인바운드 카운터 ÷ 연결시간, 방 인원 히스토그램 | 파일럿 2주 | 백엔드 온콜 |
| 첨두 계수 | 주간 최대 분당 발신 ÷ 평균 | 파일럿 2주 | 동일 |
| 연결당 상주 바이트 | 계단 부하 RSS 기울기 | 착수 1주 | S1 담당 |
| 메시지 크기·세션 길이 | 첫 10만 메시지, 세션 종료 로그 | 파일럿 2주 | 동일 |
| 암호 협상 CPU(1.5 ms) | S4 폭풍 시험 중 코어 점유 | S4 | S4 담당 |

지연 목표 500 ms·재수립 60초·조회 깊이 50행은 요구로 주어진 값이 아니라 **이 문서가 고른 임의값**이다. S2·S4 실측 뒤 서비스 측과 확정한다.

## 8. 대안과 기각 사유

- **A. 지속 연결 없이 주기 조회.** 10만 × 2초 주기 = 5만 요청/s, 매 요청이 이력 조회 → 정상 조회율이 지속 연결의 12배. 기각. **부활:** T6 발화 시 자동 채택.
- **B. 이력 전량 상주.** 30일 2.7 TB 상주 → 비용 자릿수 100배. 기각. **부활:** 보존 요구 ≤ 24시간 **그리고** 일 총량 ≤ 5 GB.
- **C. 방 단위 소유 분할을 처음부터.** 평균 전달 17,000/s에서는 조정 복잡성만 지불. 다만 첨두 5만/s가 T1 임계의 절반에 이미 닿아 있어 이것은 "필요 없다"가 아니라 **유예**다 — 그래서 A1 폴백으로 방 식별자 단일 소유점만 선행 확보한다. **부활:** T1 또는 방 정원 상한 ≥ 1,000 확정.
- **D. 단일 초대형 노드.** 메모리 총량으로는 가능(1 GB)하지만 폭풍 시 수립 20,000/s를 한 대가 받고 장애 반경이 100%. 기각, 부활 조건 없음(장애 반경은 계산이 아니라 요구다).

## 9. 리스크와 완화

- **계측 오염:** 파일럿 표본이 헤비 사용자에 쏠리면 발신율 과대 → 평균·p99·히스토그램 동시 기록.
- **법/규제:** 보존·국외 이전·삭제권 미확답 → 30일 상한을 기본값으로 잠그고 4주 미회신 시 에스컬레이션.
- **보안·남용:** 외부 유발 수립 폭주 → T5의 수립률 게이트가 같은 장치로 방어.
- **비용:** 부하 시험 자체가 전송비 발생 → 시험 총 전송량 1 TB 상한.
- **운영 부담:** 트리거 7개를 모두 즉시 알림으로 걸면 온콜이 무너짐 → T1·T2·T5만 즉시, 나머지는 주간 리포트.
- **사용자 체감:** 폭풍 시 조회 축소(20행)는 보이는 열화 → 안내 문안을 배포 전 확정.
- **조직:** S0 계측 인력 미배정이면 자릿수 전체가 미검증으로 남는다 → 4주 경과 시 문서 상단에 "미검증" 표기.

## 10. "완료"의 판정 기준

1. **노드 6대 중 1대를 전원 차단하고, 재접속 지터를 0~30초 균등으로 둔 상태에서, 그 노드가 쥐고 있던 16,700 연결이 60초 안에 재수립되며, 60초 전 구간에서 잔여 노드 상주 메모리 p99 ≤ 2.5 GB, 전달 p99 ≤ 500 ms를 유지한다.** (지터는 폭풍을 없애지 않고 창을 넓히므로 재수립 완료 시간은 여전히 실측 대상이다 — 완화 장치가 이 판정을 자동 만족시키지 못한다. 2.5 GB는 기본 버퍼 시나리오 2.1 GB의 1.2배로 도출.)
2. 7개 트리거에 합성 값을 주입해 알림 도달과 착수 항목 링크가 7/7 확인된다.
3. 손으로 고른 입력 7개 중 5개가 실측치로 교체된 뒤에도 자릿수 결론(전달 10^4/s · 저장 10^2 GB/일 · 비용 10^3~10^4 $/월)이 유지되거나, 유지되지 않을 때 대응 트리거가 발화한 기록이 남아 있다.

## 프레임 이탈 / 관성 회귀

- **§1의 단가 두 개($0.09/GB, 노드 $250/월)에 민감도 행을 주지 않았다.** 2배여도 합계 자릿수가 안 바뀐다고 판단해 아꼈지만, 그 판단은 표 밖에 있다 — §7에 수명만 걸린 유일한 숫자 쌍이다.
- **§4의 S0~S5 번호가 사다리로 읽힌다.** S0·S1은 독립이고 S3는 S2와 병렬인데 오름차순 번호가 일정으로 오독될 여지를 남긴다.
- **§8 C의 착지가 절충이다.** 첨두가 T1 임계의 절반이라는 계산을 확인한 뒤에도 "기각 + 경계 확보"로 내려앉았다. 조직이 소화하기 쉬운 형태를 계산보다 앞세웠다.
- **가장 약한 절은 §9의 마지막 줄.** "미검증 표기"는 구조가 아니라 문서 규칙이어서, 읽지 않으면 아무 일도 일어나지 않는다. 리뷰어라면 여기를 먼저 친다 — 계측 인력 미배정을 배포 게이트로 올리는 것이 정답이지만 이 문서에 그 권한이 없다.
