# 수년 된 Jenkins → GitHub Actions 점진 이전

- 추론 프레임: min-diff
- 한 줄 요약: 파이프라인 하나 단위로 섀도 실행 → 관측치 비교 → 전환 → Jenkins 잡 무동작화 상태 기계를 돌리고, 롤백을 한 문장으로 못 쓰는 단계는 전부 쪼개거나 격리한 뒤 공유 축(시크릿·러너·조직 설정)을 최후에 건드린다.

## 프레임이 요구하는 시작점 — 롤백 한 문장 원장

반사적으로 떠오른 답은 "현행 인벤토리 → 파일럿/확산/정리 3단계 로드맵 → 마이그레이션 완료율 대시보드"였다. min-diff는 그 시작점을 금지한다. 모든 후보 단계를 "롤백을 한 문장으로 쓸 수 있는가"로 먼저 심문한다. 판정 기준은 diff 크기가 아니라 **부작용의 되돌림 가능성**이다.

| 후보 단계 | 롤백 한 문장 | 판정 |
|---|---|---|
| 섀도 워크플로 추가(소비자 0, 필수 검사 아님) | 워크플로 파일을 지운다 | 통과 |
| 필수 상태 검사를 Jenkins → Actions로 교체 | 브랜치 보호에서 검사 이름을 되돌린다 | 통과(검사 이름이 저장소 전용일 때만) |
| Actions가 사내 레지스트리/배포 대상에 발행 | 없음 — 발행은 취소가 아니라 덧쓰기다 | **실패 → 4분할** |
| 크레덴셜을 조직 시크릿으로 일괄 복사 | 없음 — 복사된 비밀은 회수 불가, 조직 스코프는 전 저장소에 걸린다 | **실패 → 파이프라인별 신규 주체** |
| 셀프호스티드 러너 라벨 재편 | 없음 — 되돌리면 다른 파이프라인의 큐가 흔들린다 | **실패 → 최후 순번, 전용 라벨** |
| 이식 끝난 Jenkins 잡 삭제 | 부분만 — 아카이브한 잡 설정을 재임포트한다(히스토리·빌드 번호는 복구 불가) | **조건부 → S5, 근거는 불필요 증거** |

게이트가 실제로 쪼갠 것:

- **발행 단계 4분할.** ① 아무도 소비하지 않는 섀도 태그(커밋 SHA 접두, 별도 네임스페이스)로만 밀어 넣기 → 롤백: 태그 삭제. ② 다이제스트·매니페스트 비교(읽기 전용). ③ 소비자 포인터를 Actions 산출물로 전환 → 롤백: 포인터 원복. ④ Jenkins 발행 단계 무동작화 → 롤백: 단계 복원.
- **시크릿 격리.** 기존 크레덴셜을 옮기지 않는다. 파이프라인마다 새 서비스 주체를 발급해 저장소 수준 시크릿으로 넣는다 → 롤백: 그 주체 하나만 폐기.

공유 축을 최후로 미루는 근거도 게이트에서 나온다: 공유 네임스페이스를 건드리는 단계는 **롤백이 다른 파이프라인으로 파급되어 단계 독립성 자체를 깬다.** 순서 감각이 아니라 게이트의 결론이다.

## 문제 정의 / 목표

수년 누적된 Jenkins 파이프라인 군을 Actions로 옮긴다. 목표는 "더 좋은 CI"가 아니라 **행위 보존 이전**이며, 성공은 Jenkins 컨트롤러를 껐을 때 아무 일도 일어나지 않는 상태다. 개선(컨테이너 러너, OIDC, 캐시 재설계)은 이 플랜 이후의 별도 트랙이다.

## 명시적 가정

- **각 파이프라인에 "같은지"를 기계적으로 비교할 관측치가 존재한다**(아티팩트 다이제스트, 테스트 개수, 발행 태그, 알림 발송). 틀렸을 경우: 비교가 "양쪽 다 초록"으로 퇴화해 섀도 기간이 의식이 된다. 가장 싼 조기 검증: 1번 파이프라인의 비교 계약서를 먼저 쓰고 관측치를 실제로 뽑아본다. 대체 경로: 관측치를 프록시(종료 코드 + 테스트 개수 + 소요시간 상하한 + 알림 발송)로 명시 하향하고 그 파이프라인만 섀도 창을 2배로 늘린다 — 이 배수는 **임의값**이며 프록시 판정의 오탐률이 관측되는 시점에 리뷰어가 재설정한다.
- Jenkinsfile·잡 설정이 형상관리에 있다. 틀렸을 경우(UI 구성 프리스타일 잡): 이식 원본이 없어 단계 0에서 설정 XML 스냅샷을 떠야 하고 순번이 밀린다.
- 빌드가 사내망 자산(내부 레지스트리, DB, 라이선스 서버)에 접근한다. 틀렸을 경우: 러너 전략이 단순해져 공유 축 작업이 줄어든다(이 플랜이 과설계).
- 불일치를 판독할 사람이 있다(Jenkins 로그·설정 접근권, 잡 소유자 재직). 틀렸을 경우: 해당 파이프라인은 "행위 미상"으로 분류해 이식이 아니라 재작성 트랙으로 보낸다.

## 접근과 단계

**단계 0 — 전수 조사(다른 모든 단계의 선행).** 파이프라인 전수 목록, 각각의 **최장 트리거 주기**(분기·연 1회 인증서 갱신·컴플라이언스 리포트 포함), 부작용 계열(검사만 / 발행 / 배포), 락·동시성 사용 여부를 표로 만든다. 이 목록이 없으면 완료 판정 자체가 성립하지 않는다(아래 판정 4).

**진입 순서 규칙(도출).** 동시 섀도는 WIP 캡까지, 진입 순서는 **최장 트리거 주기 내림차순**이다. S2가 "가장 드문 트리거 1주기 포함"을 요구하므로 주기가 긴 파이프라인이 가장 오래 섀도에 머물고, 늦게 넣으면 그것이 다크 테스트의 병목 간선이 된다. 단 1번 파이프라인만 예외로 부작용 없는 검사 계열을 고른다 — 부작용 격리 자산이 아직 없기 때문이다.

**파이프라인 1개의 경로(상태 기계 — 파이프라인들은 서로 병행한다).**

| 상태 | 진입 조건 | 검증 | 롤백 한 문장 |
|---|---|---|---|
| S1 섀도 | 비교 계약서 + 저장소 전용 시크릿 | 동일 트리거에서 양쪽 다 실행됨 | 워크플로 파일 삭제 |
| S2 비교 통과 | 관측치 연속 일치 + **최장 트리거 1주기 포함** | 불일치 원장이 비었거나 전부 등록부 사인오프 | (읽기 전용) |
| S3 전환 | S2 + 롤백 드릴 1회 실측 | 필수 검사·소비자 포인터가 Actions | 검사 이름·포인터 원복 |
| S4 무동작화 | S3 이후 1주기 무사고 | Jenkins 잡은 돌지만 아무것도 하지 않음 | 단계 복원 |
| S5 잡 삭제 | 다크 테스트 통과 후 일괄 | 설정 아카이브 존재 확인 | 아카이브 재임포트(히스토리 손실) |

S5는 게이트를 온전히 통과하지 못하는 단계다. 그래서 **되돌림 가능성이 아니라 불필요 증거(다크 테스트)로 입장 자격을 얻고**, 롤백은 손실을 명시한 부분 롤백으로만 허용한다.

"연속 일치 10회"는 **임의 초기값**이다. 대체 시점: 2번 파이프라인 전환 시 1번에서 관측된 불일치율로 재설정, 측정자는 이식 PR 리뷰어. 도출된 부분은 회수가 아니라 "최장 트리거 1주기 포함" 조건이다.

**공유 축 작업(다크 테스트 통과 뒤에 열린다).** 순서는 하나만 강제된다: 새 주체로의 회전이 **구 크레덴셜 회수보다 앞선다**(아직 쓰는 곳이 있는 크레덴셜을 폐기하면 롤백 경로가 사라진다). 라벨 정리와 러너 오토스케일은 그 뒤 임의 순서. 러너는 이전 기간 내내 기존 Jenkins 에이전트 머신에 Actions 러너를 **나란히** 설치하고 파이프라인 전용 라벨만 붙인다.

**이식과 개선의 분리.**
- 이식 PR은 행위 보존만 한다. 개선은 별도 PR·별도 티켓, S3 이후에만 병합.
- **더러운 환경을 일부러 보존한다.** 손으로 깔린 툴체인, 남은 캐시, 워크스페이스 잔존 상태를 그대로 쓴다. 차이를 "누가 스케줄하는가"로 좁히지 못하면 불일치의 원인을 판별할 수 없다.
- **도구가 드러낸 진짜 버그는 보존한다.** 깨끗한 체크아웃에서 실패하는 테스트, 순서 의존, 잔존 상태 덕에 통과하던 케이스는 이식 PR에서 고치지 않는다. `port-revealed` 태그 + 티켓을 달고, 필요하면 Jenkins 쪽 조건(워크스페이스 선점, 비병렬 실행)을 재현해 초록을 맞춘다. 가장 정당해 보이는 유혹이 행위 보존을 가장 잘 깬다.

**강제 분기 등록부(프레임 부품이 아니라 내 확장).** 플랫폼 구조상 보존이 불가능한 지점에 대해 프레임은 출력을 정의하지 않는다. 항목마다 ① 보존을 막는 구체적 플랫폼 기제 ② 지명된 사인오프 ③ 소비자 관측 계약이 바뀌는지를 적는다. 사인오프 없는 항목이 하나라도 있으면 다크 테스트를 금지한다 — 이 게이트가 없으면 등록부는 "보존 불가니 개선하자"의 세탁 통로가 된다. 초기 항목 5개: 포크 PR 시크릿 미제공, 예약 실행 큐 지연·드리프트, 워크스페이스 비영속, 빌드 번호 단조 증가 부재, 락/스로틀 의미 차이.

**유혹 로그.** 기록자는 이식 담당자가 아니라 **이식 PR의 리뷰어**(리뷰 시점 기록). 항목: 겸사겸사 충동의 문장, 거절 사유, 개선 티켓 번호. 해석 규칙: **빈 로그는 규율의 증거가 아니라 기록 실패의 증거**이며, 파이프라인당 0건이면 다음 파이프라인의 S3 전환을 차단한다.

**3의 법칙.** 재사용 워크플로·컴포지트 액션은 세 번째 중복 뒤에 추출하고, 셈 단위는 파이프라인이다(한 워크플로 안의 잡 3개는 1회). Jenkins 공유 라이브러리가 이미 있어 카운트가 채워진 듯 보이지만 **카운트는 이식 경계에서 리셋한다** — Jenkins 쪽 공유를 선취 크레딧으로 인정하면 각 파이프라인이 그 라이브러리의 어느 행위에 의존하는지 모르는 상태에서 추상을 먼저 옮기게 된다. 1·2번은 필요한 부분만 인라인 복사.

**진척 장치(min-diff 외부 수입 — 이 프레임은 진척에 눈이 멀다).**
- 래칫: Jenkins 설정 동결, 신규 파이프라인은 Actions에서만 작성 가능(기본 거부 게이트 — `delete-first`의 재진입 게이트에서 차용).
- 마감: Jenkins 호스트의 OS·플러그인 지원 종료일. 그 날짜가 없으면 마감은 **임의 선언**이며 분기 계획 회의에서 재설정한다.
- WIP 캡: 동시 섀도 2개. 근거는 "섀도 1개당 컴퓨트 2배 + 불일치를 사람이 판독하는 고정 비용", 캡 = 판독 담당 인원 수. 판독자가 1명이면 1이다.

## 대안과 기각 사유

- **빅뱅 일괄 이전(프리즈 주말).** 기각: 롤백 문장이 "전부 되돌린다"이고 실측이 불가능하다. 부활 조건: 전수 목록이 3개 이하이고 전부 발행 없는 검사 계열일 때.
- **브리지(Actions가 Jenkins 잡을 호출).** 기각: 이식이 아니라 층 추가이며 롤백 표면과 두 시스템이 영구화된다. 부활 조건: 조직 결정으로 마감이 6개월 이상 밀리고 그 기간 신규 파이프라인만이라도 Actions로 유입시켜야 할 때(래칫 대체물).
- **이전과 동시에 컨테이너 러너·OIDC 도입.** 기각: 불일치 원인이 이식인지 개선인지 판별 불가. 부활 조건: 섀도 비교에서 "더러운 환경 자체가 원인"인 불일치가 2건 이상 확정되어 환경 보존이 오히려 비교를 막을 때.

위 부활 조건의 수치(3개, 6개월, 2건)는 근거 없는 **임의 선언**이다. 조건이 실제로 근접하면 그 회의에서 값 자체를 다시 정한다.

## 리스크 & 완화

- 비교 계약서 형식화("둘 다 초록") → 관측치 없는 파이프라인은 S1 진입 금지, 프록시 하향은 문서에 명시.
- 알림(Slack·메일) 침묵 파손 → 비교 계약서 필수 항목에 알림 발송 포함.
- 섀도 기간 컴퓨트·청구 2배 → WIP 캡이 비용 상한을 겸함, 월 청구액을 전환 회의 고정 안건으로.
- 락·동시성 의미 차이로 동시 배포 사고 → 단계 0에서 락 사용 여부를 조사하고 해당 파이프라인은 순번 최후.
- 감사·승인 기록 요구(배포 승인자 추적) → 등록부 항목 + 사인오프, 미충족이면 전환 보류.
- 트라이벌 지식 소실 → 이식 PR에 원본 Jenkinsfile·잡 설정 스냅샷 첨부 의무(S5의 아카이브도 이것을 재사용).
- 한 줄 스윕(전부 비교 계약서 항목으로 흡수): 아티팩트 보존 정책, 큐 우선순위, 매트릭스·타임아웃 의미차, 모노레포 경로 필터, 빌드 번호 의존 스크립트.

## "완료"의 판정 기준

번호는 의존 순서다(4는 1~3을 소비한다).

1. **유혹 로그 유지.** 파이프라인당 항목 ≥ 1, 기록자는 리뷰어. 0건이면 기록 실패로 판정.
2. **강제 분기 등록부.** 위 초기 5개 항목이 모두 존재하고 각각 사인오프가 있다. 빈 등록부나 항목이 삭제된 등록부는 통과가 아니라 미작성이다.
3. **롤백 드릴.** 전환된 각 파이프라인에서 롤백 문장을 실제로 실행하고 소요 시간을 원장에 기록한다. 목표 중위 10분은 **임의 초기값**이며 첫 3회(표본 수 3도 **임의 선언** — 드릴 실행자가 분산을 확인한 뒤 재설정한다) 실측치로 대체한다(측정자: 드릴 실행자).
4. **다크 테스트(실측).** Jenkins 컨트롤러를 정지한 채, **단계 0 전수 목록의 모든 파이프라인**이 각자의 최장 트리거를 1회 이상 발화시키고 릴리스가 1회 이상 나가는 최소 연속 구간을 통과한다. 판정: 전수 목록을 체크리스트로 두고 Actions 실행 로그로 각 행의 발화를 확인, 릴리스 태그 목록으로 릴리스를 확인, 티켓 트래커에서 "Jenkins 재시작 요청" 0건을 쿼리한다. 측정자는 이전 담당자, 확인자는 릴리스 매니저. 기간을 시간 수로 쓰지 않는 이유: "72시간"이면 아무것도 실행되지 않은 조용한 3일로도 통과되고, 범위를 "이식된 파이프라인"으로 쓰면 아직 안 옮긴 잡이 침묵하는 것으로도 통과된다.
5. **정리.** 1~4 통과 후에만 S5(잡 삭제)와 공유 축 정리를 실행한다.

## 프레임 이탈 / 관성 회귀

- **강제 분기 등록부는 프레임 부품이 아니다.** 프레임이 출력을 정의하지 않는 구간을 내 장치로 메웠고, 그러면서 프레임의 실패 모드(겸사겸사 침투)에 배지를 달아줄 위험을 만들었다. 사인오프 게이트로 막았지만 그 강제력은 "다크 테스트를 금지한다"는 문장 한 줄에 걸려 있다 — 구조가 아니라 문장이다.
- **가장 약한 곳은 비교 계약서다.** 대상 파이프라인 목록이 없어 관측치를 열거하지 못하고 "계약서를 쓴다"는 절차만 남겼다. 이 플랜의 하중 상당 부분이 아직 존재하지 않는 문서에 실려 있고, 가정 1번을 굵게 한 것은 방어가 아니라 그 사실의 자백이다.
- **리뷰어라면 WIP 캡을 때린다.** "캡 = 판독 담당 인원 수"는 인원 수를 모르는 상태에서 쓴 조건식이므로 본문에 남은 2는 실질적으로 임의값이다.
- **관행에 착지한 지점.** 1번 파이프라인을 부작용 없는 검사 계열로 고른 것은 격리 자산 의존에서 도출되지만 프레임 없이도 같은 답이 나왔을 관행이다. 프레임 적용의 증거로 세지 않는다.
