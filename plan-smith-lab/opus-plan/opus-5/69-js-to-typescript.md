# 대형 JS 코드베이스의 TypeScript 점진 전환

- 추론 프레임: min-diff / 스타일: opus
- 한 줄 요약: 타입 검사기와 방출기를 분리해 "이식 커밋은 산출물 바이트를 바꾸지 않는다"를 검증 축으로 삼고, 파일 하나씩 되돌릴 수 있는 커밋만 허용한다.

## 프레임이 요구하는 시작점 — 한 문장 롤백 입장 심사

반사적으로 떠오른 답은 "의존성 그래프를 그리고 리프부터 훑는 3단계 로드맵"이었다. 그 답은 커밋 크기·배포 단위·되돌림 단위를 하나도 말하지 않으므로 이 프레임이 금지하는 형태다. 여기서는 모든 단계가 **단독 배포 가능 + 단독 롤백 가능**해야 하며, 롤백 문장을 한 줄로 못 쓰면 쪼갠다. 게이트는 diff 크기가 아니라 **부수효과의 되돌림 가능성**을 심사한다. 게이트가 실제로 죽이거나 쪼갠 것:

- **분할 1 — "TypeScript를 도입한다" → 검사기 도입과 방출기 교체로 분리.** 방출기를 바꾸면 배포된 번들의 바이트가 바뀌고, 이미 캐시·임베드된 클라이언트에 대해서는 되돌릴 수 없다. 검사기는 `noEmit`으로만 돌리므로 롤백이 "tsconfig와 CI job을 되돌린다"로 끝난다.
- **분할 2 — "모듈 폴더 단위 전환" → 파일 단위 커밋.** 폴더 밖에서 import되는 파일이 하나라도 있으면 폴더 revert의 롤백 문장이 한 문장이 되지 않는다.
- **분할 3 — "엄격도 플래그를 하나씩 켠다" → (플래그 × 디렉터리) 격자 + 코드 수정의 선행 분리.** 플래그 한 개를 저장소 전체에 켜면 롤백 문장이 그 플래그를 전제로 수정된 코드 전부를 끌고 오므로 한 문장이 되지 않는다(S5).
- **기각 E — 방출기 교체 자체.** 사내 앱 번들에는 스트리핑으로 충분하다. 부활 조건: `.d.ts`를 퍼블리시하는 패키지가 생기는 순간. 그때도 프리릴리스 버전 뒤에서만, 롤백이 "새 버전을 deprecate하고 이전 태그를 latest로 되돌린다"로 성립하는 범위에서 집행한다.

## 문제 정의 / 목표

대형 JS 저장소를 기능 개발을 멈추지 않고 TypeScript로 옮긴다. 성공은 "전부 .ts가 됨"이 아니라 **어떤 시점에 멈춰도 저장소가 건강하고, 어떤 커밋이든 단독으로 되돌릴 수 있는 상태**다. 부분 전환은 실패가 아니라 정당한 종결 상태로 인정한다.

## 명시적 가정

가정 A와 B는 **하나의 load-bearing 묶음**이다 — 둘 중 하나라도 깨지면 플랜은 대안 A2로 통째로 갈아탄다.

- **A. 빌드가 이미 트랜스파일러(Babel/esbuild/SWC)를 통과하고, 타입 주석은 스트리핑만으로 소화된다.** 틀리면 "이식 커밋 = 바이트 동일"이라는 검증 축 전체가 붕괴한다. 최저비용 조기 검증: 현재 커밋에서 스트리핑 설정만 켜고 주석 0개로 빌드해 S0 하네스로 비교(반나절). 폴백: 대안 A2로 전환하고 rename 단계를 영구 삭제.
- **B. 모듈 해석이 rename에 견딘다(확장자 없는 specifier, 또는 TS-ESM 관례대로 `x.ts`를 `./x.js`로 적는 방식).** 해석기가 `.js`를 문자 그대로 찾으면 rename마다 소비자 N개를 함께 고쳐야 하고 파일 단위 커밋이 붕괴한다. 최저비용 조기 검증: 디렉터리 하나의 import specifier를 grep해 확장자 표기 관례를 확인(반나절). 폴백: 대안 A2로 전환하고 rename 단계를 영구 삭제.
- C. 순환 참조가 지배적이지 않다. 틀리면 순환 덩어리의 롤백 단위가 커진다 → 그 덩어리는 이식 대상이 아니라 "영구 .js" 후보로 먼저 판정한다.
- D. CI가 병합을 막을 수 있다. 틀리면 래칫·진입 게이트가 구조가 아니라 예의로 전락한다 → S2를 CI 구축으로 대체하고 그때까지 이식하지 않는다.
- E. 장수 브랜치가 소수다. 틀리면 rename 충돌이 비용을 지배한다 → WIP 상한을 1로 내리고 저churn 파일로 제한한다.

## 접근과 단계

의존 관계 순서다. 달력은 없다(S2의 컷오버 날짜만 예외).

**S0. 산출물 비교 하네스** (선행: 없음)
두 커밋에서 프로덕션 빌드를 돌려 정규화 후 바이트 비교하는 스크립트. 정규화 대상을 명시한다: 소스맵 제거, 이름이 바뀐 파일의 경로 문자열 치환, 콘텐츠 해시, 빌드 타임스탬프. 검증: 주석만 고친 커밋 쌍에서 빈 diff가 나오는가. 롤백: "스크립트 파일 하나를 삭제한다."
근거: 게이트가 "테스트로 동작 보존을 확인한다"를 기각했다 — 커버리지 없는 파일에서는 그 검증이 사라지므로, 축을 산출물 동일성으로 옮겼다.

**S1. 검사기만 도입** (선행: S0)
`noEmit`, **`allowJs: true`**, `include`는 씨앗 파일 1개로 시작해 이식 커밋마다 확장된다. `allowJs: true`는 편의가 아니라 롤백 문장의 수명을 지키는 불변식이다 — 소비자 Y가 이식된 뒤 X의 이식 커밋을 revert하면 `.ts`가 `.js`를 import하는 상태가 되는데, `allowJs`가 꺼져 있으면 그 revert는 커밋 내용과 무관하게 빨개지고 팀은 롤백 보장을 연극으로 읽는다. 씨앗 파일 선택 규칙: fan-in이 가장 낮고 런타임 방출 구문이 없는 파일. 검증: 씨앗에 의도적 타입 오류를 넣어 CI가 실제로 빨개지는가(능동 프로브) + dist diff 0. 롤백: "tsconfig와 CI job 정의를 되돌린다 — 산출물 파이프라인은 이 단계를 참조하지 않는다."

**S2. 진입 게이트 + 부채 래칫** (선행: S1) — **외부 기원 장치**
min-diff는 퇴행을 막지만 완료를 강제하지 못한다(progress-blind). 그래서 프레임 밖에서 셋을 들여온다: 신규 `.js` 병합 금지 체크, `type-debt.json`(파일별 `$FixMe`/`@ts-expect-error` 수, 미전환 파일 수) 단조 비증가 체크, 열린 이식 PR **WIP 상한 3건**(임의 선언 — 첫 달의 충돌 재작업 건수로 재설정). 검증: 신규 `.js`를 담은 시험 PR이 막히는가. 롤백: "CI에서 체크 두 개를 제거한다."
**컷오버 날짜(달력 예외 1개).** 값 = **S1 병합일 + 4주**(4주는 임의 선언 — S3 첫 이식 PR 10건의 리드타임 중앙값이 나오면 그 값으로 재설정). 이 날짜 이후 신규 `.js` 파일을 추가하는 PR은 CI에서 막히며 우회 라벨은 두지 않는다. 설정·변경 권한자: **래칫 소유자 1명**(이름을 tsconfig 옆에 한 줄로 적는다). 재설정 시점: 위 중앙값이 나온 시점 1회, 그리고 가정 D가 깨진 경우. 변경은 주간 슬롯 기록에 사유와 함께 남기며, 그 밖의 연장은 없다.

**S3. 파일 단위 이식 커밋** (선행: S1 / 파일 간 병렬)
리프부터. 규칙: ① 한 커밋 = 한 파일 rename + 타입 주석 + `include` 확장, ② **소비자 파일은 같이 건드리지 않는다**(소비자 수정이 필요하면 별개 커밋), ③ 런타임 코드를 방출하는 TS 구문 금지 — `enum`, `namespace`, 데코레이터, 매개변수 프로퍼티, 클래스 필드 문법 변경. 허용은 주석·`interface`·`type`·`import type`·단정뿐, ④ 맨 `any` 대신 grep 가능한 `$FixMe` 별칭, `@ts-ignore` 금지 `@ts-expect-error`만(원인이 사라지면 스스로 에러를 내므로 카운터가 정직하게 줄어든다).
검증: dist diff 0 + 검사기 green + 카운터 비상승. 롤백: "그 커밋 하나를 revert한다 — 규칙 ②가 같은 커밋의 소비자 변경을 막고, S1의 `allowJs`가 나중에 이식된 소비자가 있는 상태에서도 revert를 성립시킨다."

**S4. 도구가 드러낸 진짜 버그** (선행: 각 파일의 S3)
타입은 현재의 (버그 있는) 실제 동작을 서술하게 적고 `// BUG-####` + 티켓만 남긴다. 고치지 않는다 — 가장 덕스러워 보이는 유혹이 동작 보존을 가장 확실히 깬다. 예외: 프로덕션 피해가 진행 중이면 평상시 장애 경로로 이식 **전에** 단독 커밋하고, 그 커밋은 마이그레이션 커밋으로 세지 않는다. 검증: PR의 BUG 태그 수 = 새로 만든 티켓 수. 롤백: "티켓을 닫고 태그 주석을 지운다"(동작 무변).

**S5. 엄격도 상향 — (플래그 × 디렉터리) 격자** (선행: 해당 디렉터리 전 파일의 S3 완료)
전역 `strict: true` 금지. 단위는 "플래그"가 아니라 **셀 = 플래그 1개 × 디렉터리 1개**이고, 한 셀 = 한 커밋이며 그 커밋의 diff는 디렉터리 override의 **한 줄뿐**이다. 셀의 롤백 문장이 참이 되려면 코드 수정이 셀 커밋 안에 있어서는 안 되므로 순서를 뒤집는다: 셀을 로컬에서 먼저 켜서 에러 목록만 뽑고 → 그 에러를 없애는 코드 수정은 **플래그가 꺼진 상태에서 먼저 병합되는 개선 커밋**으로 보내고(테스트 요구, dist diff가 0이 아니면 런타임 변경이므로 다시 쪼갠다) → 에러가 0이 된 뒤에 셀 커밋을 병합한다. **이미 새 플래그를 전제로 수정된 코드가 셀 안에 들어 있으면**(예: 이식 중 널 가드를 미리 넣은 디렉터리) 그 수정을 셀 커밋에서 떼어내 별개 개선 커밋으로 먼저 병합한다 — 떼어낼 수 없으면 그 셀은 켜지 않는다. 셀별 롤백 문장:

| 셀 (플래그 × 디렉터리 D) | 셀 커밋의 한 문장 롤백 |
|---|---|
| `noImplicitAny` × D | "D의 override에서 그 한 줄을 지운다 — 미해결 위치는 `$FixMe`로 남았고 코드 변경은 0이다." |
| `strictNullChecks` × D | "그 한 줄을 지운다 — 널 가드는 선행 개선 커밋에 있고 플래그가 꺼져도 그대로 동작한다." |
| `strictFunctionTypes` × D | "그 한 줄을 지운다 — 시그니처 수정은 선행 개선 커밋이며 각각 단독 revert 가능하다." |
| `strictBindCallApply` × D | "그 한 줄을 지운다 — 호출부 수정은 선행 개선 커밋이며 dist diff 0으로 검증됐다." |
| `useUnknownInCatchVariables` × D | "그 한 줄을 지운다 — catch 본문 변경은 항상 런타임 변경이므로 개선 커밋으로만 들어가고 dist diff가 드러낸다." |
| `noUncheckedIndexedAccess` × D (선택) | "그 한 줄을 지운다 — 부채가 크면 이 셀은 켜지 않은 상태로 남긴다." |

검증: 셀 PR의 diff가 tsconfig 한 줄뿐이고 dist diff = 0인가. 켜지 않은 셀은 부채가 아니라 선택이며 래칫 대상이 아니다(격자 진행률은 지표로 만들지 않는다 — min-diff는 진행률을 만들지 않는다).

**S6. 공유 타입 추출 — rule of three** (선행: S3에서 같은 형태의 세 번째 중복)
같은 응답 형태를 손으로 세 번 적은 뒤에야 `types/`로 추출한다. 동일 수동 편집이 세 번 반복된 뒤에야 codemod를 쓴다. 이 규칙이 죽인 결정: "도메인 타입 모델을 먼저 세우고 파일을 얹는다"(빅뱅의 타입 버전). 검증: 추출 PR이 세 개의 지역 정의 삭제를 포함하는가. 롤백: "추출 커밋을 revert하면 세 파일이 각자의 지역 타입으로 복귀한다."

**유혹 로그(운영 규칙).** 기록자는 이식 PR 작성자, 시점은 PR 작성 시 템플릿 한 줄("참은 것: 파일 / 충동 / 했다면의 비용 / 대신 어디로 보냈나"). 리뷰는 주간 정례 안의 고정 슬롯(새 회의 없음). 해석 규칙: **0건인 주는 규율이 아니라 기록 실패**이며, 리뷰어가 그 주의 이식 PR 작성자 전원에게 "무엇을 참았나"를 묻는다. 이 해석 규칙이 리뷰를 "필요할 때"에서 고정 슬롯으로 바꿨다. 예상 항목: enum 전환(주석처럼 보이지만 방출 변경 — 최고 위험), 죽은 코드 삭제, 순수 함수 리팩터링, 전역 strict 일괄, TS 친화 라이브러리 교체.

## 대안과 기각 사유

- **A1 빅뱅 codemod(전 파일 일괄 + any 도배).** 기각: revert 단위가 하나뿐이고 열린 브랜치 전부와 충돌하며 리뷰가 불가능하다. 부활: 활성 기여자 1명 이하 + 마이그레이션 길이 이상의 동결 창 — 기각 근거인 충돌 비용이 0이 되는 조건.
- **A2 JSDoc + `checkJs`(rename 없음).** 기각: 제네릭·오버로드 표현력 한계와 생태계 마찰. 단, 가정 A 또는 B가 깨지면 이것이 폴백이다. 부활: 빌드에 트랜스파일러가 없거나 해석기가 파일명 고정을 요구할 때.
- **A3 신규 TS 패키지로 이주(strangler).** 기각: 패키지 경계 이동이 API 재설계를 강제해 이식과 개선이 구조적으로 섞인다. 부활: 독립적인 이유로 이미 패키지 분리가 진행 중일 때.
- **A4 기능 동결.** 기각: 동결 없이 하기 위해 이 프레임을 쓰며, 잃은 시장 시간은 롤백이 없다. 부활: 프레임워크 EOL 같은 외부 기한이 이미 동결을 강제할 때.

## "완료"의 판정 기준

1. **매주 순번 담당자가 이미 병합된 이식 커밋 1개를 무작위로 골라 scratch 브랜치에서 revert한다 — 다른 파일을 하나도 건드리지 않고 CI가 green이 된다.** 측정자: 주간 순번 / 도구: CI. 시간 상한 15분(임의 선언 — 이식 PR 20건 후의 CI 중앙값으로 대체).
2. 모든 이식 커밋에서 정규화 dist diff = 0 바이트. 측정: S0 하네스를 CI 단계로 상시 실행.
3. `type-debt.json`의 어떤 항목도 상승하지 않고, 미전환 파일 수가 최근 4주 중 3주에서 감소(3/4는 임의 선언 — 첫 8주 실측 중앙값으로 대체 / 측정자: 래칫 CI + 주간 리뷰).
4. `@ts-ignore` 개수 = 0 (grep, CI 체크). 그리고 **컷오버 날짜 이후 병합된 신규 `.js` 파일 0건** — 측정자: 래칫 소유자 / 도구: 진입 게이트 CI 이력 + 그 날짜 이후 커밋의 신규 `.js` 파일 목록.
5. 유혹 로그가 매주 리뷰됐고, 0건인 주마다 작성자 질문 프로토콜이 실행된 기록이 남아 있다(항목 수가 아니라 프로토콜 실행 여부가 판정 대상).
6. 종결 판정: 진입 게이트와 래칫이 6개월 유지되고(임의 선언 — 분기 리뷰 2회 주기), 남은 `.js`가 "영구 .js" 목록으로 명시 판정되면 완료. 측정자: 래칫 소유자 / 도구: 분기 리뷰 기록 2회분 + 래칫 CI 이력(그 기간에 체크를 비활성화·스킵한 커밋 0건, `required check` 설정 변경 이력 0건). 목록은 이식 PR 작성자가 후보를 제안하고 주간 슬롯에서 래칫 소유자의 승인으로만 등재된다(무기한 보류 금지 — 제안된 후보는 그 주에 등재 또는 반환). 100%는 목표가 아니다.

## 프레임 이탈 및 관성 회귀

- **S5는 초안에서 "플래그 하나씩"으로 게이트를 스스로 통과시켰고, 자백으로 넘기기 전에 실제로 쪼갰다 — 해소됨(편집 이력).** 남는 잔여 결함: 격자의 셀 수가 플래그 6 × 디렉터리 N으로 커지는데 **어느 디렉터리를 먼저 켜는지의 우선순위 규칙이 없다**(리프 우선 같은 규칙을 S3에서 빌려 쓸 수 있지만 검증하지 않았다). 그리고 셀 롤백 문장은 "선행 개선 커밋이 플래그 없이도 유효하다"에 의존하고, 그 유효성은 개선 커밋의 테스트가 그 경로를 실제로 덮을 때만 참이다 — 커버리지 없는 파일에서는 S0의 dist diff 하나만 남는다.
- 단계 번호가 S0→S6 사다리로 읽히지만 실제 의존은 S1에서 S2와 S3가 갈라지는 병렬이고 S6는 S3의 부산물이다. 번호를 고치지 않고 주석으로 때웠다.
- 완료 판정 6의 "6개월"은 측정자·도구를 붙였지만 길이 자체는 여전히 임의 선언이며, "부분 전환도 정당한 종결"과 시간 기반 유지 조건이 긴장 관계에 있다는 사실은 해소하지 않았다.
- 리스크 표는 망라를 택하고 깊이를 버렸다. `@types` 행은 관행 한 줄이며, 지역 `.d.ts`가 어느 조건에서 오히려 부채로 뒤집히는지는 다루지 않았다.
