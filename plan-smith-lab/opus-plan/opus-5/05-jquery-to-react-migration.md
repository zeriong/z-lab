# 10년 된 jQuery 관리자 페이지의 점진적 React 전환

- 추론 프레임: min-diff / 스타일: opus
- 한 줄 요약: React를 페이지가 아니라 **섬(island)** 단위로 기존 DOM에 심고, 모든 단계의 롤백을 "플래그를 off로 되돌린다" 한 문장으로 유지한다.

## 프레임이 요구하는 시작점 — 롤백 한 문장 게이트

모든 단계는 착수 전에 롤백 문장 한 줄을 통과해야 한다. 문장이 "배포를 되돌린다"가 되거나 두 문장이 되면 그 단계는 크다 — 쪼개고 다시 온다.

게이트가 실제로 죽인 것(발화 기록):

- 초안의 1단계 "React·번들러 도입 + 첫 화면 교체"는 롤백 문장이 "빌드 설정 커밋과 화면 커밋을 함께 되돌린다"가 되어 탈락 → **S0**(참조되지 않는 산출물 추가)과 **S1**(플래그 뒤 로더 주입)으로 분할.
- "저장 버튼이 있는 폼을 첫 섬으로"는 diff가 20줄이어도 탈락. 쓰기 부수효과는 플래그 off로 되돌아오지 않는다 → **첫 섬은 읽기 전용으로 강제**, 이후 쓰기 섬은 레거시와 동일 엔드포인트·동일 페이로드만 허용(요청 스키마 변경은 별도 단계).

게이트가 역산해낸 전제조건: 플래그는 요청마다 서버에서 조회(빌드 시점 상수 금지), 새 번들은 레거시 번들과 별도 파일, 이식 단계에서 API·DB 스키마 변경 금지.

**롤백 만료 규칙.** 이중 생존(레거시 경로와 섬이 동시에 살아있는) 구간에서 신규 기능이 섬에만 착지하면 플래그 off는 더 이상 동작 보존이 아니다 — 기능이 사라진다. 따라서 이중 생존 중인 섬은 기능 동결이며, 그 화면에 신규 기능이 필요해지는 순간 그 섬은 즉시 승격(레거시 경로 삭제) 대상이 된다.

## 문제 정의 / 목표

10년치 jQuery 관리자 화면. 테스트는 없고, 전역 `$`·조상 위임 핸들러·jQuery 플러그인(표·셀렉트)·서버 템플릿이 얽혀 있으며 운영과 기능 개발은 계속돼야 한다. 목표는 "React 전환 완료"가 아니다: **어떤 단계든 배포 되돌리기 없이 한 번의 플래그 조작으로 원복되는 상태를 유지한 채 화면을 하나씩 넘기는 것.** 원복할 수 없는 진전은 이 계획에서 진전으로 세지 않는다.

## 명시적 가정

1. **각 위젯에는 레거시 JS가 독점하지 않는 컨테이너 요소가 있고, 섬을 심을 때 레거시 JS를 수정하지 않아도 된다.** 틀리면 단계가 가산(additive)이 아니게 되고 롤백 문장이 전부 깨진다 — 계획의 뼈대가 무너진다. 가장 싼 조기 검증: 첫 대상 화면에서 컨테이너 셀렉터와 조상 위임 핸들러를 grep(반나절, S0 이전). 대안 경로: 레거시 컨테이너를 플래그로 숨기고 형제 컨테이너에 렌더해 레거시 코드를 무수정으로 둔다.
2. 플래그를 요청 시점에 읽을 수 있다. 틀리면(정적 호스팅) 쿠키·쿼리 파라미터를 로더가 클라이언트에서 읽는 방식으로 대체하고, 롤백 즉시성은 캐시 TTL만큼 늦어진다.
3. 관리자 브라우저 매트릭스가 모던하다. 틀리면 새 번들이 일부 사용자에게 백지 화면 → S0 이전에 접근 로그의 User-Agent 분포를 확인한다.
4. 회귀 판정은 테스트가 아니라 DOM·값 비교로 한다(테스트가 없다). 틀리면(스위트가 있으면) 검증이 싸진다.
5. jQuery는 전역 하나를 공유하고 새 번들은 jQuery를 번들하거나 버전을 올리지 않는다. 틀리면 플러그인이 두 인스턴스로 갈려 조용히 깨진다.

## 접근 및 단계

S0과 S1은 진짜 직렬이다. **섬 단계(S2~S4)는 서로 병렬**이며, 달력이 아니라 ① WIP 상한 ② 유형 위험 등급이 순서를 정한다. 삭제는 단계 수가 아니라 관측 창에 의존한다.

- **S0 — 새 번들을 옆에 놓는다.** 선행: 없음. 번들러가 새 산출물을 별도 경로로 내보내되 어디서도 참조하지 않는다. 검증: 레거시 번들 파일 해시 불변, 화면의 네트워크 요청 목록 불변. 롤백: "빌드 스텝 하나를 지운다."
- **S1 — 플래그 + 로더 + 빈 섬.** 선행: S0. 저트래픽 화면 하나에 아무것도 렌더하지 않는 섬을 마운트한다. 검증: off일 때 DOM 스냅샷·요청 목록이 이전과 동일, on일 때 요청 1개 추가·시각 변화 없음. 롤백: "플래그를 off로 되돌린다."
- **S2 — 읽기 전용 섬.** 선행: S1. 대상 선정 규칙: 다른 화면에서 참조되지 않고 전역 이벤트 버스 구독이 0인 위젯. 동작 보존만 한다. 검증 입력 케이스 목록은 레거시 핸들러의 분기 수에서 유도한다(분기 1개 = 케이스 1개). 이식 중 발견한 실제 버그는 **고치지 않고** 티켓 + 주석으로 보존한다.
- **S3 — 플러그인 보유 섬.** 선행: S2 유형 1건이 통과한 뒤(브리지 방식이 검증돼야 한다). 플러그인은 교체하지 않고, React가 컨테이너 생명주기만 소유하며 초기화·해제를 감싼다. 검증: 마운트/언마운트를 반복한 뒤 등록 핸들러 수와 노드 수가 초기값으로 복귀.
- **S4 — 공유 상태·권한 섬.** 선행: S3. 세션·CSRF·권한은 서버가 준 값을 읽기만 한다. 권한 분기를 클라이언트에서 재계산하지 않는다(보안 회귀). 검증: 권한 등급별 계정 각 1개로 렌더 결과 비교.
- **S5 — 승격과 삭제.** 선행: 해당 섬이 관측 창을 통과. 레거시 경로 코드 삭제는 독립 단계이고 롤백 문장은 "이 커밋을 되돌린다"(데이터 부수효과 없음). 플래그도 같은 커밋에서 제거한다.

중복은 3회 규칙으로 처리한다: 섬 1·2는 마운트/브리지 코드를 각자 중복 보유하고, 세 번째 섬이 필요해질 때 공용 어댑터를 추출한다. 이 규칙이 "S1에서 공용 어댑터부터 만든다"는 초안을 잘랐다.

진전 장치(외부에서 도입 — min-diff는 회귀를 막지만 완주를 강제하지 못한다): ① CI 래칫 = 이식 대상 화면의 "jQuery가 소유한 컨테이너 수"와 미삭제 플래그 수가 증가하면 빌드 실패, ② WIP 상한 = 이중 생존 섬 동시 1개(파생: 2개 이상이면 회귀를 어느 플래그에 귀속시킬 수 없다), ③ 화면별 컷오버 기한 + 기본 판정("기한 미달 시 섬 폐기, 레거시 유지" — 되돌리기가 싼 쪽). 기한 값 자체는 인벤토리 실측 전까지 비워 둔다.

## 유혹 기록장

기록자는 단계 담당자 본인, 시점은 PR 제출(PR 템플릿 필수 필드, 공란 불가). 해석 규칙: **빈 로그는 규율의 증거가 아니라 기록 실패의 증거다.**

| 발화 지점 | 유혹 | 기각 사유 | 별도 티켓이 되는 조건 |
|---|---|---|---|
| S0 | "이 기회에 빌드 도구를 전면 통일" | 레거시 번들 해시가 바뀌어 모든 화면이 한 배포에 묶인다 | 레거시 경로가 전부 삭제된 뒤 |
| S1 | "플래그 대신 브랜치를 따로 배포" | 롤백 문장이 "배포를 되돌린다"가 된다 | 없음 |
| S2 | "이식하면서 보이는 버그와 타입을 정리" | 회귀 원인을 이식/개선으로 가를 수 없다. TS 전환도 포팅 커밋에 넣지 않는다 | 이식 검증 통과 후, 같은 파일의 별도 커밋 |
| S3 | "표 플러그인을 React 표로 교체" | 이식 1건이 기능 재구현 1건으로 커진다 | 플러그인 CVE 또는 유지보수 중단 |
| S5 | "남은 화면이 셋이니 한 번에" | 세 화면의 회귀가 한 플래그에 섞인다 | 세 화면이 상호 참조 0이고 각자 플래그를 가질 때(= 한 번에가 아니다) |

## 대안과 기각 사유

- **빅뱅 재작성**(새 React 관리자 SPA를 만들고 라우팅을 전환): 롤백 단위가 제품 전체다. 기각. 부활 조건 — (a) 화면 인벤토리 실측이 병행 유지 가능한 규모로 확인되고(수치는 비워 둔다: 인벤토리가 채운다), (b) 기능 동결이 문서로 승인되고, (c) 인수 테스트 스위트가 존재할 때.
- **화면 단위 이식**(섬 없이 페이지 통째로): 큰 화면에서는 diff를 쪼갤 수 없어 기각. 단 다른 화면이 참조하지 않고 전역 구독이 0인 화면에서는 화면 단위가 오히려 더 작은 단계이므로 **그 화면들에는 채택**한다.
- **iframe으로 새 화면 삽입**: 세션·CSRF·내비게이션이 이중화되고 높이 조정 해킹이 남는다. 부활 조건: 공유 내비게이션이 없는 독립 리포트·인쇄 화면.
- **전환하지 않는다**: 접근 로그상 사용이 미미하고 폐기 일정이 있는 화면은 이식 대상 목록에서 제외하고 jQuery 그대로 둔다 — 이 계획의 정당한 결론 중 하나이며, 아래 판정 기준의 분모도 이 목록이다.

## 리스크와 완화

- 전역 CSS가 섬에 스며든다 → 섬 내부 리셋 금지(그 자체가 회귀), 클래스 프리픽스 + 렌더 결과 비교.
- 조상 위임 핸들러와 섬 핸들러의 이중 발화 → S2 검증에 "클릭 1회당 서버 요청 수" 확인 포함.
- 플러그인 언마운트 누수 → S3 검증 항목.
- 오래 열린 관리자 탭 때문에 플래그 flip이 즉시 반영되지 않는다 → 로더는 요청마다 플래그를 읽고, 원복 드릴에 stale 탭 케이스를 포함.
- 레거시 DOM 클래스에 붙은 분석 태그·GTM 셀렉터가 조용히 끊긴다 → 이식 체크리스트에 "기존 클래스·data 속성 보존" 항목.
- i18n 문자열(서버 템플릿 보유), 인쇄·내보내기 화면, 키보드 단축키, 접근성(포커스 순서·aria) → 각 섬의 이식 체크리스트 고정 항목이며, 누락된 PR은 반려한다.
- 이중 생존 중 상태의 두 출처 → 섬은 서버 값을 읽기만 하고, 레거시가 쓰는 전역 상태를 섬이 갱신하지 않는다.

## "완료"의 판정 기준

1. **원복 드릴(실측).** 이식 완료된 섬 전부에 대해, 섬을 열고 실제로 상호작용한 뒤 플래그를 off로 되돌리고 재적재해 DOM 스냅샷을 이식 전 저장본과 diff한다 — 불일치 0. 측정: QA 담당자가 스테이징에서 스냅샷 파일 비교, stale 탭 케이스 1건 포함. (상호작용 없는 재적재 비교는 "로더가 애초에 실행되지 않음"으로도 통과하므로 상호작용 후 비교로 못 박는다.)
2. 레거시 번들 파일 해시가 S0~S4 전 구간에서 불변이고 S5 삭제 커밋에서만 변한다. 측정: CI가 커밋마다 해시 비교.
3. 포팅 커밋 전수 감사: 섬 컨테이너 밖 변경 0건, 버그 수정 라인 0건. 측정: 리뷰어가 병합 시 확인, 위반은 되돌리고 재분할.
4. 유혹 기록장 유지: 이식 PR 중 기록장 필드가 공란인 것 0건.
5. **이식 대상 목록에 있는** 화면에서 jQuery가 소유한 컨테이너 수 0, 미삭제 플래그 0. 목록에서 제외된 화면은 jQuery 상태로 남는 것이 정상 결과이며 미완이 아니다. 관측 창 초기값 14일(임의값 — 접근 로그상 해당 화면의 최장 미사용 간격으로 대체하며, 첫 측정은 운영 지표 담당자가 S1 주에 수행).
6. 3회 규칙 준수: 공용 어댑터 추출 시점의 중복 수 3(프레임 규정값이며 이 도메인에서 유도한 수치가 아니다).

## 프레임 이탈 / 관성 회귀

- 이 문서가 착지한 형태는 교과서적 strangler-fig다. 프레임이 만든 것은 패턴이 아니라 분할 지점과 롤백 문장(§시작점의 탈락 기록 2건, 읽기 전용 강제)이다. 발명은 없었다.
- §접근의 S0~S5 표기는 상승 사다리로 읽힌다. 본문에 "S2~S4는 병렬"이라 적고도 번호를 남긴 것은 가독성 관성이다.
- 가장 약한 곳은 §리스크의 i18n·인쇄·단축키·접근성 줄이다. 네 범주를 한 줄에 압축하고 "체크리스트 고정 항목"이라고만 썼다 — 항목 내용이 없어 검증 가능한 형태가 아니다. 리뷰어라면 여기를 먼저 찌를 것이다.
