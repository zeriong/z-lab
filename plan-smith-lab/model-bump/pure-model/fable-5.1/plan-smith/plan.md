# 웹 브라우저 앵그리버드 게임 구현 계획

- Reasoning frame: spec-coverage / Style: opus (standalone, 단일 패스) / 작성 모델: claude-fable-5-1 / 실행: batch (게이트 자체 승인)
- 한 줄 요약: TypeScript + Vite + Matter.js + Canvas 2D로, 10개 스테이지·슬링샷 물리 루프·우측 일시정지 버튼(다시하기/메인으로)을 갖춘 브라우저 슬링샷 게임을 "얇은 end-to-end 슬라이스 → 폭 → 폴리시" 순서로 만든다.

### 표면별 품질 하한 (각 한 문장)
- 스테이지 데이터: 10개 파일 모두 실제로 다른 배치이며, 로더는 스키마 검증 실패 시 빌드 타임에 죽는다.
- 스테이지 선택: 잠금/해제/별 개수가 보이고, 잠긴 스테이지는 클릭이 무시된다.
- 물리/발사: 당긴 거리·각도가 초기 속도로 1:1 대응하고, 같은 입력은 같은 궤적을 낸다.
- 파괴: 블록이 부서질 때 사라지는 것이 아니라 "깨지는 것"이 보인다(파편+소리).
- 점수: HUD 숫자가 이벤트 발생 0.2초 안에 변하고 결과 화면 수치와 일치한다.
- 판정: 클리어/실패가 "월드가 멈춘 뒤" 한 번만 뜨고, 새 발사 중엔 절대 뜨지 않는다.
- 일시정지: 버튼이 캔버스 우측 상단에 항상 보이고, 누른 순간 월드가 그 자리에서 멈춘다.
- 영속성: 탭을 닫고 다시 열어도 해제된 스테이지와 별이 유지된다.
- 오디오: 브라우저 자동재생 정책 때문에 소리가 안 나도 게임은 멈추지 않으며, 첫 사용자 제스처 후 소리가 붙는다.

## 2. build 셀의 동사 문장 (표 밖 지시)

- A1: 구현자가 `stages/` 폴더를 열면 `01.ts`~`10.ts`가 `StageDef` 타입으로 새·돼지·블록 배치를 내보낸다; 없으면 `stageIndex.ts`의 배열 길이 검사 테스트가 실패한다.
- A2: 플레이어가 메인에서 "시작"을 누르면 1~10 카드가 그리드로 뜨고 해제된 카드만 눌린다; 없으면 잠긴 카드를 눌러도 화면이 바뀌어 버린다.
- A3: 플레이어가 1→10을 진행하면 새 수는 5→3으로 줄고 돌 블록 비율은 0%→40%로 늘어난다; 없으면 10단계가 1단계와 같은 시도 수로 깨진다.
- A4: 플레이어가 N단계를 클리어하면 N+1 카드가 즉시 해제된다; 없으면 결과 화면의 "다음" 버튼이 잠긴 스테이지로 보내진다.
- B1: 발사체가 놓이면 중력으로 포물선을 그리고 블록과 부딪혀 튕기거나 밀어낸다; 없으면 새가 허공에 멈춘다.
- B2: 플레이어가 새를 잡고 뒤로 당긴 뒤 놓으면 당긴 반대 방향으로 날아간다; 없으면 새를 클릭해도 커서만 움직인다.
- B3: 플레이어가 당기는 동안 예상 궤적 점 12개가 새 앞에 그려진다; 없으면 조준할 때 점이 안 보인다.
- B4: 새나 다른 블록이 충격 임계 이상으로 블록을 치면 HP가 깎이고 0에서 블록이 사라지며 파편이 튄다; 없으면 블록이 무한히 튕기기만 한다.
- B5: 돼지가 충격을 받으면 HP가 깎이고 0에서 제거되며 점수가 오른다; 없으면 구조물이 다 무너져도 돼지가 남는다.
- B6: 블록 파괴·돼지 제거·남은 새 보너스가 발생할 때 HUD 좌측 상단 점수가 즉시 증가한다; 없으면 결과 화면 점수가 항상 0이다.
- B7: 돼지가 0마리가 되면 월드가 멈춘 뒤 클리어 오버레이(별·점수·다음/다시/메인)가 뜨고, 새가 0마리인데 돼지가 남으면 실패 오버레이(다시/메인)가 뜬다; 없으면 새를 다 써도 화면이 그대로다.
- B8: 새가 날아가면 카메라가 새를 따라가되 월드 끝에서 멈추고, 새가 정지하면 슬링샷으로 돌아온다; 없으면 새가 화면 밖으로 나가 보이지 않는다.
- B9: 블록이 부서지거나 돼지가 제거되면 파편 파티클과 짧은 화면 흔들림이 나온다; 없으면 파괴가 "삭제"처럼 보인다.
- B10: 발사·충돌·파괴·클리어에 효과음이 나고 메인/인게임에 BGM이 돌며, 음소거 버튼이 이를 끈다; 없으면 게임이 무음이다.
- C1: 플레이어가 인게임 캔버스 우측 상단의 `⏸` 버튼을 누르면 일시정지 오버레이가 뜬다; 없으면 우측에 버튼이 없거나 눌러도 게임이 계속 돈다.
- C2: 일시정지 오버레이에서 "다시하기"를 누르면 같은 스테이지가 처음부터, "메인으로"를 누르면 메인 화면이, "계속하기"를 누르면 멈췄던 그 자리에서 재개된다; 없으면 버튼이 있어도 아무 일이 없다.
- C3: 일시정지 중엔 물리 스텝·점수 타이머·슬링샷 입력이 모두 멈춘다; 없으면 오버레이 뒤로 새가 계속 날아간다.
- D1: 게임은 `MAIN/SELECT/PLAYING/PAUSED/CLEARED/FAILED` 중 정확히 하나의 상태에 있고, 상태 전이는 `transition(to)` 한 함수로만 일어난다; 없으면 일시정지 중 클리어 오버레이가 겹친다.
- D2: 페이지를 열면 메인 화면(제목·시작·이어하기·음소거)이 뜬다; 없으면 페이지가 빈 캔버스다.
- D3: 창 크기를 바꾸면 캔버스가 16:9 비율을 유지하며 레터박스로 맞춰지고 입력 좌표가 월드 좌표로 정확히 변환된다; 없으면 새를 잡는 위치가 어긋난다.
- D4: 모바일 세로 모드에서는 "가로로 돌려주세요" 오버레이가 뜬다; 없으면 슬링샷이 화면 밖에 있다.
- D5: 클리어 결과가 나오면 `localStorage["ab.save.v1"]`에 별·해제 상태가 써지고 재접속 시 읽힌다; 없으면 새로고침마다 1단계로 돌아간다.

## 3. 문제 정의 / 목표

브라우저에서 열어 즉시 플레이 가능한 앵그리버드류 슬링샷 게임. 성공 = §9 "done" 문장 전부 충족. 서버·계정·빌드 서버 없음, 정적 파일만으로 배포.

## 4. 명시적 가정 (틀렸을 때의 영향)

- **[전체가 걸림] Matter.js 0.20이 데스크톱+모바일 브라우저에서 60fps로 100개 강체를 돌린다.** 틀리면: 스테이지 블록 수 상한을 40으로 낮춘다. 가장 싼 조기 검증: 5단계(얇은 슬라이스)에서 블록 120개 스트레스 스테이지를 하나 두고 DevTools 프레임 타임을 본다. 폴백: `engine.timing.timeScale` 유지 + 서브스텝 1로 고정, 파티클 수 절반.
- 사용자는 마우스 또는 단일 터치로 조작한다(멀티터치 제스처 없음). 틀리면: B2에서 pointer id를 하나만 추적하므로 두 번째 손가락은 무시된다 — 허용 가능.
- 오디오는 사용자 제스처 이후에만 재생된다(자동재생 정책). 틀리면: 문제 없음(더 일찍 재생될 뿐).
- 에셋은 저작권 없는 자체 도형/색상 렌더링으로 충분하다(원작 스프라이트 사용 안 함). 틀리면: `render/` 모듈만 교체, 로직 불변.
- 10단계 데이터는 코드로 저작한다(에디터 없음). 틀리면: D7 셀을 defer로 바꾸고 JSON 로더로 교체(스키마는 동일).

## 5. 접근 & 단계 (의존 순서; 각 단계는 전제 → 산출 → 검증 → 담당 셀)

**단계 0 — 골격.** 전제: 없음. Vite+TS 프로젝트, `npm run typecheck`/`test`/`build`가 빈 프로젝트에서 0으로 종료. 검증: 세 명령 종료코드 0. 셀: (인프라).

**단계 1 — 타입과 스테이지 스키마.** 전제: 0. `types.ts`에 `StageDef {id, birds: BirdKind[], pigs: {x,y,hp}[], blocks: {x,y,w,h,material,angle?}[], starThresholds:[n1,n2,n3]}`, `Material = wood|ice|stone` (HP·밀도 상수). `stages/index.ts`가 10개를 배열로 export하고 길이 10을 `satisfies` 튜플로 컴파일 타임에 강제. 검증: 길이·id 유일성·모든 pig hp>0 유닛 테스트. 셀: A1 (내용은 단계 7에서 채움; 여기선 1단계와 스트레스 스테이지만 실제 데이터).

**단계 2 — 물리 월드.** 전제: 1. `physics.ts`: Matter `Engine` 생성, 중력 y=1(초기값·§9 참고), 바닥·벽 static body, `spawnStage(def)`가 블록/돼지/새 body를 라벨(`block:wood` 등)과 함께 생성. 검증: 유닛 테스트 — 새 body에 속도를 주고 120스텝 후 y가 증가했고 바닥을 뚫지 않았다. 셀: B1.

**단계 3 — 상태 머신 + 루프.** 전제: 2. `state.ts`: 6상태 enum, `transition(to)`가 허용 전이표 밖이면 throw. `loop.ts`: `requestAnimationFrame`에서 상태가 `PLAYING`일 때만 `Engine.update(engine, 1000/60)`. 검증: 유닛 테스트 — `PAUSED`에서 `CLEARED`로 전이 시 throw; `PAUSED`에서 update 호출 시 body 위치 불변. 셀: D1, C3.

**단계 4 — 슬링샷 입력 + 발사 + 렌더 (얇은 슬라이스의 핵심).** 전제: 2, 3. `input.ts`: pointerdown이 현재 새의 반경 40px 내면 `drag.active=true`, pointermove가 `dragVector`를 최대 당김 90px로 클램프, pointerup에서 길이 > 12px이면 `Body.setStatic(bird,false)` + `Body.setVelocity(bird, -dragVector × k)` (k 초기값 0.18). `render.ts`: Canvas 2D로 body 폴리곤·고무줄·궤적 점 12개(현재 dragVector로 시뮬 12스텝). 검증: Playwright — 새 좌표에서 마우스다운 → 80px 좌하 드래그 → 업 후 500ms에 새 x가 시작보다 200px 이상 우측. 셀: B2, B3.

**단계 5 — 피해·파괴·판정·점수 (얇은 슬라이스 완결).** 전제: 4. `damage.ts`: `collisionStart`에서 두 body 상대속도·질량으로 충격량 계산, 임계 4(초기값) 이상이면 상대 HP 차감; HP≤0이면 `World.remove` + 점수(나무 100/얼음 50/돌 200/돼지 1000, 초기값). `judge.ts`: 마지막 새 발사 후 모든 non-static body 속도 < 0.05 가 30프레임 연속이거나 8초 경과 시 정착; 정착 시 돼지 0 → `CLEARED`(남은 새 ×500 보너스, 별은 `starThresholds`), 새 0 & 돼지>0 → `FAILED`. 검증: 유닛 — 돼지 위에 돌 블록을 떨어뜨리면 돼지 제거·점수 1000 이상; 통합 — 1단계를 스크립트 입력으로 클리어하면 `CLEARED`. 셀: B4, B5, B6, B7. **이 단계 종료 = 1단계 하나가 처음부터 끝까지 도는 얇은 슬라이스.**

**단계 6 — 화면·오버레이·일시정지.** 전제: 3, 5. `screens/`: 메인(D2), 선택(A2), HUD(점수·남은 새·우측 상단 ⏸ 버튼 = 캔버스 폭−56px, y 16px)(C1), 일시정지 오버레이(계속/다시하기/메인으로)(C2), 결과 오버레이(B7 UI). 버튼은 DOM 요소를 캔버스 위에 절대 배치(포인터 접근성·터치 히트 영역 확보). 검증: Playwright — PLAYING에서 ⏸ 클릭 → 오버레이 표시 & 새 좌표 500ms 동안 불변; "다시하기" → 같은 stage id로 `PLAYING`; "메인으로" → `MAIN`. 셀: A2, C1, C2, D2.

## 6. 하중 경로 (Load-bearing path)

가장 복잡한 경로가 아니라 실패하면 게임이 무의미해지는 경로: **새를 당겨 놓으면 날아가 돼지를 없애고 클리어가 뜬다.**

| hop | 이름 | 통과 조건 (passes only if) | 그 조건이 처음 참이 되는 곳 |
|---|---|---|---|
| 1 | `input.onPointerDown` | `state === PLAYING` && `currentBird !== null` && 포인터가 새 반경 40px 내 | `state`: 단계 3 `transition(PLAYING)`이 선택 화면 카드 클릭에서 호출 / `currentBird`: 단계 2 `spawnStage()`가 첫 새를 슬링샷 위치에 static으로 두고 `currentBird`에 대입 |
| 2 | `input.onPointerMove` → `dragVector` | `drag.active === true` | hop 1 진입 시 `drag.active = true` (단계 4) |
| 3 | `input.onPointerUp` → `launch(bird)` | `|dragVector| > 12` | hop 2가 이동마다 갱신 (단계 4); `k`는 `physics.ts` 상수(단계 2) |
| 4 | `damage.onCollision` → 돼지 `hp ≤ 0` → `World.remove` → `pigsRemaining--` | `collisionStart` 핸들러 등록됨 && 충돌 body 라벨이 `pig` && 충격량 ≥ 4 | 핸들러: 단계 5 `installDamage(engine)`이 `spawnStage` 직후 호출 / 라벨: 단계 2 `spawnStage` / `pigsRemaining`: 단계 2 `spawnStage`가 `def.pigs.length`로 초기화 |
| 5 | `judge.tick` → `transition(CLEARED)` → 결과 오버레이 | `settled === true` && `pigsRemaining === 0` | `settled`: 단계 5 `judge`가 마지막 발사 후 저속 30프레임 또는 8초에 true / 오버레이: 단계 6 `screens/result`가 `CLEARED` 전이 구독 |

## 7. 대안과 기각 사유 (각각 재개 트리거 포함)

- **물리 직접 구현** — 기각: 강체 회전·정지 판정·스택 안정성이 이 과제의 가치가 아닌데 비용의 절반을 먹는다. **재개 트리거:** Matter.js가 모바일에서 40fps 미만이거나 번들 크기가 300KB gzip을 넘기는 것이 관측되면, 원+AABB 전용 미니 엔진으로 교체 검토.
- **Pixi.js/WebGL 렌더** — 기각: 도형 100개 수준은 Canvas 2D로 충분하고 의존성 하나가 준다. **재개 트리거:** 파티클 포함 프레임 타임이 데스크톱에서 16ms를 넘으면 렌더 모듈만 교체.
- **React/Phaser 프레임워크** — 기각: 상태 머신과 루프가 작아 프레임워크가 강제하는 구조가 더 크다. **재개 트리거:** 화면 종류가 8개를 넘거나 UI 상태가 게임 상태와 독립적으로 복잡해지면 UI 층만 React로.
- **점수 임계 클리어(돼지 제거 대신)** — 기각: 원작 규칙(돼지 전멸)이 사용자의 "앵그리버드와 같은 시스템" 문구와 일치. 점수는 **별 등급**으로 살아있다(B6/B7). **재개 트리거:** 사용자가 별 대신 점수 목표를 요구하면 `judge.ts`의 클리어 조건 한 줄 교체.
- **JSON 스테이지 + 에디터** — 기각: 저작자가 개발자 1인. **재개 트리거:** 비개발자가 스테이지를 만들게 되면 `StageDef`를 JSON 스키마로 내보내고 로더 교체.

## 8. 리스크 & 완화

- 정착 판정이 안 끝남(블록이 미세하게 떨림) → 8초 타임아웃 + 속도 임계 0.05(초기값; 플레이테스트 후 조정). 
- 일시정지 중 `requestAnimationFrame` 재개 시 dt 폭주 → 고정 스텝 1000/60만 사용, 실제 경과시간은 쓰지 않음(단계 3).
- 터치와 마우스 이중 발화 → Pointer Events만 사용, `touchstart` 미사용.
- 자동재생 정책으로 오디오 실패가 예외를 던져 루프를 죽임 → `audio.ts` 모든 호출 try/catch, 실패는 무음.
- 스테이지 10개 저작이 늦어져 폴리시가 잘림 → 단계 7·9 병렬, 단계 9는 이름 있는 단계라 스킵 불가.
- `localStorage` 비활성(프라이빗 모드) → 메모리 폴백, 저장 실패는 조용히 무시.

## 9. "완료"의 정의 (측정 가능한 문장)

1. `npm run typecheck` 종료코드 0 (TypeScript가 사주는 보증: `StageDef` 스키마와 상태 전이표가 컴파일 타임에 검사됨).
2. `npm run test` 종료코드 0, 다음 테스트 포함: 스테이지 배열 길이 === 10, 상태 전이 위반 throw, PAUSED 중 body 불변, 저장 라운드트립, 좌표 변환 왕복.
3. `npm run e2e` 종료코드 0: (a) 1단계에서 드래그-릴리즈 후 500ms에 새가 200px 이상 이동, (b) ⏸ 클릭 → 오버레이 표시 + 새 좌표 500ms 불변 → "다시하기" → 같은 stage id, "메인으로" → 메인 화면, (c) 10개 스테이지 각각 `*.solution.ts` 입력으로 `CLEARED` 도달, (d) 새로고침 후 해제 상태 유지.
4. `npm run build` 종료코드 0이고 `dist/`를 정적 서버로 열면 메인 화면이 뜬다(e2e (e)로 검사: `dist` preview에서 `#main-screen` 존재).
5. ⏸ 버튼의 bounding box 중심 x가 캔버스 폭의 80% 이상(e2e (b)에서 assert) — "우측" 요구의 측정.

숫자 태그: 중력 1, k 0.18, 당김 최대 90px, 최소 12px, 충격 임계 4, 속도 임계 0.05, 8초, 점수표, 별 임계 — 전부 **초기값(declared arbitrary)**, 단계 7 저작 중 첫 플레이테스트(저작자 본인, 각 스테이지 10회 시도 클리어율 기록)에서 교체. 200px/500ms/40px 반경 — 테스트 판별용 파생값(200px = 최소 발사 속도 × 0.5s의 절반 이하로 잡음).

## 10. 구현자 계약

- 스택: `typescript ^5.8.0`, `vite ^6.0.0`, `matter-js 0.20.0`, `@types/matter-js ^0.19.8`, `vitest ^3.0.0`, `@playwright/test ^1.50.0`. 산 이유: TS는 스테이지 스키마·전이표 컴파일 검사, Matter는 강체/충돌, Vite는 정적 빌드, Vitest/Playwright는 §9 명령.

## Frame deviations & habit regressions

- §5 단계 번호가 사다리처럼 보이지만 8·9는 병렬이고 7·9도 병렬이다 — 본문 끝에 병렬 줄을 한 줄로만 적어 약하다. 리뷰어라면 §5 단계 8의 전제 "4"가 실은 "4와 6(뷰포트가 DOM 버튼 좌표에도 영향)"이라는 점을 공격하겠다; 수정하지 않고 남긴 이유는 8을 6 이후로 미루면 얇은 슬라이스의 모바일 확인이 늦어져서다.
