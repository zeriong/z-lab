# 구현 계획서: 웹 브라우저 슬링샷 물리 게임 (앵그리버드 스타일)

> 입력: `inputs/game-prompt.md`
> 이 문서는 구현 계획서다. 코드는 포함하지 않는다. 데이터 형식 예시와 폴더 구조만 넣었다.
> 문서 안의 수치는 모두 **초기값**이다. 특별히 "고정"이라고 적은 것만 예외다. 초기값은 Phase 0 스파이크와 플레이테스트를 거쳐 조정하고, 조정한 값은 `config/` 한 곳에서만 관리한다.

## 0. 한눈에 보기

| 핵심 질문 | 결정 | 한 줄 근거 |
|---|---|---|
| 물리 엔진 | **Planck.js (Box2D의 JS 포팅)**. 대안은 Matter.js | 적층 안정성, 탄환(CCD) 처리, 충격량 콜백이 이 장르에 맞는다. 원작도 Box2D를 썼다 |
| 렌더링 | **Canvas 2D에 직접 만든 렌더러를 쓰고, UI는 DOM 오버레이로 둔다** | 도형 수가 적어 WebGL까지는 필요 없다. 버튼과 오버레이는 DOM이 접근성, 클릭 판정, 반응형 배치에서 유리하다 |
| 빌드 | Vite + TypeScript, 정적 산출물 | 빌드 설정이 거의 필요 없다. Vitest와 Playwright를 쓰기 쉽다. 결과물은 정적 호스팅이면 충분하다 |
| 스테이지 데이터 | 스테이지당 JSON 1개(`stage01~10.json`). 빌드 시점에 번들한다. 부팅할 때 스키마를 검증한다 | 런타임 fetch가 실패할 일이 없다. 데이터와 로직을 분리했으므로 헤드리스 테스트가 된다 |
| 스테이지 전환 | 세션을 **통째로 파괴한 뒤 새로 생성**한다. 위치만 되돌리는 리셋은 하지 않는다 | 다시하기와 다음 스테이지가 같은 경로를 타게 되어, 상태 누수가 구조적으로 막힌다 |
| 슬링샷 입력 | Pointer Events로 마우스와 터치를 한 경로에서 처리한다. 드래그로 당기고 놓으면 발사된다. 당김 길이는 최대값에서 클램프한다 | 입력 경로가 하나라서 버그가 생길 곳도 하나다 |
| 궤적 예측 | 비행 초반 0.75초 분량만 점선으로 보여준다. 직전 발사 궤적은 흔적으로 남긴다 | 조준 편의는 주되 전부 알려주지는 않는다. 예측값은 엔진 적분식을 그대로 재현한다 |
| 파괴 판정 | 접촉 충격량에서 임계값을 뺀 만큼을 데미지로 준다. HP가 0 이하가 되면 파괴한다 | 원작과 같은 방식이다. 정지 접촉으로는 데미지가 생기지 않는다 |
| 클리어와 실패 | 돼지가 0마리면 클리어다. 새를 다 쓰고 월드가 정착했는데 돼지가 남아 있으면 실패다 | 판정 시점을 정착 이후로 고정했으므로 경쟁 상태가 생기지 않는다 |
| 상태 머신 | 두 층으로 나눈다. **앱 상태**(메인/선택/플레이/일시정지/클리어/실패)와 **턴 상태**(장전/조준/비행/정착)다 | 일시정지는 앱 층에서 턴 층 전체를 얼리는 방식으로 처리한다 |
| 완료 기준 | §12의 체크리스트. 10개 스테이지 모두 **기준 해법을 헤드리스로 재생해 클리어되는지** 자동 검증한다 | "된 것"을 사람 판단이 아니라 테스트로 확인한다 |

## 1. 목표와 범위

### 1.1 요구사항 (원문 기준)

| ID | 요구사항 | 이 계획에서 대응하는 곳 |
|---|---|---|
| R1 | 스테이지 10단계 | §6 스테이지 시스템, §6.5 10개 스테이지 설계표 |
| R2 | 게임 시작부터 앵그리버드식 게임플레이까지 가능해야 한다(새총 당겨 쏘기, 포물선, 중력, 충돌, 구조물 파괴, 돼지 제거) | §5 게임플레이 설계 |
| R3 | 인게임 **우측**에 일시정지 버튼이 있고, 누르면 **다시하기 / 메인으로** 버튼이 나온다 | §4.1 앱 상태 머신, §7.3 일시정지 오버레이 |

### 1.2 가정

- 대상 브라우저: 최신 데스크톱 Chrome, Edge, Firefox, Safari를 1차로 지원한다. 2차는 가로 모드의 iOS Safari와 Android Chrome이다.
- 백엔드는 없다. 진행도는 `localStorage`에 저장한다.
- UI 문구는 한국어다.
- 이미지 에셋은 쓰지 않는다. 모든 그래픽을 Canvas 경로로 직접 그린다. 로딩 단계가 없고 저작권 문제도 없다. 원작 에셋과 상표는 쓰지 않으며, 가칭은 "슬링샷 버드"다.
- 사운드는 필수 범위에 넣지 않았다(§1.3).

### 1.3 범위 밖 (이번 구현에서 하지 않음)

- 카메라 팬과 줌. 모든 스테이지가 한 화면(논리 해상도 1920×1080) 안에 들어가게 설계한다. 나중에 확장할 수 있다.
- 사운드와 BGM. 여유가 있으면 Phase 7에서 WebAudio 효과음을 넣는다.
- 레벨 에디터, 온라인 랭킹, 다국어, 클라우드 저장.
- 분열 새(파란 새) 같은 추가 새 종류. 이번에는 빨강, 노랑, 폭탄 세 종류만 만든다.

### 1.4 요구사항 해석상 추가한 것

- 일시정지 오버레이에 **"계속하기"** 버튼을 추가했다. 요구된 두 버튼(다시하기, 메인으로)은 그대로 두었다. 재개할 방법이 없으면 일시정지가 막다른 길이 되기 때문이다. 요구사항과 충돌하지 않는다.
- "게임 시작"을 누르면 **스테이지 선택 화면**을 거쳐 스테이지로 들어간다. 처음에는 1단계만 열려 있으므로 실제로는 바로 시작하는 것과 같다. 10단계 진행 구조를 보여 주는 데 필요하다.

## 2. 기술 결정 (ADR 요약)

### ADR-1 물리 엔진: Planck.js

| 선택지 | 장점 | 단점 | 판단 |
|---|---|---|---|
| 직접 구현 | 의존성이 없다 | 회전하는 강체를 마찰까지 넣어 쌓으려면 SAT, 순차 임펄스 솔버, 슬립 처리를 모두 만들어야 한다. 이것만으로 몇 주 걸리는 난제다 | **기각** |
| Matter.js | 인지도가 높고 API가 단순하며 예제가 많다 | 높이 쌓으면 흔들리거나 물렁하게 보이는 일이 잦다. CCD가 없어 빠른 새가 얇은 블록을 뚫는다. 충격량 정보가 없어 데미지를 속도로 근사해야 한다 | **대안(폴백)** |
| **Planck.js** | Box2D 계열이라 적층이 안정적이다(warm starting). `bullet` 플래그로 CCD를 켤 수 있다. `post-solve` 콜백이 실제 접촉 충격량을 준다. 슬립을 지원한다. 같은 플랫폼에서는 결정론적이다 | 단위가 MKS라서 스케일 변환이 필요하다. 콜백 안에서 월드를 수정하면 안 된다(월드 잠금) | **채택** |

- 버전: npm `planck` 1.x로 고정한다(구 패키지명은 `planck-js`). 정확한 버전은 Phase 0에 lockfile로 고정한다.
- 폴백 조건: Phase 0 스파이크 S1, S2, S4 가운데 하나라도 해결할 수 없으면 Matter.js로 바꾼다. 물리 래퍼(`core/physics/`) 밖에서는 엔진 API를 직접 부르지 않는다. 그래서 교체 비용은 래퍼와 데미지 계산 두 곳으로 한정된다.

### ADR-2 렌더링: Canvas 2D 직접 렌더링 + DOM UI

- 월드(하늘, 지면, 새총, 블록, 돼지, 새, 이펙트)는 `<canvas>` 하나에 Canvas 2D로 그린다. 스테이지당 동적 바디는 80개 이하로 제한하므로 WebGL이 필요 없다.
- 엔진에 딸린 디버그 렌더러(Planck testbed, Matter.Render)는 제품 화면에 쓰지 않는다. `?debug=1` 와이어프레임 오버레이는 직접 만든다.
- 버튼, HUD, 오버레이는 캔버스 위에 겹친 DOM 레이어다. 실제 `<button>`이라서 클릭과 포커스와 키보드를 무료로 얻는다. 일시정지 버튼 클릭이 캔버스 입력(드래그, 새 능력)으로 새지 않는다. E2E에서 셀렉터로 찾기도 쉽다.

### ADR-3 빌드와 테스트 도구

- Vite + TypeScript(strict). `vite build`는 `dist/`를 만들고 정적 호스팅으로 배포한다. `base: './'`로 경로를 상대화한다.
- 단위 테스트와 헤드리스 시뮬레이션 테스트는 Vitest(Node)로 돌린다. 브라우저 E2E는 Playwright(Chromium 필수, WebKit과 Firefox는 스모크)로 돌린다.
- `core/`에서는 DOM API를 쓰지 않는다. ESLint `no-restricted-globals`로 `window`, `document`, `requestAnimationFrame`, `setTimeout`을 막는다. 그래야 Node에서 게임 로직 전체를 돌릴 수 있다.

### ADR-4 시간 처리: 고정 스텝, 게임 시간 기반 타이머

- 물리는 고정 스텝 `dt = 1/60 s`(초기값)로 돌린다. rAF 루프에서 누산기를 쓴다. 프레임 델타는 최대 100ms로 클램프하고, 한 프레임의 스텝은 최대 5회로 제한해 과부하 악순환을 막는다.
- **`core/` 안의 모든 타이머는 세션의 시뮬레이션 시간(`simTime`)으로 잰다.** 벽시계나 `setTimeout`은 쓰지 않는다. 그래서 일시정지하면 타이머도 저절로 멈추고, 다시하기로 세션을 파괴하면 대기 중이던 타이머도 함께 사라진다.

## 3. 아키텍처

### 3.1 레이어

```
┌──────────────────────────── App (브라우저) ────────────────────────────┐
│  app/     : 앱 상태 머신, 화면 전환, rAF 루프 소유                          │
│  ui/      : DOM 화면(메인, 스테이지 선택, HUD, 일시정지, 결과)                │
│  input/   : Pointer/Keyboard → 월드 좌표 명령으로 변환                      │
│  render/  : Canvas 2D 렌더러(세션 상태를 읽기만 함)                         │
│  storage/ : 진행도 저장                                                  │
├──────────────────────────── core/ (DOM 없음) ─────────────────────────┤
│  GameSession : 스테이지 1회 플레이. create → step(dt)* → destroy          │
│  physics/    : Planck 래퍼, 단위 변환, 콜백 큐                             │
│  rules/      : 턴 상태, 데미지, 폭발, 정착, 점수(대부분 순수 함수)             │
│  slingshot / trajectory : 당김→속도, 궤적 예측(순수 함수)                   │
│  stage/      : 스키마, 검증                                               │
└──────────────────────────────────────────────────────────────────────┘
```

- 의존 방향은 `app → ui/render/input → core` 한 방향이다. `core`는 바깥을 모른다.
- `GameSession`은 이벤트(`pigKilled`, `blockDestroyed`, `scoreChanged`, `turnChanged`, `cleared`, `failed`, `explosion`)를 내보낸다. 렌더러와 UI는 이 이벤트를 구독하거나 상태를 읽기만 한다.

### 3.3 좌표계와 단위 (고정)

- **논리 해상도는 1920×1080이다(16:9).** 모든 스테이지 데이터와 렌더링이 이 단위(이하 "px")를 쓴다.
- **y축은 아래로 증가한다.** 물리 월드도 똑같이 y-down으로 두고 중력을 `(0, +G)`로 준다. 좌표를 뒤집는 곳이 없으므로 부호 버그가 생기지 않는다. 각도는 시계 방향을 양수로 하며 Canvas `rotate`와 일치한다.
- 물리 단위 변환: `PPM = 50 px/m`(초기값). 1920×1080px은 38.4×21.6m가 된다. 새 반지름 22px은 0.44m로, Box2D가 권장하는 0.1~10m 범위 안이다. 변환은 `core/physics/world.ts`에서만 한다.
- 지면 윗면은 `y = 980`이다. 지면은 x ∈ [-400, 2320] 구간을 덮는 정적 바디다.
- 스테이지 데이터에 적는 바디 위치는 **중심 좌표**다.

### 3.4 메인 루프

- rAF 루프는 하나다. App이 소유하고 화면이 바뀌어도 계속 유지한다.
  - `PLAYING`: 누산기로 `session.step(dt)`을 0~5회 실행한 뒤 렌더링한다.
  - `PAUSED`, `CLEARED`, `FAILED`: 스텝을 돌리지 않는다. 멈춘 화면을 렌더링하고, 결과 화면이면 이펙트만 계속 그린다.
  - 메뉴 화면: 캔버스를 숨기고 루프는 아무 일도 하지 않는다.
- 재개할 때는 `lastTime`을 다시 설정해 멈춰 있던 동안의 델타가 한꺼번에 들어오지 않게 한다.
- 렌더 보간(120Hz 디스플레이에서 생기는 떨림 방지)은 Phase 7 폴리시 항목이다.

## 4. 상태 머신

### 4.1 앱 상태 머신 (`app/appMachine.ts`, 순수 전이표)

```
BOOT ──ready──▶ MAIN ──start──▶ STAGE_SELECT ──select(n)──▶ PLAYING(n)
                 ▲                  │back                     │  ▲
                 │◀─────────────────┘                  pause  │  │ resume
                 │                                            ▼  │
                 │◀──────────────toMain──────────────────── PAUSED(n)
                 │                                            │ retry → PLAYING(n)
                 │◀──toMain── CLEARED(n) ◀──cleared── PLAYING(n)
                 │◀──toMain── FAILED(n)  ◀──failed─── PLAYING(n)
```

| 현재 상태 | 이벤트 | 다음 상태 | 부수 효과 |
|---|---|---|---|
| BOOT | `ready` | MAIN | 스테이지 10개 검증 완료 |
| MAIN | `start` | STAGE_SELECT | — |
| STAGE_SELECT | `select(n)` (n이 해금된 경우) | PLAYING(n) | 세션 생성 |
| STAGE_SELECT | `back` | MAIN | — |
| PLAYING | `pause` (버튼, ESC, 탭 숨김) | PAUSED | 조준 중이었으면 취소 |
| PAUSED | `resume` (계속하기, ESC) | PLAYING | `lastTime` 재설정 |
| PAUSED | `retry` (다시하기) | PLAYING(n) | 세션 파괴 후 재생성 |
| PAUSED | `toMain` (메인으로) | MAIN | 세션 파괴 |
| PLAYING | `cleared` (세션 이벤트) | CLEARED(n) | 진행도 저장, n+1 해금 |
| PLAYING | `failed` (세션 이벤트) | FAILED(n) | — |
| CLEARED | `next` (n<10) | PLAYING(n+1) | 세션 파괴 후 재생성 |
| CLEARED, FAILED | `retry` | PLAYING(n) | 세션 파괴 후 재생성 |
| CLEARED, FAILED | `toMain` | MAIN | 세션 파괴 |
| (그 외 모든 조합) | — | **무시** | 없음. 예: CLEARED에서 `pause`, 전환 중 중복 클릭 |

불변식:
- `PLAYING`과 `PAUSED`에서는 세션이 정확히 1개 있고, 그 밖의 상태에서는 0개다. 결과 화면에서는 배경으로 보여 주기 위해 멈춘 세션 1개를 유지하고, 결과 화면을 떠날 때 파괴한다.
- 세션은 언제나 **동결된 원본 스테이지 데이터를 깊은 복사**해서 만든다. 원본은 dev 빌드에서 `Object.freeze`로 보호한다.
- 버튼을 누르면 전이가 끝날 때까지 해당 오버레이의 모든 버튼을 `disabled`로 바꾼다. 연타해도 세션이 두 번 생기지 않는다.

### 4.2 턴 상태 머신 (`core/rules/turn.ts`, 세션 내부)

```
LOADING ──(0.5s)──▶ READY ──드래그 시작──▶ AIMING ──놓음(당김≥최소)──▶ FLYING
   ▲                  ▲                      │놓음(당김<최소)/취소          │
   │                  └──────────────────────┘                          │ 새 종료 조건
   │                                                                     ▼
   └──(새 남음, 돼지 남음)── EVALUATE ◀──(정착 또는 타임아웃)── SETTLING
                              │ 돼지 0 → CLEAR_PENDING ──(1.5s)──▶ [cleared 이벤트]
                              │ 새 0, 돼지 남음 → [failed 이벤트]
   (어느 상태에서든 마지막 돼지가 죽으면 즉시 CLEAR_PENDING으로 간다)
```

| 상태 | 진입 조건과 동작 | 종료 조건 |
|---|---|---|
| LOADING | 다음 새가 새총으로 이동한다(시각 트윈 0.5s). 입력을 받지 않는다 | 0.5s 경과 → READY |
| READY | 새총에 새가 올라가 있다. **새 바디는 아직 월드에 없다** | 새 근처에서 포인터 다운 → AIMING |
| AIMING | 당김 벡터를 갱신하고 궤적 예측을 표시한다 | 놓음: 당김이 `L_min` 이상이면 FLYING, 미만이면 READY. `pointercancel`이나 일시정지면 READY |
| FLYING | 발사 순간 새 바디를 생성하고(`bullet=true`) 속도를 설정한다. 능력은 1회 쓸 수 있다. 궤적 흔적을 기록한다 | 새 종료 조건(§5.5) → SETTLING |
| SETTLING | 월드가 정착하기를 기다린다 | 정착했거나 최대 3s가 지나면 EVALUATE |
| EVALUATE | 사용한 새를 제거한다(연기 효과). 판정한다 | 즉시 분기 |
| CLEAR_PENDING | 시뮬레이션을 1.5s 더 돌려 무너지는 블록 점수를 더 받는다. 남은 새 보너스를 정산한다 | 1.5s 경과 → `cleared` |

- **실패는 EVALUATE에서만 판정한다.** 마지막 새를 쏜 뒤 정착하는 동안 돼지가 죽으면 클리어로 처리한다.
- 모든 시간은 `simTime` 기준이다. 일시정지하면 턴 상태 전체가 그대로 얼어붙는다.

## 5. 게임플레이 설계

### 5.1 슬링샷 입력, 조준, 발사

| 항목 | 명세 (초기값) |
|---|---|
| 새총 위치 | 스테이지 데이터의 `slingshot.x`(기본 260). 주머니 기준점(앵커)은 `(x, 830)`으로, 지면에서 150px 위다 |
| 드래그 시작 | READY 상태에서 포인터 다운 위치가 앵커로부터 **70px 이내**일 때만 시작한다. 터치를 고려해 넉넉하게 잡았다 |
| 포인터 처리 | Pointer Events를 쓴다. 드래그를 시작하면 `setPointerCapture`로 캔버스 밖으로 나가도 추적한다. 주 포인터 1개만 따라가고 나머지 멀티터치는 무시한다. 우클릭은 무시한다. 캔버스에 `touch-action: none`을 걸고 컨텍스트 메뉴를 막는다 |
| 좌표 변환 | 화면 좌표를 뷰포트 역변환으로 월드 좌표로 바꾼다(§8.1). 드래그 중에 리사이즈가 일어나도 월드 좌표 기준이라 끊기지 않는다 |
| 당김 벡터 | `p = 포인터 − 앵커`. `|p|`는 최대 `L_max = 130px`에서 클램프한다. 방향 제한은 없다(뒤로 쏘기도 허용) |
| 발사 속도 | `v = −p / L_max × V_max`(선형). `V_max ≈ 25 m/s`. 기준은 **최대 파워 45° 발사가 x≈1850 지면에 떨어지는 것**이고, Phase 0에서 G와 함께 맞춘다 |
| 취소 | 놓을 때 `|p| < L_min = 20px`이면 발사하지 않고 READY로 돌아간다. 새는 소모되지 않는다 |
| 새 바디 생성 | 발사하는 순간 주머니 위치에 동적 바디를 만든다. `setStatic`을 켰다 끄는 방식의 질량 복원 문제를 피하려는 것이다 |
| 고무줄 | 새총의 두 갈래 끝에서 새까지 두 선을 그린다. 당김이 클수록 선을 가늘게 한다 |

### 5.2 궤적 예측 UX

- AIMING 동안 **비행 초반 0.75s 분량**을 점으로 표시한다. 3스텝(0.05s)마다 점 하나이므로 약 15개다. 뒤로 갈수록 작고 투명해진다.
- 예측 계산은 Box2D의 반암시적 오일러 적분을 **그대로 재현**한다. 순서는 `v += g·dt`, 선형 감쇠 적용, `x += v·dt`다. 새의 `linearDamping`은 0이다. 블록과의 충돌은 무시하는 순수 탄도 계산이며, 예측점이 지면 아래로 내려가면 거기서 멈춘다.
- 정확도는 테스트로 보장한다. 실제 월드에서 새 하나를 쏜 결과와 비교해 **1s 동안 최대 오차가 2px 미만**이어야 한다(§11.1 U-3).
- **직전 발사의 흔적**: FLYING 중 3스텝마다 새 위치를 기록해 흰 점으로 남긴다. 다음 발사 때 지운다.
- 예측 길이(0.75s)는 `constants.ts`의 상수 하나로 바꿀 수 있다.

### 5.3 엔티티 카탈로그 (`config/catalog.ts`)

**새**

| 종류 | 반지름 | 밀도 | 능력 (FLYING 중 캔버스 탭 1회) | 첫 등장 |
|---|---|---|---|---|
| 빨강 | 22px | 3.0 | 없음 | 1 |
| 노랑(가속) | 20px | 3.0 | 현재 진행 방향으로 속도 ×2.2(상한 60 m/s) | 4 |
| 폭탄(검정) | 26px | 4.0 | 탭하면 즉시 폭발한다. 탭하지 않으면 **첫 충돌 후 2.0s에 자동 폭발**한다(§5.6) | 7 |

- 새는 데미지를 받지 않는다. 모든 새는 `bullet=true`로 둬서 CCD를 켠다.
- 능력 입력은 FLYING 상태에서 캔버스 어디든 누르는 포인터 다운이다. DOM 버튼(일시정지)은 캔버스 위 레이어에 있으므로 능력이 발동되지 않는다.

**돼지**

| 크기 | 반지름 | 밀도 | HP | 처치 점수 |
|---|---|---|---|---|
| S | 20px | 1.0 | 40 | 5,000 |
| M | 28px | 1.0 | 70 | 5,000 |
| L | 38px | 1.0 | 120 | 5,000 |

**블록 재질**

| 재질 | 밀도 | 마찰 | 반발 | HP | 파괴 점수 | 외형 |
|---|---|---|---|---|---|---|
| 유리(얼음) | 0.9 | 0.2 | 0.05 | 50 | 300 | 반투명 하늘색 |
| 나무 | 0.6 | 0.6 | 0.1 | 100 | 500 | 갈색 나뭇결 |

- 표준 크기는 모두 20px 격자 위에 둔다. 판자 20×100과 20×200, 상자 40×40과 80×80, 슬랩 200×20이다. 형태는 사각형이 기본이고 원(r=20/40)과 삼각형은 선택이다. **최소 두께는 20px로 고정한다.**

### 5.4 충돌과 데미지 (`core/rules/damage.ts`)

1. 물리 래퍼가 `post-solve` 콜백에서 접촉마다 **법선 충격량의 최대값 J**를 받아 큐에 쌓는다. 콜백 안에서는 월드를 절대 수정하지 않는다.
2. 월드 스텝이 끝나면 큐를 처리한다. 접촉한 두 바디 중 파괴 가능한 쪽(블록, 돼지, TNT)에 대해 다음을 계산한다.
   `damage = K × max(0, J − T)`
   - `T`(임계 충격량)는 정지 접촉과 적층 하중으로는 데미지가 생기지 않게 하는 값이다. **S1 안정성 스파이크에서 관측한 정지 상태 최대 스텝 충격량의 1.5배**로 경험적으로 정한다.
   - `K`(스케일)는 캘리브레이션 앵커 A1을 만족하도록 정한다(§11.3).
3. HP가 0 이하가 되면 `pendingDestroy` 표시를 한다. 같은 스텝의 후처리에서 바디를 제거하고, 점수와 파편 이펙트 이벤트를 낸다. 제거는 월드가 잠겨 있지 않을 때만 한다.
4. **유예 시간**: 스테이지 시작 후 1.0s 동안은 데미지를 끈다. 초기 배치가 미세하게 가라앉는 것 때문에 돼지가 죽는 사고를 막는 이중 안전장치다. 1차 안전장치는 §6.4 검증이다.
5. **월드 이탈**: x < -300, x > 2220, y > 1300 중 하나에 해당하는 바디는 제거한다. 돼지가 이탈하면 처치로 치고 점수를 준다. 새가 이탈하면 새 종료로 처리한다. 위쪽(y<0)은 하늘이므로 이탈로 보지 않는다. 새가 화면 위로 나가면 상단 가장자리에 위치 마커를 표시한다.
6. 손상 표현: HP가 66% 이하와 33% 이하일 때 금 간 오버레이를 단계별로 그린다.

### 5.5 새 종료와 정착 판정 (`core/rules/settle.ts`)

- **새 종료 조건**(FLYING에서 SETTLING으로): 다음 중 하나라도 해당하면 끝난다.
  (a) 새 속도가 0.3 m/s 미만인 상태가 1.0s 이어짐, (b) 새가 월드를 이탈함, (c) 폭탄 새가 폭발함, (d) 발사 후 8s 경과.
- **월드 정착**(SETTLING에서 EVALUATE로): 모든 동적 바디가 슬립 상태이거나, 모든 바디의 선속도가 0.05 m/s 미만이고 각속도가 0.05 rad/s 미만인 상태가 0.5s 이어지면 정착으로 본다. 정착하지 않아도 **최대 3s가 지나면 넘어간다.** 계속 굴러가는 원형 블록 때문에 게임이 멈추지 않게 하려는 것이다.

### 5.6 폭발 (`core/rules/explosion.ts`)

- 폭탄 새와 TNT가 같은 함수를 쓴다. 입력은 중심, 반경 R, 최대 충격량 I_max, 최대 데미지 D_max다.
- 반경 R 안의 바디를 AABB로 조회한 뒤 중심 간 거리 d로 거른다. 각 바디에 다음을 적용한다.
  - 충격량: 방향은 `(바디 중심 − 폭발 중심)` 정규화, 크기는 `I_max × (1 − d/R)`
  - 데미지: `D_max × (1 − d/R)`. 파괴 가능한 바디에만 준다.
- 가림(엄폐)은 계산하지 않는다. 폭발로 파괴된 TNT는 다음 스텝 후처리에서 연쇄 폭발한다(같은 스텝 안에서 재귀하지 않는다).
- 초기값: 폭탄 새는 R=160px, D_max=300. TNT는 R=180px, D_max=200. I_max는 앵커 A6로 맞춘다.

### 5.7 점수, 별, 클리어와 실패 (`core/rules/scoring.ts`)

| 이벤트 | 점수 |
|---|---|
| 돼지 처치(이탈 포함) | 5,000 |
| 블록 파괴 | 유리 300 / 나무 500 / 돌 800 |
| TNT 폭발 | 1,000 |
| 클리어 시 남은 새 | 1마리당 10,000 |

- **클리어**: 살아 있는 돼지 수가 0이 되면 CLEAR_PENDING으로 가고, 1.5s 뒤 `cleared`를 낸다.
- **실패**: EVALUATE 시점에 남은 새가 0이고 돼지가 1마리 이상이면 `failed`를 낸다.
- **별**: 클리어하면 1★. 점수가 스테이지 데이터의 `stars[0]` 이상이면 2★, `stars[1]` 이상이면 3★이다. 실패하면 별도 없고 기록도 남지 않는다.
- 점수가 올라가면 해당 위치에 `+5000` 같은 팝업을 띄우고 HUD 점수를 갱신한다.

## 6. 스테이지 시스템

### 6.1 데이터 스키마 (`core/stage/schema.ts`)

| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | 1~10 | 고유 번호 |
| `name` | string | 표시 이름 |
| `birds` | `("red"\|"yellow"\|"bomb")[]` | 발사 순서대로 나열한다. 1~6개 |
| `slingshot` | `{ x }` | 새총 밑동의 x 좌표 |
| `terrain` | `{ x, y, w, h, angle? }[]` 또는 다각형 | 정적 지형 |
| `blocks` | `{ material, shape, x, y, w?, h?, r?, angle? }[]` | 동적 블록. 중심 좌표 |
| `pigs` | `{ size: "S"\|"M"\|"L", x, y }[]` | 1개 이상 |
| `tnt` | `{ x, y }[]` | 선택 |
| `stars` | `[twoStar, threeStar]` | 점수 임계값. 오름차순 |
| `solution` | `{ pull: [dx, dy], abilityAt?: 초 }[]` | **기준 해법**. 자동 테스트가 재생한다. 게임 화면에는 쓰지 않는다 |

형식 예시(데이터):

```json
{
  "id": 1, "name": "첫 발사",
  "birds": ["red", "red", "red"],
  "slingshot": { "x": 260 },
  "terrain": [],
  "blocks": [{ "material": "wood", "shape": "rect", "x": 1400, "y": 930, "w": 20, "h": 100 }],
  "pigs": [{ "size": "S", "x": 1460, "y": 960 }],
  "tnt": [],
  "stars": [15000, 25000],
  "solution": [{ "pull": [-120, 45] }]
}
```

### 6.2 로딩

- `stages/*.json`은 빌드 시점에 Vite가 JSON으로 import해서 번들에 넣는다. 런타임 fetch가 없으므로 네트워크 실패 경로도 없다.
- 부팅(BOOT) 단계에서 10개 파일 모두 스키마 검증(§6.4의 정적 규칙)을 통과해야 MAIN으로 넘어간다. dev 빌드에서 실패하면 화면에 오류를 보여 주고, 테스트에서는 실패로 처리한다.

### 6.3 전환

- 다시하기, 다음 스테이지, 스테이지 선택 모두 **`session.destroy()` 후 `new GameSession(clone(stage[n]))`** 경로 하나로 처리한다.
- `destroy()`는 Planck 월드 참조를 끊고 이벤트 구독, 입력 바인딩, 이펙트 목록을 모두 해제한다. 월드는 세션마다 새로 만들기 때문에 이전 판의 흔적이 남을 수 없다.
- 화면 전환은 200ms CSS 페이드이며 시각 효과일 뿐이다. 세션 생성은 동기로 50ms 안에 끝나야 한다.

### 6.4 스테이지 검증 규칙 (`core/stage/validate.ts`)

정적 규칙(부팅 시와 테스트에서 검사):
- 파일은 정확히 10개이고 `id`는 1~10에 중복이 없다.
- 새는 1~6마리, 돼지는 1마리 이상이다. 모든 바디는 월드 경계 안에 있고 지면 위에 있다.
- 블록의 최소 치수는 20px 이상이다. 동적 바디는 모두 합쳐 80개 이하다.
- `stars`는 양수이고 오름차순이다. `solution` 길이는 `birds` 길이 이하다.

물리 규칙(sim 테스트에서만 검사):
- 스폰 시 겹침 없음: 모든 바디 쌍이 겹치지 않아야 한다(허용 오차 0.5px). 원하는 배치가 정확히 맞닿게 하려면 좌표를 계산해서 적는다. 예를 들어 지면 980 위에 높이 100인 블록을 놓으면 y=930이다.
- **스폰 안정성**: 발사 없이 3s를 시뮬레이션하는 동안 데미지 0, 파괴 0이어야 하고, 모든 바디의 이동량이 5px 미만이어야 한다. 이 검사는 유예 시간 없이 돌린다.
- **기준 해법 재생**: `solution`을 순서대로 쏘면 클리어되어야 한다(§11.2 S-5).

### 6.6 밸런싱 규칙

- **여유 규칙**: 스테이지 1~7은 기준 해법이 새를 **1마리 이상 남기고** 클리어해야 한다. 8~10은 남는 새가 0~1마리여도 된다. 조준이 조금 어긋나도 풀리게 하려는 것이다.
- **견고성 확인**: 기준 해법의 각 샷을 당김 벡터 ±3px로 흔든 변형 8개 중 **6개 이상이 클리어**되어야 한다. 스테이지 1~5에 적용한다. 너무 정밀한 한 방에만 의존하는 스테이지를 걸러낸다.
- **별 기준**: 3★은 기준 해법 점수의 95%를 1,000 단위로 내림한 값이다. 2★은 3★ 기준의 75%다. 플레이테스트 후 조정한다.
- **플레이테스트 목표**: 스테이지를 처음 보는 사람이 1~3단계는 3회 이내, 4~7단계는 5회 이내에 클리어해야 한다. 8~10단계는 여러 번 걸려도 되지만 **포기 없이 클리어할 수 있어야** 한다.

### 7.2 HUD 배치 (게임 영역 기준)

- 좌상단: `STAGE N`, 남은 새 아이콘(발사 순서대로)
- 우상단: 현재 점수, 그 **오른쪽 끝에 일시정지 버튼**
- HUD 요소는 모두 게임 영역(레터박스 안쪽) 사각형을 기준으로 배치한다. 화면 전체가 기준이 아니다. 울트라와이드 화면에서도 버튼이 게임 화면 안의 우측에 있게 하려는 것이다.

### 7.3 일시정지 버튼과 오버레이 명세 (R3)

- **위치**: 게임 영역의 오른쪽 위다. 게임 영역 오른쪽 가장자리와 위쪽 가장자리에서 각각 게임 영역 너비의 1.5%만큼 떨어진다.
- **크기**: 논리 해상도로 64×64. 실제 CSS 픽셀로는 최소 44×44를 보장한다(터치 목표 크기).
- **모양**: 원형 반투명 배경에 ❚❚ 아이콘. `aria-label="일시정지"`, `data-testid="btn-pause"`.
- **보이는 상태**: PLAYING일 때만 보인다. PAUSED, CLEARED, FAILED에서는 숨긴다.
- **누르면**: 앱 이벤트 `pause`가 발생한다. 그러면 물리 스텝이 멈추고, `simTime`이 멈추고, 조준 중이었으면 취소되고, 오버레이가 나타난다.
- **오버레이 버튼**(세로로 쌓음, `data-testid`):
  - `btn-resume` 계속하기: PLAYING으로 돌아간다
  - `btn-retry` **다시하기**: 같은 스테이지를 처음부터 다시 한다. 새, 돼지, 점수, 블록 모두 초기 상태가 된다
  - `btn-main` **메인으로**: 세션을 파괴하고 메인 화면으로 간다. 확인창은 띄우지 않는다
- **키보드**: ESC를 누르면 PLAYING과 PAUSED 사이를 오간다. 오버레이가 열리면 첫 버튼에 포커스를 준다. Tab 포커스는 오버레이 안에서만 돈다.
- **자동 일시정지**: `visibilitychange`로 탭이 숨겨지면 PLAYING에서 PAUSED로 간다. 돌아와도 자동으로 재개하지 않고 사용자가 직접 재개한다.

### 7.4 반응형과 방향

- 게임 영역은 16:9 비율을 유지하며 뷰포트에 맞춘다. 남는 공간은 레터박스로 채운다.
- 모바일에서 세로 방향이면 "가로로 돌려 주세요" 안내를 덮어 띄우고, PLAYING이었다면 자동으로 일시정지한다.

## 8. 렌더링

### 8.1 뷰포트 (`render/viewport.ts`)

- `scale = min(가용폭/1920, 가용높이/1080)`. 캔버스의 CSS 크기는 `1920·scale × 1080·scale`이다.
- 캔버스 백버퍼 크기는 CSS 크기에 `min(devicePixelRatio, 2)`를 곱한 값이다. `setTransform`으로 논리 좌표를 그대로 쓴다.
- 화면에서 월드로 바꾸는 역변환 함수를 입력 모듈과 공유한다. `resize`나 `orientationchange`가 일어나면 다시 계산한다.

### 8.2 그리는 순서

1. 배경: 하늘 그라디언트, 먼 언덕 실루엣(정적. 한 번 그려서 오프스크린 캐시에 둔다)
2. 지면 띠
3. 새총 뒤쪽 갈래와 뒤쪽 고무줄
4. 지형, 블록(재질별 색과 무늬, 금 간 오버레이), TNT(빨간 상자에 "TNT")
5. 돼지(초록 원, 눈, 코. 크기별로 다르게. HP가 낮으면 멍 자국)
6. 새(색깔별 원, 눈썹, 부리), 대기 중인 새 줄
7. 새총 앞쪽 갈래와 앞쪽 고무줄
8. 궤적 예측 점, 직전 흔적
9. 이펙트: 파편 파티클(시각 전용이며 물리 바디가 아니다, 0.6s), 점수 팝업, 폭발 링과 섬광, 새 제거 연기
10. `?debug=1`일 때: 바디 와이어프레임, 슬립 상태 색 표시, FPS, 스텝 시간

- 렌더러는 세션 상태를 **읽기만** 한다. 이펙트는 세션 이벤트를 받아 렌더 레이어에서만 관리하므로 물리 결정론에 영향을 주지 않는다.

## 9. 진행도 저장 (`storage/progress.ts`)

- 키는 `slingshot.progress.v1`, 값은 `{ unlocked: 1..10, stages: { [id]: { bestScore, stars } } }`다.
- 스테이지 n을 클리어하면 `unlocked = max(unlocked, n+1)`로 바꾸고, 최고 점수와 별은 기존 값보다 높을 때만 덮어쓴다.
- 파싱에 실패하거나 스키마가 맞지 않으면 초기값으로 되돌린다. `localStorage`를 쓸 수 없는 환경에서는 메모리에만 저장한다.
- 디버그 파라미터: `?unlock=all`은 모든 스테이지를 해금하되 저장하지 않는다. `?stage=N`은 N단계로 바로 들어간다(dev와 test 전용).

## 10. 구현 단계

각 Phase는 **종료 조건을 모두 만족해야** 다음으로 넘어간다. 크기 S, M, L은 상대적인 작업량이다.

### Phase 0: 셋업과 물리 스파이크 (M)
- 0.1 Vite + TS + ESLint + Vitest + Playwright를 설정한다. `planck` 버전을 고정한다.
- 0.2 **S1 적층 안정성**: 나무 판자 10단 탑, 돌 5단 피라미드를 10s 동안 방치했을 때 무너지지 않고 이동량이 2px 미만이어야 한다. 반복 횟수(velocity/position iterations)는 이 스파이크로 정한다. 초기값은 8/3이고, 모자라면 10/8로 올린다.
- 0.3 **S2 터널링**: 최대 파워에 가속까지 받은 노란 새(약 55 m/s)를 20px 두께 유리판에 50가지 각도로 쏜다. 접촉 없이 통과하는 경우가 0건이어야 한다.
- 0.4 **S3 궤적 예측 일치**: 예측 함수와 실제 엔진 결과의 오차가 1s 동안 2px 미만이어야 한다.
- 0.5 **S4 결정론**: 같은 스테이지에서 같은 샷을 Node에서 2회 돌리면 최종 바디 좌표가 비트 단위로 같아야 한다. Chromium(Playwright)에서도 돌려 클리어/실패 결과가 같아야 한다.
- 0.6 **S5 튜닝**: `G`(초기값 20 m/s²), `V_max`, `PPM`을 정하고, `T`(정지 충격량 × 1.5)를 측정한다.
- **종료 조건**: S1~S4 스파이크 테스트가 통과하고, `config/constants.ts`의 초기 확정값(v0)이 커밋된다. 실패하면 ADR-1 폴백 절차를 밟는다.

### Phase 1: 코어 월드와 렌더링 골격 (M)
- 스테이지 스키마와 정적 검증, 엔티티 팩토리, 물리 래퍼(PPM 변환, 지연 파괴 큐)를 만든다.
- `GameSession`의 create, step, destroy 골격을 만들고, 이벤트 버스를 둔다.
- 뷰포트와 레터박스와 DPR 처리, rAF 고정 스텝 루프, 기본 렌더러(도형 그리기)를 만든다.
- 테스트용 스테이지(stage00)를 렌더링한다.
- **종료 조건**: stage00이 화면에 나오고 3s 동안 안정적으로 유지된다(스폰 안정성 sim 테스트 통과). 창 크기를 바꿔도 비율이 유지된다. 검증기 단위 테스트가 통과한다.

### Phase 2: 슬링샷과 턴 흐름 (M)
- 포인터 입력, 조준, 당김 클램프, 취소, 발사(발사 순간 바디 생성)를 만든다.
- 궤적 예측 점, 직전 흔적, 고무줄 렌더링을 만든다.
- 턴 상태 머신(LOADING부터 EVALUATE까지), 새 종료 판정, 정착 판정을 만든다.
- **종료 조건**: 브라우저에서 새 3마리를 차례로 쏠 수 있다. U-2, U-3, U-4 테스트가 통과한다.

### Phase 3: 규칙 (M)
- 충격량 데미지, 유예 시간, 파괴, 월드 이탈 처리를 만든다.
- 점수, 클리어/실패 판정, CLEAR_PENDING, 남은 새 보너스, 금 간 표현을 만든다.
- **종료 조건**: 캘리브레이션 앵커 A1~A4 sim 테스트와 점수 단위 테스트가 통과한다. stage00이 올바르게 클리어되고 실패한다.

### Phase 4: 앱 상태 머신과 화면 (M)
- `appMachine` 전이표, 메인, 스테이지 선택, HUD, **일시정지 버튼과 오버레이**, 결과 오버레이를 만든다.
- 진행도 저장, ESC 처리, 자동 일시정지, 전환 중 버튼 잠금, 테스트 훅(§11.4)을 만든다.
- **종료 조건**: `appMachine`의 모든 상태×이벤트 조합 테스트가 통과한다. E2E E1~E7, E10, E13이 통과한다.

### Phase 5: 특수 요소 (S)
- 노란 새 가속, 폭탄 새(탭 폭발, 자동 폭발), TNT, 공용 폭발 함수, 연쇄 폭발을 만든다.
- **종료 조건**: A5, A6 sim 테스트가 통과하고 TNT 연쇄 테스트(S-6)가 통과한다.

### Phase 6: 10개 스테이지 제작 (L)
- §6.5 표대로 `stage01~10.json`을 만든다. 스테이지마다 기준 해법을 적고 별 기준을 정한다.
- 여유 규칙과 견고성 확인(§6.6)을 거친다. 스테이지마다 수동 플레이테스트를 하고 로그를 남긴다.
- **종료 조건**: S-4, S-5, S-7 전체가 10/10 통과한다. 모든 스테이지를 수동으로 1회 이상 클리어했다. E8, E9, E12가 통과한다.

### Phase 7: 폴리시와 품질 (M)
- 파편, 팝업, 폭발 이펙트, 화면 위로 나간 새의 마커, 세로 모드 안내, (선택) 렌더 보간, (선택) 효과음을 넣는다.
- 성능을 측정하고, 여러 브라우저에서 스모크 테스트하고, 누수 테스트를 하고, 프로덕션 빌드를 확인한다.
- **종료 조건**: §12 완료 판정 기준을 모두 체크한다.

### 11.4 브라우저 E2E (Playwright)

테스트 훅: dev와 test 빌드에서 `?test=1`일 때만 `window.__game`을 노출한다. 제공하는 기능은 `appState()`, `session()`(stageId, turnState, birdsLeft, pigsLeft, score, simTime), `shoot(dx, dy)`, `killAllPigs()`다. 프로덕션 빌드에는 넣지 않는다.

| ID | 시나리오 | 통과 조건 |
|---|---|---|
| E1 | 메인에서 게임 시작 | 스테이지 선택 화면에 칸 10개가 있고 1단계만 해금되어 있다 |
| E2 | 1단계에서 **실제 마우스 드래그**로 발사 | turnState가 FLYING이 되고, 이후 birdsLeft가 1 줄어든다 |
| E3 | 일시정지 버튼 위치와 크기 | 버튼 중심 x ≥ 게임 영역 left + 0.85×width, 중심 y ≤ top + 0.15×height, 크기 44 CSS px 이상. 뷰포트 3종(1920×1080, 1280×720, 2560×1080)에서 확인 |
| E4 | 일시정지 클릭 | 오버레이가 보이고 `btn-retry`와 `btn-main`이 보인다. 1s 동안 simTime이 변하지 않는다 |
| E5 | 발사 후 일시정지 → 다시하기 | birdsLeft, pigsLeft가 초기값, score가 0, 상태가 PLAYING/READY |
| E6 | 일시정지 → 메인으로 | 메인 화면이 보이고 `session()`이 null이다 |
| E7 | 계속하기 / ESC | 재개되어 simTime이 다시 늘어난다. ESC를 누르면 일시정지와 재개를 오간다 |
| E8 | 기준 해법을 `shoot`으로 재생해 클리어 | 클리어 오버레이와 별이 나오고 2단계가 해금된다. **새로고침해도 해금 상태가 유지된다** |
| E9 | 새를 모두 빗나가게 쏨 | 실패 오버레이가 나오고, 다시하기를 누르면 초기화된다 |
| E10 | `visibilitychange`로 탭 숨김을 흉내 냄 | 자동으로 PAUSED가 된다 |
| E11 | 모든 시나리오 공통 | 콘솔 error 0건, 처리되지 않은 예외 0건 |
| E12 | `?unlock=all` 상태에서 10단계 클리어 | 올클리어 문구가 나오고 "다음 스테이지" 버튼이 없다 |
| E13 | 드래그하는 중에 ESC로 일시정지한 뒤 재개 | 조준이 취소되어 READY 상태이고, 새는 소모되지 않았으며, 정상적으로 다시 발사할 수 있다 |

- E8에서 브라우저가 기준 해법을 재현하지 못해 테스트가 불안정해지면 `killAllPigs()`로 클리어 흐름만 검증한다. 해법 재현은 S-5가 이미 보장한다.
- Chromium에서는 E1~E13 전체를 돌린다. WebKit과 Firefox에서는 E1~E7만 스모크로 돌린다.

### 11.5 수동 플레이테스트 체크리스트 (Phase 6~7)

- 스테이지마다: 클리어 1회, 실패 경로 1회, 별 3개 도전.
- 턴 상태마다 일시정지를 걸어 본다(LOADING, AIMING, FLYING, SETTLING, CLEAR_PENDING). 매번 재개해 보고 다시하기도 해 본다.
- 터치 기기(가로 모드)에서 드래그, 능력 탭, 일시정지 버튼을 확인한다.
- 창 크기를 바꾸면서 드래그해 본다.
- 결과는 표로 기록한다. 항목은 스테이지, 시도 횟수, 클리어 여부, 불편 사항이다.

## 12. 완료 판정 기준 (Definition of Done)

아래 항목이 **모두** 참이면 "된 것"이다.

**R1: 스테이지 10단계**
- [ ] `stages/`에 스테이지 10개가 있고 정적 검증(U-7 규칙)을 통과한다.
- [ ] S-4(스폰 안정성)와 S-5(기준 해법 재생)가 스테이지 10개 모두에서 통과한다.
- [ ] 스테이지 선택 화면에 10단계가 보이고, 1단계부터 순서대로 클리어하면 차례로 해금된다(E1, E8).
- [ ] 10단계를 클리어하면 올클리어 화면이 나온다(E12).
- [ ] 스테이지 10개 모두 사람이 브라우저에서 1회 이상 클리어했고 기록이 남아 있다.

**R2: 앵그리버드식 게임플레이**
- [ ] 메인에서 게임 시작, 스테이지 선택을 거쳐 플레이까지 이어진다(E1, E2).
- [ ] 드래그로 조준하고 놓아서 발사하며, 궤적 예측 점이 실제 비행과 일치한다(U-3).
- [ ] 중력에 따른 포물선 비행, 블록과 돼지의 충돌, 붕괴, 파괴가 일어난다(A1~A6).
- [ ] 새 3종의 능력과 TNT가 동작한다(A5, A6, S-6).
- [ ] 돼지가 0마리면 클리어, 새를 다 쓰고 정착 후 돼지가 남으면 실패가 된다(U-4, E8, E9).
- [ ] 점수, 별, 최고 기록이 표시되고 새로고침 후에도 유지된다(U-6, U-8, E8).

**R3: 일시정지**
- [ ] 인게임 화면에서 일시정지 버튼이 게임 영역 **우측 상단**에 보인다(E3).
- [ ] 누르면 게임이 완전히 멈추고, **다시하기**와 **메인으로** 버튼(및 계속하기)이 나타난다(E4, S-9).
- [ ] 다시하기를 누르면 같은 스테이지가 완전히 초기 상태로 다시 시작된다(E5, S-8).
- [ ] 메인으로를 누르면 메인 화면으로 가고 세션이 파괴된다(E6).

**품질**
- [ ] 단위, sim, E2E 테스트가 모두 통과한다(Chromium 전체, WebKit과 Firefox 스모크).
- [ ] 기준 장비(M1급 노트북, Chrome)에서 10단계 플레이 중 프레임 시간 p95가 16.7ms 이하다(물리 4ms 이하, 렌더 6ms 이하가 목표).
- [ ] E2E 전 구간에서 콘솔 에러가 0건이다(E11).
- [ ] `vite build` 산출물을 정적 서버에 올렸을 때 동작한다.

## 13. 엣지 케이스 처리 목록

| 상황 | 처리 |
|---|---|
| 드래그 중 일시정지, 탭 숨김, `pointercancel` | 조준을 취소하고 READY로 간다. 새는 소모되지 않는다 |
| FLYING 중 일시정지 버튼 클릭 | DOM 레이어에서 처리되므로 캔버스 능력 입력으로 전달되지 않는다 |
| 마지막 돼지가 죽는 순간 일시정지 | CLEAR_PENDING 상태로 얼어 있다가, 재개하면 남은 1.5s를 이어서 진행한다 |
| 다시하기, 메인으로 연타 | 첫 클릭에서 버튼을 모두 비활성화하고, 전이표가 중복 이벤트를 무시한다 |
| 탭 전환 후 복귀할 때 큰 델타 | 델타를 100ms로 클램프하고 스텝을 최대 5회로 제한한다. 애초에 탭을 숨기면 자동으로 일시정지한다 |
| 계속 굴러가는 원형 블록 때문에 정착하지 않음 | SETTLING 최대 3s, 새 비행 최대 8s 타임아웃 |
| 돼지가 월드 밖으로 떨어짐 | 처치로 치고 점수를 준다 |
| 새가 화면 위로 벗어남 | 상단 가장자리에 x 위치 마커를 표시하고, 이탈로 보지 않는다 |
| 아주 짧게 당겼다 놓음 | 발사를 취소한다 |
| 멀티터치 | 주 포인터만 쓰고 나머지는 무시한다 |
| 드래그 중 창 크기 변경이나 회전 | 뷰포트를 다시 계산한다. 월드 좌표 기준이라 드래그가 이어진다. 세로로 회전하면 자동 일시정지하고 안내를 띄운다 |
| `localStorage`를 쓸 수 없음 | 메모리에 저장한다. 게임은 정상 동작한다 |
| 10단계 클리어 | "다음 스테이지" 버튼을 숨기고 올클리어 문구를 띄운다 |
| 폭탄 새가 아무것에도 맞지 않고 밖으로 나감 | 이탈로 처리해 종료한다. 폭발하지 않는다 |
