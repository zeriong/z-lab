# 플랜 생성 입력 — 웹 브라우저 앵그리버드 게임

> 이 문서는 비교 실험의 **공통 입력**이다. 6개 테스트 셀(fable/opus/sonnet × /plan / /plan-smith)에 동일하게 전달되어, 각 셀이 이 요구사항으로 구현 플랜(md)을 작성한다. 게임을 구현하지 않는다 — 플랜 문서만 만든다.

## 요청사항

웹브라우저로 앵그리버드 게임을 만드세요.

1. **stage는 10단계**로 만들어야 합니다.
2. **게임시작 → 앵그리버드와 같은 게임 시스템**으로 게임플레이가 가능해야 합니다.
   (새총으로 발사체를 당겨 쏘고, 포물선 궤적·중력·충돌·구조물 파괴로 목표(돼지 등)를 제거하는 물리 기반 슬링샷 게임)
3. **일시정지 버튼**이 인게임 **우측**에 존재하고, 이를 클릭 시 **다시하기 / 메인으로** 버튼이 존재합니다.

## 플랜이 답해야 할 핵심 질문 (참고)

- 물리 엔진: 직접 구현 vs 라이브러리(Matter.js 등)?
- 렌더링: Canvas 2D vs 기타?
- 10개 스테이지 데이터 구조와 로딩/전환 방식
- 슬링샷 입력(드래그·조준·발사)과 궤적 예측 UX
- 충돌·파괴·점수·클리어 판정 규칙
- 일시정지 오버레이(다시하기/메인으로)와 상태 머신(메인 → 인게임 → 일시정지 → 클리어/실패)
- 완료의 판정 기준(무엇이 되면 "된 것"인가)

## 실험 메타

- 테스트 매트릭스: `{fable, opus, sonnet}` × `{/plan(베이스라인), /plan-smith(스킬)}` = 6 셀
- 각 셀 산출물: `test/<model>/<method>/plan.md` (셀당 플랜 1개)
- 목적: 동일 요구사항에 대해 (모델별) 베이스라인 플래닝 vs plan-smith 방법론 플래닝을 비교
