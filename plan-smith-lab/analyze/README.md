# analyze — plan-smith 고도화 근거 문서

이 폴더는 **plan-smith를 실제로 고치기 위한 근거**를 모은다. 코퍼스와 A/B는 표본이고,
여기 있는 문서는 그 표본에서 무엇을 읽었는지다.

산출물(표본)은 여기 두지 않는다:

| 무엇 | 어디 |
|---|---|
| 코퍼스 표본 (플랜·로그) | [`../opus-plan/`](../opus-plan/) · [`../fable-plan/`](../fable-plan/) |
| A/B 실험 (게임 플랜·구현) | [`../test/`](../test/) |
| 생성 조건·지표 | 각 코퍼스의 `SPEC-META.md` |
| **분석·개선안** | **여기** |

## 파일

| 파일 | 무엇 | 쓰는 곳 |
|---|---|---|
| **[`improvement-backlog.md`](improvement-backlog.md)** | 관측 → 조항 진단 → 개선 제안. **근거 강도와 SemVer 영향을 항목마다 표기** | 다음 버전에 무엇을 넣을지 결정할 때 |
| [`v1.1.2/plan-playground.md`](v1.1.2/plan-playground.md) | v1.1.2 입력 명세 (76주제 × 26프레임) — 실행 후 불변 | opus-5 코퍼스를 재현·검증할 때 |
| [`v1.1.2/diff-review.md`](v1.1.2/diff-review.md) | opus-5(v1.1.2) vs opus-4.8(pre-plugin) 01~26 **버전 간 델타** — 렌즈 3 + 종합자 grep 재검증 | 조항이 실제로 발화했는지 확인할 때 |
| [`pre-plugin/plan-playground.md`](pre-plugin/plan-playground.md) | 플러그인 이전 26주제 자기완결 지시서 — `frames.md`의 조상 | 프레임의 출처를 추적할 때 |
| [`pre-plugin/diff-review.md`](pre-plugin/diff-review.md) | Opus 4.8 vs Fable 5 26플랜 로그 비교 (T1~T6 오염 회계) | 스타일 라이브러리의 근거를 확인할 때 |

버전 폴더는 **그 문서가 어느 플러그인 상태를 다루는지**를 나타낸다 — 폴더 이름이 곧 분석 대상 버전이다.
새 버전을 분석하면 `analyze/<version>/`을 추가하고, `improvement-backlog.md`는 **버전을 가로지르는
단일 문서로 유지**한다(항목마다 근거 버전을 적는다).

## 이 폴더를 읽을 때의 규칙

1. **자가 채점을 근거로 쓰지 않는다** (lab 제5조). 각 코퍼스의 `00-meta-review.md`는 모델이 자기
   산출물을 평가한 것이다. 그 안의 **관측**(무엇을 했는지)은 인용할 수 있으나 **등급**(잘했는지)은 안 된다.
2. **측정한 것과 측정하지 않은 것을 섞지 않는다** (제4조). 각 문서에 "측정하지 않은 것" 절이 있다.
   개선안을 세울 때 그 절을 먼저 읽어야 한다 — 측정 안 된 것을 근거로 조항을 만들면 다음 버전이
   같은 실패를 반복한다.
3. **어휘 일치는 이행의 증거가 아니다.** 조항의 단어가 플랜에 나타나는 것과 조항이 의도한 결과가
   일어난 것은 다르다. v1.1.2의 canon 조항이 그 사례다 — 조항 어휘는 이행됐지만 **조항이 없던
   pre-plugin 코퍼스에서도 같은 결과가 나왔다**(비차별적). 근거로 쓸 때는 대조군을 함께 봐야 한다.
4. **여기서 나온 제안을 곧바로 릴리스하지 않는다.** 프레임·조항을 바꾸면 **이후 생성되는 모든
   코퍼스가 다른 명세**가 되어 과거 표본과 비교 불가가 된다. 변경은 버전으로 격리하고
   `plan-smith/CHANGELOG.md`에 근거를 함께 남긴다.
