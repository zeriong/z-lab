# pure-model 계열 — 입력 명세와 전제 (실행 후 불변)

이전 `test/` 계열(라운드 1~3)과 **전제가 다르다.** 같은 게임 요구사항을 쓰지만 측정하려는 것이 바뀌었으므로
새 계열로 분리한다(lab 제9조 — 조건이 바뀌면 새 계열).

## 무엇이 바뀌었나

| 축 | test/ 계열 (R1~R3) | **pure-model 계열** |
|---|---|---|
| 에이전트 | `plan-smith:plan-writer` — "플랜 집필자" 페르소나 주입 | **`bare-model`** — 역할·방법론 문장 0, 도구 `Read`/`Write`만 |
| 산출 형태 | 오케스트레이터가 분량·구성·필수 절을 지정 | **전부 모델 재량** — 분량 상한·파일 구성·문서 형식 지정 없음 |
| 구현 입력 | `plan.md` + 원 요구사항 | **`plan.md` 단독** — 플랜이 못 담은 것은 구현자가 메울 수 없다 |
| 측정 목적 | 조항이 발화하는가 | **이 모델이 자기 추론만으로 어디까지 완성하는가** |

## 순수성 조건 (이 계열의 정의)

1. **주입 없음** — `bare-model` 에이전트 정의는 역할·규율·품질 기준을 담지 않는다.
2. **도구 없음** — `Read`/`Write`뿐. 빌드·설치·실행·테스트·검증·자가수정·git이 **구조적으로 불가능**하다.
3. **하네스 없음** — 실측 기반 리뷰(`ux-ui-builder` 계열), 감사 에이전트, 배선 감사, 채점 루프를
   **파이프라인 안에 두지 않는다.** 산출물은 만들어진 그대로 표본이 된다.
4. **오케스트레이터 개입 없음** — 프롬프트는 요구사항 파일 경로와 출력 경로만 준다.
   "몇 단어로 써라", "이 절을 넣어라" 같은 지시를 하지 않는다.

## ⚠️ 제거하지 못한 오염 (반드시 고지)

- **사용자 전역 `~/.claude/CLAUDE.md`(61줄)와 프로젝트 `CLAUDE.md`(145줄)의 서브에이전트 유입 여부는
  이 계열의 통제 밖이다.** 실행 세션에서 트랜스크립트를 grep해 유입 여부를 확인하고 그 결과를 기록해야 한다.
  유입된다면 "순수 모델"이라는 라벨은 그만큼 약해진다.
- 모델은 학습 시점에 이 게임 장르를 알고 있다. "순수 추론"은 **외부 도구·지시가 없다는 뜻**이지
  사전 지식이 없다는 뜻이 아니다.

## arm 정의

| arm | 플랜 단계 입력 | 처치 |
|---|---|---|
| `plan` | `game-prompt.md` 만 | 없음 (대조군) |
| `plan-smith` | `game-prompt.md` + plan-smith 스킬 문서 4종 | 스킬 문서를 읽고 그 방법론을 따름 |

**두 arm의 유일한 차이는 스킬 문서의 유무다.** 그 외 프롬프트 문안·도구·모델·출력 경로는 동일하다.

## 측정 계획 (제4조 — 미리 적는다)

- **측정한다:** 산출 파일 수·코드 행수, 토큰·시간, resolved model id, 구조적 순수성 증거
  (`node_modules`/`dist` 부재), 그리고 사후에 오케스트레이터가 빌드·구동해 **하중 경로 1개(발사)** 판정.
- **측정하지 않는다:** 게임의 재미·난이도·시각 품질, 10스테이지 전체 동작, 코드 품질 점수.
- **채점 루브릭을 두지 않는다.** 이 계열은 조항 발화를 재지 않는다 — 그것은 `test/` 계열의 목적이었다.
- 사후 빌드·구동은 **파이프라인이 아니라 관측**이며, 소스는 수정하지 않는다.
