# 웹 앵그리버드 게임 구현 계획

## 1. 개요

10개 스테이지를 갖춘 웹 기반 물리 슬링샷 게임 구현.
핵심: 물리 시뮬레이션, 목표물 파괴, 일시정지 UX.

---

## 2. 핵심 의사결정

### 2.1 물리 엔진
**선택: Matter.js (라이브러리 사용)**

근거:
- 앵그리버드는 강체 동역학(rigid body dynamics), 충돌, 제약(constraints) 필수
- 직접 구현은 NaN 버그(무한질량 등)와 안정성 이슈 높음
- Matter.js: 입증된 성능, 웹 표준, 문서 풍부

의존성: matter-js (npm)

### 2.2 렌더링
**선택: Canvas 2D**

근거:
- 게임 루프(물리 → 그리기)는 Canvas가 최소 레이턴시
- Three.js/Babylon은 3D 불필요 (2D 게임)
- DOM은 60fps 게임에 부적절

구현: `canvas.drawRect()`, `drawImage()`, 트랜스폼 매트릭스 활용

### 2.3 입력 모델
**슬링샷 동작**
- 드래그 시작 → 드래그 중 예측 궤적 표시 → 드래그 종료 시 발사
- 예측: Matter.js 바디를 `isStatic: true`로 미리 시뮬레이션 후 시각화
- 터치/마우스 둘 다 지원

## 3. 아키텍처

### 3.1 모듈 구조

```
Game (전체 상태 + 루프)
├── PhysicsEngine (Matter.js 래퍼)
│   ├── createBody()
│   ├── step()
│   └── queryCollisions()
├── StageManager (10 스테이지 로드/전환)
│   └── stages[0..9]
├── GameState (상태 머신)
│   ├── menu / playing / paused / levelComplete / gameOver
│   └── currentStage / score / lives
├── Renderer (Canvas 그리기)
│   ├── draw()
│   └── drawTrajectory()
└── Input (마우스/터치)
    ├── onDragStart()
    ├── onDrag()
    └── onDragEnd()
```

### 3.2 클래스 설계 개요

**Game**
- 게임 루프 관리 (requestAnimationFrame)
- 각 모듈 협조
- 상태 천이

**PhysicsEngine**
- Matter.js 엔진 래핑
- 콜라이더 이벤트 → 파괴 로직
- 손상 계산 (충돌 에너지 → 구조물 내구도 감소)

**StageManager**
- JSON 또는 JS 객체로 각 스테이지 정의:
  ```
  {
    id: 0,
    bird: { x, y, type },
    pigs: [ { x, y, hp } ],
    blocks: [ { x, y, w, h, material } ],
    maxMoves: 5
  }
  ```
- 스테이지 로드 → 바디 생성

**GameState (FSM)**
```
menu → (play) → playing
              ↓
         paused ← (pause)
         ↑ ↓
    (resume) (main)
         ↓
    playing
    ↓
 [파괴 조건 만족?]
    ↓yes → levelComplete → [다음 스테이지?] → playing / gameOver
    ↓no  → gameOver (포기/이동 초과) → menu
```

**Renderer**
- `drawGame()`: 바디/블록/돼지 렌더
- `drawUI()`: 점수, 남은 이동, 발사 예정 위치
- `drawTrajectory()`: 궤적 선 시뮬레이션
- `drawPauseOverlay()`: 일시정지 화면

**Input**
- 슬링샷 바디에만 드래그 감지
- 드래그 거리 → 초기 속도 (거리 비례)
- 마우스/터치 이벤트 통합

## 5. 게임 루프 및 상태 머신

### 5.1 주 루프 (16.67ms = 60fps)

```
requestAnimationFrame:
  1. input.update()           // 드래그 입력 처리 → trajectoryPoints 계산
  2. if (playing) physics.step(dt)   // Matter 시뮬레이션
  3. collision.checkAndResolve()     // 충돌 → 파괴 판정
  4. gameState.checkWinCondition()   // 클리어 판정
  5. renderer.draw(gameState)        // Canvas 렌더
  6. gameState.transition()          // 상태 천이
```

### 5.2 상태 천이

**menu → playing**
- "Play" 버튼 클릭
- 첫 스테이지 로드

**playing → paused**
- 우측 일시정지 버튼 클릭
- 물리 시뮬레이션 일시 정지
- 오버레이 표시: [다시하기] [메인으로]

**paused → playing**
- "다시하기" 클릭 → 현 스테이지 리셋
- "메인으로" 클릭 → 메뉴 돌아가기

**playing → levelComplete**
- 조건: (모든 돼지 제거) AND (발사 완료 상태)
- 2초 대기 후 자동 전환 또는 "다음" 버튼

**levelComplete → playing** (다음 스테이지) 또는 **→ gameOver** (10단계 완료)

**playing → gameOver** (실패)
- 조건: 남은 새 없음 AND 돼지 남음
- "다시하기" / "메인으로" 옵션

## 6. 핵심 게임 규칙

### 6.1 슬링샷 발사

1. 슬링샷 위치에 새 배치
2. 플레이어가 새를 드래그 (뒤로 당김)
3. 드래그 거리 → 초기 속도 (거리 × 계수)
4. 드래그 해제 → 새 발사
5. 새가 화면 밖 or 정지 상태 2초 → "발사 완료" (다음 발사 가능 또는 라운드 종료)

### 6.2 충돌 및 파괴

- Matter.js `afterUpdate` 이벤트로 충돌 감지
- 충돌 에너지 (속도의 크기) → 손상량
- 블록 hp < 0 → 제거
- 돼지 hp < 0 → 제거
- 돼지 전부 제거 → 스테이지 클리어

### 6.3 점수

- 돼지 파괴: +1000점
- 블록 남김 (비효율): -10점/블록
- 남은 이동: +500점/회 (보너스)

## 9. 완료 기준

게임 구현이 완료되었다는 판정:

1. **기능적 완성**
   - [ ] 10개 스테이지 모두 로드 가능
   - [ ] 슬링샷 드래그 → 발사 동작
   - [ ] 물리 시뮬레이션 (중력, 충돌, 회전)
   - [ ] 돼지/블록 파괴 시스템
   - [ ] 클리어 판정 (돼지 제거 확인)
   - [ ] 일시정지/재개/메인 메뉴 버튼

2. **상태 관리**
   - [ ] 상태 머신 (menu → playing → paused → levelComplete → ...)
   - [ ] 스테이지 전환 시 상태 초기화
   - [ ] 재시작 시 현 스테이지 리셋

3. **UI/UX**
   - [ ] 일시정지 버튼이 우측에 위치
   - [ ] 예측 궤적 시각화 (드래그 중)
   - [ ] 점수 및 진행도 표시
   - [ ] 메뉴 화면 (시작 / 게임오버)

4. **플레이 테스트**
   - [ ] 어느 스테이지든 플레이 가능 (처음부터 끝까지)
   - [ ] 포물선 물리가 시각적으로 일관성 있음
   - [ ] 충돌 판정이 정확함 (거짓 양성/음성 최소화)

5. **성능**
   - [ ] 60fps 유지 (또는 대부분의 프레임)
   - [ ] 메모리 누수 없음 (스테이지 전환 시 이전 바디 정리)

**실패 기준**
- 물리 버그 (NaN, 무한 루프)로 실행 불가
- 클리어 조건이 도달 불가능
- 일시정지 오버레이 미표시
- 메뉴 내비게이션 동작 불가

## 10. 구현 전략

### 10.1 진행 순서

1. **Step 1**: Canvas + Matter.js 기본 셋업
   - 빈 캔버스, 시뮬레이션 루프 구동 확인
   
2. **Step 2**: 스테이지 1 최소 구현
   - 새 1개, 돼지 1개, 블록 2개
   - 슬링샷 드래그 입력
   - 간단한 충돌 파괴 로직

3. **Step 3**: 상태 머신 + UI
   - 메뉴 / 게임 / 일시정지 상태
   - 일시정지 버튼 + 오버레이

4. **Step 4**: 남은 9개 스테이지 데이터 정의
   - JSON/JS 객체로 각 스테이지 스펙

5. **Step 5**: 예측 궤적 + 점수 시스템
   - 드래그 중 궤적 계산 및 시각화
   - 게임 클리어 시 점수 계산

6. **Step 6**: 테스트 및 미세 조정
   - 각 스테이지 플레이 불가능성 확인
   - 물리 파라미터 튜닝

### 10.2 주요 라이브러리/도구

- **Matter.js**: 물리 시뮬레이션
- **HTML5 Canvas**: 렌더링
- **Vanilla JS**: 상태 관리, 입력 처리
- **번들러 선택지**: Vite / Webpack (옵션)

## 12. 개발 환경 및 배포

- **개발**: Node.js + npm
- **파일 구조**:
  ```
  project/
  ├── index.html
  ├── js/
  │   ├── game.js (메인 루프)
  │   ├── physics.js (Matter 래퍼)
  │   ├── renderer.js (Canvas 드로우)
  │   ├── input.js (마우스/터치)
  │   ├── gameState.js (상태 머신)
  │   └── stages.js (10 스테이지 데이터)
  ├── assets/
  │   └── (스프라이트 또는 shape 정의)
  └── package.json
  ```
- **테스트**: 각 스테이지를 브라우저에서 수동 플레이 (자동 테스트는 스코프 외)

## 요약

이 계획은 **Matter.js + Canvas 2D** 기반으로 안정적이고 확장 가능한 앵그리버드 게임을 구현한다.
상태 머신으로 메뉴/게임/일시정지/클리어 흐름을 명확히 하고,
10개 스테이지는 난이도 템플릿으로 효율적으로 정의된다.
완료 기준은 기능적 완성 + 플레이 테스트로 검증한다.
