# 웹 브라우저 앵그리버드 게임 — 구현 계획서

> 대상: 브라우저(데스크톱 + 모바일 웹)에서 동작하는 물리 기반 슬링샷 게임, 스테이지 10단계.
> 이 문서는 구현 전 설계 결정과 작업 순서를 확정하기 위한 계획서다. 코드는 포함하지 않는다.

---

## 0. 요구사항 요약과 해석

| # | 원문 요구 | 구현 해석 |
|---|---|---|
| R1 | stage 10단계 | 선언형 JSON 레벨 데이터 10개 + 레벨 로더 + 레벨 선택/진행 화면 |
| R2 | 앵그리버드와 같은 게임 시스템 | 새총 드래그 조준 → 발사 → 포물선 비행 → 강체 충돌 → 구조물 붕괴 → 돼지 제거 → 클리어 판정 |
| R3 | 우측 일시정지 버튼 + 다시하기/메인으로 | 인게임 HUD 우측 상단 일시정지 버튼, 클릭 시 모달 오버레이(계속하기 / 다시하기 / 메인으로), 오버레이 중 물리 시뮬레이션 정지 |

### 명시적으로 범위 밖(Non-goals)
- 멀티플레이, 서버, 계정, 랭킹 서버
- 실제 앵그리버드 IP 에셋(캐릭터 아트·사운드) 사용 — 저작권 회피를 위해 도형 기반 자체 아트로 대체
- 블록의 진짜 파편화(voronoi/실시간 메시 분할) — 파괴는 "바디 제거 + 파편 파티클 연출"로 근사
- 레벨 에디터 UI (단, 레벨 데이터는 손으로 편집 가능한 JSON으로 유지)

## 1. 핵심 기술 결정

### 1.1 물리 엔진 — Matter.js 사용 (직접 구현 안 함)

**결정: Matter.js (`matter-js`, MIT)**

근거:
- 이 장르의 난이도는 "포물선"이 아니라 **강체 스택의 안정성**에 있다. 나무 블록 6~10개를 쌓아 올리고 흔들리지 않게 유지하려면 sequential impulse solver + warm starting + 접촉 캐싱 + sleeping이 필요하다. 직접 구현하면 이것만 2~3주이며, 대부분 "탑이 스스로 무너지는" 버그로 소모된다.
- Matter.js는 broadphase(grid), 다각형 SAT 충돌, 제약(constraint), sleeping, 충돌 이벤트를 모두 제공하고, 슬링샷 데모가 공식 예제에 존재할 만큼 이 유즈케이스에 검증되어 있다.
- 대안 비교:
  - **직접 구현**: 학습 목적 외에는 손해. 탈락.
  - **Planck.js(Box2D 포팅)**: 물리 품질은 Matter보다 우수(특히 스택 안정성)하나 API가 무겁고 MKS 단위계 변환이 필요. 만약 Matter로 스택이 계속 무너지면 **교체 후보 1순위**로 남겨둔다.
  - **Rapier(wasm)**: 성능 최고지만 wasm 로딩·번들 복잡도 대비 이득 없음(이 규모에서 병목은 물리가 아님).

**엔진 격리 규칙:** Matter 타입을 게임 로직 전역에 퍼뜨리지 않는다. `physics/` 레이어에서만 Matter를 import하고, 게임 로직은 `PhysicsWorld` 인터페이스(`addBody`, `removeBody`, `applyImpulse`, `onCollision`, `step`)만 사용한다. 이유는 순수한 추상화 취향이 아니라 **Planck.js 교체 가능성을 남기기 위한 보험**이다.

### 1.2 렌더링 — Canvas 2D 직접 렌더

**결정: 단일 `<canvas>` + Canvas 2D API. Matter의 내장 `Matter.Render`는 개발용 디버그 오버레이로만 사용.**

근거:
- 이 게임의 렌더 부하는 최대 수십~수백 개 강체 + 파티클 수준. 2D 컨텍스트로 충분하며 60fps 유지가 어렵지 않다.
- WebGL/PixiJS는 파티클 수천 개 이상일 때 유의미. 여기서는 번들·복잡도만 늘어난다.
- `Matter.Render`를 프로덕션 렌더러로 쓰면 카메라, 스프라이트, 파괴 연출, HUD 합성에서 곧 한계에 부딪힌다. 처음부터 자체 렌더러를 쓴다.

**해상도/스케일 전략:**
- 논리 해상도 **1280×720 고정**(물리 월드 단위 = 논리 픽셀). 물리 튜닝 값이 화면 크기에 따라 흔들리는 것을 원천 차단한다.
- 실제 캔버스는 `devicePixelRatio`를 곱해 백버퍼를 잡고, CSS로 **letterbox**(가로/세로 비율 유지, 남는 영역은 검은 띠) 처리.
- 입력 좌표는 항상 `clientX/Y → 캔버스 로컬 → 논리좌표 → 월드좌표`의 단일 변환 함수를 통과시킨다.

### 1.3 UI(메뉴/오버레이) — DOM 오버레이

**결정: 게임 화면은 Canvas, 메뉴·일시정지·클리어 오버레이는 캔버스 위에 절대배치한 DOM 레이어.**

근거: 버튼 히트박스, 포커스, 키보드 접근성, 텍스트 렌더링을 캔버스에서 재구현할 이유가 없다. 인게임 HUD 중 **일시정지 버튼도 DOM 버튼**으로 만든다(요구 R3의 클릭 신뢰성 확보).
예외: 남은 새 아이콘, 점수 팝업 등 게임과 시각적으로 붙어야 하는 요소는 캔버스에 그린다.

### 1.4 언어/빌드

- **TypeScript + Vite**. 레벨 데이터 스키마와 상태 머신 전이를 타입으로 고정하면 이 규모에서 가장 흔한 버그(레벨 JSON 오타, 잘못된 상태 전이)를 컴파일 타임에 잡는다.
- 프레임워크(React 등) 없음. UI가 화면 6개 수준이라 프레임워크 도입 비용이 이득을 넘는다. 오버레이는 템플릿 문자열 + 이벤트 위임으로 처리.
- 외부 런타임 의존성: `matter-js` 단 하나.

### 2.2 게임 루프 — 고정 타임스텝

```
rAF(t):
  frameTime = min(t - last, 100ms)       // 탭 복귀 시 death spiral 방지 클램프
  accumulator += frameTime
  while accumulator >= 1000/60:
      physics.step(1000/60)              // 항상 동일 dt
      game.fixedUpdate()                 // 데미지 처리, 클리어 판정, 카메라 목표 갱신
      accumulator -= 1000/60
  alpha = accumulator / (1000/60)
  renderer.render(alpha)                 // 위치 보간 렌더
```

고정 dt를 쓰는 이유: 가변 dt를 Matter에 넣으면 튜닝한 발사 세기·파괴 임계치가 기기 프레임레이트에 따라 달라진다. 발사 결과가 60Hz/120Hz 모니터에서 달라지는 것은 이 장르에서 치명적이다.

**일시정지 처리:** `PAUSED` 상태에서는 `accumulator`를 누적하지 않고 `physics.step`도 호출하지 않는다. 렌더는 마지막 프레임을 그대로 유지(정지 화면). 재개 시 `last = now`로 리셋하여 정지 시간이 한 번에 쏟아지지 않게 한다.

## 3. 상태 머신

```
        ┌──────────────────────────────────────────────┐
        ▼                                              │
     [BOOT] → [MAIN_MENU] ⇄ [LEVEL_SELECT]             │
                   │              │                    │
                   └──────┬───────┘                    │
                          ▼                            │
                     [LOADING] → [PLAYING] ⇄ [PAUSED] ─┘ (메인으로)
                                    │  │        │
                                    │  │        └─ 다시하기 → [LOADING]
                                    │  ├──→ [LEVEL_CLEAR]
                                    │  └──→ [LEVEL_FAIL]
                                    │
                     [LEVEL_CLEAR] ─┼→ 다음 스테이지 → [LOADING]
                                    ├→ 다시하기 → [LOADING]
                                    └→ 메인으로 → [MAIN_MENU]
                     [LEVEL_FAIL]  ─┬→ 다시하기 → [LOADING]
                                    └→ 메인으로 → [MAIN_MENU]
```

**세부 규칙**
- `PLAYING` 내부에는 하위 페이즈가 있다: `AIMING`(새 장전 완료, 드래그 대기) → `FLYING`(발사체 비행/충돌 중) → `SETTLING`(입력 무시, 월드 안정화 대기) → 다음 새 장전 or 결과 판정.
- 전이는 `StateMachine`의 허용 테이블로만 가능. 허용되지 않은 전이는 개발 모드에서 throw(잘못된 전이로 인한 유령 상태 방지).
- `PAUSED`는 `PLAYING`에서만 진입 가능. `LEVEL_CLEAR/FAIL` 오버레이가 떠 있을 때 일시정지 버튼은 숨긴다.
- 화면 전환마다 리소스 정리 훅(`Level.dispose()`)을 강제한다 — Matter 바디, 이벤트 리스너, 파티클 풀 반환. 이 게임에서 가장 흔한 누수 지점이 "다시하기를 반복하면 프레임이 떨어진다"이므로, 다시하기는 **월드를 통째로 새로 만드는 경로**로 단일화한다(부분 리셋 금지).

### 4.1 스키마 (JSON, 손으로 편집 가능)

```jsonc

  "camera": { "minX": 0, "maxX": 2400, "minZoom": 0.6, "maxZoom": 1.2 },
  "slingshot": { "x": 220, "y": 520, "maxPull": 120, "power": 0.055 },
  "birds": ["basic", "basic", "speed"],       // 순서 = 발사 순서, 길이 = 시도 횟수
  "ground": [ { "x": 0, "y": 640, "w": 2400, "h": 80 } ],
  "blocks": [
    { "type": "wood",  "shape": "rect", "x": 900, "y": 600, "w": 24, "h": 120 },
    { "type": "stone", "shape": "rect", "x": 1020,"y": 600, "w": 24, "h": 120 },
    { "type": "glass", "shape": "rect", "x": 960, "y": 528, "w": 160,"h": 24 },

  ],
  "pigs": [ { "size": "small", "x": 960, "y": 600 } ],
  "starThresholds": [15000, 25000, 35000]     // 1★/2★/3★ 점수 기준

```

- 좌표는 **월드 픽셀, y는 아래로 증가**(캔버스와 동일). 블록 좌표는 편집 편의를 위해 **바닥 중앙 기준**으로 정의하고 로더가 Matter의 중심 좌표로 변환한다(탑 쌓기 데이터를 손으로 쓸 때 이게 압도적으로 편하다).
- `levelSchema.ts`에서 로드 시 런타임 검증: 필수 필드, 블록이 지면 아래로 내려가지 않는지, 돼지가 블록과 초기 겹침이 없는지. **초기 겹침은 폭발적 반발력을 유발하는 1순위 버그**이므로 로드 단계에서 경고를 띄운다.
- 레벨은 정적 import(번들 포함). 10개 × 수 KB이므로 네트워크 로딩·프리로더가 불필요하다. `LOADING` 상태는 월드 구축 1프레임을 위한 형식적 상태로 유지(추후 비동기 로딩 전환 여지).

## 5. 슬링샷 입력과 궤적 예측

### 5.1 입력 흐름

1. `AIMING` 진입 시 새를 슬링샷 앵커에 **정적(static) 상태**로 배치.
2. `pointerdown`이 새 주변 히트 반경(약 40px, 손가락 고려) 안이면 `dragging = true`.
3. `pointermove`: `pull = anchor - pointer`, `|pull| > maxPull`이면 방향 유지하고 길이를 `maxPull`로 clamp. 슬링샷 뒤쪽(오른쪽) 반원 밖으로는 각도 제한(위로/뒤로만 당길 수 있게).
4. `pointerup`/`pointercancel`: 새를 dynamic으로 전환하고 `impulse = pull * power * bird.mass` 적용 → `FLYING`.
5. 취소: `Esc` 또는 앵커 근처로 다시 끌어오면(당김 길이 < 10px) 발사 취소.

**포인터 이벤트 통일**: `PointerEvent`만 사용(마우스/터치/펜 동시 지원). 캔버스에 `touch-action: none`을 지정해 모바일 스크롤·핀치줌 개입을 차단하고, `setPointerCapture`로 캔버스 밖으로 드래그가 나가도 추적을 유지한다.

### 5.2 궤적 예측

- **표시 방식**: 반투명 점 8~12개, 점 간격은 발사 후 일정 프레임 간격(예: 6프레임마다 1점). 예측선은 **충돌 미고려**로 그린다(실제 게임과 동일한 관습이고, 충돌 예측까지 하면 난이도가 사라진다).
- **계산**: 물리 엔진과 동일한 이산 적분으로 계산해야 실제 궤적과 어긋나지 않는다. Matter의 Verlet 적분 + `airFriction` 감쇠를 그대로 반영한 예측 함수를 쓴다.
  - `v(n+1) = v(n) * (1 - frictionAir) + g * dt`
  - `p(n+1) = p(n) + v(n+1) * dt`
  - 해석적 포물선 공식(`y = v·t - ½gt²`)을 쓰면 `frictionAir` 때문에 실제와 눈에 띄게 어긋난다. **해석식 금지**.
- **검증 방법**: 디버그 모드에서 실제 비행 궤적을 잔상으로 남기고 예측점과 겹치는지 육안 확인. 첫 6점이 어긋나면 감쇠 반영 오류다.
- **난이도 조절**: 스테이지 1~3은 점 12개(친절), 4~7은 8개, 8~10은 5개로 줄여 자연스러운 난이도 상승을 만든다. 레벨 JSON의 `trajectoryHints` 필드로 제어.

### 5.3 카메라

- `AIMING`: 슬링샷이 화면 좌측 1/3에 오도록 고정, 살짝 줌인.
- `FLYING`: 발사체를 지연 추종(lerp 0.08), 월드 경계에서 클램프.
- `SETTLING`/결과: 스테이지 전체가 보이도록 줌아웃.
- 드래그 아닌 빈 공간 드래그로 수동 카메라 팬 허용(발사 전 구조물 정찰). 이는 앵그리버드의 표준 UX이며 없으면 후반 스테이지가 답답해진다.

## 6. 충돌·파괴·점수·클리어 판정

### 6.1 재질 테이블

| 재질 | density | friction | restitution | HP | 파괴 임계 임펄스 | 점수 |
|---|---|---|---|---|---|---|
| glass | 0.0008 | 0.4 | 0.1 | 30 | 낮음 | 500 |
| wood | 0.0015 | 0.6 | 0.15 | 80 | 중간 | 700 |
| stone | 0.0035 | 0.7 | 0.05 | 200 | 높음 | 1000 |
| pig(small) | 0.0012 | 0.5 | 0.2 | 40 | 낮음 | 5000 |
| bird | 0.0025 | 0.5 | 0.4 | — | — | — |

수치는 초안이며 튜닝 대상. 표로 한곳에 모아두는 것이 목적(엔티티 파일마다 흩어지면 튜닝 불가능해진다).

### 6.2 데미지 규칙

`collisionStart` 이벤트에서:

```
relV      = |bodyA.velocity - bodyB.velocity|   (충돌 법선 방향 성분)
impact    = 0.5 * effectiveMass * relV²          (근사 운동에너지)
damage    = max(0, impact - material.threshold) * material.damageScale
```

- 임계치(`threshold`) 이하는 데미지 0 — 이것이 없으면 블록들이 서로 스치기만 해도 HP가 닳아 구조물이 저절로 붕괴한다.
- HP ≤ 0이면 **다음 fixedUpdate 경계에서** 바디 제거(콜리전 콜백 안에서 월드를 수정하면 Matter 내부 순회가 깨진다). 제거 대기 큐를 둔다.
- 파괴 연출: 바디 위치·크기·재질에 맞는 파편 파티클 8~14개 + 먼지. 파티클은 물리 바디가 아닌 **순수 렌더 파티클**(성능·안정성).
- 돼지 사망: HP 0 또는 낙하 데미지(높은 곳에서 지면 충돌). 사망 시 점수 팝업 + 파괴 연출.
- `bomb` 새 폭발: 반경 내 바디에 거리 감쇠 임펄스 + 데미지 일괄 적용(레이캐스트 없이 반경 검사로 근사, 벽 뒤도 관통 — 게임성상 문제 없음).

### 6.3 안정화(Settle) 판정

라운드 종료를 판단하는 핵심 로직. 다음 중 하나면 "정지":
- 모든 동적 바디의 `speed < 0.35` 이고 `angularSpeed < 0.02` 상태가 **연속 45프레임(0.75초)** 유지, 또는
- `SETTLING` 진입 후 **6초 타임아웃**(끝없이 굴러다니는 공 대비).

추가로, 발사체가 월드 경계 밖으로 나가거나 정지하면 즉시 소멸 처리하여 판정을 지연시키지 않는다.

### 6.4 클리어/실패 판정

- **클리어**: 돼지 수 == 0. 판정 시점은 "마지막 돼지 사망 후 settle 완료" — 즉시 판정하지 않는 이유는 붕괴 연출이 잘리면 타격감이 사라지기 때문. 단, 새가 남아 있어도 돼지가 0이면 즉시 클리어이며 **남은 새는 보너스 점수**로 환산(개당 10,000).
- **실패**: 새 소진 && settle 완료 && 돼지 ≥ 1.
- 엣지 케이스: 마지막 새가 발사 직후 화면 밖으로 나갔는데 구조물이 여전히 무너지는 중 → settle까지 기다린 뒤 판정(붕괴로 돼지가 죽으면 클리어가 되어야 한다). 이 케이스는 반드시 수동 테스트 항목에 넣는다.

### 6.5 점수/별

```
총점 = Σ파괴블록점수 + Σ돼지점수(5000) + 남은새 × 10000
별   = 총점 >= starThresholds[i] 인 최대 i+1 (0~3)
```
별/최고점은 `localStorage`에 레벨별로 저장. 레벨 해금은 "이전 레벨 클리어 시" 순차 해금(초기 1스테이지만 해금). 개발용 URL 파라미터 `?unlockAll=1`로 전체 해금(테스트 시간 절약).

## 7. UI 화면 명세

### 7.1 메인 메뉴
- 타이틀, `게임 시작`(마지막 플레이 지점 또는 스테이지 선택으로), `스테이지 선택`, `설정`(사운드 on/off).

### 7.2 스테이지 선택
- 10개 그리드(2행 × 5열). 각 카드: 번호, 획득 별(0~3), 최고 점수. 잠긴 스테이지는 자물쇠 표시 + 클릭 불가.

### 7.3 인게임 HUD
- **좌측 상단**: 현재 점수(획득 시 카운트업 애니메이션).
- **좌측 하단**: 남은 새 아이콘 리스트.
- **우측 상단**: **일시정지 버튼 (요구 R3)** — 최소 44×44px 터치 타깃, `aria-label="일시정지"`, 단축키 `Esc`/`P`.

### 7.4 일시정지 오버레이 (요구 R3)
- 진입 즉시 물리 스텝 중단, 화면 어둡게(반투명 검정 60%) + 중앙 패널.
- 버튼 3개 (세로 배치):
  1. **계속하기** — `PAUSED → PLAYING` (요구에 없지만 없으면 UX가 성립하지 않음. 일시정지 후 게임으로 못 돌아가는 것은 결함이다.)
  2. **다시하기** — 현재 레벨을 처음부터 재생성(월드 전체 파기 후 재구축).
  3. **메인으로** — `MAIN_MENU`로. 진행 중 점수는 저장하지 않음.
- 오버레이 열림 중 캔버스 포인터 입력 차단(오버레이가 이벤트를 가로챔). 이걸 빠뜨리면 일시정지 상태에서 새를 당길 수 있게 된다.
- 키보드: `Esc`로 토글, `Tab` 포커스 트랩, 열릴 때 첫 버튼에 포커스.

### 7.5 결과 오버레이 (클리어/실패)
- 클리어: 별 애니메이션, 점수 내역(블록/돼지/남은 새), `다음 스테이지` / `다시하기` / `메인으로`. 10스테이지 클리어 시 엔딩 문구.
- 실패: `다시하기` / `메인으로`.

각 마일스톤은 **눈으로 확인 가능한 종료 조건**을 가진다. 조건 미달이면 다음으로 넘어가지 않는다.

| M | 내용 | 완료 검증 |
|---|---|---|
| **M0** | 프로젝트 셋업(Vite+TS), 캔버스 부트, letterbox 스케일, 고정 타임스텝 루프, FPS 표시 | 창 크기를 바꿔도 비율 유지, FPS 60 안정 |

| **M3** | 블록/돼지 엔티티 + 충돌 데미지 + 파괴(바디 제거) + 파티클 | 유리는 한 방, 돌은 여러 방. 스치는 접촉으로는 안 부서짐 |

| **M8** | 아트/사운드/이펙트 폴리시, 모바일 터치 검증, 성능 점검 | 모바일 실기기에서 60fps 근접, 터치 조작 위화감 없음 |

작업량 추정: M0~M6이 전체의 약 60%, M7(레벨 디자인·튜닝)이 25%, M8이 15%. **레벨 튜닝 시간을 과소평가하지 않는다** — 이 장르에서 재미는 물리 코드가 아니라 블록 배치에서 나온다.

## 10. 완료 판정 기준 (Definition of Done)

아래 항목이 **전부** 충족될 때 "완료"로 본다. 하나라도 미달이면 미완이다.

**기능 (요구 직결)**
1. 메인 메뉴에서 게임을 시작해 스테이지 1을 플레이할 수 있다.
2. 스테이지가 **10개** 존재하며, 각각 로드되어 **클리어 가능함이 실제 플레이로 확인**되었다.
3. 새총을 드래그해 조준하고 놓으면 발사되며, 궤적 예측이 표시된다.
4. 발사체가 중력에 따라 포물선을 그리고, 블록·돼지와 충돌하며, 구조물이 물리적으로 붕괴한다.
5. 돼지를 모두 제거하면 클리어, 새를 모두 소진하고 돼지가 남으면 실패로 판정된다.
6. **인게임 우측에 일시정지 버튼이 있고**, 클릭하면 **다시하기 / 메인으로** 버튼이 있는 오버레이가 뜬다.
7. 일시정지 중 시뮬레이션이 완전히 멈추고, 계속하기/다시하기/메인으로가 각각 정확히 동작한다.
8. 클리어/실패 결과 화면에서 다시하기·다음 스테이지·메인으로 이동이 가능하다.
9. 별/최고점이 저장되어 재방문 시 유지된다.

**품질**
10. 데스크톱 Chrome/Safari/Firefox 최신 버전에서 동작하며 콘솔 에러가 없다.
11. 모바일 터치로 조준·발사·일시정지가 모두 가능하다.
12. 데스크톱에서 평균 60fps, 최대 붕괴 장면에서도 45fps 이상.
13. 같은 레벨을 20회 연속 다시하기 해도 FPS 저하·메모리 증가가 관측되지 않는다.
14. TypeScript 컴파일 에러 0, 사용하지 않는 디버그 코드는 플래그 뒤로 격리.

**수동 테스트 시나리오 (릴리스 전 필수 통과)**
- T1: 스테이지 1~10을 순서대로 클리어한다.
- T2: 비행 중 일시정지 → 계속하기 → 발사체가 정확히 이어서 비행한다.
- T3: 마지막 새 발사 후 붕괴로 마지막 돼지가 죽는 상황에서 클리어 판정이 난다.
- T4: 일시정지 오버레이가 열린 상태에서 캔버스를 드래그해도 새가 당겨지지 않는다.
- T5: 브라우저 탭을 전환했다가 돌아와도 물리가 폭주하지 않는다.
- T6: 새로고침 후 별/해금 상태가 유지된다.

## 11. 열린 질문 (구현 착수 전 확인 필요)

1. **에셋**: 도형 기반 자체 아트로 진행할지, 별도 스프라이트 에셋을 제공받을지. (계획서는 도형 기반을 전제)
2. **사운드**: 필수인지 선택인지. (계획서는 M8의 선택 항목으로 배치)
3. **모바일 우선순위**: 데스크톱만 보장하면 되는지, 모바일도 1급 대상인지에 따라 M8 비중이 달라진다.
4. **새 종류**: 3종(basic/speed/bomb)으로 충분한지, 원작처럼 더 다양해야 하는지.
5. **레벨 난이도 기준**: "클리어 가능"만 만족하면 되는지, 3별 달성 경로까지 설계해야 하는지.
