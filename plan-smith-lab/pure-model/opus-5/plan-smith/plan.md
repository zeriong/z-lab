# 웹 브라우저 앵그리버드 — 10스테이지 물리 슬링샷 게임 구현 플랜

- 추론 프레임: spec-coverage (물리 엔진 결정 1건에 dialectic 차용) / 스타일: opus
- 한 줄 요약: TypeScript + Vite + Matter.js + 자체 Canvas 2D 렌더러로, 데이터로 저작된 10개 스테이지와 DOM 오버레이 UI를 얹은 단일 페이지 게임을 만든다. 파괴·데미지 규칙은 엔진 밖 자체 레이어가 소유한다.

이 과제에서 내 반사적 습관은 "물리 루프와 새총 조작을 먼저 재미있게 만들고 나머지는 나중에"다. 그 습관대로 쓰면 사운드·파티클·저장·스테이지 저작이 문서 끝의 한 줄로 남고 실제로는 안 지어진다. 그래서 이 문서는 표면 원장을 최상단에 두고, 콘텐츠 저작과 폴리시를 **이름 붙은 단계**로 못 박는다.

## 1. 요구 × 표면 커버리지 매트릭스

### 1.1 표면별 품질 바닥선 — 여기서 "다 됐다"가 무슨 뜻인가

| 표면 | 이 표면이 "완성"이라는 뜻 |
|---|---|
| 메인 메뉴 (S-MENU) | 첫 방문자가 설명 없이 3초 안에 첫 스테이지에 들어간다. |
| 스테이지 선택 (S-SEL) | 10칸이 한 화면에 보이고, 각 칸이 해금 여부와 획득 별 수를 저장된 값으로 표시한다. |
| 플레이필드 (S-FIELD) | 당긴 만큼 날아가고, 맞은 곳이 부서지고, 부서진 것이 무너진다 — 이 세 가지가 소리와 파편을 동반한다. |
| HUD (S-HUD) | 남은 새와 점수가 항상 보이고, 일시정지는 조준 드래그와 겹치지 않는 우측 상단에 있다. |
| 일시정지 오버레이 (S-PAUSE) | 물리가 실제로 멎고, 계속하기·다시하기·메인으로 세 갈래가 모두 살아 있다. |
| 클리어 오버레이 (S-CLEAR) | 점수와 별이 정산되어 보이고, 다음 스테이지로 이어지는 길이 화면 안에 있다. |
| 실패 오버레이 (S-FAIL) | 왜 끝났는지(새 소진)가 보이고 재시작이 1클릭이다. |

| 개발 툴 (S-TOOL) | 스테이지 파일의 저작 실수를 플레이가 아니라 커맨드가 잡아낸다. |

## 2. 문제 정의와 목표

브라우저에서 URL 하나로 열리는 정적 웹 게임. 플레이어는 메인 → 스테이지 선택 → 인게임으로 들어가 새총을 당겨 새를 쏘고, 중력·충돌·구조물 붕괴로 돼지를 전부 제거하면 스테이지를 클리어한다. 10개 스테이지가 난이도 곡선을 이루고, 인게임 우측의 일시정지 버튼으로 언제든 멈춰 다시하기 또는 메인으로 나갈 수 있다.

성공의 정의: **§13의 커맨드 6개가 전부 종료코드 0이고, §1.2 원장의 34개 `build` 행 중 어느 것도 문서 갱신 없이 사라지지 않았을 것.**

## 3. 요구별 동작 문장 — 원장 행마다 하나, 표 밖에서

원장은 대장이고, 아래가 지시문이다. 각 문장은 "행위자가 무엇을 하면 무엇이 관측되고, 없으면 어떤 증상으로 드러나는가" 형태다.

1. **(R1)** 플레이어가 메인 메뉴의 "게임 시작"을 누르면 스테이지 선택 그리드가 화면을 덮는다; 빠지면 버튼을 눌러도 타이틀에 머물러 연타하게 된다.
2. **(R2)** 플레이어가 해금된 칸을 누르면 해당 스테이지 월드가 로드되고 카메라가 구조물 전경을 1초간 훑은 뒤 새총 위치로 돌아온다; 빠지면 어느 칸을 눌러도 같은 배치가 나온다.
3. **(R3)** 플레이어가 스테이지 선택에 들어오면 상단에 총 별 수(예: `★ 17 / 30`)와 칸별 0~3별이 저장값 그대로 표시된다; 빠지면 브라우저를 다시 켤 때마다 모든 칸이 0별로 보인다.
4. **(R4)** 플레이어가 스피커 아이콘을 누르면 그 순간부터 모든 오디오 출력이 멎고 다음 실행에서도 꺼진 채 시작한다; 빠지면 아이콘이 꺼짐 상태인데 충돌음이 계속 난다.
5. **(R5)** 플레이어가 새총 위의 새를 잡아 끌면 새가 커서를 따라오되 앵커에서 최대 96px까지만 늘어나고 고무줄 두 가닥이 새에 붙어 따라온다; 빠지면 새가 커서로 순간이동하거나 화면 밖까지 끌려간다.
6. **(R6)** 플레이어가 드래그를 유지하는 동안 발사 방향으로 점 10개가 0.08초 간격의 예상 위치에 찍히고 손을 떼는 순간 사라진다; 빠지면 어느 세기로 당겼는지 몰라 첫 서너 발이 전부 감으로 나간다.
7. **(R7)** 새가 한 번 날고 나면 그 새가 실제로 지난 경로가 옅은 점선으로 남아 다음 발사 순간까지 유지된다; 빠지면 조준 보정을 기억에 의존해 같은 실수를 반복한다.
8. **(R8)** 플레이어가 드래그를 놓으면 새가 당긴 벡터의 반대 방향으로 임펄스를 받고 정적 바디에서 동적 바디로 전환되어 중력 아래 포물선을 그린다; 빠지면 손을 뗀 자리에 새가 그대로 멈춰 있다.
9. **(R9)** 두 바디가 충돌하면 상대속도와 유효질량으로 임펄스가 계산되어 재질 임계를 넘는 초과분만큼 상대 HP가 깎인다; 빠지면 새가 나무 상자를 밀기만 하고 상자에 아무 변화가 없다.
10. **(R10)** 블록 HP가 0 이하가 되면 그 바디가 월드에서 제거되고 파편 3~5조각이 튀며 위에 얹혀 있던 블록이 지지를 잃고 무너진다; 빠지면 부서진 것으로 표시된 블록이 여전히 다른 바디를 떠받친 채 공중에 걸린다.
11. **(R11)** 돼지 HP가 0 이하가 되면 돼지가 사라지고 `pigsRemaining`이 1 줄며 점수가 5,000점 오른다; 빠지면 돼지를 정통으로 맞혀도 스테이지가 끝나지 않는다.
12. **(R12)** 플레이어가 비행 중인 새를 한 번 탭하면 종류별 능력이 그 비행에서 1회만 발동한다(기본=없음, 폭탄=즉시 폭발, 스피드=진행 방향 가속); 빠지면 폭탄 새가 벽에 부딪혀 굴러다니다 멈춘다.
13. **(R13)** TNT 상자가 데미지를 받으면 반경 120px 안의 동적 바디에 거리 반비례 임펄스와 고정 데미지 20이 가해지고, 그 데미지가 다른 TNT를 다시 터뜨린다; 빠지면 TNT가 그냥 나무 상자처럼 조용히 부서진다.
14. **(R14)** 새가 발사되면 카메라가 새를 화면 좌측 1/3 지점에 두고 따라가다, 새가 정지하면 1.5배속으로 새총 위치로 되돌아온다; 빠지면 새가 화면 밖으로 사라져 어디에 맞았는지 보이지 않는다.
15. **(R15)** 모든 동적 바디의 속도가 0.35 미만인 상태가 0.8초 지속되거나 발사 후 6초가 지나면 턴이 끝나고 다음 새가 새총에 얹힌다; 빠지면 잔해가 미세하게 떨리는 동안 다음 발사가 무한정 막힌다.
16. **(R16)** 스테이지가 로드되면 `theme` 값에 따라 하늘 그라디언트·원경 실루엣·지면 타일이 그려지고, 지면 폴리곤이 물리 지형과 동일한 좌표를 사용한다; 빠지면 새가 눈에 보이는 땅보다 위나 아래에서 튕긴다.
17. **(R17)** 블록이 파괴되거나 폭발이 일어나면 재질 색 파편과 먼지가 0.6초간 뿌려지고 화면이 진폭 3px로 0.15초 흔들린다; 빠지면 블록이 소리 없이 증발해 타격이 들어갔는지 판단이 안 된다.
18. **(R18)** 발사·충돌·파괴·돼지 제거·클리어 다섯 순간마다 해당 효과음이 재생되고 동시 발음은 8채널로 제한된다; 빠지면 대형 붕괴에서 수십 개 소리가 겹쳐 출력이 찢어진다.
19. **(R19)** 플레이어가 창 크기를 바꾸면 캔버스가 디바이스 픽셀 비율에 맞춰 재설정되고 월드 좌표는 유지된 채 화면 스케일만 변한다; 빠지면 리사이즈 후 클릭 좌표가 실제 새총 위치와 어긋나 조준이 안 된다.
20. **(R20)** 스테이지가 로드되면 HUD 좌측에 남은 새가 아이콘 열로 표시되고 발사할 때마다 하나씩 회색으로 바뀐다; 빠지면 몇 발 남았는지 몰라 마지막 새를 낭비한다.
21. **(R21)** 점수가 오르면 HUD 상단 숫자가 목표값까지 0.3초 롤업으로 증가한다; 빠지면 무엇이 몇 점이었는지 대응이 되지 않아 별 등급이 임의로 느껴진다.

## 5. 상태 머신

| 상태 | 진입 계기 | 나가는 전이 | `Engine.update` | 오버레이 |
|---|---|---|---|---|
| `BOOT` | 페이지 로드 | 초기화 완료 → `MENU` | 미가동 | 로딩 |
| `MENU` | 부팅 완료, 메인으로 | `START`→`STAGE_SELECT` | 미가동 | 메인 |
| `STAGE_SELECT` | 시작 버튼, 클리어 후 | `SELECT(n)`→`PLAYING`, `BACK`→`MENU` | 미가동 | 선택 |
| `PLAYING` | 스테이지 선택/다시하기/다음 | `PAUSE`→`PAUSED`, `CLEAR`→`CLEARED`, `FAIL`→`FAILED` | 가동 | 없음(HUD만) |
| `PAUSED` | 우측 일시정지 버튼 | `RESUME`→`PLAYING`, `RETRY`→`PLAYING`(재로드), `MENU`→`MENU` | **정지** | 일시정지 |
| `CLEARED` | 돼지 0 + 정지 판정 | `NEXT`→`PLAYING(n+1)`, `RETRY`→`PLAYING`, `MENU`→`MENU` | 정지 | 클리어 |
| `FAILED` | 새 0 + 정지 판정 + 돼지 잔존 | `RETRY`→`PLAYING`, `MENU`→`MENU` | 정지 | 실패 |

전이표는 `Record<Phase, Partial<Record<Event, Phase>>>` 리터럴로 두어 정의되지 않은 전이가 타입 수준에서 `undefined`로 드러나게 한다. `PAUSED`/`CLEARED`/`FAILED`로 들어갈 때 `PhysicsLoop.pause()`가 누산기를 0으로 만들고, `PLAYING`으로 돌아올 때 다시 0에서 시작한다.

## 7. 판정 규칙

### 7.1 물리 루프
고정 타임스텝. `dt = 1000/60 ms`(파생: 표준 60Hz 디스플레이, Matter의 기본 적분 스텝). 프레임 간 실제 경과를 누산기에 더하고 `dt` 단위로 소비하되 **한 프레임 최대 5스텝**(파생: 5×16.67 = 83ms 상한이면 탭 비활성 복귀 시 폭주가 나지 않으면서 순간 프레임 저하는 흡수된다). 남는 시간은 버린다. `PAUSED` 진입 시 누산기 0.

### 7.2 데미지
`damage.ts`가 `collisionStart`에서 쌍을 받아 자체 계산한다.

```
impulse = |상대속도| × (m1·m2 / (m1+m2))
dmg     = max(0, impulse − material.threshold)
```

Matter가 주는 것은 충돌 쌍과 속도·질량뿐이고, 임계·HP·파괴는 전부 이 모듈이 소유한다. 블록끼리의 충돌에도 같은 식을 쓰므로 낙하 데미지가 별도 규칙 없이 성립한다.

### 7.3 파괴와 폭발
HP ≤ 0 → 바디 제거 + 파편 파티클(물리 바디 아님, `effects.ts`가 소유) + 파괴 점수 가산. TNT는 제거 시 반경 120px 안 동적 바디에 `impulse = 0.06 × (1 − d/120)`와 고정 데미지 20을 주고, 그 데미지가 다른 TNT의 제거 조건을 만족하면 같은 프레임에 재귀 처리한다(재귀 깊이 상한 8 — 임의값, 무한 연쇄 방지용).

### 7.4 정지와 턴
`settle.ts`가 매 프레임 모든 동적 바디의 최대 속도를 본다. `maxSpeed < 0.35`가 0.8초 유지되거나 발사 후 6초 경과 → 턴 종료. 세 값 모두 **초기값**이며, Step 10에서 "잔해 진동으로 다음 발사가 지연된다"가 관측되면 임계를 올리고 유지 시간을 줄이는 방향으로 교체한다.

### 7.5 점수와 별
- 돼지 제거 5,000 / 보스 10,000 / 블록 파괴 500 / TNT 1,000 / **잔여 새 1마리당 10,000**.
- 잔여 새 10,000은 파생값이다: 새 1마리의 가치가 돼지 1마리보다 커야 "적은 새로 끝내기"가 우세 전략이 되고, 그때만 별 3개가 실력의 신호가 된다.
- 별: 1별 = 클리어, 2별 = `targetScore × 0.75`, 3별 = `targetScore`. 0.75는 초기값. 교체 트리거: 구현자가 스테이지별로 5회씩 플레이해 2별 달성률이 전 스테이지에서 100%거나 0%면 계수를 재산정한다.
- 블록 파괴 500은 임의값(무너뜨리기 자체에 최소 보상만 주려는 값). 수명: Step 10 밸런싱 패스에서 대체.

### 7.6 클리어·실패
- 클리어: `pigsRemaining === 0` **그리고** 정지 판정. 두 조건이 다 필요하다 — 마지막 돼지가 죽는 순간 무너지던 블록의 파괴 점수가 정산에 들어가야 한다.
- 실패: 남은 새 0 **그리고** 정지 판정 **그리고** `pigsRemaining > 0`.
- R36의 세로 뷰포트 비중은 `progress.ts`에 세션 시작 시 뷰포트 방향만 카운트로 남겨 관측한다(개인정보 없음).

## 8. 명시적 가정

- **A1 (이 플랜 전체가 여기 걸려 있다)** matter-js 0.20.0이 동적 바디 약 80개와 제약 몇 개를 60fps에서 프레임당 8ms 안에 처리한다(8ms는 파생값 — 16.67ms 예산의 절반을 렌더·UI에 남긴다). **틀리면**: 스테이지당 바디 상한을 60으로 낮추고 `enableSleeping`을 켜고 파편은 전부 비물리 파티클로 유지한다. **가장 싼 조기 검증**: Step 2에서 더미 블록 80개 스택을 낙하시켜 `performance.now()` 차이를 콘솔에 찍는다 — Step 3 이전에 끝난다.
- **A2** Pointer Events 하나로 마우스와 터치를 모두 덮는다. 틀리면: `touchstart/move/end` 폴백을 `slingshot.ts`에 추가(약 30줄), 다른 층은 불변.
- **A3** localStorage를 쓸 수 있다. 틀리면(사파리 프라이빗 등): `progress.ts`가 인메모리 폴백으로 내려가고 스테이지 선택 상단에 "이 브라우저에서는 진행도가 저장되지 않습니다" 배너를 띄운다.
- **A4** 외부 아트·오디오 에셋 없이 프로그램 드로잉과 WebAudio 합성음으로 충분하다. 틀리면: Step 9에 스프라이트/오디오 로더를 추가하고 `render/canvas.ts`의 드로잉 호출을 아틀라스 참조로 교체한다.
- **A5** 임펄스 기반 데미지가 "때린 만큼 부서진다"는 감각을 만든다. 틀리면: Step 10에서 임계 대신 HP를 조정하거나, 재질별 데미지 배율 한 칸을 테이블에 추가한다.
- **A6** 1인 개발이다(요구사항에 인원 언급이 없어 추정). 틀리면: Step 5·6·9는 서로 의존하지 않으므로 그대로 병렬 분할 가능하다 — 순서는 바뀌지 않고 배정만 바뀐다.

## 11. 대안과 기각 사유

> 물리 엔진 항목은 이 문서에서 유일하게 열린 either/or였고, 그 한 칸에 한해 **dialectic**(양 진영 최강 논거 + 사전 고정 판정 함수 + 패자 논거의 제약 승격)을 차용했다.

**물리를 직접 구현한다 vs Matter.js를 쓴다.**
판정 함수는 이 과제의 실제 희소 자원 위에 세웠다: **10개 스테이지 저작에 남는 시간**. 두 축으로 채점한다 — (a) 첫 발사가 화면에서 도는 시점까지의 작업량, (b) 회전 강체 더미가 "무너지는" 느낌이 날 때까지의 튜닝 반복 횟수.
직접 구현 진영의 최강 논거: 회전 강체 + 마찰 + 안정적 스택은 충돌 해결자(solver) 품질 문제이고, 엔진을 쓰면 그 품질이 블랙박스가 되어 **파괴 규칙이 엔진 내부 수치에 종속되고 튜닝 손잡이를 잃는다.**
라이브러리 진영의 최강 논거: (a)에서 자릿수가 다르고, (b)의 반복은 대부분 이미 남이 돌렸다.
**판정: Matter.js.** 그리고 패자 논거를 제약으로 승격한다 — **데미지·HP·파괴·폭발은 `damage.ts`와 `materials.ts`가 소유하며 Matter은 충돌 검출과 적분만 제공한다.** 임펄스도 엔진 내부 값이 아니라 상대속도·질량으로 우리가 계산한다(§7.2). 이 제약이 없었다면 재질 튜닝이 Matter의 `restitution`/`slop` 조합 탐색이 됐을 것이다.
**부활 트리거**: 스테이지 10에서 프레임당 물리 시간이 8ms를 넘거나, 파괴 감각 튜닝이 엔진 내부 수치 접근 없이는 불가능하다고 판명되면 — 좁은 범위의 자체 솔버(원/박스 전용)로 교체를 재검토한다.

**Matter 내장 렌더러(`Matter.Render`)** — 기각: 디버그 렌더러라 스프라이트·파티클·카메라 흔들림을 못 한다. 부활 트리거: 최종 아트가 전부 단색 도형으로 확정되고 카메라 연출을 버리기로 하면.

**Phaser / PixiJS** — 기각: 게임 루프·씬·입력을 이미 우리가 갖게 되므로 남는 이득은 스프라이트 배칭뿐이고, 학습·번들 비용이 Step 8·9의 시간을 먹는다. 부활 트리거: `effects.ts`의 파티클 직접 구현이 3일을 넘거나, 스테이지 10에서 드로우 콜이 프레임 예산을 초과하면.

**캔버스 안에 UI를 직접 그린다** — 기각: 버튼 히트테스트·포커스·리사이즈 레이아웃을 전부 재구현해야 하고, 그 비용이 스펙 명시 요구(우측 일시정지 + 2버튼)의 완성도를 깎는다. 부활 트리거: DOM 오버레이가 캔버스 포인터 이벤트를 가로채는 문제가 `pointer-events: none`으로 해결되지 않으면.

**스테이지를 TS 코드로 작성** — 기각: 밸런싱 왕복이 재빌드와 코드 리뷰에 묶인다. 부활 트리거: JSON 스키마 표현력이 부족해 8스테이지의 constraint 기믹이 데이터로 표현되지 않으면.

**서버에 진행도 저장** — 기각: 백엔드가 없고 스펙에 없다. 부활 트리거: 기기 간 진행도 동기 요구가 추가되면.

## 13. "완료"의 정의

아래 여섯 커맨드가 전부 종료코드 0이고, §1.2 원장의 `build` 34행 중 문서 갱신 없이 판정이 바뀐 행이 0개일 때 완료다.

1. `npm ci` — 종료코드 0. §4의 핀이 실제로 resolve된다는 유일한 증명. (측정: CI 또는 로컬 셸의 `$?`)
2. `npx tsc --noEmit` — 종료코드 0. TypeScript를 산 이유(스테이지 스키마·상태 전이표의 컴파일 타임 검사)가 실제로 집행됨을 보인다.
3. `npm run build` — 종료코드 0, `dist/`에 진입 HTML과 번들이 생성된다.
4. `npm run validate:stages` — 종료코드 0, 표준출력에 `10/10 stages valid`. 검사 항목: 스키마 적합, 돼지 ≥ 1, 새 ≥ 1, 초기 바디 겹침 0쌍, 참조 재질 존재, 바디 수 ≤ 80.
5. `npm run test:state` — 종료코드 0. 포함 단언: (a) `PAUSED` 동안 `Engine.update` 스파이 호출 횟수 = 0, (b) `PAUSED → RETRY` 후 `pigsRemaining`이 `StageDef.pigs.length`와 일치, (c) `PAUSED → MENU` 후 엔진의 등록 리스너 수 = 0, (d) §5 표에 없는 전이는 전부 거부.
6. `npm run test:replay` — 종료코드 0. 스테이지 1~10 각각에 대해 기록된 발사 시퀀스를 헤드리스로 재생했을 때 `pigsRemaining === 0`에 도달한다. **10개 전부 통과해야 한다.**

이 중 5·6은 이 플랜의 어떤 방어 장치로도 자동 충족되지 않는다 — 일시정지가 물리를 실제로 멈추지 않으면 5-(a)가 깨지고, 임계값을 잘못 만지면 6이 깨진다.

각 수치의 측정 주체: 1~6은 구현자가 셸에서 실행하고 종료코드를 읽는다. §6.2·§7.4·§7.5의 초기값은 Step 10에서 구현자가 스테이지 3·6·9를 각 5회 플레이해 대체하며, 대체된 값 옆에 근거 한 줄을 남긴다.

## 14. 구현자 계약

- **스택 핀**: `typescript@5.4.5`, `vite@5.2.0`, `matter-js@0.20.0`, `@types/matter-js@0.19.6`, `vitest@1.6.0`, `tsx@4.7.0`. resolve 실패 시 **패치 버전만** 올리고 마이너는 올리지 않는다. 증명은 `npm ci` 종료코드 0.
- **Matter.js는 충돌 검출과 적분만 산 것이다.** 데미지·HP·파괴·폭발을 Matter의 API나 내부 수치로 구현하지 말 것. 그 규칙의 소유자는 `damage.ts`와 `materials.ts`다. 부활 트리거: 스테이지 10의 프레임당 물리 시간이 8ms 초과.
- **직접 물리 구현은 기각됐다** — 이유는 저작 시간 잠식. 그 이유가 거짓으로 관측되면(엔진 튜닝이 자체 구현보다 오래 걸리면) 재검토하라.
- **Matter 내장 렌더러 기각** — 스프라이트·파티클·카메라 불가. 아트를 단색 도형으로 확정하면 재검토.
- **캔버스 내 UI 기각** — DOM 오버레이가 포인터를 가로채는 문제를 `pointer-events`로 못 잡으면 재검토.
- **JSON 스테이지 기각 조건**: 8스테이지 constraint 기믹이 스키마로 표현되지 않으면 그 스테이지만 코드 저작으로 예외 처리하고 스키마 확장 이슈를 남긴다.
- **컴파일 타임 검사 보장의 증명은 `npx tsc --noEmit` 종료코드 0**이고, 일시정지 요구의 증명은 `npm run test:state` 종료코드 0이며, 10스테이지 요구의 증명은 `npm run validate:stages`와 `npm run test:replay` 종료코드 0이다. 산문으로 "타입 안전하다", "클리어 가능하다"고 쓰지 말 것.
- **원장(§1.2)을 지우지 말 것.** 어떤 행을 `build`에서 내리려면 트리거를 적어 `defer`로 옮긴다.

## 15. Frame deviations & habit regressions

- **8스테이지 constraint 기믹의 스키마가 반쯤 비어 있다.** §6.1에 `constraints` 배열은 있지만 `stiffness`·`length`를 저작자가 어떤 범위에서 고르는지, 시소의 회전 마찰을 어디에 두는지는 §6.1에도 §9 Step 8에도 없다. Step 8 저작 중 스키마 변경이 일어날 확률이 높은 지점이고, 이 문서에서 데이터가 실제 요구를 못 담을 위험이 가장 큰 칸이다.
- **카메라 줌 기준이 초기값 없이 스테이지 데이터로 미뤄졌다.** §3-14는 추적만 규정하고, 스테이지 9·10처럼 구조물이 화면 폭을 넘는 경우의 줌 아웃 계수를 §6.1의 `minZoom/maxZoom` 필드 존재로만 처리했다. 필드를 열어 두는 것과 값을 정하는 것은 다르며, 이건 후자를 안 한 것이다.
- **정지 판정 하나에 두 표면이 이중으로 걸려 있다.** §7.4의 임계가 클리어(§7.6)와 실패(§7.6) 양쪽의 발화 조건이라, 이 값이 틀리면 두 오버레이가 동시에 깨진다. 분리하려 했으나 두 판정 모두 "월드가 멎었다"는 같은 사실을 필요로 해서 합친 채로 뒀다 — 대신 Step 10의 교체 대상 1순위로 올렸다.
- **Step 5와 Step 8은 사다리로 번호가 붙었지만 실제로는 왕복이다.** §9 끝에 그 사실을 적긴 했으나, 문서 형태는 여전히 0→10의 오름차순이고 되돌아가는 화살표는 문장 하나로만 존재한다. 단계 번호를 보고 일하는 구현자는 Step 8에서 발견한 밸런스 문제를 Step 10까지 쌓아 둘 가능성이 있다.
- **내가 리뷰어라면 §7.2 데미지 공식을 친다.** `impulse − threshold` 한 줄이 이 게임의 파괴 감각 전부를 결정하는데, 이 공식이 "스치면 안 부서지고 정통으로 맞으면 무너진다"를 만드는지는 문서로는 알 수 없다. 이 플랜에서 가장 튜닝 반복이 많이 필요한 곳이며, §6.2의 숫자 여섯 줄이 전부 초기값인 것도 같은 이유다.
- **관습을 택한 곳**: DOM 오버레이 UI, 고정 타임스텝 누산기, localStorage 진행도 — 셋 다 프레임이 시킨 게 아니라 이 도메인의 정석이다. 프레임이 실제로 바꾼 것은 원장의 `defer`/`n-a` 판정과 §10 홉 4의 `plugin.kind` 태그 소재지(로더가 부여한다는 결정)였고, 관습 부분은 프레임의 공로가 아니다.
