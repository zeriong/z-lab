# pure-model 실행 절차

## ⚠️ 이 문서의 전제가 하나 바뀌었다 (2026-08-09 정정)

처음 이 파일은 "새 세션에서만 실행 가능"이라고 적었다. 근거는 이 저장소에 기록돼 있던
"커스텀 에이전트 정의는 세션 중 핫로드되지 않는다"는 사실이었다. **그러나 `bare-model` 을 정의한
바로 그 세션에서 이후 `agentType` 으로 등록된 것이 관측됐다.**

따라서 CLAUDE.md의 그 조항은 **항상 참이 아니다.** 정확한 진술은 "핫로드를 기대할 수 없다"이며,
안전한 절차는 **세션과 무관하게 아래 0번을 먼저 확인하는 것**이다. 등록돼 있으면 같은 세션에서 실행해도 된다.

## 0. 가장 먼저 — 에이전트 로드 확인

`bare-model` 이 실제로 등록됐는지 확인한다. 등록되지 않았다면 **실행하지 말 것** —
등록 실패 상태에서 돌리면 다른 에이전트로 대체되어 계열의 전제가 깨진다.

## 1. 순수성 사전 점검 (실행 전, 결과를 SPEC 옆에 기록)

`bare-model` 의 정의가 아래와 같은지 눈으로 확인한다.

| 항목 | 기대값 |
|---|---|
| `tools` | `Read, Write` — **오직 2개** |
| 본문 | 역할·방법론·품질기준 문장 0 |
| `model` | `inherit` (워크플로의 셀별 model 지정이 적용되도록) |

## 2. 실행

[`runner.js`](runner.js) 의 **내용을 그대로** `Workflow({ script: <내용> })` 로 넘긴다.
8셀(4모델 × 2arm)이 각각 플랜 1회 + 구현 1회를 돈다. 셀 간 배리어 없음.

- 중단되면 디스크를 재스캔해 **plan.md 와 result/ 가 모두 있는 셀만 완료로 보고** 나머지만 재실행한다(제6조).
- 실험 도중 오케스트레이터가 프롬프트를 고치지 않는다. 고치면 그 사실을 지표에 남긴다(제10조).

## 3. 실행 후 반드시 확인할 것

### (a) 구조적 순수성

```
find pure-model -name node_modules -o -name dist -o -iname 'RUN.md'   → 전부 0건이어야 한다
```

### (b) 전역 지침의 서브에이전트 유입 — 이 계열 최대의 미확인 변수

트랜스크립트에서 사용자 전역/프로젝트 지침 문구가 서브에이전트 컨텍스트에 들어갔는지 grep한다.
예: `Behavioral Guidelines`, `Simplicity First`, `실험 저장소 규칙`, `제1조`.

**유입됐다면 "순수 모델" 라벨을 그대로 쓸 수 없다.** 유입 사실과 범위를 SPEC.md 하단에 적고,
그 조건에서의 결과라고 명시한다. 유입되지 않았다면 그 확인 결과도 적는다.

### (c) resolved model id

`agent-*.jsonl` 을 grep해 4개 모델 id를 확정한다. 별칭(`opus`/`fable`/…)은 버전이 아니다.

### (d) 지표

토큰은 **트랜스크립트 직접 집계**(`input + cache_creation + cache_read + output`)로 낸다.
워크플로 자가보고 값은 캐시 토큰을 세지 않아 10~20배 작게 나온 전례가 있다.

## 4. 관측 (파이프라인이 아니라 사후)

빌드·서빙·구동은 **오케스트레이터가 사후에** 한다. 소스는 수정하지 않는다.
판정은 하중 경로 1개(발사: 조준 → 놓기 → 발사체가 날아가고 상태가 변함) PASS/FAIL로만 한다.

측정 방법의 알려진 함정 두 가지 — 라운드3에서 실제로 겪었다:

1. **합성 PointerEvent는 `setPointerCapture` 가 실패한다.** 모든 셀에 동일하게 무력화하고,
   그 사실을 방법 기록에 남긴다. 무력화하지 않으면 정상 코드도 FAIL로 보인다.
2. **슬링샷 좌표를 추정하지 마라.** 라운드3에서 좌표를 추정해 정상 셀을 FAIL로 오판했다.
   각 셀의 소스에서 실제 앵커 값을 읽어 쓴다. **0이 나오면 제품보다 계측을 먼저 의심한다.**

## 5. 하지 않을 것

- 실측 기반 리뷰 하네스(`ux-ui-builder` 계열), 감사 에이전트, 배선 감사, 채점 루브릭 — **전부 없다.**
  이 계열은 조항 발화를 재지 않는다.
- 산출물 수정. 깨진 표본은 깨진 채로 보고한다(제1조).
