## 0. 요구사항 요약과 해석

| # | 요구사항 | 해석 |
|---|---|---|
| R1 | 스테이지 10단계 | 데이터 주도(stage 정의 파일 10개 또는 배열 10개)로 구현. 난이도는 점진 상승 |
| R2 | 앵그리버드와 같은 게임 시스템 | 슬링샷 드래그 → 발사 → 포물선·중력 → 구조물 충돌·파괴 → 목표물(돼지) 제거 |
| R3 | 인게임 우측 일시정지 버튼, 클릭 시 "다시하기 / 메인으로" | 우측 상단 고정 버튼 + 모달 오버레이. 오버레이 표시 중 물리·입력 정지 |

명시되지 않았지만 R2("앵그리버드와 같은")를 만족하려면 사실상 필요한 것:

- **새 수(발사 횟수) 제한** — 스테이지별 부여, 소진 시 실패 판정의 근거
- **점수** — 파괴·명중에 대한 피드백 (별점은 선택 확장)
- **클리어/실패 화면** — 상태 머신의 종단 상태
- **메인 화면과 스테이지 선택** — "메인으로" 버튼이 돌아갈 곳

범위에서 제외하는 것(요구에 없고 핵심이 아님): 사운드, 새 종류별 특수 능력, 저장/진행도 영속화(localStorage는 선택 확장), 모바일 터치 최적화(마우스 우선, 터치는 포인터 이벤트로 자연 지원되는 수준까지만).

## 1. 핵심 기술 결정

### 1.1 물리 엔진: **Matter.js 채택** (직접 구현 대비)

| 기준 | 직접 구현 | Matter.js |
|---|---|---|
| 강체 회전·적층 안정성 | 매우 어려움(적층 구조물이 핵심인 게임) | 검증됨 |
| 충돌 해석(SAT, 마찰, 반발) | 수 주 규모 | 내장 |
| 파괴 판정용 충격량 | 직접 계산 필요 | `collisionStart` 이벤트의 상대속도/depth로 산출 가능 |
| 번들 크기 | 0 | ~80KB(min) — 허용 범위 |

앵그리버드의 재미는 "블록 탑이 그럴듯하게 무너지는 것"에 있고, 이는 적층 강체 시뮬레이션의 안정성 문제다. 직접 구현은 이 프로젝트 범위를 초과한다. → **Matter.js**.

- 사용 모듈: `Engine`, `World`, `Bodies`, `Body`, `Events`, `Composite`. 렌더링은 Matter 내장 `Render`를 **쓰지 않고** 자체 Canvas 렌더러 사용(스프라이트·UI 제어를 위해).
- 알려진 주의점: 고속 발사체의 터널링 → 발사체 속도 상한을 두고, 필요 시 engine `positionIterations`/`velocityIterations` 상향으로 대응. 얇은 바디(판자)는 최소 두께를 유지.

### 1.2 렌더링: **Canvas 2D**

- 단일 `<canvas>`에 게임 월드를 그린다. WebGL은 이 규모(바디 수십 개)에서 이점이 없다.
- 논리 해상도 고정(예: 1280×720) + CSS 스케일로 창 크기 대응. 물리 좌표 = 논리 좌표(1:1)로 두어 변환 복잡도를 제거한다.
- 아트는 외부 에셋 없이 **도형 + 색 + 간단한 얼굴 표현**으로 그린다(원=새/돼지, 사각형=블록). 에셋 파이프라인을 계획에서 제거하기 위한 결정.
- HUD·메뉴·일시정지 오버레이는 **DOM으로** 얹는다(canvas 위 absolute 레이어). 이유: 버튼 히트 판정·접근성·텍스트 렌더링이 DOM이 압도적으로 싸다. canvas는 월드만 담당.

### 1.3 실행 형태와 스택

- **빌드 도구 없는 정적 웹앱**: `index.html` + ES 모듈(`<script type="module">`), Matter.js는 로컬 파일 또는 CDN 단일 스크립트. `npm install` 없이 브라우저에서 바로 열려 실행되는 것을 목표로 한다.
- 언어: 바닐라 JavaScript. 프레임워크 없음(상태 머신 하나로 충분한 규모).

## 2. 아키텍처

### 2.1 상태 머신 (요구 질문 6 대응)

```
              ┌────────────────────────────┐
              ▼                            │
MAIN ──play──▶ PLAYING ──pause──▶ PAUSED ──resume
  ▲              │  ▲               │ │
  │              │  └──restart──────┘ │
  │              │          (다시하기) │
  │        clear/fail                 │
  │              ▼                    │
  │           RESULT (클리어/실패)     │
  │              │ retry → PLAYING    │
  └──"메인으로"───┴───────────────────┘
```

- 상태: `MAIN`(메인+스테이지 선택), `PLAYING`, `PAUSED`, `RESULT`(clear|fail).
- 전이 규칙:
  - `MAIN → PLAYING`: 스테이지 선택. 스테이지 데이터 로드 → 월드 구성.
  - `PLAYING → PAUSED`: 우측 상단 일시정지 버튼. **물리 엔진 업데이트 중단 + 입력 차단**, 렌더는 마지막 프레임 유지.
  - `PAUSED → PLAYING`(계속하기), `PAUSED → PLAYING`(다시하기: 현재 스테이지 재구성), `PAUSED → MAIN`(메인으로: 월드 해체).
  - `PLAYING → RESULT`: 클리어/실패 판정(§4.4).
  - `RESULT → PLAYING`(다시하기) / `RESULT → PLAYING`(클리어 시 다음 스테이지) / `RESULT → MAIN`.
- 구현: 문자열 상태 + 전이 함수 하나면 충분. 상태 라이브러리 불필요.

### 2.2 모듈 구성 (파일 계획)

```
angry-birds/
├── index.html          # canvas + DOM 오버레이 컨테이너, Matter.js 로드
├── style.css           # 레이아웃, HUD, 오버레이(일시정지/결과/메인)
└── src/
    ├── main.js         # 부트스트랩: 상태 머신 소유, 화면 전환, 게임 루프 시작
    ├── game.js         # PLAYING 세션: 엔진 생성/해체, 스테이지 구성, 판정 루프
    ├── physics.js      # Matter 래핑: 바디 팩토리(새/돼지/블록/지면), 재질 상수
    ├── slingshot.js    # 드래그 입력, 제약(constraint), 발사, 궤적 예측
    ├── stages.js       # 10개 스테이지 데이터 (선언적 정의)
    ├── entities.js     # 파괴 가능 오브젝트 공통(HP, 피해 적용, 사망 처리)
    ├── renderer.js     # canvas 렌더링(월드 + 궤적 점 + 지난 발사 잔상)
    └── ui.js           # DOM HUD/오버레이 표시·숨김, 버튼 바인딩
```

원칙: `game.js`가 세션의 소유자. `PAUSED`는 `game.js` 내부 플래그가 아니라 `main.js` 상태 머신이 결정하고 `game.js`는 `update()` 호출을 받지 않는 방식(정지 로직이 한 곳에만 존재).

### 2.3 게임 루프

- `requestAnimationFrame` 기반. 물리는 **고정 타임스텝**(1000/60ms)으로 `Engine.update` — 프레임 드랍 시 누적 시간으로 최대 N회 보정(스파이럴 방지 상한 3회).
- `PAUSED`/`RESULT`/`MAIN`에서는 물리 업데이트를 호출하지 않는다. rAF 루프 자체는 유지(오버레이 뒤 정지 화면 렌더).

## 3. 게임플레이 설계

### 3.1 엔티티와 재질

| 엔티티 | 형태 | 물리 속성 | 파괴 |
|---|---|---|---|
| 새(발사체) | 원 r≈20 | 밀도 높음, 반발 0.4 | 파괴 안 됨. 정지 또는 수명 만료 시 제거 |
| 돼지 | 원 r≈18~26 | 가벼움 | HP 1단계 — 임계 충격 1회로 제거 (§3.4) |
| 나무 블록 | 사각(판/기둥) | 중간 밀도 | HP 낮음(약한 충격 2회 또는 강한 충격 1회) |
| 돌 블록 | 사각 | 고밀도 | HP 높음 |
| 유리 블록 | 사각 | 저밀도 | HP 최저(스치면 깨짐) — 스테이지 후반 다양성용 |
| 지면/받침 | static 사각 | 정적 | 불파괴 |

- 재질 3종(나무/돌/유리)은 색으로 구분. `entities.js`에 재질 테이블(밀도·HP·색) 상수로 정의.

### 3.2 슬링샷 입력 (요구 질문 4 대응)

- **장전**: 스테이지 시작/발사 후, 남은 새가 있으면 다음 새를 슬링샷 위치에 스폰(발사 전에는 물리 비활성 또는 static).
- **드래그**: 포인터 다운이 새 근처(반경 여유 포함)에서 시작하면 드래그 모드. 새 위치 = 포인터 위치, 단 **슬링샷 기준점에서 최대 반경(예: 90px)으로 클램프**.
- **발사**: 포인터 업 시 `발사속도 = k × (기준점 − 당긴위치)` 벡터. `k`와 속도 상한은 튜닝 값(터널링 방지 상한 포함). 당김 거리가 최소치(예: 15px) 미만이면 발사 취소로 처리(오발 방지).
- 구현 방식: Matter의 `Constraint`(고무줄) 방식 대신 **드래그 중 새를 수동 배치 → 발사 순간 `Body.setVelocity`** 방식을 채택. 이유: constraint 해제 타이밍 튜닝(한 프레임 지연 발사 등)이 까다로운 반면, 수동 방식은 결과가 결정적이고 궤적 예측(3.3)과 같은 수식을 공유한다.

### 3.3 궤적 예측 UX

- 드래그 중, 발사 초기속도로 **등가속 포물선을 수식으로 샘플링해 점선(점 10~15개) 표시**. Matter 중력·`frictionAir`와 계수를 맞추되, 완벽 일치가 목표가 아니라 조준 보조가 목표(공기저항 0으로 근사 허용 — 계획상 명시된 단순화).
- 직전 발사의 실제 경로를 옅은 잔상 점으로 남기면 조준 반복이 쉬워진다(선택 확장, P2).

### 3.4 충돌·파괴 규칙 (요구 질문 5 대응)

- `Events.on(engine, 'collisionStart')`에서 각 쌍의 **충격 크기**를 산출: 상대속도의 법선 성분 × 상대 질량 근사(또는 pair의 `collision.depth`+속도 조합 — 구현 시 한 가지로 통일하고 튜닝).
- 충격이 재질별 임계값을 넘으면 해당 엔티티 HP 차감. HP ≤ 0 → 월드에서 제거 + 점수 가산 + 파편 파티클(사각 조각 4~6개, 물리 없는 장식, 1초 후 소멸).
- 돼지는 새 직격뿐 아니라 **블록에 깔리거나 낙하 충격**으로도 제거 가능해야 한다(동일한 충격 임계 규칙이 자동으로 보장 — 별도 코드 불필요, 임계값만 낮게).
- 화면 밖(월드 경계 밖) 이탈 바디는 제거(돼지가 밖으로 굴러떨어져도 제거로 인정).

### 3.5 점수

- 돼지 제거 5000, 블록 파괴 500(유리 300/나무 500/돌 800), 남은 새 1마리당 보너스 10000(클리어 시).
- 점수는 HUD 표시 + 결과 화면 표시. 별점/최고점 저장은 P2.

### 3.6 발사 턴 종료 판정

다음 중 하나면 현재 새를 정리하고 다음 장전 또는 클리어/실패 판정으로:

1. 발사된 새와 모든 동적 바디의 속도가 임계 이하(정지)로 **연속 1초** 유지
2. 발사 후 **5초 경과** (타임아웃 — 미세 진동으로 영원히 안 끝나는 것 방지)
3. 새가 월드 밖으로 이탈

### 3.7 클리어/실패 판정 (요구 질문 7의 일부)

- **클리어**: 돼지 수 0 (턴 종료를 기다리지 않고 즉시 판정해도 됨 — 마지막 돼지 제거 시 1초 여유 후 RESULT.clear)
- **실패**: 돼지 > 0 이고 남은 새 0 이고 턴 종료 조건 충족 → RESULT.fail
- 순서 주의: 마지막 새 발사가 굴러가서 돼지를 제거할 수 있으므로 **실패 판정은 반드시 턴 종료 후**에 한다.

## 4. 스테이지 시스템 (요구 질문 3 대응)

### 4.1 데이터 구조

`stages.js`에 순수 데이터 배열 10개. 스키마:

```
{
  id: 1..10,
  name: 문자열,
  birds: 발사 가능 횟수 (예: 3),
  slingshot: {x, y},
  pigs:   [{x, y, size}],
  blocks: [{x, y, w, h, material: 'wood'|'stone'|'glass', angle?}],
  statics:[{x, y, w, h}]        // 지면 외 추가 발판(절벽·기둥 등)
}
```

- 좌표는 논리 해상도(1280×720) 기준 절대값. 지면(y=680 부근 전폭 static)은 전 스테이지 공통이라 스키마에 넣지 않는다.
- 로딩: import된 배열에서 인덱스 접근(네트워크 로딩 없음). 전환: 현 월드 `Composite.clear` + 엔진 이벤트 해제 → 새 스테이지 구성. **재시작과 다음 스테이지가 동일한 "해체 후 구성" 경로**를 쓰도록 해 상태 누수를 막는다.

### 4.2 10단계 난이도 커브 (콘텐츠 계획)

| # | 콘셉트 | 새 | 구성 요지 |
|---|---|---|---|
| 1 | 튜토리얼: 직격 | 3 | 맨바닥 돼지 1, 블록 없음 |
| 2 | 첫 구조물 | 3 | 나무 기둥 2 + 지붕 1, 돼지 1 (기둥 무너뜨리기) |
| 3 | 두 목표 | 3 | 떨어진 돼지 2, 각각 낮은 나무 담 |
| 4 | 유리 소개 | 3 | 유리 탑 안 돼지 1 + 지상 돼지 1 |
| 5 | 첫 돌 | 3 | 돌 지붕 아래 돼지 — 측면 공략 유도 |
| 6 | 2층 구조 | 4 | 나무+유리 2층, 각 층 돼지 1 |
| 7 | 절벽 지형 | 4 | 높이 다른 static 발판 2단, 돼지 3 |
| 8 | 도미노 | 4 | 세로 기둥 열 — 연쇄 붕괴로 원거리 돼지 처리 |
| 9 | 요새 | 4 | 돌 외벽 + 유리 내벽 + 돼지 3 |
| 10 | 최종 | 5 | 8·9 요소 결합, 돼지 4, 새 여유 1 |

수치는 초안이며 §6의 튜닝 단계에서 조정한다. 단, "스테이지 10개 존재 + 각각 클리어 가능한 구성"이 완료 조건이다.

## 5. UI 계획

### 5.1 화면별 DOM 구성

- **MAIN**: 타이틀, "게임 시작"(스테이지 1), 스테이지 선택 그리드(1~10 버튼 — 전부 즉시 선택 가능. 잠금/해제 진행도는 P2).
- **PLAYING HUD**: 좌측 상단 — 스테이지 번호·점수·남은 새 아이콘. **우측 상단 — 일시정지 버튼(R3)**.
- **PAUSED 오버레이**(반투명 암막 + 중앙 패널): **다시하기 / 메인으로**(R3 필수) + 계속하기(닫기). 요구사항은 두 버튼을 명시했고 "계속하기"는 일시정지가 성립하려면 사실상 필요하므로 포함한다.
- **RESULT 오버레이**: 클리어 — 점수, 다음 스테이지(10단계면 "메인으로"만), 다시하기, 메인으로 / 실패 — 다시하기, 메인으로.

### 5.2 정지의 의미 (구현 규칙)

- PAUSED 진입 시: 물리 업데이트 중단, canvas 포인터 이벤트 무시, HUD 버튼 비활성. 타이머류(턴 종료 카운트)는 **경과 누적을 멈춘다**(벽시계가 아닌 시뮬레이션 시간 기준으로 카운트하면 자동 해결 — 이 방식 채택).
- "다시하기" = 현재 스테이지 완전 재구성(점수는 스테이지 진입 시점 값으로 복원 — 단순화를 위해 점수는 스테이지 단위로만 유지하고 누적 총점은 P2).

## 6. 구현 순서와 단계별 완료 기준

각 단계는 이전 단계 산출물 위에서만 진행한다.

| 단계 | 작업 | 완료 기준(검증 가능) |
|---|---|---|
| 1. 뼈대 | index.html, canvas, 게임 루프, Matter 엔진 가동, 지면+낙하 원 1개 | 원이 떨어져 지면에 정지하는 것이 보임 |
| 2. 상태 머신 | MAIN/PLAYING/PAUSED/RESULT 화면 전환, 오버레이 DOM 전부 | 버튼만으로 모든 전이 순회 가능(물리 정지 포함) |
| 3. 슬링샷 | 드래그·클램프·발사·궤적 점선·새 장전 사이클 | 드래그로 조준해 원하는 방향으로 발사 가능, 궤적과 실탄이 대체로 일치 |
| 4. 파괴·판정 | 재질/HP, 충격 파괴, 돼지 제거, 턴 종료, 클리어/실패 | 스테이지 1개에서 클리어와 실패 양쪽 모두 도달 가능 |
| 5. 스테이지 10종 | stages.js 데이터 10개 + 스테이지 선택·전환·다음 스테이지 | 1~10 각각 로드되고 시각적으로 §4.2 콘셉트와 일치 |
| 6. 점수·연출·튜닝 | 점수 HUD, 파편, 발사 계수·HP 임계 조정, 각 스테이지 클리어 가능성 확인 | §7 완료 판정 체크리스트 전항 통과 |

리스크와 대비:

- **적층 구조물이 스폰 직후 저절로 무너짐**: 블록 간 초기 겹침 0 보장(좌표를 크기에서 계산), 필요 시 스테이지 시작 후 0.5초 안정화 프레임 동안 판정 무시.
- **터널링**: 발사 속도 상한 + iteration 상향(§1.1). 그래도 발생하면 발사체 반지름 증가.
- **파괴 임계 튜닝 난항**: 임계·HP를 재질 테이블 한 곳에 모아 조정 지점을 단일화(§3.1).

## 7. 완료의 판정 기준 (요구 질문 7 — "무엇이 되면 된 것인가")

아래 전부가 브라우저에서 확인되면 완료:

1. `index.html`을 열면 메인 화면이 뜨고, 게임 시작으로 스테이지 1에 진입한다.
2. 마우스 드래그로 새를 당겨 쏘면 포물선으로 날아가 구조물이 물리적으로 무너지고, 충분한 충격을 받은 블록·돼지가 파괴된다. (R2)
3. 스테이지 1~10이 모두 존재하고, 각각 선택·플레이·클리어가 가능하다. (R1)
4. 모든 돼지 제거 시 클리어 화면, 새 소진 + 돼지 잔존 시 실패 화면이 뜬다.
5. 인게임 우측(상단)에 일시정지 버튼이 있고, 클릭 시 "다시하기"와 "메인으로" 버튼이 있는 오버레이가 뜬다. 오버레이 중 게임이 완전히 정지하며, 다시하기는 현 스테이지를 재시작하고 메인으로는 메인 화면으로 돌아간다. (R3)
6. 클리어 화면에서 다음 스테이지로 진행해 1→10을 연속 플레이할 수 있다.

P2(이번 범위 밖, 여력 시): 사운드, 별점·최고점 localStorage, 스테이지 잠금 진행도, 발사 잔상, 누적 총점, 터치 전용 UX.
