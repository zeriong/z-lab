# 웹 앵그리버드 게임 — 구현 플랜
- Reasoning frame: spec-coverage (물리 엔진 1건에 dialectic 차용) / Style: opus
- 한 줄 요약: Canvas 2D + Matter.js + TypeScript로 슬링샷 물리 루프를 얇은 엔드투엔드 슬라이스로 먼저 닫고, 그 위에 10개 저작 스테이지·일시정지·진행저장·피드백을 커버리지 매트릭스대로 빠짐없이 얹는다.

## 2. 빌드 항목의 동사 문장 (25/25 — 원장 행과 1:1)

**R1 — 스테이지**
1. (M1) 구현자가 `stages.ts`에 10개 스테이지를 저작하면 선택 화면 10칸이 그 데이터로부터 렌더된다; 부재 시 선택 화면이 1~2칸이거나 같은 판만 반복된다.
2. (M2) 플레이어가 스테이지 n을 선택하면 물리 월드가 비워지고 해당 데이터의 바디들이 조립되어 조준 상태로 시작된다; 부재 시 이전 스테이지 잔해 위에 새 판이 겹쳐 쌓인다.
3. (M3) 플레이어가 선택 화면을 열면 해제된 스테이지는 획득 별 수와 함께, 잠긴 스테이지는 잠금 표식으로 보인다; 부재 시 어디까지 깼는지 화면만으로 알 수 없다.
4. (M4) 플레이어가 클리어 후 브라우저를 껐다 켜면 해제 상태와 최고 별이 남아 있다; 부재 시 재방문마다 스테이지 1부터다.

**R2 — 슬링샷 물리**
5. (M5) 스테이지가 로드되면 구조물이 중력 아래 수 초 내 정지 안착한다; 부재 시 손대지 않은 탑이 저절로 흔들리거나 무너진다.
6. (M6) 플레이어가 새를 누르고 끌면 새가 당김 방향으로 패드 주변을 따라오고 고무줄 밴드가 그려진다; 부재 시 클릭해도 화면에 아무 변화가 없다.
7. (M7) 플레이어가 드래그를 놓으면 새가 당김 반대 방향으로 당김 길이에 비례한 속도로 날아간다; 부재 시 새가 제자리에서 굴러떨어진다.
8. (M8) 플레이어가 당기는 동안 예상 포물선 점선이 실시간 갱신된다; 부재 시 조준이 순전히 감이라 초반 스테이지부터 반복 실패가 쌓인다.
9. (M9) 새나 파편이 임계 이상 세기로 블록을 때리면 블록 hp가 깎이고 0에서 제거된다; 부재 시 구조물이 영구 장애물이 되어 뒤에 숨은 돼지가 있는 스테이지는 클리어 불가가 된다.
10. (M10) 충돌 세기가 돼지 임계를 넘으면 돼지가 제거되고 잔여 돼지 수가 준다; 부재 시 명중해도 클리어 판정이 영원히 나지 않는다.
11. (M11) 발사 후 모든 동적 바디가 정지하거나 8초가 지나면 다음 새가 패드에 장전되거나 판정으로 넘어간다; 부재 시 첫 발사 후 게임이 조준 불능 상태로 멈춘다.
12. (M12) 잔여 돼지가 0이 되면 클리어 오버레이가, 새 소진 + 정산 후 돼지가 남으면 실패 오버레이가 뜬다; 부재 시 판을 끝낼 방법이 없다.
13. (M13) 파괴·제거·잔여 새가 점수로 합산되고 클리어 시 스테이지별 임계 대비 별 1~3개가 뜬다; 부재 시 클리어의 잘함/못함 구분이 사라져 재도전 동기가 없다.
14. (M14) 매 프레임 물리 바디의 위치·각도가 Canvas에 도형으로 그려진다; 부재 시 화면이 빈 캔버스다.
15. (M15) rAF 콜백이 누적 시간을 고정 스텝(1000/60ms)으로 나눠 물리를 갱신한다; 부재 시 프레임 드랍 기기에서 물리 결과가 달라지고 빠른 새가 벽을 관통한다.

**R3 — 일시정지**
16. (M16) 플레이 중 화면 우측 상단 버튼을 클릭하면 즉시 PAUSED로 전환된다; 부재 시 플레이를 멈출 수단이 탭을 닫는 것뿐이다.
17. (M17) PAUSED에서 반투명 오버레이에 계속하기/다시하기/메인으로가 뜨고, 다시하기는 같은 스테이지를 초기 상태로 재로드, 메인으로는 메인 화면으로 전환한다; 부재 시 일시정지가 탈출구 없는 정지 화면이 된다.
18. (M18) PAUSED 동안 물리 갱신·슬링샷 입력·턴 타이머가 전부 멈추고 계속하기 시 그 시점 그대로 재개된다; 부재 시 정지 화면 뒤에서 새가 계속 날아가 일시정지가 기능하지 않는다.

**화면 흐름**
19. (M19) 모든 화면 전환이 단일 `scene` 값의 전이 함수 한 곳에서만 일어난다; 부재 시 오버레이가 겹치거나 메인 화면 뒤에서 물리가 도는 유령 상태가 생긴다.
20. (M20) 접속하면 타이틀과 "게임 시작" 버튼이 보이고 클릭 시 스테이지 선택으로 넘어간다; 부재 시 게임에 진입점이 없다.
21. (M21) 클리어 시 별·점수·다음 스테이지/다시하기/메인으로가, 실패 시 다시하기/메인으로가 뜬다; 부재 시 판이 끝나도 다음 행동이 없다.

**마감 품질**
22. (M22) 블록·돼지가 제거되는 순간 그 위치에 파편 파티클과 점수 팝업이 뜬다; 부재 시 무엇이 부서졌는지 귀속이 안 보여 타격감이 죽는다.
23. (M23) 발사·충돌·파괴·클리어에 WebAudio 합성 효과음이 재생된다; 부재 시 게임 전체가 무음이라 미완성으로 느껴진다.
24. (M24) 창 크기가 바뀌면 1280×720 논리 좌표가 비율 유지 레터박스로 스케일된다; 부재 시 작은 창에서 슬링샷이 화면 밖으로 잘린다.
25. (M25) 탭 복귀 시 누적 dt가 50ms로 잘려 소화된다; 부재 시 탭 전환 후 구조물이 폭발하듯 튀어 있다.

## 3. 표면별 품질 바닥선 (한 문장씩)

- **메인**: 접속에서 첫 발사까지 클릭 3회(시작→스테이지→드래그) 이내.
- **스테이지 선택**: 잠금/해제/별이 텍스트 없이도 한눈에 판독된다.
- **인게임 조준**: 드래그 중 당김 방향·세기·예상 궤적이 항상 동시에 보인다.
- **파괴 피드백**: 모든 파괴는 반드시 시각(파티클)+청각(효과음)+점수 팝업 셋으로 응답한다.
- **일시정지**: 동결은 완전하고(재개 시 바디 위치 오차 0) 버튼 세 개는 항상 즉답한다.
- **결과 화면**: 점수·별과 다음 행동(다음/다시/메인)이 판독에 1초를 넘기지 않는다.

## 4. 문제 정의 / 목표

브라우저에서 동작하는 앵그리버드류 슬링샷 물리 게임. 성공 정의: 이 문서만 가진 구현자가 (a) 10개 스테이지를 전부 플레이·클리어 가능하게, (b) 드래그-발사-파괴-판정의 물리 루프가 닫히게, (c) 우측 일시정지 버튼과 다시하기/메인으로 오버레이가 스펙대로 동작하게 만들 수 있다. 서버 없음, 오프라인 단일 플레이어, 에셋 0(도형 렌더 + 합성음).

## 5. 핵심 규칙 명세

**씬 상태 머신 (M19)** — `MAIN → SELECT → PLAYING ⇄ PAUSED`, `PLAYING → CLEAR | FAIL`, `CLEAR → (다음 스테이지) PLAYING | SELECT | MAIN`, `FAIL → PLAYING(재시도) | MAIN`. PAUSED의 다시하기는 `PLAYING(같은 n 재로드)`. 이 전이 목록에 없는 전환은 금지.

**인게임 페이즈** — `AIMING(조준) → FLYING(비행) → SETTLING(정산) → AIMING(다음 새) 또는 판정`. 슬링샷 입력은 `PLAYING && AIMING`에서만 수용.

**스테이지 스키마 (M1·M2)** — TS 모듈 `stages.ts`, 스테이지당: `id`, `birds`(발사체 수), `blocks[]{shape, material, x, y, w, h, angle}`, `pigs[]{x, y, r}`, `starScores[2]`(2·3별 점수 임계), `intent`(저작자 의도 해법 주석 — 필수 필드). 재료: `wood | stone | ice`. 지형은 평지 + 정적 받침 블록으로 표현(별도 지형 시스템 없음).

**데미지 모델 (M9·M10)** — `collisionStart` 쌍에서 충돌 세기 `severity = |v_A − v_B|`(두 바디 속도 벡터 차의 크기). `severity > 재료 임계`이면 `hp -= (severity − 임계)`. hp ≤ 0 → 제거 + 이펙트 + 점수. 돼지도 같은 규칙(자체 임계·hp).

**턴 종료 (M11)** — FLYING/SETTLING 중 "모든 동적 바디 speed < 0.15가 45프레임 연속" 또는 "발사 후 8초 경과" → 정산: 돼지 0이면 CLEAR, 새 남으면 다음 장전, 아니면 FAIL.

**점수·별 (M13)** — 돼지 5,000 / 블록 파괴 500 / 클리어 시 잔여 새 1마리당 10,000. 별: 1별 = 클리어 자체, 2·3별 = `starScores` 임계 도달.

**슬링샷·궤적 (M6~M8)** — 당김 벡터 `d`(최대 120px 클램프), 발사 속도 `v0 = −k·d`. 새는 `frictionAir = 0`으로 고정하고 발사는 `setVelocity`로 — 그래야 궤적 예측이 폐형식 등가속 공식(`p(t) = p0 + v0·t + ½g·t²`)과 정확히 일치한다. 점선은 3틱 간격 24점.

**초기값 표** — 모든 수치는 세 태그 중 하나를 단다.

| 값 | 초기값 | 태그 |
|---|---|---|
| 논리 해상도 | 1280×720 | (a) 도출 — 16:9 관례, 레터박스 전제 |
| 중력 | Matter 기본 `y=1` | (a) 도출 — 엔진 캘리브레이션 기본값 |
| 고정 스텝 / dt 클램프 | 1000/60ms / 50ms | (a) 도출 — 터널링·나선 폭주 방지 관례 |
| 점수 배점 | 5,000/500/10,000 | (a) 도출 — 원작 관례 차용 |

| 파괴 임계 / hp | ice 4/2 · wood 7/4 · stone 11/8 · 돼지 5/6 | (c) 임의 — 동일 수명 |

## 6. 차용 판정: 물리 엔진 — 직접 구현 vs Matter.js (dialectic 1절)

판정 함수(사전 고정): **오판 시 되돌림 비용 × 발생 확률**. 직접 구현의 실패(적층 안정·회전 충돌 해석이 안 됨)는 수 주 재작업이고 발생 확률이 높다(검증된 솔버가 아님). Matter.js의 실패(성능·엣지 버그)는 국지 우회가 가능하고 확률이 낮다(성숙 라이브러리). **판정: Matter.js.**
패자 논거 승격 — 직접 구현 진영의 최강 논거는 "의존성 통제와 결정론"이며, 이는 승자의 제약이 된다: **Matter 접촉은 `physics.ts` 어댑터 한 파일로 격리하고, 게임 규칙 코드는 Matter 타입을 직접 import하지 않는다.** 재판정 트리거: 적층 떨림이 sleeping 활성·iteration 상향·저작 규칙(§8 R1)으로도 안 잡히면 이 판정을 재개한다.

## 7. 명시적 가정

- **A1 (하중 가정): Matter의 `collisionStart` 쌍에서 두 바디의 `velocity`로 §5의 severity를 계산할 수 있다.** 틀리면: 데미지 모델 전체가 공중분해. 최저가 조기 검증: 스텝 3의 첫 충돌에서 쌍 바디의 velocity 값을 1회 로그로 확인. 폴백: 어댑터가 틱 전후 속도 차를 자체 기록해 severity를 산출(같은 인터페이스, 구현만 교체).
- A2: 대상은 evergreen 브라우저(Pointer Events, ES2020, WebAudio). 틀리면: 지원 범위 명시로 종료 — 폴리필은 범위 밖.
- A3: 도형+색 렌더로 표현이 충분하다(에셋 0). 틀리면: 렌더러가 `renderer.ts`로 격리돼 있어 스프라이트 도입은 국지 수정.
- A4: 서버 없음, 단일 플레이어. 틀리면: 범위 재협상 — 이 플랜은 무효.

## 9. Load-bearing path — 이 사슬이 닫히지 않으면 나머지 전부가 장식이다

경로: **게임 시작 → 스테이지 로드 → 발사 → 충돌·파괴 → 클리어 표시** (패킷 후보와 동일 판단).

| hop | 이름 | passes only if | 그 조건이 처음 참이 되는 곳 |
|---|---|---|---|
| h1 | 메인 "게임 시작"→선택→`loadStage(n)` 호출 | `scene`이 MAIN/SELECT이고 `STAGES[n]` 존재 | `scene=MAIN`: 스텝 1 부트스트랩 / `STAGES`: 스텝 2 `stages.ts` |
| h2 | pointerup에 슬링샷이 새에 `v0=−k·d` 적용, phase→FLYING | `scene===PLAYING && phase===AIMING && bird` 존재 | `loadStage()`(스텝 2·3)가 bird 생성 + `phase=AIMING`; PLAYING 전환은 h1의 전이 함수 |
| h3 | 고정 스텝 루프가 `Engine.update` 실행, `collisionStart` 발화 | rAF 루프 가동 && 충돌 핸들러 등록됨 | 둘 다 스텝 1 부트스트랩(1회 실행) — 핸들러 본체는 스텝 3 |
| h4 | severity ≥ 임계 → 돼지 제거, `remainingPigs--` | 핸들러가 바디를 엔티티(돼지/블록)로 식별 가능 | 스텝 3: `loadStage`가 각 바디에 엔티티 태그 부착; 임계는 스텝 4 `config.ts` |
| h5 | `remainingPigs===0` → `scene=CLEAR`, 결과 오버레이 렌더 | 정산 체크가 매 틱 실행 중 | 스텝 4의 판정 루틴을 스텝 1 루프에 등록; 오버레이는 스텝 5 |

**콜드스타트 표** — 위 "passes only if"에 등장하는 모든 상태:

| 상태 | 최초 진입 시 값 | 누가 바꾸나 | 언제 실행되나 |
|---|---|---|---|
| `scene` | `MAIN` (부팅 시) | 전이 함수(스텝 1) 단독 | 버튼 클릭·판정 발생 시 |
| `STAGES` | 컴파일 타임에 10원소 확정 | 저작자만(런타임 불변) | 스텝 2·7에서 저작 |
| `phase` | `loadStage()`가 `AIMING` 설정 | 발사(→FLYING)·정지 감지(→SETTLING)·장전(→AIMING) | 스텝 3 |
| `bird` | `loadStage()`가 생성·패드 배치 | 발사 소비, 턴 종료 시 재장전 | 스텝 3 |
| rAF 루프 | 부트스트랩에서 시작, 상시 가동(PAUSED엔 `Engine.update`만 스킵) | 없음(중단 안 함) | 스텝 1 |
| 충돌 핸들러 | 부트스트랩에서 1회 등록 | 없음(재등록 안 함) | 스텝 1(등록)·3(본체) |
| `remainingPigs` | `loadStage()`가 `pigs.length`로 설정 | 데미지 시스템이 감소 | 스텝 3·4 |
| `birdsLeft` | `loadStage()`가 `birds`로 설정 | 발사 시 감소 | 스텝 3 |
| 입력 리스너 | 부트스트랩에서 1회 바인딩; `PLAYING && AIMING` 아니면 무시 | 없음 | 스텝 1(바인딩)·3(가드) |

빈 셀 없음. 사슬의 모든 심볼(`loadStage`, `stages.ts`, 전이 함수, 태그, 판정 루틴, 오버레이)은 §8의 스텝이 생성을 약속한 것들이다.

## 10. 대안과 기각 근거 (각 기각에 부활 트리거)

- **물리 직접 구현** — 기각: §6 판정. 부활: §6의 재판정 트리거.
- **WebGL/Pixi 렌더링** — 기각: 도형 수십 개 렌더에 과함, Canvas 2D로 충분. 부활: 파티클 포함 상태에서 기준 기기 60fps 미달이 관측되면.
- **React 등 UI 프레임워크** — 기각: 오버레이 몇 장에 캔버스-DOM 이중 상태 관리 비용이 더 큼. 부활: 메뉴·설정류 화면이 3개를 넘게 늘어나면.
- **JSON 파일 스테이지 로딩** — 기각: 런타임 파싱·검증 코드가 필요해지고 스키마 보장이 약해짐(TS 모듈은 컴파일 타임 보장, N2 참조). 부활: 비개발자 저작 도구/에디터 요구가 생기면.
- **Matter Constraint(고무줄 물리)로 발사** — 기각: 발사 속도가 제약 해제 타이밍에 좌우돼 궤적 예측(M8)과 불일치. `setVelocity`는 예측 공식과 수식을 공유한다. 부활: 밴드의 물리적 출렁임 연출이 요구로 승격되면.

## 11. 리스크와 완화

- **적층 불안정**(탑이 저절로 무너짐 — M5 위협): sleeping 활성, `positionIterations` 상향, 저작 규칙 "받침 없는 세장비 3 초과 금지". 잔존 시 §6 재판정.
- **궤적-실물리 불일치**(M8): 새 `frictionAir=0` + `setVelocity` + 폐형식 공식의 3자 일치가 설계 자체로 보장 — 파편·블록은 기본 마찰 유지(예측 대상 아님).
- **튜닝 실패로 난이도 붕괴**(M1): 임의 값이 `config.ts` 한 곳 + 스텝 7이 튜닝 전용으로 명명됨 — 흩어진 매직넘버가 원인이 되는 경로를 차단.
- **일시정지 누수**(M18): 시간은 rAF 벽시계가 아니라 시뮬레이션 누적기로만 계산 — PAUSED 동안 누적기가 안 돌면 8초 타임아웃도 같이 멈춘다.
- **타입 정의 불일치**(`@types/matter-js`가 실제 API와 어긋남): Matter 접촉이 `physics.ts`로 격리돼 있어 `any` 국지 처리로 흡수.

## 12. 완료 정의

1. `npx tsc --noEmit`이 exit 0, `npm run build`가 exit 0. (스택이 산 보증의 명령 증명 — §13)
2. localStorage를 비운 새 프로필로 접속하면 스테이지 1만 해제돼 있고, 1을 클리어하면 2가 해제되며, 새로고침 후에도 유지된다.
3. 10개 스테이지 각각, 데이터의 `intent` 주석에 적힌 해법대로 발사하면 클리어에 도달한다(스텝 7 저작 시 스테이지당 확인 — 판정 로직이 자동 충족할 수 없는 사람 플레이 기준).
4. 플레이 중 우측 상단 일시정지 클릭 → 물리 동결 + 계속하기/다시하기/메인으로 표시. 다시하기는 같은 스테이지 초기 상태, 메인으로는 메인 화면, 10초 정지 후 계속하기 시 모든 바디 위치가 정지 시점과 동일.
5. 임의 블록 하나를 파괴하면 파티클·효과음·점수 팝업 셋이 모두 발생한다(§3 바닥선).

## 13. 구현자 계약

- **스택(전부 npm에서 해석되는 버전)**: `vite@5.4.8`, `typescript@5.5.4`, `matter-js@0.20.0`, `@types/matter-js@^0.19.0`. 산 이유와 증명: TS는 스테이지 스키마·씬 전이의 컴파일 타임 강제를 위해 — `npx tsc --noEmit` exit 0이 그 증명. Vite는 번들·데브 서버 — `npm run build` exit 0이 그 증명.
- **기각안 부활 트리거**: §10의 다섯 트리거가 전부다 — 트리거 없는 금지는 없다. 관측되면 해당 기각을 재개하라.
- **격리 규칙**: Matter API 접촉은 `physics.ts` 한 파일. 게임 규칙 코드에 Matter import가 보이면 §6 패자 제약 위반이다.
- **수치 규칙**: (c) 태그 값은 전부 `config.ts`에 있고, 스텝 7이 유일한 교체 지점이다. 거기 없는 매직넘버는 결함.

## Frame deviations & habit regressions

- §5 초기값 표의 (c) 값들에 수명(스텝 7)은 걸었지만, 스텝 7의 튜닝 합격 기준("재미있다")은 조작화하지 못했다 — 리뷰어라면 여기를 공격하겠다.
- 관례 우선 채택: 계속하기 버튼(M17)·선택 화면(M3)·점수/별(M13)을 스펙 없이 build로 승격했다. 프레임의 "완성으로 느껴지기 위해 필요" 조항으로 정당화했으나, 그 경계선 자체는 내 판단이다.
- 가장 약한 절은 M8 궤적 예측이다: 예측-실물리 일치를 §11에서 "설계로 보장"이라 주장했지만 §12 완료 정의에는 그 일치를 검사하는 문장이 없다.
- 시간축 회귀 점검: §8의 0→5는 실제 직렬 의존이라 사다리 서술이 정당하나, 6·7·8의 병렬성은 표의 한 칸과 각주 한 줄에만 실려 있어 구현자가 직렬로 읽을 소지가 남아 있다.
