# z-lab

*다른 언어로 읽기: [English](./README.md)*

출시를 앞둔 플러그인의 실험, 그리고 그 과정에서 생기는 크고 작은 실험들을 검증하는 공간이에요.

여기서 만드는 것은 제품이 아닙니다. 이 저장소의 모든 작업은 단 하나를 만들기 위해 존재하는데, 바로 **증거가 붙어 있는 측정된 발견**입니다. 그리고 검증을 통과한 발견만이 실제 플러그인(예: [plan-smith](https://github.com/zeriong/plan-smith))의 릴리스로 나갑니다.

## 랩이 돌아가는 방식

실험 설계, 오염 방지, 기록 규약은 [CLAUDE.md](./CLAUDE.md)에 법령으로 정리되어 있어요. 조항 하나하나가 이 저장소에서 실제로 겪은 실패에서 나왔기 때문에, 근거 없이 존재하는 규칙은 없습니다. 핵심만 추리면 이렇습니다.

- **표본은 손대지 않습니다.** 실험 산출물을 검증하거나 리뷰하거나 스스로 고치는 순간, 무엇을 측정했는지 말할 수 없게 돼요.
- **금지는 프롬프트가 아니라 구조로 겁니다.** 하지 말라고 부탁하는 대신, 도구 자체를 제거합니다.
- **실험은 기록이 완성되었을 때 끝납니다.** 입력 명세, arm별 산출물, `METRICS.md`, 발견 문서 — 넷 중 하나라도 없으면 미완이에요.
- **측정하지 않은 것은 주장하지 않습니다.** 모든 보고서는 측정한 것과 측정하지 않은 것을 분리해서 적습니다.

## 실험 계열

| 디렉토리 | 내용 |
|---|---|
| `plan-smith-lab/` | plan-smith 플러그인 검증 계열이에요. 모델별 플랜 코퍼스(`fable-plan/`, `opus-plan/`), 순수 모델 1-shot 측정(`pure-model/`), 플랜→약한 구현자 전이 실험(`transfer/`), 작동하는 산출물까지의 총비용 비교(`tco/`), 통제 A/B 라운드(`test/`), 그리고 표본과 엄격히 분리된 분석(`analyze/`)으로 구성됩니다. 이 계열의 발견들이 plan-smith v1.1~v1.4 릴리스의 근거가 되었어요. |

새 실험 계열은 `<주제>-lab/` 디렉토리로 추가합니다. 디렉토리 규약은 CLAUDE.md 제9조를 참고해 주세요.
